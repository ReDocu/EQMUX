# 0.6 실기 확인 목록

2026-11-02 · 리드 eqmux-68 · 근거 `update-0.6-scope.md` §7, 진행 기록 `update-0.6-work-split.md`

단위 테스트로 볼 수 없는 것만 적는다. 각 절은 그 스트림이 쓴다. 자기 절만 덧붙이고 남의 절은 고치지 않는다.

형식: `| 항목 | 절차 | 기대 결과 | 플랫폼 |`. 플랫폼은 Win · mac · 둘 다.

| 항목 | 이유 |

| Codex 실측 2건 — `apply_patch` 경로, PermissionRequest 결정 형식 | 측정에 `codex --dangerously-bypass-hook-trust`가 필요하다. 세션 권한에서 거부돼 하지 않았다 |

## W1 — 런타임 · 저장 · 종료 · 확장

준비: 셸 세션 하나 이상, 에이전트(Claude) 세션 하나. 앱 데이터 폴더 = Windows `%APPDATA%\com.eqment.eqmux`, mac `~/Library/Application Support/com.eqment.eqmux`. 세션 기록 DB는 그 아래 `workspaces/<워크스페이스>/session.db`.

## W2 — 에이전트 · 훅 · 진단

준비: Claude Code 2.1.316 이상, 시험 저장소 하나. 진단 로그는 `diagnostics.log`(앱 데이터 폴더).

| 항목 | 절차 | 기대 결과 | 플랫폼 |
|---|---|---|---|
| A1 승인함 허용 | 세션을 `--permission-mode default`로 띄워 `mkdir x`를 시킨다 → 승인함에서 [허용] | 페인 대화상자가 닫히고 명령이 실행된다. 대기 중 세션 상태 칩에 도구 요약(`Bash · mkdir x`)이 보인다 | 둘 다 |
| A2 승인함 거부 | A1과 같이 → [거부] | 도구가 실행되지 않고 에이전트가 거부 사유를 받는다 | 둘 다 |
| A3 페인이 먼저 답함 | 승인 대기 중 페인에서 직접 1/Esc로 답한 뒤 승인함 버튼 | 페인 답이 이긴다. 승인함 항목이 사라지거나 버튼이 "기다리는 승인이 없음"(NOT_WAITING)으로 끝난다. 둘이 엇갈려 두 번 실행되지 않는다 | 둘 다 |
| A4 긴 대기 | 승인 요청을 10분 가까이 둔다 | 9분 30초에 훅이 물러나 페인 대화상자만 남는다. 앱이 멈추지 않는다 | 둘 다 |
| A5 Codex 승인 | Codex 세션에서 승인이 필요한 명령 | 승인함에 뜨지 않는다(훅 응답 형식 미측정 — 맨 위 "사용자 허락" 참고). 페인에서 답하면 된다 | 둘 다 |
| C1 동시 편집 경고 | 같은 워크스페이스 세션 두 개에 같은 파일을 10분 안에 각각 고치게 한다 | 두 번째 편집 뒤 동시 편집 경고 하나(`edit-conflict` 이벤트). 경로는 워크스페이스 기준 상대 경로 | 둘 다 |
| C2 다른 파일 | 두 세션이 서로 다른 파일만 고친다 | 경고 없음 | 둘 다 |
| M1 mac 빌드 | mac에서 `cd src-tauri && cargo check` · `cargo test --lib` | 경고 · 오류 없음. `job.rs` mac 분기(terminate · `process_start_ms`)와 `agent.rs` `cfg(macos)` 코드는 **Windows에서 컴파일하지 못했다** | mac 필수 |
| T1 종료 유예 | mac에서 에이전트가 도는 페인을 닫는다 / 앱을 끈다 | 루트는 SIGHUP, 나머지는 SIGTERM → 1.5초 안에 정리 → 남은 것만 SIGKILL. `claude` 레지스트리 파일이 정상 종료로 지워진다(좀비 · 고아 프로세스 없음, `ps -ef \| grep claude`) | mac 필수 |
| I1 주입 도착 로그 | 세션에 메시지를 보낸다(`eqmux send` 또는 UI) → 에이전트가 그 턴을 받는다 | `diagnostics.log`에 `INJECT-SUBMITTED <세션> <id…>` 한 줄. 화면 쪽은 `message-injected` 이벤트로 "도착" 표시(W7) | 둘 다 |
| V1 버전 알림 | 낮은 버전 Claude Code(2.1.316 미만, 예 `npm i -g @anthropic-ai/claude-code@2.1.300`)로 세션 시작 | 알림 센터에 엔진 버전이 낮다는 알림 한 번(`notify-item` kind `cli-version`). 같은 버전으로 세션을 더 열어도 다시 뜨지 않는다. 세션은 막히지 않는다. 시험 뒤 최신으로 되돌린다 | 둘 다 |
| V2 버전 정상 | 최신 Claude Code · Codex 0.146.0 이상 | 알림 없음 | 둘 다 |
| S1 멈춤 표시 | 에이전트가 도구 실행 중 10분 넘게 훅이 오지 않게 한다(예: `sleep 700`을 Bash로) | 상태 칩에 멈춤 표시(`stalled`)가 붙고 판정 근거에 마지막 훅 이름 · 시각. 훅이 다시 오면 풀린다 | 둘 다 |
| R1 레지스트리 낡은 기록 | 페인에서 `claude`를 띄웠다 끝내고 같은 페인에서 다른 `claude`/`node`를 띄운다 | 끝난 대화가 페인에 다시 붙지 않는다 · 피어 이름이 이전 세션 것으로 보이지 않는다 | 둘 다 |
| P1 심볼릭 링크 cwd (B121) | 저장소를 가리키는 심볼릭 링크/정션 폴더를 워크스페이스로 열고 대화 → 재개 · 대화 탭 | 대화 기록이 보이고 [재개]가 켜진다(실제 경로 폴더를 찾는다) | 둘 다 |
| P2 한글 폴더 (B121 · NFD) | mac에서 한글 이름 폴더를 워크스페이스로 열고 대화 → 재개 | 대화 기록이 보인다. 안 보이면 `~/.claude/projects/`의 폴더 이름과 앱이 찾은 이름(자모 수만큼 `-`)을 적어 W2에 넘긴다 | mac 필수 |
| D1 진단 묶음 | 진단 묶음 만들기(`diag_bundle`) | 사용자 이름 · 홈 경로 · 토큰류(`token=` · `Bearer` · `sk-…`)가 가려져 있다. Claude · Codex 버전 줄이 있다 | 둘 다 |
| D2 다른 도구 감지 | `~/.claude/settings.json`에 다른 도구 훅을 하나 넣는다 | 진단의 다른 도구 목록(`diag_foreign_tools`)에 그 도구 이름이 나온다 | 둘 다 |

## W3 — 메시지 버스 · CLI · 과거 세션 · 팔레트

준비: 같은 워크스페이스의 Claude Code 세션 둘(A · B, B에는 직함이 있다), 다른 워크스페이스 세션 하나(C). Windows는 pwsh 7 페인과 Windows PowerShell 5.1 페인을 하나씩. 다른 절과 겹치는 항목은 그 절을 따른다: 매 턴 상기 · 기억은 W4 C3 · C6, 선행 임무 알림은 W4 M5, `eqmux read` 가림은 W6 L2, 클립보드 기록 제외는 W6 E11.

### 메시지 버스 · CLI (§2 · §4)

| 항목 | 절차 | 기대 결과 | 플랫폼 |
|---|---|---|---|
| Q1 PowerShell 한글 | pwsh 7 · Windows PowerShell 5.1 페인에서 `eqmux who` · `eqmux send "@B" "한글 — 확인"` | 결과 줄의 한글이 깨지지 않는다. 시스템 코드 페이지(949)로 바꿔 내보내므로 `—`는 `―`로 보일 수 있다 | Win |

## W4 — 역할 · 캐릭터 · 임무

준비: git 저장소인 시험 워크스페이스 하나, 페르소나 셋 이상(기본 · 중급 · 고급 하나씩), 팀 캐스팅으로 띄운 Claude Code 세션 둘 이상. 역할 파일은 `.eqmux/roles/<세션>.md`, 임무 파일은 `.eqmux/missions/<id>.md`.

### 임무 — 시작점 · 선행 임무 · 비용 (§13-2 · §4 · §13-6)

| 항목 | 절차 | 기대 결과 | 플랫폼 |
|---|---|---|---|
| M1 시작점 기록 | 임무를 만들고 세션 하나에 처음 배정 → 임무 파일 frontmatter | `base_commit: <HEAD 해시>`. 카드에 "시작 abc1234" | 둘 다 |
| M2 그 뒤 커밋 수 | M1 뒤에 커밋 두 개 → 임무 화면을 다시 연다 | "시작 abc1234 · 그 뒤 커밋 2개". 다른 세션을 더 배정해도 `base_commit`은 그대로 | 둘 다 |
| M3 브리프 전달이 시작점을 덮는다 | 임무 탐색기에서 임무 파일을 고르고 [브리프 전달] | `base_commit`이 그때의 HEAD로 바뀐다. git 저장소가 아니면 키가 생기지 않고 오류도 없다 | 둘 다 |
| M4 선행 임무 칩 | 임무 B 파일 frontmatter에 `depends_on: <A id> zzz`를 적는다 → 임무 화면 | B 카드에 "선행 임무" 칩 A · zzz. 모르는 id(zzz)도 그대로 보인다. A가 done이면 칩 앞에 "✓ " | 둘 다 |
| M5 선행 임무 끝 알림 | B에 세션을 배정 → A를 [검토하기] → [승인](또는 상태를 done으로) | B 담당 세션에 report "선행 임무 'A' 끝남 — 'B'의 선행 임무가 모두 끝났다". 선행이 더 남았으면 "아직 …를 기다린다" | 둘 다 |
| M6 임무별 비용 | 배정된 세션에게 일을 시켜 비용이 생기게 한다 → 1분 기다린다 | 그 임무 카드와 검토 화면 머리 줄에 "비용 $x.xx". 비용 없는 임무에는 줄이 없다. 배정을 바꾼 직후 1분 안의 비용은 이전 임무로 갈 수 있다(W2 캐시) | 둘 다 |

### 임무 검토 화면 (§13-3)

준비: `.eqmux/commands.json`에 `{"version":1,"commands":[{"name":"test","run":"npm test","kind":"test"}]}`. 서버 탭 셸 하나.

| 항목 | 절차 | 기대 결과 | 플랫폼 |
|---|---|---|---|
| R1 진입 | 완료 보고(`eqmux report --done`)가 온 IN-PROGRESS 임무 · IN-REVIEW 임무 · TODO 임무 | 앞의 둘에만 [검토하기]. 대화 탭 [검토 →]로도 같은 화면이 열린다 | 둘 다 |
| R2 왼쪽 열 | 목표 · 산출물 체크 · 완료 보고(보낸 세션 이름) · "담당 세션이 고친 파일 · N개" | 고친 파일은 배정 뒤 그 임무 담당 세션이 편집 도구로 고친 것만, 저장소 기준 경로(`/`)로 | 둘 다 |
| R3 diff 필터 | 담당 세션이 a.ts를, 담당이 아닌 세션이 b.ts를 고친다 → 검토 화면 | 오른쪽 diff 목록에 a.ts만. [전체 변경 보기]를 켜면 b.ts도. 편집 기록이 없는 임무는 처음부터 전체 | 둘 다 |
| R4 시작점 기준 | 임무 시작 뒤 커밋된 파일 · 커밋 안 된 파일 · 새 파일이 섞인 상태 | 셋 다 목록에 있다. 이름 변경은 R. 브랜치 · 동기화 줄과 ✕가 없다. 시작점 없는 임무는 HEAD ↔ 작업 트리이고 머리 줄에 그렇게 적힌다 | 둘 다 |

| R7 테스트 실행 — 셸 없음 | 서버 탭 셸을 닫고 [테스트 실행] | 서버 탭이 열리고 "서버 탭 셸이 없습니다…다시 누르세요". 셸이 뜬 뒤 다시 누르면 돈다 | 둘 다 |
