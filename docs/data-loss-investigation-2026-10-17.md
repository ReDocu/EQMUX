# 앱 데이터 소실 원인 조사 (2026-10-17)

`docs/update-0.5.1-scope.md` §1의 "사용자 앱 데이터 소실(원인 미상)"을 다시 조사했다. 사건 기록은 `docs/fix-0.5.0-qa-status.md` "남은 것"에 있다.

## 결론

- **가장 유력한 원인은 0.5 이전 EQMUX가 같은 앱 데이터 폴더에서 실행된 것이다.**
  - 0.4.x 이하는 시작할 때 `data.ver`가 자기 버전과 다르면 `%APPDATA%\com.eqment.eqmux`를 비운다. 이때 `settings.json`·`jobs`·`personas`·`presets` 네 가지만 남기고 나머지를 지운다(`v0.4.2:src-tauri/src/lib.rs` 2335~2362행).
  - 0.5.0과 0.4.x는 식별자가 같아 같은 폴더를 쓴다. 그래서 0.5.0을 쓰다가 옛 버전을 한 번 실행하면 등록부·워크스페이스 데이터·배치가 지워진다.
- **0.5 코드에는 이 파일들을 지우는 경로가 없다.** 등록부 쓰기 경로(`ws_register`·`ws_unregister`·`ws_repath`·`ws_touch`)는 모두 `load_strict`를 쓴다. 그래서 읽기 실패를 빈 목록으로 덮어쓰지 않는다. `workspaces/` 데이터 폴더를 지우는 코드는 앱 어디에도 없다(테스트 제외 전수 검색).
- **사건 시각에 앱이 시작됐는데, 그것을 띄운 Claude 세션이 없다.** 사람이 직접 띄운 실행으로 본다. 이 PC에는 `C:\Users\USER\Downloads\EQMUX_0.4.2_x64_portable\EQMUX\eqmux.exe`(0.4.2, 9/21 압축 해제)가 있다.
- **남은 불확실성:** 두 번째 사건 직후 백업의 `data.ver`가 0.4.2가 아니라 0.5.0이다(아래 §사건 2). 옛 버전 실행 자체를 직접 본 증거(실행 기록)는 없다. 그 시각에 0.4.2 포터블(또는 다른 옛 버전)을 실행했는지 사용자 확인이 필요하다.

### 사건 2의 어긋남

- 22:25 백업(`appdata-backup2`)은 정상이었다(등록 1개 + 데이터 폴더).
- 22:40:3x 백업(`appdata-backup3`, 22:40:57 재실행 전)에는 `workspaces.json`·`workspaces/`가 없고 `layout.json`은 빈 열린 목록이었다. `data.ver`는 **0.5.0**, `running.flag`가 있었다.
- 옛 버전이 마지막으로 실행됐다면 `data.ver`는 0.4.2여야 한다. 0.5.0이 적혔다는 것은 wipe 뒤에 0.5.0 계열 앱이 한 번 더 빈 폴더로 시작했다는 뜻이다. 22:34:53 시작이 그것이고, wipe는 22:31:12~22:34:53 사이에 진단 기록을 남기지 못한 짧은 옛 버전 실행이었을 수 있다. 0.4.2의 wipe는 웹뷰가 뜨기 전 `setup`에서 일어나므로, 화면이 뜨기 전에 닫으면 `startup` 기록이 남지 않는다.
- 이 부분은 추정이다.

### 배제한 것

- **0.5 앱 코드:** 위 §결론.
- **Claude 세션의 셸 명령:** 앱 데이터 경로를 건드린 명령은 백업 복사(`cp -r`)와 QA용 `qa-ws` 폴더 정리(`rm -rf …/workspaces/qa-ws-de054b`)뿐이다. 사건 시각과 맞는 삭제 명령은 없다.
- **테스트:** Rust 테스트는 모두 `temp_dir()` 아래를 쓴다. 프런트 테스트는 Tauri 밖에서 돈다.
- **다운로드한 0.4.2(`27918306…/scratchpad/rel/prev`):** 23:26에 받았으므로 사건보다 늦다.

## 대응 제안

1. **지금 바로 (사용자):** `Downloads\EQMUX_0.4.2_x64_portable`을 지우거나 이름을 바꿔, 실수로 다시 실행하지 않게 한다. 다른 옛 버전 바로가기도 같다.
   - **반영(2026-10-17):** Downloads의 0.4.2·0.5.0 포터블 폴더와 zip을 지웠다. 앱 데이터의 `session.db.bak*`와 QA 세션의 `appdata-backup`~`appdata-backup4`도 함께 지웠다. 위 증거 중 백업 사본에 기댄 부분은 이제 다시 확인할 수 없다.
2. **0.5.1 코드 — 안전망:** 0.5.x가 `workspaces.json`·`layout.json`을 저장할 때 같은 내용을 앱 데이터 폴더 밖(`~/.eqmux/backup/`)에도 둔다. 시작할 때 등록부가 없거나 비었는데 백업이 있으면 되살리고 알린다. 옛 버전의 wipe는 앱 데이터 폴더 안만 지우므로 이 백업은 남는다. 세션 DB(대화·스크롤백)는 크기 때문에 대상에서 뺀다.
   - **반영(2026-10-17):** 사본 위치는 `~/.eqmux/backup/` 대신 앱 데이터 폴더 옆 `%APPDATA%\com.eqment.eqmux.backup\`으로 정했다. 앱 데이터 루트에서 바로 계산되어 테스트가 임시 폴더 옆에 따로 쓰고 실제 사본을 건드리지 않는다.
     - `workspace::save`·`layout_save`가 저장할 때마다 사본에도 쓴다(`workspace::mirror`).
     - 시작 때 `workspace::restore_backup`이 사본에만 있는 등록을 합친다. 합친 것이 있으면 배치도 사본으로 돌린다. 배치 파일이 없을 때도 사본으로 채운다.
     - 되살렸으면 `diagnostics.log`에 `REGISTRY-RESTORED`를 남기고 OS 알림을 띄운다.
     - 등록부가 깨져 있으면 손대지 않는다. 등록 해제는 사본에도 반영되므로 해제한 항목은 되살아나지 않는다.
     - 테스트: `restore_backup_recovers_wiped_registry`.
3. **릴리스 안내:** 0.5.x 릴리스 노트와 README에 "0.4.x 이하를 다시 실행하면 등록·배치가 지워진다"를 적는다.
