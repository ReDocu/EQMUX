# EQMUX macOS 지원 QA·사용성 테스트

2026-10-29 · 브랜치 `macos-support` · 리드 + 세 세션(MB 백엔드 · MU UI · MF 프론트엔드) · 원장 `interview.csv`

> **기준 버전.** 시험은 0.5.0 위의 macOS 커밋(`8b552f8`)에서 했다. 그 뒤 브랜치를 0.5.1(`origin/sub_main` `d7bee4f`) 위로 rebase했다(macOS 커밋은 `29cee64`). 0.5.1 위에서 vitest 135개·cargo test 153개가 macOS에서 모두 통과했고, release 빌드(0.5.1)도 성공했다. 0.5.1이 근거 파일에서 바꾼 것은 버전 문자열과 스크롤백 상한 주석뿐이다. 높음·실기 확인 행의 근거(`ExitRequested` 미처리, 셸 목록, `ctrlKey` 키 처리, 설치 명령, `maximized`+`center`, `pick_folder`, README 문구)는 0.5.1 코드에서 그대로다. 원장의 `0.5.x`·`8b552f8` 표기는 시험 당시 기준이다.

## 요약

macOS 지원 커밋을 네 세션이 영역을 나눠 봤다. 세션별 결과 47행을 중복 8묶음으로 합쳐 36행을 붙였고, 리드 실기에서 11행을 더해 모두 47행을 `interview.csv`에 이어 붙였다. 각 행의 `재현 절차·근거` 칸 앞에 `[0.5.x macOS QA · 세션 원번호]`를 적었다. 실기로 확인한 행은 `제안` 칸 앞에 `[실기 확인 — 리드 …]`, 재현되지 않은 행은 `[실기 재현 안 됨 — 리드]`를 붙였다.

| 분류 | 번호 | 행 | 높음 |
|---|---|---|---|
| 버그 리포트 | B112–B138 | 27 | 2 |
| UI 설계 | U67–U78 | 12 | 0 |
| 사용성 평가 | P41 | 1 | 종합 2/5 |
| 태스크 기반 테스트 | T30–T36 | 7 | 2 |

- 테스트는 macOS에서 모두 통과했다. vitest 132개, cargo test 146개.
- 0.5.0 높음 항목 B67·B69·B71·B72·B82는 회귀가 없고 macOS 분기에서도 유효하다(B133).
- bus.sock 이상 입력(깨진 JSON·가짜 토큰·NUL·두 줄)은 모두 거부 경로로 갔다. 남은 것은 연결 고갈과 줄 길이 상한 두 건이다(B124·B125).

종합 평가(P41): 기능은 돌지만 **화면이 'Windows 앱'이라고 말하고, 손에 밴 macOS 키가 엉뚱하게 동작한다.**

## 먼저 고칠 것

1. **B112 — ⌘Q·Dock 종료·로그아웃이 종료 절차를 건너뛴다(실기 확인).** 이 경로는 `RunEvent::ExitRequested`로 들어오는데, 앱은 창의 `onCloseRequested`만 듣는다. Claude 세션이 돌던 중 ⌘Q를 누르자 다음 일이 한꺼번에 일어났다.
   - 확인창 없이 즉시 꺼졌다.
   - 페인에서 띄운 서버는 고아로 남았다(B115).
   - `running.flag`가 남아 다음 기동이 크래시 창을 띄웠다.
   - 그 창은 Claude 세션을 빠뜨렸고, '셸만 복원'이라던 기본 터미널은 사라졌다(B137).
   - 같은 상태에서 앱 안 [종료]는 모두 정상이었다.
2. **B134 — 기동할 때마다 창이 화면 밖으로 밀려난다(실기 확인).** `maximized`와 `center`를 함께 쓰면 1440×900 기준 가운데 원점을 그대로 둔 채 크기만 최대화된다. 1920×1080 화면에서 [설정]·[종료]·알림 벨·팝업의 [✕ 닫기]가 잘린다. 기동 4회 모두 같았다.
3. **B135 — [폴더 찾기…]가 첫 과업을 막는다.** 앱이 뒤에 있으면 선택 창이 보이지 않게 열리고, 다시 누르면 하나 더 열린다. 선택 창은 메인 스레드의 `runModal`로 돈다.
4. **B136 — 터미널에서 띄우면 그 터미널의 환경이 모든 에이전트로 샌다(실기 확인).** cmux에서 띄운 EQMUX의 Claude가 cmux 래퍼·훅·`CMUX_SURFACE_ID`를 달고 떴다.
5. **Windows 전제 묶음:**
   - 셸 목록이 pwsh·cmd뿐이고, 고른 셸과 실제로 뜨는 셸이 다르다(B114, 실기 확인: 'PowerShell 7'인데 zsh).
   - Claude 설치 명령이 `irm … | iex`다(B128).
   - 터미널 키가 Ctrl만 보고 ⌘는 보지 않는다(B126·B127 실기 확인, U67).
   - 경로 링크가 드라이브 문자만 알아본다(B129).
   - '탐색기' 문구(U76)와 문서의 'Windows 데스크톱 앱'(U74)이 남아 있다.

## 실기에서 본 것 (리드)

HEAD로 새로 빌드한 `EQMUX.app`을 cmux-cua(AX + 스크린샷)로 조작했다. 화면은 1920×1080이다. 과업 행은 T30–T36이다.

| 과업 | 결과 |
|---|---|
| T30 앱 기동 → 관제 대시보드 | 성공. 단 창이 화면 밖으로 밀린다(B134) |
| T31 저장소 등록 [폴더 찾기…] | 실패. 선택 창이 숨거나 중복으로 열린다(B135). 선택 창·메뉴 막대가 영어다(U77). 자동 조작으로는 선택 창에서 경로를 고르지 못해, 레지스트리를 `ws_register`와 같은 형식으로 써서 우회했다 |
| T32 기본 터미널 | 부분. 'PowerShell 7'로 표시되는데 실제는 zsh다(B114). 로케일은 정상이고, 한글 글자 사이가 벌어진다(U78) |
| T33 셸 단축키 | 실패. Ctrl+F 검색 바, 선택 시 Ctrl+C 복사(B126), ⌘V 이미지 무반응(B127) |
| T34 Claude 역할 세션 | 성공. 단 띄운 터미널의 환경이 섞여 든다(B136) |
| T35 세션 실행 중 ⌘Q → 재기동 | 실패(B112·B115·B137·B138) |
| T36 앱 안 [종료] · 렌더러 강제 종료 | 성공. [종료]는 확인창 뒤 정상 정리됐다. WebContent를 죽이면 자동 리로드되고 셸은 산다 |

재현되지 않아 낮음으로 내린 것:

- **B113:** 터미널 기동과 LaunchServices 기동 모두 LANG=ko_KR.UTF-8이었고 한글도 정상이었다. Finder 더블클릭 직접 확인은 못 했다.
- **B117:** 빈 창으로 남지 않았다.

## 실기 미확인 (다음 라운드)

- **B130 한글 조합 중 Enter:** 자동 조작은 IME 조합 상태를 만들지 못한다. 사람이 손으로 확인해야 한다.
- **B135 선택 창 입력:** 자동 조작으로는 선택 창이 마우스·키 입력을 받지 않았다. 도구 한계인지 사람이 확인해야 한다.
- **B113 Finder 더블클릭 기동:** 직접 확인하지 못했다. 다른 언어 설정 계정에서도 볼 것.
- 장시간 에이전트 부하, B67 회귀의 실기 재현(코드상 고쳐짐, B133).

## 진행 메모

- 시작 전에 앱 데이터(`~/Library/Application Support/com.eqment.eqmux`, `~/.eqmux/logs`)를 리드 스크래치패드에 백업했다. 실기에서 시험 저장소 `~/eqmux-qa-ws`를 등록했다. 끝난 뒤 저장소·`workspaces.json`·`workspaces/` 폴더를 지우고 `layout.json`을 되돌렸으며, `diff -rq`로 백업과 같은 것을 확인했다. 고아로 남은 시험 서버(8765)도 정리했다. 진단 로그(`~/.eqmux/logs/diagnostics.log`)에는 시험 기동 기록이 남아 있다.
- 증거 스크린샷(B134)은 리드 스크래치패드 `shots/`에 있다.
- 세션별 원본 CSV는 각 세션 스크래치패드에 있고, 병합 대응표는 리드 스크래치패드 `qa-raw/merge-map.txt`에 있다.
