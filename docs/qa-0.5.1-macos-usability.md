# EQMUX macOS 지원 QA·사용성 테스트

2026-10-29 · 브랜치 `macos-support` · 리드 + 세 세션(MB 백엔드 · MU UI · MF 프론트엔드) · 원장 `interview.csv`

> **기준 버전.** 시험은 0.5.0 위의 macOS 커밋(`8b552f8`)에서 했다. 그 뒤 브랜치를 0.5.1(`origin/sub_main` `d7bee4f`) 위로 rebase했다(macOS 커밋은 `29cee64`). 0.5.1 위에서 vitest 135개·cargo test 153개가 macOS에서 모두 통과했고, release 빌드(0.5.1)도 성공했다. 0.5.1이 근거 파일에서 바꾼 것은 버전 문자열과 스크롤백 상한 주석뿐이다. 높음·실기 확인 행의 근거(`ExitRequested` 미처리, 셸 목록, `ctrlKey` 키 처리, 설치 명령, `maximized`+`center`, `pick_folder`, README 문구)는 0.5.1 코드에서 그대로다. 원장의 `0.5.x`·`8b552f8` 표기는 시험 당시 기준이다.

## 먼저 고칠 것

1. **B112 — ⌘Q·Dock 종료·로그아웃이 종료 절차를 건너뛴다(실기 확인).** 이 경로는 `RunEvent::ExitRequested`로 들어오는데, 앱은 창의 `onCloseRequested`만 듣는다. Claude 세션이 돌던 중 ⌘Q를 누르자 다음 일이 한꺼번에 일어났다.
   - 확인창 없이 즉시 꺼졌다.
   - 페인에서 띄운 서버는 고아로 남았다(B115).
   - `running.flag`가 남아 다음 기동이 크래시 창을 띄웠다.
   - 그 창은 Claude 세션을 빠뜨렸고, '셸만 복원'이라던 기본 터미널은 사라졌다(B137).
   - 같은 상태에서 앱 안 [종료]는 모두 정상이었다.
2. **B134 — 기동할 때마다 창이 화면 밖으로 밀려난다(실기 확인).** `maximized`와 `center`를 함께 쓰면 1440×900 기준 가운데 원점을 그대로 둔 채 크기만 최대화된다. 1920×1080 화면에서 [설정]·[종료]·알림 벨·팝업의 [✕ 닫기]가 잘린다. 기동 4회 모두 같았다.
3. **B135 — [폴더 찾기…]가 첫 과업을 막는다.** 앱이 뒤에 있으면 선택 창이 보이지 않게 열리고, 다시 누르면 하나 더 열린다. 선택 창은 메인 스레드의 `runModal`로 돈다.
4. **B136 — 터미널에서 띄우면 그 터미널의 환경이 모든 에이전트로 샌다(실기 확인).** cmux에서 띄운 EQMUX의 Claude가 cmux 래퍼·훅·`CMUX_SURFACE_ID`를 달고 떴다.
5. **Windows 전제 묶음:**
   - 셸 목록이 pwsh·cmd뿐이고, 고른 셸과 실제로 뜨는 셸이 다르다(B114, 실기 확인: 'PowerShell 7'인데 zsh).
   - Claude 설치 명령이 `irm … | iex`다(B128).
   - 터미널 키가 Ctrl만 보고 ⌘는 보지 않는다(B126·B127 실기 확인, U67).
   - 경로 링크가 드라이브 문자만 알아본다(B129).
   - '탐색기' 문구(U76)와 문서의 'Windows 데스크톱 앱'(U74)이 남아 있다.

### 먼저 고칠 것

1. **B139 — 0.0.0.0·[::]로 연 서버를 '외부 노출 0 · ✓ 루프백에만'으로 안내한다(실기 확인).** `isExposed`는 구체적인 LAN 주소만 노출로 센다. macOS에서는 `lsof`가 IPv4·IPv6 와일드카드를 모두 `*`로 내고, `parse_lsof`가 이를 0.0.0.0으로 바꾼다. 그래서 `vite --host`나 node 기본 listen처럼 가장 흔한 노출을 안전하다고 안내한다.
2. **B140 — B67 회귀로 보이는 증상.** 쉬던 Claude가 약 60초 뒤 '승인 대기 · 질문 선택 대기'로 바뀌었다. 그 뒤 보낸 두 번째 메시지는 13분 넘게 전달되지 않았다. 트랜스크립트에 AskUserQuestion 호출은 없다. 원인은 아직 모른다. 앱을 cmux에서 띄워 훅 경로가 오염됐을 수 있다(B136). Finder로 띄운 앱에서 다시 재현해야 한다.
3. **B141 — B134 보강.** Window › Fill로 창을 화면 안에 맞춰도, 재기동하면 다시 화면 밖으로 밀려난다. 앱이 창 위치를 기억하지 않는다.
4. **비밀값 노출 묶음:**
   - .env의 여러 줄 값(PEM 키)이 줄마다 쪼개져 평문으로 보인다(B146).
   - [값 보기]가 워크스페이스를 바꿔도 켜진 채로 남는다(B147).
   - 값을 복사하면 클립보드 기록과 유니버설 클립보드로 퍼진다(B148).
   - 페인 로그에 비밀값이 평문으로 남는다(B150).
   - diff에서 .env가 평문으로 보인다(B154).
5. **포트 실측(macOS):**
   - IPv6 전용 서버가 127.0.0.1로 열려 연결이 거부된다(B142).
   - 포크한 워커 수만큼 같은 포트가 중복으로 뜬다(B143).
   - 다른 사용자 소켓은 보지 못한다(B144).
   - 서버 명령 확정이 [다시 실측]을 눌러야만 일어난다(B145).

B69 회귀는 통과했다. 다시 캐스팅하면 확인창이 뜬다. 다만 그 확인창이 미전달 메시지를 알리지 않는다(B158).

### 먼저 고칠 것 — 미커밋 수정이 만든 문제

탭 화살표와 UI 일관화는 아직 커밋 전이다. 아래는 커밋 전에 같이 고치는 편이 낫다.

1. **B159 — 자동 넘김이 화살표 폭만큼 모자라다(실기 확인).** 화면 밖 탭이 활성이 되면, 화살표 ‹가 생기기 전 폭으로 넘김 거리를 계산한다. 그래서 활성 탭의 ✕가 › 밑에 28px 가린다. ›를 처음 누를 때도 끝까지 못 간다.
2. **B160 — 끝에 닿으면 ›가 사라지고, 그 자리에 마지막 탭의 ✕가 들어온다(실기 확인).** 그 ✕를 누르면 탭이 닫힌다. 키보드로 ›를 누르던 사용자는 포커스를 잃는다(코드 판단).
   - B159·B160은 해법이 같다. ‹ ›를 `Show`로 넣고 빼지 말고 늘 자리를 차지하게 두고, `visibility`나 `aria-disabled`만 바꾼다.
