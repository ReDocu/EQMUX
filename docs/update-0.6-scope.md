## 요약

- 0.5.1은 안정화 패치로 나갔다. CPU·RAM 위험 30여 건, PTY 출력 Channel 전환, 워크트리 기능 제거, 앱 데이터 소실 안전망이 들어갔다. 0.5.x로 잡아 둔 기능 13건과 0.5.1 범위 §2-1 11줄은 하나도 들어가지 않았다.
- 0.5.1 뒤에 이미 만든 것이 있다. 환경변수 탭, 포트 수동 실측, 방송 묶기, 스크롤백 3000줄 등이다. 버전을 고정했으니 이것들은 0.6으로 나간다(§0).
- 0.6은 다섯 묶음이다. ① 이미 만든 것의 실앱 확인, ② 안정성·데이터 보존과 트레이, ③ 저장 계층, ④ 기능, ⑤ 서명·자동 업데이트.
- **VT 서버 모델은 0.6에 넣으면 0.6이 0.5.0 두 배 크기가 된다.** 0.6에서는 트레이까지만 하고, VT 서버는 0.7로 떼기를 권한다(§1-6).
- **0.6은 첫 공개 버전이다(11-02 추가).** 외부 사용자가 처음 받는 버전으로 보고, 공개 준비(§9)와 처음 쓰는 사람이 막히지 않는 기본 기능(§10)을 기능 묶음보다 앞에 둔다.
- **macOS 지원은 이미 `origin/sub_main`에 머지돼 있다**(PR #1, `48f0e72`). 로컬 `sub_main`은 8커밋 뒤에 있다. 공통 코드도 바뀌었으므로 Windows 회귀 확인이 필요하다(§11).
- **승인·검토·합치기 고리를 닫는다(§13).** 같은 파일 동시 편집 경고, 임무 시작점 기록, 임무 검토 화면, 대시보드 승인함, 자리 비운 사이 요약, 비용 예산 알림. 앞의 둘은 작아서 0.6 초반에 한다.
- **다른 도구의 전역 지시가 EQMUX 세션에 섞이는 것을 막는다(§14).** wmux가 `~/.claude`에 써 넣은 지시를 EQMUX 세션의 에이전트가 따른 일이 실제로 있었다. 세션 안내문에 우선 규칙을 싣고, 전역 설정은 읽기만 해서 알린다.
- **스킬·플러그인 관리에 범위 축을 더한다(§12).** 전체(이 PC의 모든 워크스페이스), 워크스페이스, 세션(역할) 단위로 보고 켜고 끈다. 세션 단위는 사용자 설정을 건드리지 않고 기동 인자(`--plugin-dir`, `--settings`)로만 싣는다.
- **역할을 "이 세션은 그 캐릭터다"로 키운다(§15).** 매 턴 상기 한 줄(페르소나마다 켜고 끈다), 워크스페이스별 캐릭터 기억, 팀원 표의 정체성 열, 초상 이미지, 중급의 대사 예시 칸.

### 4-1. git 패널 브랜치 전환 — 에이전트 작업 중 경고 (2026-10-17 요청)

- **흐름:** git 패널의 `⎇ main`을 누르면 로컬 브랜치 목록이 뜬다. 고르면 그 워크스페이스 세션의 상태를 보고 다음과 같이 한다.
  - 작업 중(busy)인 에이전트가 있으면 `ConfirmDialog`를 띄운다. 누가 무엇을 하는 중인지와 "이 폴더의 모든 세션 발밑 파일이 바뀐다"는 말을 보인다. 버튼은 [취소]·[그래도 바꾸기]이고 기본은 [취소]다.
  - 승인 대기(waiting) 에이전트만 있으면 같은 창을 약한 문구로 띄운다.
  - 모두 유휴이거나 세션이 없으면 확인 없이 바꾼다.
- **커밋 안 된 변경:** 확인창에 변경 건수를 같이 보인다. 앱이 몰래 stash하지 않는다. git이 거부하면 그 오류를 그대로 보인다.
- **경쟁 조건:** [그래도 바꾸기]를 누른 순간 상태를 한 번 더 본다. 확인창이 떠 있는 사이에 바뀌었으면 다시 묻는다.
- **에이전트 알림(선택):** 바꾼 뒤 그 폴더의 에이전트에게 "브랜치가 A → B로 바뀌었다. 파일을 다시 읽어라"를 보낸다. 대가는 메시지 한 건만큼의 토큰이다.
- **구현 메모:**
  - 지금 `ws_checkout`(`lib.rs:1684`)은 브랜치가 없으면 `-b`로 만든다. 패널용은 있는 브랜치로 바꾸기만 하게 나눈다.

## 12. 스킬 · 플러그인 관리 — [전체 / 개별] (2026-11-02 추가)

기본 화면과 구현은 0.5 때 쓴 두 기획을 따른다: `docs/archive/skill-manager-panel-2026-10-15.md`(스킬), `docs/archive/plugin-panel-2026-10-15.md`(플러그인, 엔진 CLI `claude plugin … --json`을 부른다). 이 절은 거기에 **범위 축**을 더하고, 두 기획이 뺀 것 중 두 가지를 되돌린다(결정 X1 · X3).

### 12-1. 범위

| 범위 | 뜻 | 스킬이 있는 곳 | 플러그인을 싣는 방법 | EQMUX가 쓰는 방식 |
|---|---|---|---|---|
| **전체** | 이 PC의 모든 워크스페이스·세션 | `~/.claude/skills/` (Codex는 실측) | `claude plugin … --scope user` | 사람이 확인창을 거쳐 누를 때만. 엔진 CLI 또는 휴지통을 쓰는 파일 조작 |
| **개별 — 워크스페이스** | 그 저장소에서 뜨는 모든 세션 | `<ws>/.claude/skills/` | `--scope local`(나만) · `--scope project`(커밋되어 팀 공유) | 같음 |
| **개별 — 세션(역할)** | 슬롯 하나 | 세션 전용 묶음 `.eqmux/bundles/<이름>/`(스킬을 담은 로컬 플러그인 폴더) | 기동 인자 `--plugin-dir <묶음>`(반복 가능), 끌 것은 `--settings '{"enabledPlugins":{"<id>":false}}'` | **사용자·프로젝트 설정 파일을 고치지 않는다.** 역할 파일 frontmatter가 원본이다 |

- 세션 범위는 권한과 같은 원칙을 쓴다. 역할 파일 frontmatter가 그 세션의 실행 플래그를 정한다.
- Claude Code 2.1.316 `--help`에서 `--plugin-dir`(디렉터리 또는 .zip, 여러 번)와 `--settings <file-or-json>`을 확인했다. `--settings`의 `enabledPlugins`가 사용자 설정을 세션에서만 덮는지는 구현 첫날 실측한다(결정 X4).
- 스킬 하나만 세션에서 끄는 플래그는 없다(`--disable-slash-commands`는 전부 끈다). 그래서 세션별 스킬은 "묶음을 싣는다" 쪽으로만 다룬다. 전역 스킬을 세션에서 빼는 기능은 넣지 않는다.

```yaml
# .eqmux/roles/<세션>.md frontmatter — 새 필드
extensions:
  bundles: [qa-kit]                      # .eqmux/bundles/qa-kit → --plugin-dir
  plugins_off: [chrome-devtools-mcp@x]   # 이 세션에서만 끈다 → --settings enabledPlugins
```

### 12-2. 화면

"확장" 그룹 `[MCP | 플러그인 | 스킬]`은 그대로 둔다. 플러그인·스킬 세그먼트 머리에 범위 칩을 더한다.

```
[ 전체 | 이 워크스페이스 | 세션별 ]
```

- **전체 · 이 워크스페이스**: 기존 기획의 목록 화면에 범위 열을 단다. 전체 범위의 변경 버튼은 "모든 워크스페이스의 새 세션에 적용됩니다" 확인창을 거친다.
- **세션별(적용 현황 표)**: 행은 스킬·플러그인, 열은 이 워크스페이스의 세션이다. 칸은 ✓ 실림 / ⊘ 이 세션에서 끔 / – 없음. 칸을 누르면 그 세션 역할 파일의 `extensions`를 고친다. 열 머리에 세션별 상시 토큰 비용의 합을 보인다(`claude plugin details`의 예상 비용 × 실린 플러그인).
- **한꺼번에**: 행 머리의 [모든 세션에 켜기 / 끄기]는 그 워크스페이스 세션 역할 파일을 한 번에 고친다. 전체 범위를 바꾸지 않는다.
- 바꾼 뒤에는 기존 "재시작 필요" 카드(역할·권한 변경과 같은 것)를 그 세션에 띄운다. 자동 재시작은 하지 않는다.

### 12-3. 결정

| # | 정할 것 | 권장 | 이유 |
|---|---|---|---|
| X1 | 전체 스킬 쓰기 (기존 기획 S1은 읽기 전용) | **허용으로 바꾼다.** 확인창 + 휴지통 + mtime 충돌 검사 | "전체 관리"가 요구다. 결정 9(사용자 설정 불가침)의 예외는 "사람이 그 화면에서 전체 범위를 골라 누른 경우"로 좁힌다 |

### 12-5. 검증

- 세션 A에만 `plugins_off`를 걸고 둘 다 재시작한다. A의 `/plugin` 목록에서만 꺼져 있고, B와 다른 워크스페이스는 그대로인지 본다.
- 세션 A에 `bundles: [qa-kit]`을 걸면 A의 `/` 메뉴에만 그 스킬이 보이는지 본다.
- 전체 범위 변경 뒤 이미 떠 있는 세션에 "재시작 필요" 카드가 뜨고, 자동으로 재시작되지 않는지 본다.
- 단위 테스트: 역할 frontmatter의 `extensions`를 기동 인자로 바꾸는 함수 하나(`agent.rs`의 기존 플래그 조립 테스트 옆). 없는 묶음 경로는 인자에서 빼고 경고를 남기는지 본다.

## 13. 작업 고리 닫기 — 승인 · 검토 · 합치기 (2026-11-02 추가)

에이전트 팀의 일은 **맡긴다 → 지켜본다 → 승인한다 → 검토한다 → 합친다** 순서로 돈다. EQMUX는 "지켜본다"(대시보드, 상태 감지, 알림)가 강하다. 반면 승인·검토·합치기는 사람이 페인과 터미널을 오가며 손으로 한다. 이 절의 여섯 건은 그 고리를 닫는다. 모두 이미 들어오는 훅 이벤트와 기존 저장소를 쓴다. 앱이 AI를 부르지 않고, 상태를 바꾸는 것은 사람의 버튼이라는 원칙도 그대로다.

| # | 기능 | 크기 | 순서 |
|---|---|---|---|
| 13-1 | 같은 파일 동시 편집 경고 | 작음 | **앞** |
| 13-2 | 임무 시작점 기록 | 작음 | **앞** — 13-3의 전제 |
| 13-3 | 임무 검토 화면 | 중간 | 기능 묶음 |
| 13-4 | 승인함 — 대시보드에서 허용·거부 | 중간 | 기능 묶음. §4 "승인·결정 게이트 버튼"을 이것으로 대체한다 |
| 13-5 | 자리 비운 사이 요약 | 작음–중간 | 기능 묶음 |
| 13-6 | 비용 예산 알림 | 작음 | 기능 묶음 — statusLine 묶음(§3)과 같이 |

### 13-1. 같은 파일 동시 편집 경고

- **왜:** 0.5.1에서 워크트리를 걷어내서(§8) 에이전트들이 한 폴더에서 일한다. 둘이 같은 파일을 고치면 서로 덮어쓰고, 사람은 나중에야 안다.
- **방식:** `PreToolUse`는 이미 받는다. 지금은 `tool_name`만 읽는다(`agent.rs` `hook_effect`). 편집 도구(Claude `Edit`·`Write`·`MultiEdit`·`NotebookEdit`, Codex는 실측)이면 `tool_input.file_path`도 읽어 세션별 "최근 편집 파일"에 넣는다.
- **경고:** 다른 세션이 최근 10분 안에 같은 파일을 편집했으면 두 세션의 페인 머리와 대시보드 주의 카드에 "Kai · Rin이 `src/x.ts`를 동시에 편집 중"을 띄운다. 알림 센터에도 한 건 쌓는다. 에이전트를 막거나 메시지를 자동으로 보내지 않는다. 사람이 [Kai에게 알리기]를 누르면 `ask` 메시지 초안을 연다.
- **담당 경로와 연결:** §4의 "직함별 담당 경로"가 들어오면 같은 자리에서 "담당 밖 파일 편집"도 경고한다.
- **저장:** 1차는 메모리에 둔다(경고에는 최근 것만 필요하다). 13-3·13-5가 쓰는 편집 기록은 `session.db`의 새 테이블 `file_touch(session, path, tool, ts)`에 둔다. 스키마 이전(§1-2)과 같이 넣는다.
- **한계:** Bash로 고친 파일(`sed -i`, 리다이렉트)은 잡지 못한다. 경고 문구에 "편집 도구로 고친 것만"이라고 적는다.

### 13-2. 임무 시작점 기록

- 임무를 배정하거나 [브리프 전달]을 누를 때, 그 워크스페이스의 `HEAD` 커밋을 임무 파일 frontmatter `base_commit`에 적는다. 같은 자리의 `assigned_at`(B92)과 같은 방식이다.
- 임무 카드에 "시작 `a1b2c3d` · 그 뒤 커밋 3개"를 보인다.
- **되돌리기는 0.6에 넣지 않는다**(결정 Q2). 폴더를 함께 쓰므로 한 임무의 변경만 골라 되돌리면 다른 세션의 작업까지 건드릴 수 있다. git 패널은 읽기 전용이라는 정책 G7과도 부딪힌다.

### 13-3. 임무 검토 화면

- **진입:** `report --done` 알림, 임무 카드의 [검토], 상태가 IN-REVIEW인 임무.
- **화면:** 한 화면에 세 칸을 둔다.
  1. 임무 목표와 완료 보고 본문.
  2. `base_commit` → 지금(작업 트리 포함)의 diff. 기존 `GitDiffEditor`를 쓴다. 기본 필터는 "이 임무 담당 세션이 편집한 파일"(13-1의 `file_touch`)이고, [전체 변경 보기]로 풀 수 있다. 한 폴더를 같이 쓰므로 필터가 없으면 다른 세션의 변경이 섞인다.
  3. [테스트 실행] — 저장 명령(§3 D2 `.eqmux/commands.json`)에서 고른 명령을 서버 탭에서 돌리고 종료 코드를 보인다. 저장 명령이 없으면 버튼을 숨긴다.
- **결정 버튼:** [승인] → 임무를 DONE으로 옮긴다. 커밋과 PR은 리드 세션이나 사람이 한다. 화면이 대신 커밋하지 않는다(G7). [되돌려 보내기] → 의견을 적으면 담당 세션에 `review` 메시지로 보내고 임무를 IN-PROGRESS로 되돌린다.
- **diff 줄 코멘트:** §4 "diff 줄 코멘트 → `review`"를 이 화면에서 한다. 따로 만들지 않는다.

### 13-4. 승인함 — 대시보드에서 허용·거부

- **왜:** 지금은 승인할 때마다 그 페인으로 가서 키를 눌러야 한다. 세션이 4~8개면 승인이 하루 일의 대부분이 된다.
- **목록:** 모든 워크스페이스의 waiting 세션을 기다린 순으로 보인다. 행마다 세션, 기다린 시간, **기다리는 도구와 원문**을 둔다. 원문은 waiting 직전 `PreToolUse`의 `tool_input`이다(예: `Bash: npm publish`, `Edit: src/x.ts`). 질문(`AskUserQuestion`)과 계획 승인(`ExitPlanMode`)은 [페인으로 가기]만 둔다. 답을 고르는 일은 페인에서 한다.
- **버튼:** [허용] · [거부] · [페인으로 가기]. 사람이 누를 때만 움직인다. "항상 허용"은 두지 않는다. 그것은 역할 파일 권한(frontmatter)을 고치는 일이고 역할 라이브러리에서 한다.
- **응답 경로(결정 Q1):** (a) 그 PTY에 승인 프롬프트의 키를 넣는다. 구현은 작지만 Claude Code TUI가 바뀌면 깨진다. (b) 엔진의 권한 요청 훅이 앱의 답을 기다리게 한다. 훅이 사람의 버튼을 전달할 뿐이라 원칙에 맞고 TUI 변화에 강하다. 다만 Claude Code에 그런 훅이 있는지와 시간 상한은 실측해야 한다. 권장은 (b)를 실측하고, 안 되면 (a)에 프롬프트 화면 확인(직전 출력에 승인 문구가 있을 때만 키를 넣는다)을 붙이는 것이다.
- **경쟁 조건:** 누르는 순간 그 세션이 여전히 같은 도구로 waiting인지 다시 본다. 그 사이 사람이 페인에서 먼저 답했으면 아무것도 넣지 않고 목록에서 뺀다.

### 13-5. 자리 비운 사이 요약

- **기준 시각:** 사람이 그 세션 페인을 마지막으로 본 시각, 또는 앱 창이 포커스를 잃은 시각.
- **내용(세션별):** 편집한 파일(13-1), 실행한 Bash 명령 수와 실패 수(`PostToolUse`), 새 커밋(`git log --since`), 주고받은 메시지(원장), 비용 증분, 지금 상태. 모두 이미 있는 데이터를 모은다. 요약 문장을 AI로 만들지 않는다.
- **자리:** 앱 창이 다시 포커스를 받았을 때 대시보드 맨 위의 접을 수 있는 카드. 기준 시각 뒤 바뀐 것이 없으면 띄우지 않는다.

### 13-6. 비용 예산 알림

- 세션 비용(`cost_usd`)은 statusLine으로 이미 모은다. 비용 증분을 그 시점에 배정된 임무에 붙여 임무별·하루 합계를 낸다.
- 설정에 하루 예산(USD, 기본 꺼짐)을 둔다. 넘으면 알림 센터와 OS 알림으로 한 번 알린다. 세션을 멈추지 않는다.
- 구독 요금제 사용자에게는 금액보다 한도(F1)가 더 의미가 있다. 두 표시를 한 칸에 둔다.

### 13-7. 결정

| # | 정할 것 | 권장 |
|---|---|---|
| Q1 | 승인함의 응답 경로 | 13-4 (b)를 먼저 실측하고, 안 되면 (a) + 프롬프트 화면 확인 |
| Q2 | 임무 변경 되돌리기 | 0.6에 넣지 않는다. 시작점 기록과 diff 기준점만 한다. 워크트리를 다시 넣을지 정할 때 같이 본다 |
| Q3 | 동시 편집 경고 시간 창 | 10분. 써 보고 바꾼다 |

### 13-8. 검증

- 13-1: 두 세션이 같은 파일을 `Edit`하게 하고 두 페인 머리와 주의 카드에 경고가 뜨는지 본다. 단위 테스트는 `hook_effect` 옆에 둔다. 편집 도구 payload에서 경로를 꺼내는 함수와 시간 창 판정 하나다.
- 13-2: 배정 뒤 임무 파일에 `base_commit`이 적히는지, 다시 배정하면 바뀌는지 본다.
- 13-3: 다른 세션이 고친 파일이 기본 필터에서 빠지는지, [되돌려 보내기]가 `review` 메시지와 상태 전환을 같이 하는지 본다.
- 13-4: [허용]과 [거부]가 각각 그 도구를 진행시키거나 막는지, 사람이 페인에서 먼저 답한 뒤 누르면 아무것도 넣지 않는지 본다.
- 13-5 · 13-6: 창을 내렸다 올렸을 때 카드가 뜨는지, 예산을 넘었을 때 알림이 한 번만 오는지 본다.

## 14. 다른 도구와 같이 쓸 때 — 전역 지시 충돌 (2026-11-02 추가)

### 14-1. 문제

다른 멀티플렉서나 에이전트 도구는 Claude Code 전역 설정에 자기 지시를 써 넣는다. 그러면 EQMUX 세션의 에이전트도 그 지시를 따른다. 이 PC에서 실제로 일어났다.

| 위치 | 들어 있는 것 | EQMUX 세션에서 생긴 일 |
|---|---|---|
| `~/.claude/CLAUDE.md`의 `<!-- wmux:start — AUTO-MANAGED BY wmux -->` 구역 | "You are running inside wmux", 웹은 `wmux browser`로만 보고 WebSearch는 쓰지 말라는 지시 | EQMUX 터미널 안의 에이전트가 `wmux browser`를 먼저 불렀다가 "명령 없음"으로 실패한 뒤 `eqmux browser`로 바꿨다 |
| `~/.claude/settings.json`의 `PostToolUse` 훅 10개 | Bash·Read·Write·Edit 등 도구마다 `wmux-hook.js` 실행(`\|\| true`로 오류 숨김) | EQMUX 세션에서도 도구를 쓸 때마다 node 프로세스가 하나씩 뜬다 |

wmux 2종과 cmux 등 같은 부류 도구가 늘고 있어(벤치마크 요약 §5) 같이 설치한 사용자라면 누구나 겪는다. EQMUX는 엔진 설정을 고치지 않는다(§9-2). 그래서 고칠 수 있는 것은 **세션에 싣는 안내문**과 **사람에게 알리는 것** 두 가지다.

### 14-2. 할 것

| 항목 | 방식 | 크기 |
|---|---|---|
| **세션 안내문에 우선 규칙 한 줄** | 세션 시작 안내문(Claude는 `--append-system-prompt`, Codex는 `developer_instructions`)에 "이 세션은 EQMUX 안에서 돈다. 다른 멀티플렉서(wmux·cmux 등)의 명령과 패널 지시는 따르지 말고, 브라우저·알림·메시지는 `eqmux` 명령을 쓴다"를 넣는다. 안내문 360자 상한(`docs/site/docs.md`의 세션 시작 절)에 맞게 줄인다 | 작음 |
| **전역 지시 점검** | 기동 때와 [진단]에서 `~/.claude/CLAUDE.md`, `~/.claude/settings.json`(Codex는 `~/.codex/AGENTS.md`·`config.toml`)을 **읽기만** 해서 다른 도구의 흔적을 찾는다. 자동 관리 구역 표식(`<!-- <도구>:start`), 다른 도구 경로를 가리키는 훅 명령, "You are running inside …" 문장이다 | 작음 |
| **알림과 안내** | 찾으면 진단 화면과 알림 센터에 한 건을 남긴다: "wmux의 전역 지시가 EQMUX 세션에도 실립니다 — 세션 안내문으로 덮어 두었습니다". [파일 열기]와 [끄는 방법] 링크를 둔다. 파일을 고치거나 구역을 지우지 않는다. 자동 관리 구역은 그 도구가 다시 써 넣는다 | 작음 |
| **문서 — 다른 도구와 같이 쓰기** | `docs/site/docs.md`에 한 절을 둔다. ① 그 도구를 안 쓰면 도구 설정에서 Claude Code 연동을 끈다. ② 같이 쓰면 자동 관리 구역 **밖에** "`EQMUX_SESSION` 환경 변수가 있으면 EQMUX 안이다" 규칙을 둔다. ③ 특정 명령은 `permissions.deny`(예: `Bash(wmux:*)`)로 막는다 | 작음 |

- 세션 안내문만으로 전역 `CLAUDE.md`를 완전히 이기는지는 보장되지 않는다. 둘 다 같은 대화에 실리기 때문이다. 그래서 점검과 안내를 같이 둔다.
- 훅 충돌(다른 도구의 훅이 EQMUX 세션에서도 도는 것)은 EQMUX가 막을 수 없다. `--settings`는 사용자 설정에 더해질 뿐이다. 점검 결과에 "도구 호출마다 실행되는 다른 도구 훅 N개"로 보이기만 한다.

### 14-3. 검증

- 이 PC의 지금 상태(wmux 구역 + 훅 10개)에서 점검이 둘 다 찾는지 본다.
- 우선 규칙을 넣은 세션에서 "이 페이지 열어 줘"를 시켰을 때 첫 시도부터 `eqmux browser`를 쓰는지 본다. 넣기 전과 비교한다.
- 단위 테스트: 점검 함수 하나. 표본 `CLAUDE.md`(wmux 구역 있음·없음)와 `settings.json`(다른 도구 훅 있음·없음)으로 결과를 본다.

## 15. 캐릭터 몰입 — 세션이 그 인물로 행동하게 (2026-11-02 추가)

역할 확장의 목적은 **한 세션이 특정 캐릭터(페르소나)인 것처럼 행동하게 만드는 것**이다. 역할이 실행 설정을 더 많이 정하게 하는 쪽(모델·도구 규칙·담당 경로)은 이 절의 목적이 아니다. 그쪽은 §3 "직무별 모델"과 §12 세션별 확장의 기존 계획대로 둔다.

### 15-1. 지금 캐릭터가 깨지는 곳

| 깨지는 곳 | 지금 동작 |
|---|---|
| **대화가 길어지면 말투가 흐려진다** | 캐릭터는 SessionStart 훅이 한 번 싣는다(`cli.rs` `role_context`). 훅에 matcher가 없어 compact 뒤에는 다시 실리지만(`lib.rs` `write_hook_settings`), 그 사이 수십 턴 동안 다시 짚는 장치가 없다 |
| **기억이 없다** | 세션을 새로 띄우면 캐릭터는 매번 처음 보는 사람이다. "같은 인물"이라는 연속성이 없다 |
| **캐릭터끼리 서로 모른다** | 팀 관계 표(`roles.rs` `save`)는 슬롯·이름·직무만 싣는다 |
| **화면에서는 캐릭터가 아니다** | 레일·카드는 이니셜 원(`RoleLibrary.tsx` `initial`)이다 |
| **중급은 재현력이 낮다** | 말투·성격 각 3줄뿐이다. 캐릭터 가이드가 "가장 효과가 크다"고 한 대사 예시 칸이 중급에는 없다(`docs/character-guide.md` §2) |

### 15-2. 할 것

| # | 기능 | 방식 | 크기 |
|---|---|---|---|
| 15-1 | **매 턴 상기 한 줄** | 아래 15-3 | 작음 |
| 15-2 | **캐릭터 기억 (워크스페이스별)** | 아래 15-4 | 작음–중간 |
| 15-3 | **팀원 표에 정체성 열** | 각 팀원의 시트 정체성 1줄(고급) 또는 판단 성향 첫 줄(기본·중급)을 팀 관계 표에 열로 더한다. 캐릭터끼리 서로를 그 인물로 부르고 대한다 | 작음 |
| 15-4 | **초상 이미지** | `personas/<id>.png`가 있으면 레일·페인 머리·대화 탭·알림에서 이니셜 대신 쓴다. 없으면 지금 그대로 | 작음–중간 |
| 15-5 | **중급에 대사 예시 칸** | 상황 → 응답 2~3개. 역할 파일에 `## 대사 예시`로 싣는다. 비면 토큰 0 | 작음 |

### 15-3. 매 턴 상기 — 페르소나마다 켜고 끈다

- **켜고 끄는 곳:** 역할 라이브러리 페르소나 편집에 체크박스 하나("매 턴 캐릭터 상기"). 단계(기본·중급·고급)와 무관하게 둔다. 페르소나 파일 frontmatter에 켰을 때만 `remind: on`을 쓴다. 꺼짐이 기본이다. 기존 파일은 그대로 꺼져 있고 토큰도 늘지 않는다.
- **역할 파일:** 합성 때 켜져 있으면 frontmatter에 `remind: <한 줄>`을 쓴다. 문장은 단계마다 다르다.
  - 고급: `[캐릭터 유지] 너는 <시트 이름 (원전)>다 — 시트의 말투 규칙을 지킨다. 코드·커밋·파일 산출물에는 말투를 쓰지 않는다.`
  - 중급: `… 너는 <이름>다 — 말투: <말투 한 줄로 접은 것>. …`
  - 기본: `… 너는 <이름>다 — 판단 성향을 지킨다. …`
  - 임무 배정(`set_mission`)은 다른 frontmatter 줄을 보존하므로 이 줄도 남는다.
- **훅:** 이미 등록된 UserPromptSubmit 훅(`eqmux _hook UserPromptSubmit`)이 `EQMUX_ROLE_FILE`의 frontmatter `remind:`를 읽어 `hookSpecificOutput.additionalContext`로 낸다. SessionStart와 같은 자리에서 IPC보다 먼저 출력한다. 팀원 메시지 주입도 프롬프트 제출이므로 같이 상기된다.
- **반영 시점:** 훅이 매 프롬프트마다 파일을 다시 읽는다. 켜고 끈 뒤 역할 파일만 다시 만들면(직함 변경과 같은 `resaveTeams`) 재시작 없이 다음 프롬프트부터 적용된다. "다시 읽기" 안내 주입은 필요 없다.
- **비용:** 턴당 수십 토큰. 편집 화면 체크박스 옆에 그렇게 적는다.
- **Codex:** UserPromptSubmit 출력을 실측하지 않았다. 출력이 프롬프트를 막을 위험이 있어 실측 전까지 `EQMUX_AGENT`가 Codex면 내지 않고, 화면에도 "Claude Code만"이라고 적는다.
- **시트에 `## 상기` 칸을 따로 두는 것**은 하지 않는다. 고급은 시트가 이미 컨텍스트에 있으니 가리키기만 하면 된다. 일반 문장으로 부족하다는 실사용 불만이 나오면 그때 넣는다.

### 15-4. 캐릭터 기억 — 워크스페이스별

- **위치:** `<ws>/.eqmux/memory/<페르소나 id>.md`. 같은 캐릭터라도 프로젝트마다 다른 경험을 갖는다. `.eqmux/.gitignore`에 `memory/`를 더한다(`roles.rs` `ensure_gitignore`). 역할 파일과 같은 이유로 개인 기록이다.
- **싣기:** SessionStart 훅이 역할 파일·시트 다음에 기억 파일의 **최근 부분**을 싣는다. 상한은 시트 인라인 상한(`MAX_SHEET_CHARS` 4000자)과 같은 방식으로 뒤에서부터 자른다.
- **쓰기:** 앱은 AI를 부르지 않는다. 역할 파일에 지시 한 줄을 둔다: "세션을 마치거나 큰 일을 끝내면 `.eqmux/memory/<id>.md`에 날짜와 함께 이번에 한 일·인상·다음에 기억할 것을 3줄 이내로 덧붙인다." 캐릭터 본인이 1인칭으로 쓴다.
- **사람의 관리:** 역할 라이브러리 페르소나 편집에 [이 워크스페이스 기억 열기]·[비우기]. 비우기는 휴지통으로 보낸다.
- 같은 페르소나가 한 워크스페이스에 두 슬롯 이상이면 한 파일에 같이 쓴다. 덧붙이기만 하므로 충돌은 줄 순서 섞임뿐이다.

### 15-5. 결정

| # | 정할 것 | 결정 | 이유 |
|---|---|---|---|
| C1 | 매 턴 상기의 범위 | **페르소나마다 켜고 끈다. 기본은 꺼짐** | 토큰 비용을 사람이 고른다. 기존 사용자의 비용이 몰래 늘지 않는다 |
| C2 | 캐릭터 기억의 범위 | **워크스페이스별** | 프로젝트마다 다른 경험. 다른 저장소의 내용이 섞이지 않는다 |
| C3 | 음성(TTS), 앱이 AI로 말투를 바꿔 주는 것 | 하지 않는다 | "앱은 AI를 부르지 않는다" 원칙. 범위만 넓힌다 |

### 15-6. 순서

15-1(상기) → 15-3(정체성 열) → 15-5(대사 예시) → 15-2(기억) → 15-4(초상). 앞의 셋은 역할 파일과 훅 출력만 바꾼다. 뒤의 둘은 새 파일 규약이 하나씩 생긴다. 15-1은 따로 떼어 §3 "앞" 항목과 함께 할 수 있다.

### 15-7. 검증

- 상기를 켠 페르소나로 30턴 넘게 대화해 말투가 유지되는지 본다. 끈 상태와 비교한다.
- 대화 중에 상기를 끄면 재시작 없이 다음 프롬프트부터 `additionalContext`가 빠지는지 본다(트랜스크립트로 확인).
- Codex 세션에서는 상기가 나가지 않고 프롬프트가 막히지 않는지 본다.
- 기억: 세션을 끝낸 뒤 새로 띄우면 첫 응답에서 지난 일을 언급할 수 있는지 본다. 다른 워크스페이스의 같은 페르소나에는 실리지 않는지 본다.
- 단위 테스트: ① 페르소나 `remind` 읽기·쓰기 왕복(`library.rs` 직함 왕복 테스트 옆). ② 역할 합성의 `remind:` 줄 — 꺼짐이면 키 없음, 여러 줄 말투가 한 줄로 접힘, `set_mission` 뒤에도 남음(`roles.rs`). ③ 훅 출력 — `remind:`가 있을 때만 UserPromptSubmit 컨텍스트가 나옴(`cli.rs`).
