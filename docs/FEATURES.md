## 읽는 법

**판정**

| 표기 | 뜻 |
|---|---|
| ✅ 완비 | wmux와 동등 이상으로 넣는다 |
| 🔻 축소 | 넣되 범위를 줄인다 |
| 🔄 대체 | 다른 방식으로 같은 목적을 달성한다 |
| ❌ 제외 | 안 넣는다 |
| ⭐ 신규 | wmux에 없다. 우리가 더한다 |

**우선순위 — 중요도가 아니라 "나중에 넣으면 얼마나 아픈가"로 매겼습니다**

팀장님이 *"클론에서 확장시킬 예정"*이라고 하셨으니, 순서는 이 기준이어야 합니다.

| 등급 | 기준 | 시점 |
|---|---|---|
| **P0** | 나중에 넣으려면 **전체를 뜯어야 함** (렌더러·입력·프로토콜·스키마 근간) | v0.1~v0.2 |
| **P1** | 독립 모듈로 나중에 붙일 수 있으나 없으면 실사용 불편 | v0.2~v1.0 |
| **P2** | 언제 붙여도 비용이 같음. 순수 편의 | v1.0 이후 |

> 폰트 크기 단축키는 3년 뒤에 넣어도 30분이면 됩니다.
> 유니코드 폭 처리는 3년 뒤에 넣으면 렌더러를 다시 씁니다.
> **이 차이가 P0와 P2를 가릅니다.**

## ⚠️ 먼저 — wmux 문서에 없는데 우리에겐 필수인 것

전수 조사 중 wmux 공식 문서·README 어디에도 **언급이 없는** 항목이 나왔습니다.
문서에 없다는 건 두 가지 중 하나입니다: 당연해서 안 썼거나, **잘 안 돼서 안 썼거나.**

| # | 항목 | 왜 위험한가 |
|---|---|---|
| **A5** | **CJK 문자 폭 처리** (East Asian Wide) | 한글·한자는 2칸을 차지합니다. 폭 계산이 틀리면 **테이블·박스 그리기·TUI가 전부 깨집니다.** 터미널 버그의 고전이고, 렌더러 근간이라 나중에 못 고칩니다 |
| **A6** | **IME 조합 입력** | 한글 입력 시 조합 중인 글자(`ㄱ`→`가`→`감`)를 터미널이 어떻게 표시하느냐의 문제입니다. 잘못하면 **한글을 못 칩니다.** 앱이 아니라 제품이 안 됩니다 |

**팀장님과 저희 팀은 한국어로 일합니다.** 이 둘이 깨지면 나머지 88개 기능이 완벽해도 못 씁니다.

> **그래서 v0.1 Walking Skeleton의 관문에 이 둘을 추가합니다.**
> 기존 관문(키 입력 지연 16ms)에 더해 — 한글 입력이 되는가, `┌─┐` 박스가 한글 옆에서 안 깨지는가.
> 가장 싸게 확인하고, 안 되면 그 자리에서 렌더러 전략을 다시 봅니다.

## E. 에이전트 통합 ⭐ — 제품의 심장

**전부 ✅ 완비 + 신규 추가.**
A~D는 터미널이면 다 하는 것이고, **여기가 EQMUX가 존재하는 이유**입니다.

| # | 기능 | EQMUX | 등급 |
|---|---|---|---|
| E1 | Claude Code 훅 자동 등록 (`SessionStart` `PostToolUse` `SubagentStop` `Stop`) | ✅ | **P0** |
| E2 | `~/.claude/CLAUDE.md` 지침 자동 주입 | ✅ | P1 |
| E3 | 활동 표시등 (주황 작업중 / 초록 완료 / 빨강 중단 / 회색 유휴) | ✅ | **P0** |
| E4 | 화면 읽기 `read-screen --lines N` | ✅ | **P0** |
| E5 | 텍스트 전송 `send` | ✅ | **P0** |
| E6 | 키 전송 `send-key Enter --ctrl` | ✅ | **P0** |
| E7 | 에이전트 spawn / list / status / kill | ✅ | P1 |
| E8 | 일괄 spawn `spawn-batch --json` | ✅ | P1 |
| E9 | 오케스트레이터 플러그인 | ❌ 제외 — Claude Code가 이미 함 | — |
| E10 | **⭐ "입력대기" 상태 구분** | ⭐ 신규 | **P0** |
| E11 | **⭐ 사이드바 배지 = 입력대기 개수만** | ⭐ 신규 | **P0** |

> **E10이 wmux와의 진짜 차이입니다.**
> wmux 표시등은 `작업중 / 완료 / 중단` 3종입니다. 그런데 사용자가 실제로 알고 싶은 건
> **"지금 나를 기다리는 놈이 있나"** 하나입니다.
> `작업중`과 `입력대기`가 같은 색이면 화면을 계속 지켜봐야 합니다. 그럼 멀티플렉서를 쓰는 의미가 없습니다.
>
> 이건 기능 하나가 아니라 **제품의 정의**입니다. PRD 6절 값 곡선에서 "여기에 몰빵한다"고 쓴 그 항목입니다.

> **E4~E6 주의 — 확장의 핵심 접점.**
> 에이전트가 EQMUX를 조작하는 통로입니다. 팀장님이 확장하실 때 가장 먼저 손댈 곳이므로
> **명령 이름과 인자 형태를 v0.2에 확정하고 이후 하위 호환을 지킵니다.**

| F6 | `system.tree` (`eqmux tree`) | ✅ | P1 |
| F7 | `browser.*` (navigate/snapshot/click/screenshot/eval) | 🔄 대체 — 외부 Chrome CDP 대상 | P1 |

> 하위 호환 때문에 생긴 부채입니다. 우리는 신규니까 처음부터 하나만 씁니다.
> 프로토콜이 둘이면 확장할 때마다 두 번 고쳐야 합니다.

> **F10은 보안 검토 전까지 안 만듭니다.** 원격에서 터미널에 임의 명령을 보내는 기능입니다.
> 토큰 하나로 막는 구조를 공개 배포판에 넣는 건 위험합니다. 필요해지면 그때 제대로 설계합니다.
