# EQMUX 0.6.5 릴리스 노트

2026-11-23 · 태그 `v0.6.5` · 변경 전체는 `CHANGELOG.md` [0.6.5]

## 다운로드

| 운영체제 | 파일 | 비고 |
|---|---|---|
| Windows 10·11 (x64) | `EQMUX_0.6.5_x64_portable.zip` | 압축을 풀어 `EQMUX\eqmux.exe` 실행 |

이번 판은 Windows만 냅니다. macOS는 [0.6.4](https://github.com/ReDocu/EQMUX/releases/tag/v0.6.4)의 dmg를 그대로 쓰세요. 1.0 전에는 설치 파일을 내지 않습니다. 아직 코드 서명이 없습니다. Windows는 SmartScreen에서 [추가 정보] → [실행]을 누릅니다. 받은 파일은 릴리스에 붙은 `SHA256SUMS.txt`와 `Get-FileHash`로 대조할 수 있습니다.

## 새로 생긴 것

### 페인 간격을 고릅니다

설정 › 일반 › **페인 간격**에서 0 · 2 · 4 · 8(기본) · 16px 중 고릅니다. 터미널 사이 간격과 분할선이 함께 따라갑니다. 간격을 0으로 해도 분할선을 잡아 끌 수 있습니다.

### 키보드로 옆 페인에 갑니다

터미널 페인 안에서 **Ctrl+Shift+←↑↓→**(macOS는 ⌘⇧)를 누르면, 그 방향에 있는 페인을 고르고 키보드 포커스를 옮깁니다. 화면에 그려진 자리로 이웃을 찾으므로 배치 6종 모두, 분할 비율을 바꿔도 맞습니다. 단축키 표에도 적었습니다.

## 바뀐 것

### 저장소 경계: 밖은 읽기만 합니다

지금까지 역할 세션의 에이전트는 배정된 저장소 밖을 읽지도 고치지도 못했습니다. 이제는 밖도 **읽을 수 있고, 고칠 수는 없습니다.**

- 파일 읽기 · 검색(Read · Grep · Glob)은 어디든 됩니다.
- 밖 파일을 고치는 Edit · Write는 전처럼 막습니다.
- **셸 명령도 봅니다.** Bash · PowerShell 명령에 저장소 밖 경로가 나오면, 읽기 명령(`cat` · `ls` · `Get-Content` · `git log` 등)일 때만 통과시킵니다. 밖을 지우거나 고치는 명령(`rm` · `sed -i` · `find -delete` · 밖으로 가는 `>` 등)은 거부합니다. 밖 경로가 없는 명령은 지금처럼 무엇이든 됩니다.

### 셸 페인에서 띄운 `claude`에도 경계가 걸립니다

워크스페이스 폴더에서 연 셸 페인에서 `claude`를 직접 치면, EQMUX가 저장소 경계 훅 하나를 실어 띄웁니다. 역할 세션과 같은 규칙(밖은 읽기만)입니다. 상태 · 승인 훅은 싣지 않으므로 셸 페인 동작은 그대로입니다. 사용자 Claude 설정과 저장소의 `.claude/`는 건드리지 않습니다. 홈 폴더에서 연 셸 페인은 배정된 저장소가 없으니 해당하지 않습니다.

## 아는 한계

- 셸 명령 검사는 명령 문자열의 낱말을 보는 방식입니다. 조각을 이어 붙여 만든 경로(`"D:\" + "x"`)나, 스크립트 파일 안에서 하는 쓰기(`node x.js`)는 잡지 못합니다. 심볼릭 링크도 따라가지 않습니다.
- 셸 페인에서 `claude --settings …`를 따로 주면, 어느 설정이 이기는지는 Claude Code가 정합니다.
- Codex 세션에는 경계 훅이 없습니다. 전처럼 Codex 샌드박스와 안내문으로만 지킵니다.
