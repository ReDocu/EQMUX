# 코드 리뷰 — 스크롤백 조립기 vt100 가상 화면 전환 (2026-11-03)

대상: 커밋 전 diff `src-tauri/src/store.rs`(LineAssembler) · `src-tauri/src/lib.rs`(PtySession.size · pty_resize) · `Cargo.toml`(vt100 0.18)
요청: eqmux-d1 세션 · 코드는 고치지 않고 발견 사항만 보고

## 검증 방법

- store.rs의 조립기 코드를 스크래치 크레이트로 그대로 복사해(vt100 =0.18.1) 의심 시나리오를 돌렸다.
- `~/.eqmux/logs`의 원시 PTY 로그를 8KB 청크로 재생했다.
- `cargo test --lib accum_tests`는 돌리지 않았다. 다른 세션이 store.rs를 고치는 중이라 빌드 잠금이 겹치지 않게 하려는 것이다.
- 로그에 크기 표식이 없어(size_marker는 방금 추가됨) 재생 크기는 짐작한 값이다. 그래서 감쌈·중복 품질은 로그 재생으로 판단하지 않았다.

## 치명

### 1. 대체 화면에서 도는 에이전트 세션은 줄이 거의 하나도 저장되지 않는다

- 위치: `Spill::on_scroll`의 `if alternate_screen { return; }`
- 근거: shell2·3·4@eqmux-1e3b93.log에서 Claude Code가 `ESC[?1049h ESC[2J ESC[?1000h…1006h`(전체 화면 렌더러 + 마우스)로 들어가 그 안에서 계속 돈다. shell4(9.8MB)를 재생하면 저장되는 줄은 11개뿐이고, 모두 셸 배너·프롬프트·`Resume this session with:` 같은 셸 줄이다.
- 영향: 이런 세션은 재생·검색·내보내기·크래시 복구가 모두 비게 된다. 테스트 `alternate_screen_is_not_stored`는 이 공백을 정상 동작으로 굳히고 있다.
- inline 모드 Claude Code(designtool·customstrategy 로그)는 1049h가 없어 이번 방식이 해당한다.
- 정할 것: 대체 화면 세션을 어떻게 저장할지는 설계 결정이 필요하다.

## 높음

### 2. 리사이즈 경합

- 위치: lib.rs `pty_resize` — `size.store`를 `m.resize()`가 끝난 뒤에 한다.
- 원인: ConPTY는 ResizePseudoConsole 안에서 리페인트를 파이프에 동기로 밀어 넣는다. 그래서 리더가 새 크기로 그린 리페인트를 옛 크기의 화면으로 먼저 처리하기 쉽다.
- 재현: 3행 화면에 x1~x3 → 6행 기준 CUP 리페인트를 옛 크기로 처리 → 결과는 `["r1","r2","r6"]`. x1~x3과 r3~r5를 잃는다.
- 제안: store를 resize 앞으로 옮기고, 실패하면 되돌린다.

### 3. 높이를 키울 때 중복 (크기가 맞아도 생긴다)

- 원인: vt100은 키울 때 빈 행을 위에 끼운다. ConPTY는 이미 밀려난 이력 행까지 `ESC[H` + 행마다 `ESC[K\r\n`으로 다시 그린다.
- 재현: 4행 화면에 l1~l5 → 6행으로 키우고 리페인트 → 결과는 `["l1","l2","l1","l2","l3","l4","l5","PS> "]`. 연속 중복이 아니어서 last_spilled 필터로 걸러지지 않는다.
- 폭을 줄일 때 ConPTY가 다시 감싸면서 맨 위 행을 자기 스크롤백으로 넘기면 그 행은 유실될 것으로 본다(실측 안 함).

### 4. mac/linux에서 폭을 줄이면 화면의 행이 잘려 영구 유실된다

- 원인: vt100 set_size는 폭이 바뀌면 행을 그냥 자른다. 유닉스 셸은 지난 출력을 다시 그리지 않는다.
- 재현: 40열에서 10열로 줄이면 `"this is a fairly long line of output"`이 `"this is a "`로 저장된다.

## 중간

### 5. `ESC[2J`가 화면에 있던 줄을 잃게 한다

- 원인: cls·clear·/clear는 화면을 스크롤 없이 지운다. 그래서 그 줄들이 위로 밀려나지 않는다.
- 재현: a·b·c를 쓴 뒤 `ESC[H ESC[2J after` → 저장되는 것은 `["after"]`뿐이다. shell4 로그에도 2J가 27회 있다.
- 제안: 주 화면일 때 2J 앞에서 화면을 미리 밀어낸다.

### 6. 2칸 글자가 1칸을 남기고 감싸면 줄이 둘로 갈라진다

- 원인: vt100이 이 경우 wrapped 플래그를 일부러 세우지 않는다.
- 재현: 9열에서 `"한글한글한글"` → `["한글한글","한글"]`.
- 기존 테스트는 10열(짝수)이라 이 경우를 잡지 못한다.

### 7. styled 색이 감싼 행 경계를 넘어 번진다

- 재현: 10열에서 `ESC[31m0123456789ESC[0mabc` → abc까지 빨갛게 나온다.
- 제안: 행을 이어 붙일 때 사이에 `ESC[0m`을 넣는다.
- 이 경우를 빼면 논리 줄 하나하나는 제 SGR로 시작하므로 혼자 완결된다.

### 8. finish 경로에는 필터가 없다

- 위치: lib.rs의 finish 클로저 — `is_tui_noise`와 `last_spilled` 검사를 건너뛴다.
- 영향: 세션이 끝날 때 화면 한 장 전체(입력 상자·상태줄·스피너)가 그대로 저장된다.

## 낮음

9. 가장 최근 화면 한 장은 스크롤되기 전까지 메모리에만 있다. 실행 중 검색·내보내기에 안 나오고, 크래시 때 잃는다.
10. 위쪽 스크롤 영역(`ESC[2;5r`)에서 스크롤된 행은 버려진다. vt100이 `scroll_top==0`일 때만 콜백을 부르기 때문이다.
11. 4000자 기준이 SGR을 포함한 바이트 수라서, 색이 많은 줄은 평문 약 700자에서 쪼개진다. 감싼 행과 만나도 유실·중복은 없다.
12. 평문 끝에 ConPTY가 채운 공백이 남는다. trim_end를 권한다.
13. Ink 동적 영역이 화면보다 높으면 중간 프레임의 윗행이 남는다. 실제 터미널과 같은 한계다.

## 성능

- shell4 9.8MB를 62ms(약 155MB/s), shell1 4MB를 29ms에 처리했다(release 빌드).
- 리더 스레드에는 문제가 없다.

## 재검증 — 리뷰 반영본 (같은 날)

- `cargo test --lib accum_tests`는 12/12 통과했다.
- 반영본을 같은 하니스로 돌렸다. host_repaints는 Windows·유닉스 둘 다 확인했다.

### 고쳐진 것

- 크기가 맞을 때의 2, 그리고 3·4·5·6·7·8·11·12는 같은 재현으로 고쳐진 것을 확인했다.
- 2의 덩어리 경계 경합은 주석에 적은 대로 남아 있다.

### 새로 찾은 것

중간
- **A.** 단계적으로 키우면(창 드래그) 여전히 중복된다. resize가 아직 소비되지 않은 replay를 덮어쓰기 때문이다. 재현: 4→6→8행 → l3~l6이 두 번 저장된다. 제안: 남은 replay를 grow만큼 앞으로 늘린다.
- **B.** 유닉스에서 폭을 줄일 때 push_screen_off가 지금 그려진 스피너·프롬프트 프레임을 줄로 저장한다. 커서 줄도 갈라진다(`$` / `  ls -la`). 제안: 커서 위 행만 밀어낸다.

낮음
- **C.** DECSC/DECRC가 앱이 저장해 둔 커서 자리를 덮는다. 제안: CUP로 되돌린다.
- **D.** wide_wrap 오판 — 폭이 cols-1인 줄 다음에 2칸 글자로 시작하는 줄이 오면 합쳐진다. 드물다.
- **E.** 색 없는 감싼 줄도 ESC[0m 이음 때문에 styled가 Some이 된다. 제안: ESC가 있을 때만 리셋을 넣는다.
- **F.** 유닉스에서 대체 화면 중 폭을 줄이면 주 화면이 여전히 잘린다. 2J가 읽기 경계에서 잘리면 선행 밀어내기를 놓친다.

### 실제 로그 재생

- 줄 수는 이전과 거의 같다. 차이는 갈라졌던 한글 줄이 합쳐진 것과 끝 공백 제거뿐이다.
- 속도는 130~190MB/s로 같다.
- 로그에 크기 표식이 없어 크기를 짐작해 재생했으므로, 감쌈 판정이 맞는지는 이 재생으로 확인되지 않는다.
