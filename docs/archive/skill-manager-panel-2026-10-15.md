# 스킬 탭 기획서 — 사이드 패널에서 SKILL 관리

최종 반영: [update-plan-0.5.0.md](../update-plan-0.5.0.md) §결정 22 · §개선 — 오른쪽 위 메뉴 정리 · §0.5.x로 넘기는 것 — 탭 위치·이름·출시 시점을 최종본에 맞춰 고쳤다.

2026-10-15 · 초안

## 개요

사이드 패널 "확장" 그룹에 `스킬` 세그먼트를 추가한다(`[MCP | 플러그인 | 스킬]`, 0.5.x). 아래 범위에서 "넣음"인 항목이 0.5.x의 1차다. 이 화면에서 워크스페이스의 에이전트(Claude Code · Codex)가 쓰는 `SKILL.md`를 한 화면에서 보고, 만들고, 고치고, 지운다.

- **왜 필요한가**: 에이전트가 어떤 스킬을 쓸 수 있는지 지금은 탐색기나 바깥 편집기로 `.claude/skills/`를 직접 열어 봐야 안다. 세션 상세 패널에는 "설치된 SKILL" 자리만 있고 내용은 없다(`docs/archive/agentManager-features.md` §8 예정 슬롯).
- **벤치마킹**: Emdash는 프롬프트·스킬·MCP를 Library 한 화면에서 관리한다(`docs/archive/emdash-benchmark-2026-10-14.md`). Superset·Sculptor·herdr는 오케스트레이션과 작업 절차를 스킬 파일로 표준화한다. 스킬을 보고 고치는 화면이 없는 도구는 EQMUX뿐이다.
- **원칙**: 파일이 원본이고 화면은 그 파일을 보여 준다(FR-E-74). 사용자 설정은 건드리지 않는다(0.5 결정 9). 그래서 쓰기는 워크스페이스 안 스킬만 하고, 사용자 전역 스킬은 읽기 전용으로 보여 준다.

## 범위

| 항목 | 1차 | 비고 |
|---|---|---|
| 스킬 목록 (프로젝트 · 사용자 · 플러그인) | 넣음 | 위치별로 묶어 보인다 |
| `SKILL.md` 미리보기 | 넣음 | 기존 마크다운 렌더러(`markdownHtml.ts`)를 쓴다 |
| 프로젝트 스킬 만들기 · 편집 · 삭제 | 넣음 | 기존 탐색기 파일 CRUD(`fs_*`)를 그대로 쓴다 |
| frontmatter 검사 (`name` · `description`) | 넣음 | 목록에 경고 표시. 저장을 막지는 않는다 |
| 사용자 스킬 → 프로젝트로 복사 | 넣음 | 사용자 스킬을 고치고 싶을 때의 경로 |
| 세션 상세의 "설치된 SKILL" | 넣음 | 그 세션 엔진·cwd 기준으로 보이는 스킬 목록만 |
| 사용자 전역 스킬 편집 · 삭제 | 뺌 | 결정 S1 |
| 스킬 켜기/끄기 | 뺌 | 엔진 설정 파일(`settings.json`의 권한 규칙)을 고쳐야 한다. 결정 9와 충돌 |
| 마켓플레이스 · 원격 설치 · 플러그인 관리 · MCP | 뺌 | 같은 "확장" 그룹의 `플러그인`·`MCP` 세그먼트가 맡는다(`docs/archive/plugin-panel-2026-10-15.md`, `docs/archive/mcp-panel-plan-2026-10-15.md`) |
| 스킬 실행 · 세션에 스킬 사용 지시 | 뺌 | 사람이 페인에 직접 `/스킬명`을 친다. 자동 실행 없음 원칙 |

## 스킬이 있는 곳

| 위치 | 경로 | 엔진 | 탭에서 |
|---|---|---|---|
| 프로젝트 | `<워크스페이스>/.claude/skills/<이름>/SKILL.md` | Claude Code | 읽기 · 쓰기 |
| 사용자 | `%USERPROFILE%\.claude\skills\<이름>\SKILL.md` | Claude Code | 읽기 전용 · 폴더 열기 · 프로젝트로 복사 |
| 플러그인 | `%USERPROFILE%\.claude\plugins\…\skills\<이름>\SKILL.md` | Claude Code | 읽기 전용 |
| Codex 프로젝트 · 사용자 | 구현 전 실측해 확정 (결정 S3) | Codex | 프로젝트는 읽기 · 쓰기, 사용자는 읽기 전용 |

- 워크트리 세션은 자기 사본의 `.claude/skills/`를 본다. 역할 파일 경로 규약(FR-E-63)과 같다. 세션 상세의 목록은 세션 cwd 기준으로 만든다.
- 같은 이름이 여러 위치에 있으면 목록에 모두 보이고 "같은 이름" 표시를 단다. 어느 쪽이 이기는지는 엔진이 정하므로 EQMUX가 판정하지 않는다.

## 화면

```
┌ 대화 │ 확장 │ 코드 │ 실행 │ 브라우저 ──────────────────────┐
│ [MCP | 플러그인 | 스킬]          [＋ 새 스킬] [↻]          │
│ ▾ 프로젝트 (3)                                              │
│   review-pr        PR을 리뷰할 때…              Claude      │
│   release-notes    릴리즈 노트를 쓸 때…         Claude      │
│   ⚠ db-migrate     description 없음             Claude      │
│ ▾ 사용자 (5) · 읽기 전용             [폴더 열기]            │
│   commit-style     커밋 메시지 규칙…            Claude      │
│ ▸ 플러그인 (12) · 읽기 전용                                 │
├─────────────────────────────────────────────────────────────┤
│ review-pr · .claude/skills/review-pr/SKILL.md               │
│ [편집] [삭제]           (사용자 스킬이면 [프로젝트로 복사]) │
│ ── 미리보기 ──                                              │
│ # Review PR …                                               │
└─────────────────────────────────────────────────────────────┘
```

- 자리는 "확장" 그룹의 세 번째 세그먼트다(최종본 §결정 22). 0.5에서 사이드 패널 탭은 대화 · 코드 · 실행 · 브라우저 4개 그룹으로 묶이고, 0.5.x에서 `대화` 다음에 "확장"이 들어온다. `SidePanel.tsx`의 "확장" 그룹에 하위 키 `skills`(라벨 `스킬`)를 넣고 `PanelTab` 타입에 `"skills"`를 더한다.
- 위는 목록, 아래는 선택한 스킬의 미리보기다. 편집을 누르면 아래가 `CodeEditor`로 바뀐다(탐색기 M24와 같은 편집기).
- 워크스페이스가 없으면 서버 탭처럼 "워크스페이스를 먼저 여세요"를 보인다. 사용자 스킬은 워크스페이스 없이도 보인다.
- 플러그인 묶음은 기본으로 접는다. 개수가 많고 고칠 수 없다.

## 사용자 흐름

### 새 스킬

1. `＋ 새 스킬`을 누르고 이름을 쓴다. 이름은 소문자·숫자·하이픈, 64자 이하만 받는다. 같은 이름의 폴더가 있으면 거부한다.
2. `.claude/skills/<이름>/SKILL.md`를 아래 틀로 만들고 바로 편집 모드로 연다.

```markdown
---
name: <이름>
description: 언제 이 스킬을 쓰는지 한두 문장으로 적는다
---

# <이름>

## 할 일

## 하지 말 것
```

### 편집 · 저장

- 저장은 `fsWrite`에 편집 시작 mtime을 넘긴다. 밖에서 파일이 바뀌었으면 저장을 거부하고, 역할 라이브러리와 같은 문구로 알린다(P-7). 파일이 이긴다.
- 저장 후 frontmatter를 다시 읽어 목록을 갱신한다. `name`이 폴더 이름과 다르거나 `description`이 비었거나 1,024자를 넘으면 목록에 ⚠를 단다. 저장 자체는 막지 않는다. 엔진이 받아들이는 형식이 버전마다 바뀔 수 있어서다.
- 살아 있는 세션에 반영되는지는 엔진에 달렸다. 저장 후 "실행 중인 세션은 재시작해야 반영될 수 있습니다" 한 줄을 띄운다. 역할 파일처럼 PTY에 "다시 읽어라"를 넣지 않는다. 스킬은 에이전트가 읽는 파일이 아니라 CLI가 기동 때 찾는 목록이라 안내가 소용없다(결정 S4에서 실측 후 바꿀 수 있다).

### 삭제

- 확인창을 거쳐 스킬 폴더 전체를 휴지통으로 옮긴다(`fsDelete`). 영구 삭제는 하지 않는다.

### 사용자 스킬을 프로젝트로 복사

- 사용자 스킬을 고치고 싶으면 `프로젝트로 복사`를 누른다. 폴더째 `.claude/skills/<이름>/`로 복사한 뒤 그 사본을 연다. 같은 이름이 이미 있으면 거부한다.
- 원본 사용자 스킬은 그대로 둔다. 같은 이름 표시가 둘 다에 붙는다.

## 구현

새 코드는 목록 실측 하나와 복사 하나다. 나머지는 이미 있는 것을 쓴다.

| 할 일 | 위치 | 재사용 |
|---|---|---|
| 스킬 목록 실측 커맨드 `skills_list(wsPath?)` | `src-tauri/src/skills.rs` (신규, 작게) | `roles.rs`의 `split_frontmatter`·`fm_value`, `library.rs`의 `read_dir_md`·`file_mtime_ms` |
| 사용자·플러그인 스킬 본문 읽기 `skill_read(path)` | 같은 파일 | 경로가 스킬 루트 아래인지 검사한다 (임의 파일 읽기 차단) |
| 사용자 → 프로젝트 복사 `skill_copy_to_ws(src, wsPath)` | 같은 파일 | 대상이 이미 있으면 거부 |
| 프로젝트 스킬 만들기·저장·삭제 | 프런트 | `panels.ts`의 `fsCreate`·`fsWrite`·`fsDelete` (워크스페이스 스코프·mtime 충돌·휴지통이 이미 있다) |
| 브리지 | `src/backend/skills.ts` (신규) | `panels.ts`처럼 `isTauri()` 아니면 빈 목록 |
| 탭 화면 | `src/components/SkillsPanelTab.tsx` (신규) | `MdViewTab`의 렌더, 탐색기의 `CodeEditor` 편집 흐름 |
| 세션 상세 "설치된 SKILL" | 세션 상세 화면 | 같은 `skills_list`를 세션 cwd와 엔진으로 걸러 쓴다 |
| 문구 | `src/i18n/shell.ts` | |

`skills_list`가 돌려주는 행:

```ts
interface SkillRow {
  scope: "project" | "user" | "plugin";
  engine: "claude" | "codex";
  name: string;        // frontmatter name, 없으면 폴더 이름
  description: string;
  path: string;        // SKILL.md 절대 경로
  rel?: string;        // 프로젝트 스킬이면 워크스페이스 상대 경로 — fs_* 호출에 쓴다
  mtimeMs: number;
  problems: string[];  // "description 없음" · "name이 폴더와 다름" 등
}
```

- 목록은 탭을 열 때와 `↻`를 누를 때 다시 실측한다. 파일 감시는 1차에 넣지 않는다. `.eqmux` 감시(M35)를 `.claude/skills`로 넓히는 것은 써 보고 외부 편집이 잦으면 더한다.
- 플러그인 폴더는 깊이가 있으므로 `SKILL.md`만 찾고 깊이 6에서 멈춘다. 상한에 걸리면 탐색기(B15)처럼 "더 있음"을 표시한다.
- 실측은 메인 스레드를 막지 않게 async 커맨드로 만든다(0.5 개선 트랙의 멈춤 원칙).

## 검증

- 프로젝트 스킬을 만들고 Claude Code 세션을 새로 띄워 `/` 메뉴에 그 스킬이 보이는지 본다.
- 바깥 편집기로 `SKILL.md`를 고친 뒤 탭에서 저장하면 충돌 문구가 뜨고 파일 내용이 이기는지 본다.
- 삭제한 스킬이 휴지통에 있는지 본다.
- 워크트리 세션의 세션 상세가 자기 사본의 스킬을 보이는지 본다.
- `skills_list`에 단위 테스트 하나를 둔다: 임시 폴더에 정상 스킬·frontmatter 없는 스킬·이름 불일치 스킬을 만들고 `problems`가 맞게 나오는지 본다(`library.rs` 테스트의 `temp_root` 방식).

## 나중에 볼 것

- 스킬 파일 감시로 목록 자동 갱신 — 외부 편집이 잦으면.
- 팀 프리셋에 "이 팀이 쓰는 스킬" 묶음 — 저장소의 팀 편성으로 시작(D3)과 함께 설계.
