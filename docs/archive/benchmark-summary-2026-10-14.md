## 1. 결론

1. **EQMUX의 해자는 네 가지다. 47개 도구 중 이를 함께 가진 도구가 없다.** 역할·페르소나, 권한을 정하는 역할 파일, 타입이 강제된 메시지(ask/handoff/report/review/escalate), 파일로 남는 메시지 원장이다.
2. **"에이전트끼리 말한다"는 더 이상 차별점이 아니다.** wmux(openwong2kim)는 Claude Code↔Codex `send_message`와 Fleet "Needs you" 목록을 갖췄다. herdr는 Windows 네이티브 GA에 위임 프리미티브를 갖췄다. cmux는 Claude Code Agent Teams를 네이티브 분할로 띄운다. Agent Teams 자체도 Claude Code에 실험 기능으로 들어 있다.
3. **EQMUX가 뒤처진 곳은 두 고리다.**
   - **주의 고리**: 알림을 누르면 그 페인으로 가고, 기다리는 에이전트를 한눈에 보고, 다 끝났는데 아직 안 본 세션을 표시한다.
   - **회신 고리**: 보낸 메시지가 전달됐는지, 받은 쪽이 답했는지 안다.
   분류 셋 모두에서 이 두 고리가 시장 기본기로 나왔다. 둘 다 기존 코드(알림 게이트, 상태 전이 훅, 메시지 원장)를 재사용해 작게 만들 수 있다.
4. **가져오지 않을 것도 분명하다.** 자동 승인(Yolo), 예약·자율 루프, 크래시 자동 재시작, 에이전트가 세션을 만드는 기능, 채팅 UI, 모바일·클라우드는 넣지 않는다. 경쟁 도구 대부분이 가졌지만 EQMUX 원칙과 정면으로 충돌한다. **"사람이 버튼을 누르는 팀"이 오히려 포지셔닝이다.** Paneflow("프롬프트는 채우고 Enter는 사람이")와 Agent Teams("에이전트 간 메시지는 승인 효력이 없다")가 이 방향의 외부 근거다.
5. **전략 결정이 하나 남았다. 앱을 꺼도 세션이 사는가.** TUI 도구 거의 전부, 데스크톱 4개(wmux·Paneflow·Superset·Orca), 범용 멀티플렉서 전부가 이를 지원한다. EQMUX는 Job Object로 정리하고 재개를 제안하는 쪽을 택했다. 0.5에서 바꿀 일은 아니다. 다만 기본기가 되어 가므로 0.6 기획 첫 안건으로 올린다.

## 5. 시장 신호

- **소멸과 합병이 빠르다.** Vibe Kanban(별 28k)은 종료를 공지했다. Opcode(별 22k)는 2025-10 이후 멈췄다. crmux 저자는 herdr로 옮겼다. Crystal은 Nimbalyst로, Mux는 Xum으로, claude-team은 maniple로 이름을 바꿨다. 기능 개수 경쟁만으로는 오래 못 간다.
- **층이 생기고 있다.** amux가 herdr를 백엔드로 쓰고, cmux가 Agent Teams를 띄우고, CCManager가 Agent Teams와 공존한다. EQMUX도 "다른 도구 위에 얹히는 관제 층"이 될 수 있는지 0.6 외부 인터페이스 재설계 때 검토한다.
- **Windows가 더 이상 빈 땅이 아니다.** wmux 2종, herdr, Paneflow, Nimbalyst, Orca, Codex 앱이 Windows를 낸다. "Windows 네이티브"만으로는 부족하고, 역할 팀 + 사람 관제를 앞세워야 한다.
- **공식 플랫폼이 흡수한다.** Claude Code Agent Teams와 Codex 앱(ChatGPT 데스크톱으로 통합)이 병렬·팀 기능을 내장한다. 다만 Agent Teams는 실험 기능이고, Windows Terminal에서 분할 페인이 안 되며, 메시지 타입·원장·관제 화면이 없다.
