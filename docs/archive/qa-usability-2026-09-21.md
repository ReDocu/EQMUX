# 1부 — 사용성

## U-3 · 슬롯을 만든 뒤에는 엔진을 바꿀 수 없다

**심각도**: 높음 (되돌리려면 세션을 지워야 하고, 그 과정에서 역할 파일과 임무 배정이 함께 사라진다)

### 재현 절차
1. `+ 세션 추가` → `에이전트 열기` → 엔진 `Codex` → `열기`.
2. 마음을 바꿔 그 슬롯을 Claude Code로 되돌리려 한다.
3. 세션 상세를 열어 `역할 변경`을 본다. 팀 캐스팅 화면도 본다.

### 기대 결과
권한(FR-E-34)처럼 슬롯 단위로 바꾸고, 재시작이 필요하다는 안내가 붙는다.

### 실제 결과
어디에도 엔진을 바꾸는 자리가 없다. `역할 변경`은 페르소나·직무만 바꾸고
(`SessionDetailPanel.tsx:455`), 팀 캐스팅 화면에는 엔진 개념이 아예 없다(`TeamCasting.tsx`에
`cli` 언급 0건). 남은 길은 둘뿐이다 — `.eqmux/team.json`을 손으로 고치거나, 슬롯을 제거하고
다시 만드는 것. 후자는 역할 파일 삭제와 임무 배정 해제를 동반하므로 되돌리기가 아니라 파괴다.

### 원인
엔진을 `team.json` 슬롯의 `cli` 필드로 영속시키면서(`team.rs`), 그 값을 **쓰는 입구를 생성 시점
하나로만 뒀다**(`ControlCenter.tsx:1330`). 권한은 같은 성격의 값인데 오버라이드 편집 + 재개 기반
재시작(E11′)이라는 왕복이 이미 있다.

### 제안
세션 상세의 `역할 변경` 블록 옆에 엔진 선택을 둔다. 엔진 변경은 대화를 이어갈 수 없으므로
(재개 앵커가 CLI마다 다르다) "바꾸면 새 대화로 시작합니다"를 명시하고, 권한 변경과 달리
`agent_restart`가 아니라 새 기동으로 처리한다. 그게 부담이면 최소한 캐스팅 화면에 **읽기 전용
표시**라도 넣어, 편성을 보는 자리에서 엔진이 보이게 한다.

## U-1 · 엔진이 편성에는 남는데 화면에는 세션 상세에만 보인다

**심각도**: 중 (혼성 팀에서 "지금 이 페인이 무엇인가"를 매번 상세를 열어 확인해야 한다)

### 재현 절차
1. 한 워크스페이스에 Claude 슬롯과 Codex 슬롯을 하나씩 만든다.
2. 기동하지 않은 채 레일·페인 헤더·관제 대시보드 카드·대화 패널을 본다.

### 기대 결과
어느 슬롯이 Codex인지 한눈에 보인다.

### 실제 결과
네 곳 모두 구분이 없다. 실측한 문자열 그대로다.

| 자리 | Claude 슬롯 | Codex 슬롯 |
|---|---|---|
| 레일 행 | `미라 / 리드` | `노엘 / 개발` |
| 페인 헤더 | `미라 · shell · ▶ 에이전트 기동` | `노엘 · shell · ▶ 에이전트 기동` |
| 대시보드 카드 | `노엘 / 개발` | `노엘 / 개발` |
| 세션 상세 | `엔진 · Claude Code` | `엔진 · Codex` ← 유일하게 보이는 자리 |

대시보드의 `Claude`·`Codex` 배지는 **감지된 프로세스**(`s.agent`, `Dashboard.tsx:188`)라서
기동 전에는 비어 있고, 기동 뒤에도 편성과 다를 수 있다(사람이 그 셸에서 손으로 다른 CLI를 띄우면).
즉 지금 화면에 있는 엔진 표시는 "무엇으로 띄우기로 했는가"가 아니라 "무엇이 실제로 돌고 있는가"다.
둘은 다른 값이고, 지금은 앞의 것이 거의 안 보인다.

### 원인
`Session.cli`를 타입과 파일에는 넣었지만 표시 경로는 세션 상세 한 곳만 받았다
(`SessionDetailPanel.tsx:333-337`). 레일(`ControlCenter.tsx:1004`)과 페인 헤더는 종전대로
이름·직무·상태만 그린다.

### 제안
레일 행과 페인 헤더에 엔진 칩을 하나 둔다. 배지가 둘(편성·실측) 겹쳐 시끄러워지지 않게 규칙을
하나로 정하는 편이 낫다: **기동 전에는 편성 엔진을 흐리게, 기동 뒤에는 실측 배지로 대체하고,
둘이 다를 때만 경고색.** 그러면 "관제가 핵심"이라는 원칙과도 맞는다 — 다름을 숨기지 않는다.

## U-2 · `▶ 에이전트 기동`이 무엇을 띄울지 말하지 않는다

**심각도**: 중 (Codex 슬롯에서 누르면 codex가 뜨는데, 그 사실을 누르기 전에 알 수 없다)

### 재현 절차
Codex 슬롯의 페인 헤더 버튼에 마우스를 올린다. 우클릭 메뉴의 `에이전트 기동`도 본다.

### 실제 결과
Claude 슬롯과 **문구도 툴팁도 완전히 같다.**

```
▶ 에이전트 기동
title: 이 셸을 끝내고 역할·권한·훅이 붙은 에이전트로 다시 엽니다
```

기동은 셸을 죽이고 새 프로세스를 띄우는 비가역 조작인데(`killAndWait` → `spawnAgent`),
무엇이 뜰지 모른 채 누르게 된다. U-3과 겹치면 더 나쁘다 — 잘못 눌러도 되돌릴 자리가 없다.

### 원인
`ControlCenter.tsx:481`·`721`이 엔진과 무관한 고정 문구를 쓴다.

### 제안
`▶ Codex 기동` / `▶ Claude Code 기동`으로 엔진을 문구에 넣는다. 툴팁도 같이.
i18n은 `tf("{name} 기동", …)` 한 줄이면 된다.

## U-4 · 미설치 경고가 엔진 선택보다 위에 있다

**심각도**: 낮음 (읽는 순서가 뒤집혀 있다)

### 실제 결과
다이얼로그를 열면 빨간 줄이 먼저 온다.

```
페르소나·직무를 정해 바로 기동 · … (Claude Code · Codex)
PATH에 claude가 없습니다 — 설치 후 설정 > CLI 에이전트에서 다시 확인하세요   ← 경고
엔진  [ Claude Code ▾ ]                                                  ← 무엇에 대한 경고인지
```

경고 문구가 선택한 엔진을 따라 바뀌는 것은 맞다(Codex로 바꾸면 `PATH에 codex가 없습니다`로 갱신됨,
실측 확인). 다만 **무엇을 고르는 자리인지 보기 전에 그 선택에 대한 경고부터 읽게 된다.**

### 원인
`ControlCenter.tsx:1321`의 `<Show when={addCliMissing()}>`가 엔진 셀렉트(`:1330`)보다 앞에 있다.
원래 claude 하나뿐이던 시절의 배치가 그대로 남았다.

### 제안
경고 블록을 엔진 셀렉트 **아래**로 옮긴다. 두 줄 순서만 바꾸면 된다.

## U-5 · 엔진 셀렉트만 폭이 다르다

**심각도**: 낮음 (시각 정렬)

엔진 셀렉트는 행 전체를 차지하고, 바로 아래 페르소나·직무는 절반씩 나눠 쓴다. 덜 중요한 값이
가장 크게 보인다. `role-edit-row` 그리드를 그대로 쓰면서 라벨 한 칸이 붙어 생긴 결과다.
엔진 셀렉트에 페르소나와 같은 폭을 주고 남는 칸을 비우는 편이 읽기 좋다.

# 2부 — 통과한 것

- **흐름이 끝까지 돈다.** 탭 전환 → 빈 페인 → 다이얼로그 → 엔진 Codex → 열기 → 레일에 슬롯 추가까지
  막히는 지점이 없었다. 전 과정에서 **콘솔 오류·경고 0건**.
- **영어 사전 누락 0.** 이번에 바뀐 화면 4곳의 한국어 키 218개가 모두 사전에 있다
  (`엔진`, `에이전트 열기`, `PATH에 {cmd}가 없습니다 …` 포함).
- **세션 상세의 플래그 표시가 엔진별로 갈리고 정직하다.** Codex 슬롯에서:

  ```
  엔진 · Codex
  --sandbox workspace-write --ask-for-approval on-request (지시로만: Bash(git commit *) Bash(git push *))
  ```

  git 금지가 플래그가 아니라 지시라는 사실을 `(지시로만: …)`로 밝힌다. 막혀 있지 않은 것을
  막혀 있다고 믿게 두지 않는다는 점에서 이 제품의 기존 태도와 같다.
- **경고 문구가 선택을 따라간다.** 엔진을 바꾸면 `claude` → `codex`로 즉시 갱신된다.
- **엔진 선택지가 실측이 오기 전에도 흔들리지 않는다.** 명부가 비어 있으면 둘 다 내놓는 폴백
  (`managedClis()`)이라, 목업과 기동 직후에 셀렉트가 비는 일이 없다.

# 4부 — 실기에서 확인해야 할 것

목 백엔드로는 닿지 않는 자리들이다. 새 바이너리로 앱을 바꿔 켠 뒤 순서대로 본다.

1. Codex 슬롯 기동 → 페인에 codex가 뜨고, 첫 턴 뒤 세션 상세의 재개 칩이 살아나는가
   (SessionStart 훅이 `session_id`·`transcript_path`를 물어다 주어야 한다).
2. 상태 전이 — 프롬프트 제출에 `busy`, 턴 종료에 `idle`, 승인 요청에 `waiting`이 뜨는가.
   `idle`이 안 오면 대화 인박스가 영영 배출되지 않으므로 이것이 제일 중요하다.
3. Claude 슬롯에서 `eqmux send --to "@<Codex 페르소나>" …` → 그 페인의 턴이 실제로 도는가.
   반대 방향도 같이 본다.
4. 마지막 한 줄 요약이 Codex 페인에도 남는가(Stop 훅의 `last_assistant_message`).
5. 트랜스크립트 탭이 Codex 롤아웃을 턴 단위로 읽는가.
6. **이 PC의 Codex 샌드박스.** 지금 `--sandbox` 모드에서 명령 실행이 실패한다
   (`codex-windows-sandbox-setup.exe` 실행 실패 → `CreateProcessWithLogonW failed: 2`).
   EQMUX가 권한을 샌드박스로 번역하므로, 이걸 먼저 풀지 않으면 Codex 슬롯은 파일을 읽는 것
   말고 아무것도 못 한다. `codex update`(0.155.1 대기 중)부터 시도한다.
