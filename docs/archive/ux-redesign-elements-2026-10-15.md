# EQMUX 0.5 UX 개편 요소 제안

원본: [Claude Docs](https://claude.ai/code/artifact/4fa88fcd-5e4a-4a2c-9209-b4e3a4488a79)

최종 반영: [update-plan-0.5.0.md](../update-plan-0.5.0.md) §UX 기반 외 — 각 제안을 어떻게 반영했는지는 맨 아래 §최종본 반영 결과에 있다.

2026-10-15 · `docs/update-plan-0.5.0.md` 기반

0.5는 화면에 새 표시를 20개 가까이 더한다. 대부분이 페인 헤더 한 줄과 레일·대시보드에 몰린다. 기능을 하나씩 붙이면 헤더가 칩으로 넘치고, 색이 늘어나 "지금 봐야 할 세션"이 묻힌다. 그래서 개편의 중심은 새 화면이 아니라 세 가지 규칙이다. **주의 단계(무엇에 색을 쓰나)**, **페인 헤더 슬롯(무엇을 어디에 두나)**, **공통 부품(같은 일을 같은 모양으로)**. 이 셋을 3단계(직함·세션 이름) 전에 정해 두면 3~5단계의 기능이 그 위에 얹힌다.

## 1 · 주의 단계

색은 세 단계에만 쓴다. 나머지는 모두 흐린 글자다. 정렬도 이 순서를 따른다(기획서의 대시보드 주의 정렬과 같다).

| 단계 | 상태 | 색 | 뜻 |
|---|---|---|---|
| 행동 필요 | waiting, dead | amber, red (지금 그대로) | 사람이 입력하거나 되살려야 한다 |
| 확인 필요 | 완료 보고, 턴 완료(미확인), 보고 없음, 메시지 대기(`넣기`) | blue 한 색 + 점 | 끝났거나 쌓였다. 봐야 하지만 급하지 않다 |
| 정보 | busy, idle, 엔진, 직무, 재시작 필요, 한도·컨텍스트 % | 색 없음 (`--eq-muted`) | 상태를 알려 줄 뿐이다. 70%를 넘는 컨텍스트만 확인 단계로 올린다 |

- 완료에 초록을 쓰지 않는다. 초록은 "괜찮다"로 읽혀 확인할 일이 남았다는 뜻이 약해진다.
- 확인 단계는 한 색이다. 종류는 칩 글자(`✓ 완료 보고`, `보고 없음`, `메시지 3`)로 가른다.

## 2 · 페인 헤더 슬롯

```
지금
[ 카이 ··························· 요약… · ⛶ Bash 승인 · waiting · 2m ]

0.5 제안
[ 03 카이 · 클라이언트 개발자 ◇ │ 요약…(남는 폭) │ ●보고 없음 [보고 요청] +1 │ idle ]
  └ 정체성 (고정 폭, 말줄임) ─┘  └ 가변 ─────┘  └ 주의 칩 1개 + 나머지 수 ─┘  └ 상태 ┘
```

- 정체성 칸은 `번호 이름 · 직함 엔진`이다. 번호는 흐린 고정폭이고, 엔진은 글자 대신 작은 아이콘이다. 직함은 정체성 칸 폭을 넘으면 먼저 말줄임된다.
- 주의 칩 칸은 가장 높은 단계의 칩 하나만 보인다. 우선순위는 `승인 대기 > 메시지 대기(넣기) > 보고 없음 > 완료 보고 > 턴 완료 > 재시작 필요`다. 나머지는 `+N`이고, 누르면 칩 목록이 펼쳐진다.
- 칩의 동작 버튼(`넣기`·`보고 요청`·`재시작`)은 칩 안의 작은 버튼이다. 칩을 누르면 지금처럼 페인을 Focus로 잡는다.
- 요약은 남는 폭만 쓰고, 칩이 늘면 먼저 줄어든다(지금 동작 그대로).
- 레일 행은 같은 순서에서 요약을 빼고, 주의 칩 대신 단계 점 하나만 둔다.

## 3 · 공통 부품 목록

새로 만들 부품은 다섯 개다. 모두 `src/components/ui.tsx`에 둔다(지금 `StatusLabel`·`ContextMenu`가 있는 곳).

| 부품 | 쓰는 곳 (0.5) |
|---|---|
| `Chip` (단계 · 글자 · 동작 버튼 · 툴팁) | 헤더 · 레일 · 대시보드 · 벨 · 대화 탭 |
| `Identity` (번호 · 이름 · 직함 · 엔진, 좁은/넓은 모드) | 헤더 · 레일 · 대시보드 · 세션 상세 · 캐스팅 · 벨 |
| `ConfirmDialog` | 세션 중지 3곳 · 기본 터미널 제거 · 역할 세션 제거 |
| `Segmented` | 설정 · 사이드 패널 그룹 · 완료 알림 설정 · 임무 팝업 |
| `FieldHint` (검증 이유 · 기본값 안내) | 세션 이름 · 직함 · 메시지 본문 800자 |

`ContextMenu`는 새로 만들지 않는다. 그룹 순서 규칙(#10)과 키보드 열기(#14)만 더한다.

## 넣지 않는 것

- **새 테마·리스킨** — 색 토큰은 이미 있고(`styles.css:5-58`) 문제는 색이 아니라 색을 쓰는 규칙이다.
- **아이콘 세트 교체·애니메이션** — 0.5 범위를 늘린다. 엔진 아이콘 두 개만 더한다.
- **헤더 두 줄** — 페인이 8개일 때 터미널 높이를 깎는다. `+N`으로 접는다.

## 기획서에 반영할 때

- 작업 순서 2단계(P0)와 3단계 사이에 **UX 기반**을 둔다. #1~#5를 정하고 `Chip`·`Identity`를 만든다. 관문: 지금 헤더(이름 · 요약 · 승인 대기 · 상태)를 새 부품으로 바꿔도 화면이 같다.
- §결정에 두 건을 더한다. (1) 완료 칩 색: 확인 단계 blue 한 색 vs 종류별 색. 권장은 한 색이다. (2) 헤더 주의 칩 수: 1개 + `+N` vs 전부. 권장은 1개다.
- 각 기능 섹션의 "화면" 표는 그대로 두고, 새 칩은 `Chip` 단계 하나를 고르는 것으로 적는다.

## 확인 필요

- 페인 8개(2×4) 배치에서 정체성 칸에 `03 이름 · 직함`이 들어갈 폭이 있는지 실측하지 않았다. 안 들어가면 좁은 모드에서는 직함을 툴팁으로만 보인다.
- `docs/design.pen` 시안에 헤더·레일 디자인이 이미 있는지 보지 않았다. 있으면 그 시안을 기준으로 위 슬롯을 맞춘다.
