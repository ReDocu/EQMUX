# 토큰 최적화 — 최소 기능 제안 (2026-10-15)

최종 반영: [update-plan-0.5.0.md](../update-plan-0.5.0.md) §개선 트랙 · §통신 간소화 · §0.5.x로 넘기는 것 · §0.6 이후로 미루는 것 — 다르게 정한 것은 맨 아래 §최종본 반영 결과에 있다.

에이전트(Claude Code·Codex)가 EQMUX 안에서 쓰는 **LLM 토큰**을 줄이는 기능 후보.
`optimization-candidates-2026-10-14.md`(앱 성능)와는 별개다. 코드로 확인한 것만 적었고, **코드는 고치지 않았다.**

원칙: 새 시스템을 만들지 않는다. 이미 있는 경로(인박스·batches·recap·statusline·역할 파일)에 상한이나 분기 하나를 얹는 수준만.

## 토큰이 새는 자리 (코드 확인)

| 자리 | 근거 | 왜 비싼가 |
|---|---|---|
| 캐릭터 시트 인라인 | `cli.rs` `MAX_SHEET_CHARS = 20_000` | SessionStart 훅이 시트 본문을 최대 2만 자까지 싣는다. 한글은 글자당 토큰이 비싸 **세션당 수만 토큰**이 상주하고, 매 턴 재전송된다(캐시 읽기라도 0은 아님). 컴팩트 뒤 재시작 때도 다시 실린다 |
| `@all` 방송 | `conversation.ts` `deliver` / `recipients` | 수신자마다 **턴 하나씩** 돈다. 팀원 N명 = 방송 1건에 N-1턴. 턴마다 전체 컨텍스트를 다시 읽는다 — 가장 큰 증폭기 |
| 유휴 즉시 주입 | `deliver` → `canInject` → `injectMessages([m])` | 유휴 세션은 메시지마다 바로 턴을 돌린다. 몇 초 간격으로 3건이 오면 3턴. 묶기(`batches`)는 바쁠 때 쌓인 것에만 적용된다 |
| 브라우저 결과 | `browser.rs` `MAX_RESULT = 30_000` | `snapshot`·`get-text` 한 번에 최대 3만 자가 도구 결과로 들어간다 |
| 시스템 프롬프트 | `lib.rs` `--append-system-prompt` 조립부 | 브라우저 사용법 문단이 브라우저를 안 쓰는 세션에도 항상 실린다 |
| 부풀어 오른 세션 | 컨텍스트 사용량 추적 없음 (`context_window` 0건) | 사람이 컨텍스트가 찼는지 모른 채 계속 대화 → 턴당 비용이 계속 커진다 |
| 모델 고정 | `--model` 인자 0건 | 리뷰·보고 같은 가벼운 직무도 기본(최상위) 모델로 돈다 |

## 제안 (효과 ÷ 수고 순)

| # | 기능 | 하는 일 | 수고 | 손댈 곳 |
|---|---|---|---|---|
| 1 | **시트 상한 축소** | `MAX_SHEET_CHARS` 20,000 → 4,000. 정체성·말투 규칙·대사 예시가 앞에 오므로(주석 그대로) 앞 4천 자로 캐릭터는 유지된다. 잘린 뒤는 기존 안내문("원본 파일을 읽을 것")이 그대로 처리 | 한 줄 | `cli.rs` |
| 2 | **조용한 메시지 타입** | `report`·`review`처럼 답이 필요 없는 타입은 유휴 수신자를 **깨우지 않고** 인박스에 재운다. 다음 진짜 턴(사람 입력 또는 ask/handoff 도착) 때 함께 흘러간다 | 작음 (분기 1개) | `conversation.ts` `deliver` |
| 3 | **유휴 주입 묶기 창** | 유휴 세션에도 바로 쏘지 않고 1.5~3초 기다렸다 `batches`로 한 턴에 묶는다. 연속 메시지 N건 = 1턴 | 작음 (타이머 1개) | `conversation.ts` `deliver` |
| 4 | **긴 메시지는 포인터로** | 본문이 N자(예: 800)를 넘으면 `.eqmux/msgs/<id>.md`에 쓰고 주입은 `첫 줄 + 경로`만. 원문은 이미 메시지 원장에 있다. `@all`이면 절감이 수신자 수만큼 곱해진다 | 작음 | `conversation.ts` `fmt` |
| 5 | **컨텍스트 사용량 배지** | 상태 줄 훅이 이미 매번 payload를 받는다(`_statusline`). 여기 실린 컨텍스트 사용량을 페인 헤더에 % 배지로, 70% 넘으면 경고 색. payload에 없으면 트랜스크립트 마지막 assistant `usage`(input + cache_read + cache_creation)로 계산 — `transcript.rs`가 이미 JSONL을 파싱한다 | 중간 | `cli.rs` statusline, 페인 헤더 |
| 6 | **새로 시작 (요약 이월)** | "재개" 옆에 버튼 하나: 기존 대화를 잇지 않고 새 세션을 띄우되 `last_recap`(M35, 이미 SQLite에 있음)을 첫 프롬프트로 넣는다. 부푼 컨텍스트를 버리는 가장 싼 길. `/compact`는 압축 자체가 토큰을 쓴다 | 작음 | 세션 메뉴, `agent_restart` 경로 |
| 7 | **브라우저 결과 상한 축소** | `MAX_RESULT` 30,000 → 10,000, `snapshot`에 `-i`(클릭 가능한 요소만) 옵션 | 한 줄 + 작음 | `browser.rs` |
| 8 | **직무별 모델** | 직무(job) 정의에 `model` 필드 하나 → 스폰 때 `--model`(Codex는 `-c model=`). 리뷰어·보고 담당은 Sonnet/Haiku | 작음 | 직무 스키마, `lib.rs` 스폰 |
| 9 | **브라우저 안내 분리** | 시스템 프롬프트의 브라우저 문단을 한 줄 포인터(`웹은 eqmux browser — 사용법은 eqmux browser help`)로 줄인다 | 한 줄 | `lib.rs` |

먼저 할 것: **1 · 2 · 3** — 각각 한 줄~분기 하나이고, 1은 세션당 상주 토큰을, 2·3은 팀 대화의 턴 수 자체를 줄인다(턴 수 감소가 토큰 감소보다 크다).

## 안 하는 것 (지금은)

- **자체 요약기/압축 엔진** — Claude Code의 `/compact`와 recap(M35)이 이미 있다. 6번(요약 이월)으로 충분하다.
- **토큰 대시보드·예산 한도** — 5번 배지로 먼저 보이게 하고, 실제로 넘치는 일이 잦으면 그때.
- **메시지 의미 중복 제거** — 휴리스틱이 오판하면 메시지가 사라진다. 비용 대비 위험이 크다.

## 확인 필요

- 5번: 지금 쓰는 Claude Code 버전의 statusline payload에 컨텍스트 사용량 필드가 있는지 (없으면 트랜스크립트 계산으로).
- 2번: 조용한 타입이 너무 오래 잠들지 않도록 — 인박스 대기분이 있는 세션에 배지(이미 `inboxTick`으로 그려짐)만 있으면 사람이 깨울 수 있다.
