# MCP 관리 탭 기획 — 2026-10-15

최종 반영: [update-plan-0.5.0.md](../update-plan-0.5.0.md) §결정 22 · §개선 — 오른쪽 위 메뉴 정리 · §0.5.x로 넘기는 것 — 탭 위치·이름·출시 시점을 최종본에 맞춰 고쳤다.

기준: `sub_main` 0.4.2와 미커밋 변경(서버 탭 포함). Claude Code 2.1.299, codex-cli 0.155.1에서 CLI 도움말을 확인했다.
요약: 사이드 패널 **"확장" 그룹에 `MCP` 세그먼트**를 만든다(`[MCP | 플러그인 | 스킬]`, 0.5.x). 화면은 이 워크스페이스의 에이전트가 쓰는 MCP 서버를 읽어서 보여 준다. 앞으로 띄울 세션에서 특정 서버를 끌 수 있다. 사용자의 설정 파일에는 쓰지 않는다.

## 1. 왜 필요한가

- 지금 EQMUX에는 MCP를 볼 화면이 없다. 어떤 서버가 붙는지 알려면 페인마다 `/mcp`를 쳐야 한다.
- MCP 도구 정의는 세션마다 컨텍스트를 차지한다. 에이전트 4~8명이 같은 서버를 다 띄우면 비용도 그만큼 든다. 역할에 필요 없는 서버를 끄는 것이 가장 싼 토큰 절감이다.
- 클론한 저장소의 `.mcp.json`은 승인 전에는 붙지 않는다. 사람이 그 사실을 모르면 "도구가 없다"는 오해가 생긴다.
- 벤치마크 도구 중 Agent Deck(프로젝트별 MCP 켜기·끄기), Opcode, emdash(Library), Superset이 이 기능을 갖고 있다(`docs/archive/benchmark-tui-managers-2026-10-14.md`, `docs/archive/emdash-benchmark-2026-10-14.md`).
- 기획서 `docs/archive/agentManager-features.md`의 세션 상세 패널에 "설치된 MCP"가 예정돼 있다. 이 탭이 그 데이터를 먼저 만든다.

`docs/update-plan-0.5.0.md`가 0.6 이후로 미룬 "MCP 서버"는 **EQMUX가 MCP 서버가 되는 것**이다. 이 문서는 에이전트가 쓰는 MCP를 **관리하는 화면**이라 그것과 별개다.

## 2. 지켜야 할 원칙

| 원칙 | 이 탭에서의 뜻 |
|---|---|
| 사용자 설정 불가침 (FR-E-70) | `~/.claude.json`, `~/.codex/config.toml`, 저장소의 `.mcp.json`·`.claude/`·`.codex/`는 **읽기만** 한다. 훅 주입과 같은 방식으로 세션별 CLI 인자로만 얹는다(`lib.rs:1028`, `agent.rs:123`) |
| 앱은 키·자격 증명을 쥐지 않는다 | Rust가 설정을 읽을 때 `env`·`headers`의 **값을 버리고 키 이름만** 프런트로 넘긴다. 값은 화면·로그·스크롤백 어디에도 남기지 않는다 |
| `.eqmux/` 파일이 원본이다 | 워크스페이스의 "끈 서버" 목록은 `.eqmux/mcp.json`에 둔다. 손으로 고쳐도 된다 |
| 상태를 바꾸는 것은 사람의 버튼이다 | 서버 추가·삭제·로그인은 앱이 실행하지 않는다. 명령을 서버 탭 터미널에 **채워 두고 Enter는 사람이** 누른다 |
| 자동 실행 경로 없음 | 상태 점검(`claude mcp list`)은 서버 프로세스를 띄운다. 그래서 사람이 `점검`을 누를 때만 돌린다. 주기 점검은 하지 않는다 |

## 3. 위치와 화면

### 3-1. 위치

0.5에서 사이드 패널 탭은 그룹 4개(대화 · 코드 · 실행 · 브라우저)로 묶인다(최종본 §개선 — 오른쪽 위 메뉴 정리). 0.5.x에서 `대화` 다음에 "확장" 그룹이 들어오고, 이 화면은 그 첫 세그먼트다(§결정 22).

```
[대화] [확장] [코드] [실행] [브라우저]  ◧ ✕
        └ [MCP | 플러그인 | 스킬]
```

`SidePanel.tsx`의 "확장" 그룹에 하위 키 `mcp`(라벨 `MCP`)를 넣는다. `state.ts:50`의 `PanelTab` 유니온에 `"mcp"`를 더한다. 서버 탭처럼 `scopeWorkspace()` 기준이고, 워크스페이스가 없으면 "워크스페이스를 먼저 여세요"를 보인다(`ServerPanelTab.tsx`와 같은 폴백).

### 3-2. 화면

```
┌ MCP ─────────────────────────────── [점검] [추가 ▾] ┐
│ 엔진 [Claude ▾]                       마지막 점검 14:02 │
├────────────────────────────────────────────────────┤
│ ● github     user     http   env: GITHUB_TOKEN   [켬] │
│ ● playwright local    stdio  npx @playwright/mcp [켬] │
│ ⏸ figma      project  stdio  승인 대기 — 페인에서 /mcp  │
│ ○ sentry     user     http   이 워크스페이스에서 끔 [끔] │
├────────────────────────────────────────────────────┤
│ 재시작해야 적용되는 세션: 김설계 · 박검토  [모두 보기]   │
└────────────────────────────────────────────────────┘
```

- **행**: 이름 · 범위(user / local / project) · 전송(stdio / http / sse) · 명령이나 주소 · env 키 이름 · 켬/끔 토글.
- **상태 점**은 `점검`을 누른 결과다. ● 연결됨 · ✕ 실패 · ⏸ 승인 대기 · ○ 끔 · 회색 = 점검 전. 점검 전에는 파일에서 읽은 목록만 보인다.
- **엔진 선택**: Claude와 Codex의 설정은 따로다. 이 워크스페이스에 Codex 세션이 없으면 선택지를 숨긴다.
- **승인 대기**(project 범위 `.mcp.json`): 앱이 승인하지 않는다. "페인에서 `/mcp`로 승인" 안내만 한다.
- **재시작 필요 줄**: 토글을 바꾼 뒤에도 그 전에 뜬 세션은 옛 설정으로 돈다. 해당 세션 이름을 보이고, 누르면 그 페인으로 간다. 자동 재시작은 하지 않는다.
- **추가 ▾**: `claude mcp add --scope local <이름> -- <명령>` 같은 틀을 서버 탭 터미널 입력줄에 채운다. 삭제는 행 메뉴의 `제거 명령 채우기`, OAuth는 `로그인 명령 채우기`(`claude mcp login <이름>`)로 한다.

## 5. 끄기 — 세션에 적용하는 방법

### 5-1. 저장

`.eqmux/mcp.json`:

```json
{ "claude": { "off": ["sentry"] }, "codex": { "off": [] } }
```

토글은 이 파일만 고친다. 쓰기는 `workspace::atomic_write`를 쓰고, 기존 fs CRUD(M24)처럼 mtime으로 외부 변경 충돌을 막는다.

### 5-2. 스폰 때 적용 (`lib.rs` 스폰 경로, 역할 파일을 읽는 자리)

- **Claude**: 끈 서버마다 `mcp__<이름>`을 기존 `disallowed` 목록에 합친다. 기존 `--disallowedTools` 인자가 그대로 실린다(`lib.rs:1017`). 서버 설정을 복사하지 않으므로 자격 증명이 앱 데이터로 옮겨지지 않는다.
- **Codex**: 끈 서버마다 `-c mcp_servers.<이름>.enabled=false`를 더한다. 훅과 같은 인라인 오버라이드 방식이다.
- `--strict-mcp-config`는 쓰지 않는다. 그러려면 서버 정의 전체(env 값 포함)를 앱이 다시 써야 한다.

### 5-3. 세션 기록

스폰 때 적용한 off 목록을 세션 플래그(`noteSpawnFlags`)에 남긴다. 그러면 "재시작 필요" 판정과 세션 상세의 "설치된 MCP"가 같은 데이터를 쓴다.

## 7. 확인이 필요한 것

| # | 질문 | 확인 방법 | 안 되면 |
|---|---|---|---|
| Q1 | `--disallowedTools mcp__<이름>`이 도구 정의를 컨텍스트에서도 빼는가, 호출만 막는가 | 끄기 전후로 `/context`의 MCP 토큰 수를 비교한다 | 호출만 막는다면 "토큰 절감"을 문구에서 뺀다. 서버 프로세스는 어느 쪽이든 뜬다는 점을 화면에 적는다 |
| Q2 | Codex 0.155.1이 `mcp_servers.<이름>.enabled=false`를 받는가 | `codex -c mcp_servers.x.enabled=false mcp list --json` | Codex는 끄기 토글을 숨기고 목록만 보인다 |
| Q3 | `~/.claude.json`의 프로젝트 키 표기 | 실제 파일에서 워크스페이스 경로를 찾아본다 | 대소문자 무시 비교로 찾는다 |
| Q4 | `claude mcp list` 출력 형식이 버전마다 안정적인가 | 2.1.x 몇 버전의 출력을 비교한다 | 파싱 실패 시 원문 표시(4장)로 버틴다 |

## 8. 넣지 않는 것

- 앱이 `claude mcp add/remove`나 승인을 대신 실행하는 것 — 2장 원칙.
- 자격 증명 입력란·저장 — 2장 원칙. 비밀은 사용자의 환경 변수나 각 CLI의 저장소에 둔다.
- 주기적 상태 점검, 실패 서버 자동 재시작 — 자동 실행 경로다.
- 역할(직무)별 기본 MCP 세트 — 워크스페이스 단위 끄기를 먼저 써 보고, 필요가 보이면 역할 파일에 `mcp_off`를 더한다.
- EQMUX 자체를 MCP 서버로 노출 — 0.6 이후(`update-plan-0.5.0.md`).

## 9. 단계와 수용 기준

| 단계 | 내용 | 수용 기준 |
|---|---|---|
| 1 | 읽기 전용 목록 (Claude) | user·local·project 서버가 범위와 함께 보인다. env 값은 개발자 도구 응답에도 없다. `~/.claude.json`이 깨져도 앱이 멈추지 않는다 |
| 2 | 점검 버튼 | 누르는 동안 UI가 굳지 않는다. 승인 대기 서버가 ⏸로 보인다. 30초 넘으면 "시간 초과"를 보인다 |
| 3 | 끄기 토글 | 끈 뒤 새로 띄운 Claude 세션에서 그 서버 도구를 호출하면 거부된다. 그 전에 뜬 세션은 "재시작 필요"에 나온다. `.eqmux/mcp.json`을 손으로 고쳐도 반영된다 |
| 4 | 명령 채우기 | 추가·제거·로그인 명령이 서버 탭 입력줄에 채워지고 실행되지 않는다 |
| 5 | Codex | Q2가 통과하면 같은 토글, 아니면 목록만 |

배치: 최종본에서 정했다(§0.5.x로 넘기는 것). 0.5 범위는 이미 크다. 그래서 **0.5.x**에 1~4단계를 넣고 5단계는 Q2 결과를 보고 정한다. 세션 상세 패널의 "설치된 MCP"는 5-3 데이터가 생긴 뒤에 붙인다.
