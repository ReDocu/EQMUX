# Orca 벤치마킹 — 2026-10-14

대상: https://www.onorca.dev/ (랜딩 · changelog · docs 목차 · enterprise)
기준: EQMUX `sub_main` 0.4.2 + `docs/update-plan-0.5.0.md`
기능 전체 목록은 `docs/orca-features.md`(2026-08-02 조사)에 있다. 이 문서는 그 뒤에 바뀐 것과, EQMUX가 가져올 것·가져오지 않을 것을 정리한다.

## 3. 포지셔닝 차이

| | Orca | EQMUX |
|---|---|---|
| 단위 | 태스크 1개 = 워크트리 1개 = 에이전트 1명 | 저장소 1개 = 팀 1개, 세션 4~8개 |
| 협업 모델 | 에이전트끼리 **경쟁**한다(같은 프롬프트를 여러 에이전트에 뿌리고 비교해 머지). 사람이 diff를 리뷰한다 | 에이전트끼리 **협업**한다(역할·페르소나, 타입이 강제된 메시지 버스). 사람이 관제한다 |
| 권한 기본값 | Yolo(`--dangerously-skip-permissions` 등)가 기본이다. 워크트리를 일회용으로 본다 | 역할 파일 frontmatter가 권한을 정한다. 자동 실행 경로가 없다 |
| 원본 | 앱 상태와 git | `.eqmux/` 파일(DB는 캐시) |
| 대상 | 3개 OS, 개인부터 기업까지 | Windows 전용, 한국어 우선 |

Orca에서 EQMUX와 가장 겹치는 것은 `orca orchestration`(Run → Task → Dispatch → Message, `@all`·`@idle` 주소, 결정 게이트)이다. 다만 Orca에서는 CLI 부가 기능이고, EQMUX에서는 메시지 버스와 관제가 제품의 중심이다. 정면 승부(에이전트 수, OS, 원격, 모바일)는 할 수 없다. **"팀 관제"라는 축을 더 좁고 깊게 파는 것**이 맞다.

## 5. 가져올 것 — 우선순위

EQMUX 원칙(자동 실행 없음, API 키 없음, 파일이 원본)과 맞는 것만 골랐다. 비용은 기존 코드를 재사용할 수 있는 정도로 매겼다.

| 순위 | 기능 | Orca에서 | EQMUX에 넣는 방식 | 비용 | 시기 |
|---|---|---|---|---|---|
| 1 | **업데이트해도 상태 유지** | 항상 복원한다 | 0.5 결정 1에서 (b)안 — `workspaces.json`·`layout.json`은 남긴다. Orca 사용자는 상태가 사라지는 것을 겪어 보지 않았다. 비교되면 바로 이탈 사유가 된다 | 작음 | 0.5 (이미 P0) |
| 2 | **알림 클릭 → 해당 페인** | 벨 · 독 배지 · 클릭하면 이동 | 0.6으로 미룬 이유가 "플러그인에 클릭 콜백이 없음"이다. 대안: 알림이 뜨면 앱 안 벨에 미확인 수를 쌓고, 창이 포커스를 얻을 때 마지막 알림 세션으로 이동하는 칩을 띄운다. OS 콜백이 없어도 된다 | 작음 | 0.5 P2 후보 |
| 3 | **사용량·한도 창** | `~/.claude` 등 로컬 파일만 읽고, 5시간·주간 리셋 시각과 80% 경고 | statusLine 수집 경로가 이미 있다. 거기서 받는 rate-limit 필드를 상태바에 "5h 62% · 리셋 14:20"으로 보인다. API 호출이나 키가 필요 없어 원칙과 맞다 | 작음 | 0.5.x |

## 6. 가져오지 않을 것

| 기능 | 이유 |
|---|---|
| Yolo 기본 실행 | 역할 파일이 권한을 정한다는 원칙과 정면으로 충돌한다. "권한을 지키는 팀"은 Orca 대비 차별점으로 내세운다 |
| 예약 자동화 · 하이버네이션 자동 재개 | "자동 실행 경로는 없다" 원칙과 충돌한다. 하이버네이션은 재개 *제안*으로 이미 대신하고 있다 |
| Native Chat | Orca의 주력 투자 영역이다. 따라가면 터미널이 작업 공간이라는 원칙이 흐려지고, 출시 속도로 이길 수 없다 |
| SSH · 원격 서버 · 클라우드 VM · 모바일 | 규모가 크다. Windows 로컬 팀 관제라는 범위 밖이다 |
| 에디터·뷰어(Monaco, 마크다운, CSV, Jupyter) | 사용자가 이미 쓰는 IDE가 있다. 탐색기에서 "외부 에디터로 열기"로 충분하다 |
| GitHub · Linear · Jira 통합 | 에이전트가 `gh`로 직접 한다. 앱이 토큰을 들면 "키를 보유하지 않는다" 원칙이 깨진다 |
| 27개 에이전트 지원 경쟁 | Claude Code와 Codex 둘의 깊이(훅·재개·혼성 팀 대화)가 먼저다. 혼성 팀 QA 미해결 6건부터 닫는다 |

## 7. 위협과 대응

- **Orca가 orchestration을 UI로 올리면 정면으로 겹친다.** 지금은 CLI와 실험적 칸반뿐이다. EQMUX의 해자는 역할·페르소나, 타입 메시지, 관제 그리드다. 이 셋을 0.5~0.6에서 끝까지 다듬는 것(직함, 세션 이름, 통신 간소화, 게이트)이 대응이다.
- **Windows 지원 격차가 줄었다.** Orca도 Windows 독립 CLI, PowerShell·WSL 셸, WSL Codex를 낸다. "Windows 네이티브"만으로는 차별점이 되지 않는다. ConPTY + Job Object로 프로세스 트리를 정리하고 크래시에서 살아남는 안정성을 수치(QA 재현 0건)로 보여야 한다.
- **출시 속도.** Orca는 2~3일마다 낸다. EQMUX는 자동 업데이트가 없어 사용자가 버전을 따라오기 어렵다. 0.6에 자동 업데이트를 넣지 않으면 버그 수정이 사용자에게 닿지 않는다.
