## 요약

## 1. 페인 헤더 칩 우선순위 규칙

### 문제

지금 헤더는 `이름 · 요약 · (waiting 배지) · 상태` 4요소다(`ControlCenter.tsx:650-675`). 0.5 기획서대로 다 넣으면 이렇게 된다.

```
03 카이 · 클라이언트 개발자 [개발] [Codex] [✓ 완료] [보고 없음] [메시지 2건 · 넣기] [⛶ Bash 승인] 요약… ● busy
```

기본 창(1440px)에 4분할이면 페인 폭이 약 600px다. 여기에 다 들어가지 않고, 들어가더라도 어느 것이 급한지 읽히지 않는다. 기획서는 "직함이 길면 말줄임"만 정해 두었다.

### 권유

헤더에 **고정 자리 4개 + 신호 칩 1개**만 둔다. 나머지는 레일·툴팁·세션 상세가 맡는다.

| 자리 | 내용 | 규칙 |
|---|---|---|
| 번호 | `03` | 항상. 흐린 고정폭 |
| 이름 | `카이` | 항상 |
| 직함 · 엔진 | `클라이언트 개발자 · Codex` | 흐린 한 덩어리로 묶는다. 폭이 모자라면 이 덩어리부터 말줄임. 직무 배지는 레일에만 둔다(직함이 있으면 직무는 덜 중요하다) |
| **신호 칩 1개** | 아래 순서에서 가장 높은 하나 | waiting 사유 > `메시지 N건 · 넣기`(BR-02) > `보고 없음` > `✓ 완료 보고` > `✓ 완료`. 나머지 신호가 있으면 칩 끝에 `+1` |
| 상태 | `● busy` | 항상 오른쪽 끝 |

- 요약 한 줄(M35)은 **신호 칩이 없을 때만** 보인다. 신호가 있으면 요약보다 신호가 급하다.
- `+1`에 마우스를 올리면 나머지 신호를 다 보이고, 누르면 세션 상세를 연다.
- 레일 행은 폭이 좁아 지금처럼 이름·직무만 두고, 신호는 점 색 하나(기존 `unread-dot`)로만 보인다.
- 순서는 대시보드 주의 정렬(waiting > dead > 완료·미확인 > busy > idle)과 같은 방향이라 새 규칙이 아니다. `ATTENTION_ORDER` 옆에 배열 하나로 둔다.

### 수용 기준

- [ ] 4분할 · 1440px에서 모든 0.5 신호가 동시에 켜져도 헤더가 한 줄이고, 번호·이름·상태가 잘리지 않는다
- [ ] 신호가 둘 이상이면 가장 급한 하나와 `+N`만 보인다

## 2. 공용 알림 줄(토스트) 하나

### 문제

앱에는 "내가 누른 동작이 실패했다"를 알리는 공용 자리가 없다(`grep toast` 0건). 그래서 기획서는 같은 문제를 다섯 군데에서 따로 고친다.

| 기획서 항목 | 지금 |
|---|---|
| BR-11 상한 무반응 3곳 | 아무 반응 없음 |
| BR-12 임무 생성·상태 변경 실패 | `.catch(() => {})` |
| P1 서버 탭 `다시 열기` 실패 | 아무 반응 없음 |
| §통신 `--file` 저장소 밖 경로(대화 탭에서 사람이 전달할 때) | 새로 생김 |
| §바로 가기 `reveal_path` 실패(경로가 사라진 경우) | 새로 생김 |

### 권유

`ui.tsx`에 `notify(text, kind)` 하나와 화면 아래 가운데 한 줄을 둔다. 4초 뒤 사라지고, 같은 문구는 겹치지 않는다. 위 다섯 곳은 `.catch(e => notify(...))` 한 줄로 끝난다.

- **벨(알림 센터)과 섞지 않는다.** 벨은 *세션이* 사람을 부르는 신호, 토스트는 *사람이 한 동작의* 결과다. 토스트는 쌓지 않는다.
- 성공에는 띄우지 않는다. 실패와 "상한이라 못 함" 같은 거부만 띄운다. 성공 토스트는 소음이 된다.
- 기획서의 "상한이면 비활성화하고 이유를 보인다"(P1)는 그대로 둔다. 비활성 버튼은 이유를 툴팁으로, 그래도 눌리는 경로(단축키 등)는 토스트로.

## 3. `다음 미확인으로`를 기존 `응답 대기` 칩과 합친다

기획서 §주의 고리 2는 `Ctrl+Shift+U`로 "가장 오래 기다린 미확인 세션 페인으로 간다"고 한다. 같은 동작이 워크스페이스 헤더의 `⛶ 응답 대기 N` 칩에 이미 있다(`focusSession(waitingSessions()[0])`). 다른 점은 범위(이 워크스페이스만)와 대상(waiting만)뿐이다.

- 칩과 단축키가 **같은 함수**를 부르게 한다. 함수는 열린 모든 워크스페이스의 미확인(waiting·dead·완료)을 기다린 순으로 보고, 다른 워크스페이스면 `jumpToSession`, 같으면 `focusSession`.
- 칩 툴팁에 단축키를 적는다: `응답 대기 3 · Ctrl+Shift+U`.
- 칩을 관제 화면 헤더에도 같은 자리에 둔다. 관제에서 가장 자주 하는 일이 "기다리는 놈한테 가기"다.

## 4. 슬롯 번호 단축키 `Ctrl+Alt+1~8`

0.5에서 헤더와 레일에 `01~08` 번호가 붙는다. 번호가 보이면 번호로 가고 싶어진다. 지금은 페인 사이를 키보드로 옮길 방법이 없다(`altKey` 처리는 진단용 `Ctrl+Alt+D` 하나뿐).

- `Ctrl+Alt+N` → 지금 워크스페이스의 N번 슬롯 페인에 키보드 포커스(줌·Focus 아님, `term.focus()`만).
- `Ctrl+숫자`는 쓰지 않는다. 터미널 안 TUI(vim, Claude Code)가 받을 수 있다. Windows Terminal도 페인/탭 이동에 `Ctrl+Alt`·`Alt` 조합을 쓴다.
- 확인할 것: 독일어 등 AltGr 배열에서 `Ctrl+Alt+숫자`가 문자 입력과 겹친다. 한국어 배열은 오른쪽 Alt가 한/영 키라 해당 없다. 영어 UI 사용자를 위해 단축키 목록(권유 5)에 적어 두는 정도로 충분하다.
- `App.tsx`의 기존 단축키 핸들러 옆에 한 블록이다.

## 5. 단축키 목록을 P2 → P1로

기획서는 "단축키 목록 화면"을 P2 접근성에 두었다. 0.5가 끝나면 전역 단축키가 `Ctrl+Shift+L`·`Ctrl+Shift+D`·`Ctrl+Shift+U`·`Ctrl+Alt+1~8`·`Ctrl+F`·터미널 복사/붙여넣기로 늘어나는데, 지금은 어디에도 모여 있지 않다(일부만 터미널 우클릭 메뉴의 `kbd`로 보인다).

- 설정 팝업에 `단축키` 섹션 하나(읽기 전용 표). 새 화면이 아니다.
- 각 버튼 `title`에 단축키를 붙인다(`페인 배치 · Ctrl+Shift+L`). 비용은 문구뿐이고 발견성은 이쪽이 더 크다.
- 단축키 바꾸기(리바인딩)는 넣지 않는다.

## 6. 미확인 신호 3종의 역할 정리

0.5가 끝나면 앱 바에 "봐야 할 것이 있다"는 표시가 세 가지가 된다.

| 표시 | 소스 | 지금 툴팁 |
|---|---|---|
| 관제 탭의 점 | 세션 `unseen` | 없음 |
| `대화` 버튼의 점 | 안 읽은 메시지 | "대화 패널 토글…" |
| 벨 숫자 (0.5 새로) | 알림 센터 항목 | — |

관제 탭 점과 벨은 소스가 거의 같아 사람이 둘을 구분할 이유가 없다. 권유:

- **관제 탭 점은 그대로 두되 벨과 같은 소스로 맞춘다** — 벨에 미확인이 있으면 점, 없으면 없음. 서로 다른 답을 하는 순간 둘 다 못 믿게 된다.
- 세 표시에 툴팁을 단다: `미확인 세션 2` / `안 읽은 메시지 5` / `알림 3`.
- 벨 목록의 각 항목을 열면(점프하면) 그 세션의 `markSeen`도 같이 돈다. 반대로 페인을 직접 눌러 `markSeen`이 되면 벨 항목도 읽음으로 바뀐다. 기획서는 "목록은 앱을 다시 켜면 비운다"만 정했고 읽음 동기화는 적지 않았다.

## 7. 확인창 기본 포커스는 `취소`

P0에서 세션 중지 확인창 3곳과 기본 터미널 제거 확인창이 생긴다. 기존 역할 세션 제거 확인창을 같이 쓰기로 했으니, 그 부품에서 한 번만 정한다.

- 열릴 때 포커스는 `취소`. `Enter`는 취소, `Esc`도 취소. 실행은 마우스나 `Tab`으로 위험 버튼에 가서 `Enter`.
- 이유: 터미널 앱이라 사람이 계속 `Enter`를 치고 있다. 메뉴 클릭 직후 습관적인 `Enter`로 프로세스가 죽으면 확인창을 넣은 의미가 없다.
- "다시 묻지 않기" 체크박스는 넣지 않는다.

| 권유 6 미확인 3종 | 벨 수를 세션 `unseen`에서 계산하고 `markSeen`을 맞추는 것은 넣었다. 세 표시에 툴팁(`미확인 세션 2` 등)을 다는 것은 넣지 않았다 | §UX 기반 › 주의 신호 |
| §넣는 자리 요약의 단계 번호 | 최종본 작업 순서는 7단계다. 권유 2·7은 2단계(P0), 권유 1은 3단계(UX 기반), 권유 3·5는 6단계(주의 고리 · 나머지 P1)에 들어간다. 권유 4는 §UX 기반 › 단축키에 있지만 작업 순서에 단계가 적혀 있지 않다 | §작업 순서와 릴리즈 기준 |

제안대로 들어간 4건의 자리: 권유 2 `notify()`와 권유 7 `ConfirmDialog`는 §UX 기반 › 공통 부품(2단계에서 먼저 만든다), 권유 4 `Ctrl+Alt+1~8`은 §UX 기반 › 단축키, 권유 5 단축키 목록은 P1이다.
