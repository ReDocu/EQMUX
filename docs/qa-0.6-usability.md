## 요약

0.6에 들어온 기능을 네 갈래로 나눠 봤다.

- **리드:** 브라우저 목 모드(vite + Chrome)를 띄워 사용자 과업 3개를 실제로 눌러 봤다.
- **세 세션:** 자기가 만들지 않은 영역을 코드 근거(file:line)로 검증했다. B는 블레임 panic처럼 재현이 되는 것을 스크래치패드의 버린 저장소에서 직접 재현했다.
- **실앱:** 이 PC에는 데스크톱 조작 도구가 없어 실앱(Tauri 창)은 띄우지 않았다. 코드로만 확인한 행에는 `제안` 칸 앞에 `[코드 근거, 실기 미확인]`을 붙였다.

결과 89행을 `interview.csv`에 이어 붙였다. 각 행의 `재현 절차·근거` 칸 앞에 `[0.6 QA · A|B|C|리드 목 모드]`로 출처를 적었다. 영역끼리 겹친 행은 없었다. 서로 이어지는 행에는 번호를 서로 적어 두었다.

## 먼저 고칠 것

1. **B169 — [되돌려 보내기] 의견이 담당 세션에 닿지 않는다.** `sendBackMission`이 수신자를 세션 id가 아니라 `@이름` 문자열로 넘긴다(`src/backend/missions.ts:256`). 대화 탭 입력창은 `@이름`을 세션 id로 바꾼 뒤 보낸다(`src/components/ConversationTab.tsx:285`). 그런데 이 경로만 바꾸지 않아 어느 세션에도 맞지 않는다. 그런데도 화면은 "N명에게 보냈습니다"를 띄우고 임무를 IN-PROGRESS로 돌린다. 리드가 이 코드 경로를 다시 읽어 확인했다.
2. **B170 — 한글 커밋 메시지가 있는 파일의 blame이 Rust panic으로 죽는다.** 커밋 줄을 찾는 분기가 아무 줄이나 바이트 40에서 자른다(`src-tauri/src/gitx.rs:256` `line[..40]`). 그래서 `summary <한글>` 줄에서 UTF-8 글자 중간을 자르게 된다. 이 저장소의 `GitScreen.tsx`로 재현했다.
3. **B171 — 충돌 파일을 [모두 ↓]·[+]로 스테이지할 수 있다.** 스테이지하면 배너가 "충돌을 다 풀었습니다"로 바뀌고, 이어서 [계속]을 누르면 `<<<<<<<` 표식째 커밋된다(`src/screens/GitScreen.tsx:663-665`, `:934`).
4. **B172 · B175 — 고리 끝 두 개.**
   - B172: 되돌려 보낸 임무가 옛 `report --done`을 그대로 집어 다시 '완료 보고'로 보인다.
   - B175: HEAD 변경 알림이 커밋 해시가 아니라 브랜치 이름을 비교한다. 그래서 같은 브랜치에서 pull·merge·reset을 하면 알리지 않는다.
5. **B184 — 성공 알림이 실패용 빨간 토스트로 뜬다.** `notify()`는 실패 전용으로 만들어서 테두리가 늘 빨갛다(`src/components/ui.tsx:164-181`, `src/screens.css:3375`). 그런데 성공 문구도 19곳에서 이 함수로 띄운다. 사용자는 방금 한 일이 실패한 줄 안다.

### 먼저 고칠 것

1. **B198 — [빠른 시작]이 있던 역할 세션을 확인 없이 지운다.** 빠른 시작은 편성을 대치하는 방식으로 적용한다(`LaunchMode.tsx:64-70`, `mock.ts:801-825`). 그래서 목록에 없는 역할 세션의 PTY를 죽이고, 임무 배정을 풀고, `team.json`을 덮는다. 목 모드에서 `lin@docs`가 사라지는 것을 재현했다. **B201**(셸만 있는 워크스페이스에서 [탭으로 가기]를 누르면 마법사로 들어감, 재발: B107)이 이 경로로 바로 이어진다.
2. **B199 — 전체 화면에서 ESC가 터미널로 들어간다.** 키보드가 터미널에 있으면 xterm이 ESC를 먹어서(stopPropagation) 앱의 ESC 처리기에 닿지 않는다. 그래서 전체 화면이 닫히지 않고 ESC가 셸이나 에이전트로 들어간다. 일하던 Claude의 턴이 끊길 수 있다. [⛶] · 승인 칩 · [페인으로 가기]로 들어오면 거의 항상 이 상태다.
3. **B200 — 워크스페이스를 바꿔도 파일 탐색기의 선택이 남는다.** 이 상태에서 [삭제] · [이름]을 누르면 새 워크스페이스에서 같은 상대 경로의 파일이 지워지거나 바뀐다(`MissionExplorerTab.tsx:70-74`, `:202-213`, 실기 미확인).
