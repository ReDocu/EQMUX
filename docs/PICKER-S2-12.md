## 1. 디자인 모순 판단 — "선택 즉시 재배열" vs 푸터 `[적용]` 버튼

> 코드가 이 절을 근거로 건다(`layout-picker.ts` 머리말 21행). 브리프 §3이 *"해원 판단으로 정하고 적으라"* 고
> 넘긴 자리다 — `S2-4` 때와 같은 형식이다.

**시안 자체가 두 가지를 동시에 약속한다.** 부제는 *"선택 즉시 재배열"* 이라 즉시 적용이고,
푸터에는 `[적용]` 버튼이 있어 확정 단계가 있다. 둘 다 구현하면 사용자는 "고른 게 이미 적용된
건가, 눌러야 되는 건가"를 화면에서 알 수 없다.

### 택한 것 — **즉시 적용.** `[적용]`은 "확정·닫기"로 뜻을 바꿨다

| 대안 | 무엇 | 왜 안 골랐나 |
|---|---|---|
| A. 확정형 | 고르면 미리보기만, `[적용]`을 눌러야 실제 배치 | **지켜 줄 것이 없다.** 확정 단계는 되돌릴 수 없는 조작 앞에 두는 장치인데, `applyPreset`은 비파괴적이다 |
| **B. 즉시형 (채택)** | 고르는 즉시 적용 · `[적용]`·Enter는 **확정·닫기** | 부제의 약속을 지킨다. 버튼도 안 지운다 — "이 배치로 하겠다"는 뜻으로 살아 있다 |
| C. 즉시형 + Esc 되돌리기 | 즉시 적용하되 Esc면 원래대로 | **반만 되는 되돌리기가 된다** — 아래 참조 |

**근거는 `applyPreset`이 비파괴적이라는 사실 하나다.** 잎(세션)을 옮겨 담을 뿐 PTY도 xterm
버퍼도 안 죽는다 (`S2-11` — *"재배열이지 재생성이 아니다"* · 잎 신원 보존). 잘못 골라도 다른
프리셋을 고르면 그만이다. 위험이 없는 조작 앞에 확인 단계를 두면 그건 안전장치가 아니라 마찰이다.

### ⚠️ Esc 취소(되돌리기)를 **안 넣은** 이유 — 이게 제일 중요하다

프리셋에서 벗어난 배치는 복원할 수 없다. 사용자가 분할선을 드래그해 만든 **비율**은 어떤
프리셋 id로도 표현이 안 되고, 레이아웃 스냅숏 API가 없다. 그래서 Esc 되돌리기를 넣으면
**프리셋으로 들어온 경우만 되돌려지고 드래그로 만든 배치는 못 돌아온다.**

*"Esc면 안전하다"* 는 잘못된 기대를 만드느니 안 만드는 쪽이 정직하다. Esc는 **닫기**다.
필요해지면 **레이아웃 스냅숏 API가 선행**이고, 그건 트리 소유자(세아 · 코어)의 일이다.

## 2. 동작 정의

| 입력 | 동작 |
|---|---|
| `Ctrl+Shift+L` | 피커 열기 / 닫기(토글). 열려 있는 동안 **모달** — 어떤 키도 터미널로 안 내려간다 |
| `←` `→` `↑` `↓` | 칸 이동. **이동이 곧 적용이다** — 훑으면 화면이 따라 바뀐다 (3열 그리드) |
| `Home` / `End` | 처음 / 마지막 칸 (역시 적용) |
| `Enter` / `[적용]` 버튼 | **확정·닫기** (선택은 이미 적용돼 있다) |
| `Esc` / `×` / 바깥 클릭 | 닫기 (§1 — 되돌리지 않는다) |
| 칸 클릭 | 그 배치 적용 |
| 관제 화면 `배치` 버튼 · 상단 패널 내비 `배치` | 같은 피커를 연다 (`openPickerNow()`) |

부제는 `현재 팀의 세션 N개 · 선택 즉시 재배열` — **N은 `host.size` 실물이다.** 시안의 "8"을 안 박았다.

## 3. 설계 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | **경계 API 7종만 쓴다** — `size`·`listPresets`·`currentPreset`·`applyPreset`·`activeLeaf`·`focus`·`onLayoutChanged` | `PRESET-S2-11` §3. `PanelManager`를 import조차 안 한다(구조적 타입 `PickerHost`) — 내부 DOM·필드에 기대면 다음 reconcile에 깨진다 |
| 2 | `layout_apply_preset`을 **직접 안 부른다** | 트리만 바꾸면 화면(패널 DOM·줌·포커스)이 안 따라온다. 그 둘을 맞추는 게 `PanelManager`의 일이다 |
| 3 | **프리셋 목록 하드코딩 금지 · 열 때마다 재요청** | 6종이 늘거나 이름이 바뀌면 백엔드만 고치면 된다. `groups`가 **지금 세션 수 기준**이라 패널을 나눈 뒤 열면 다른 그림이 나와야 맞다 |
| 4 | 키는 `e.code === "KeyL"` (물리 키) | `e.key`는 한글 IME 상태에 흔들린다 — `S2-4`와 같은 판단 |
| 5 | 리스너를 **계측 모드 포함 전 경로**에 건다. 상시 비용은 분기 둘(`open` · `!ctrlKey`) | 실사용 키가 항상 이 리스너를 지나므로 A-3도 같은 조건에서 재야 회귀를 잡는다 (`focus.ts`와 같은 이유) |
| 6 | 미연결(계측 모드)이면 **아무 키도 안 가로챈다** | 계측 화면의 조건을 1px·1분기도 안 바꾼다 |
| 7 | **반복(`e.repeat`)은 이동도 안 시킨다** | `focus.ts`는 반복 이동을 허용했지만 거기서 이동은 공짜였다. **여기서 이동은 곧 적용**이라, 반복을 이동만 시키고 적용을 빼면 강조 칸과 커서가 갈린다 — Enter를 눌렀을 때 커서 칸이 아닌 배치로 닫힌다 |
| 8 | 끝에서 **감아 돌지 않는다** (clamp) | `focus.ts` 결정 3과 같다 — 손이 위치 감각을 잃는다 |
| 9 | 오버레이는 **첫 열기 때 만든다** | 안 열면 DOM이 0이다. 관문 A2가 재는 게 "유휴 RAM"이라, 안 쓰는 화면을 미리 지어 둘 이유가 없다 |
| 10 | 열 때 **현재 배치를 고른 상태로** 연다 | 상태바가 이미 `2 × 4`를 보여주는데 피커만 아무것도 안 고른 얼굴이면 어긋난다 |
| 11 | 밖에서 배치가 바뀌면 **강조만 고친다**(`markCurrent`) | 여기서 다시 그리면 `applyPreset → onLayoutChanged → 재그리기`로 돈다 |
| 12 | 목록이 비면 **빈 상자 대신 경고 문구** | 조용한 실패가 제일 위험하다 (`panels.ts`가 이미 stderr에 남긴 뒤다) |
| 13 | 썸네일은 `axis`/`groups`로 그린다 — 정원(8)이 아니라 **실제 배치** | 세션이 3개면 3칸 그림이 나온다. *"고르면 이렇게 된다"* 를 그대로 그리는 게 미리보기의 일이다 |

## 5. 다음 사람이 밟을 함정

1. 🔴 **`layout-picker.ts` 주석의 `panels.ts` 줄번호가 낡았다.** `panels.ts:376-388`(focus)·
   `673-683`(applyFocus)로 적혀 있는데, `S2-5` 탭이 들어오며 `panels.ts`가 **701 → 1,214줄**로
   늘어 지금 `focus()`는 **622행**이다. 주석을 믿고 그 줄을 열면 다른 코드가 나온다.
   → 줄번호 대신 **함수 이름으로** 고쳐야 한다(내 파일이니 내 몫 · §6-3).
2. **`applyPreset`은 끝에 `applyFocus()`를 타고 DOM 포커스를 터미널로 가져간다.** 피커가 열린 채면
   방금 고른 칸의 포커스 링이 사라진다 — `choose()`가 되돌려 놓는다. 이 두 줄을 지우면
   Tab 기점이 터미널로 새고 포커스 링이 죽는다. (키 입력 자체는 캡처 단계에서 막고 있어 안 샌다)
3. **`onLayoutChanged`에서 다시 그리지 말 것.** `applyPreset → 알림 → render` 고리가 생긴다.
   강조만 고치는 게(`markCurrent`) 그 방어다.
4. **`opening` 플래그를 지우지 말 것.** `listPresets()` 왕복 사이에 같은 키가 또 오면 두 번 열린다.
5. `installPickerKeys()`를 계측 경로에서 빼고 싶어지면 **A-3 회귀 근거부터 다시 세울 것**(결정 5).
6. `COLUMNS = 3`은 CSS `grid-template-columns: repeat(3, 1fr)`와 **짝이다.** 한쪽만 바꾸면
   화살표 이동이 화면과 어긋난다.
