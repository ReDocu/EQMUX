## B1. 프로젝트 폴더 탐색기

**상태**: 검토중 · **차수 제안**: 2차 · **규모**: M~L

### 제 읽기

작업 중인 프로젝트 폴더의 파일 트리를 **패널로 띄워 보고 이동**하는 것.

### 왜 1차가 아닌가

1차의 목적은 *"AgentCommender를 대체한다 — 동등성이 목표"*(`OBJECTIVES.md` 4절)다.
**AgentCommender에 폴더 탐색기가 없다.** 즉 이건 동등성 항목이 아니라 **새 기능**이고,
1차에 넣으면 관문 B("아무도 옛 앱으로 안 돌아간다")의 판정이 흐려진다 —
탐색기 때문에 안 돌아간 건지, 터미널이 제대로 돼서 안 돌아간 건지 못 가른다.

**2차가 맞다.** 2차 목적은 *"쓸 수 있다 → 쓰고 싶다"* 이고, 철학 3(**GIT 연결성**)이 실현되는 단계다.
탐색기에 **git 상태(수정·추가·무시)를 얹으면** 그 철학과 한 몸이 된다.

### 확인이 필요한 것 (→ 팀장님)

| # | 질문 | 왜 이게 갈리면 규모가 바뀌나 |
|---|---|---|
| 1 | **읽기 전용인가, 조작까지인가** | 생성·삭제·이름변경·드래그 이동이 붙으면 규모가 M → **L**이 된다. 되돌리기·충돌 처리가 따라온다 |
| 2 | **클릭하면 무슨 일이 일어나나** | ① 터미널에 `cd` ② 경로를 프롬프트에 삽입 ③ 외부 에디터로 열기 — 셋이 완전히 다른 기능이다 |
| 3 | 루트는 어디인가 | 워크스페이스마다 하나인지, 임의 폴더를 열 수 있는지 |

**제 기본안** (답이 없으면 이걸로 잡습니다): **읽기 전용 + 클릭 시 경로 삽입 + git 상태 표시.**
가장 싸고, 터미널 중심 도구라는 성격을 안 깬다. 조작 기능은 붙이는 순간 "파일 관리자"가 된다.

### ⚠️ 성능 지표와 정면으로 만난다

파일 감시(watcher)는 **큰 폴더에서 RAM과 CPU를 먹는다.** `node_modules` 하나가 수만 개다.

- `KR4`(유휴 RAM) — 탐색기를 켠 채 방치하면 그게 유휴 RAM이다
- `KR2`(런타임 데이터 ≤60MB) — 트리 캐시를 디스크에 두면 여기 얹힌다

> **설계 조건으로 미리 박아 둔다**: ① 기본 제외 목록(`node_modules`·`.git`·`target`·`dist`)
> ② 감시 대상 상한 ③ **접힌 폴더는 감시하지 않는다.** 이건 나중에 붙이는 최적화가 아니라
> **처음부터 없으면 `S3-6`의 상한 논의를 다시 하게 되는 항목**이다.

## B2. 멀티플렉스 상호 대화 세션 구성

**상태**: 검토중 · **차수 제안**: 4차 (배관은 1·2차에 이미 있음) · **규모**: **?** (범위가 안 정해짐)

### 제 읽기

지금은 **관제(사람 또는 CLI)가 세션에 한 방향으로 밀어 넣는** 구조다 — 오늘 제가 세아·해원에게
`acmux send`로 보낸 그 방식이다. **"상호 대화"는 세션 A의 출력이 세션 B의 입력이 되는 것**으로 읽었다.

### 배관은 이미 있다

| 근거 | 내용 |
|---|---|
| `FEATURES.md` F4 | `surface.send_text` / `.read_text` — **P0** |
| `FEATURES.md` F8 | CLI `send` / `send-key` / `read-screen` — **P0** |
| AgentCommender 코드 | `acmux send --team <팀> <텍스트>` 브로드캐스트가 **이미 구현돼 있다** (`FEATURE-DIFF.md`) |

**즉 "보내고 읽는" 배관은 1차 범위에 이미 들어 있다.** 새로 필요한 것은 배관이 아니라
**그 위에 얹는 대화 규약**이고, 그건 세션에 인격과 역할이 생기는 **4차 팀모드**의 물건이다.

### 🔴 확인이 필요한 것 — 여기가 진짜 안건이다

| # | 질문 | 왜 중요한가 |
|---|---|---|
| 1 | **누가 말을 거는가** | 사람이 중계하는가, **세션이 스스로** 다른 세션에게 말을 거는가. 후자면 아래 2번이 즉시 문제가 된다 |
| 2 | **무한 루프를 무엇으로 막는가** | A가 B에게 말하고 B가 A에게 답하면 **사람 없이 토큰이 계속 탄다** |
| 3 | 기록은 남는가 | 누가 누구에게 무슨 말을 했는지. 남지 않으면 사고가 나도 원인을 못 찾는다 |
| 4 | 권한 | 아무 세션이나 아무 세션에게 말 걸 수 있나. 팀 경계는 |

### ⚠️ 철학 1(기능은 토큰 0)과 정면으로 충돌할 수 있다

`OBJECTIVES.md`의 첫 철학은 **"기능은 토큰을 쓰지 않는다"** 이고, `KR7`은 세션당 자동 로드 토큰을
**≤ 500 고정**으로 못 박았다. 그런데 **세션끼리 대화하면 토큰은 사람이 안 보는 사이에 소모된다.**

> **그래서 이 기능은 "무엇을 할 수 있나"보다 "언제 멈추나"를 먼저 설계해야 한다.**
> 최소한 셋이 필요하다 — ① **왕복 횟수 상한** ② **정지 조건**(사람 확인 없이는 N회까지)
> ③ **끄기.** 이 셋이 없는 설계안은 제가 반려하겠습니다.
>
> 이건 기능을 막으려는 게 아니다. 상한 없이 켜면 **첫 사고가 요금으로 온다.**
> `S3-6`(디스크 상한)에서 *"상한은 코드에 박는다"* 로 정한 것과 같은 원칙이다.

### 4차까지 미루지 않아도 되는 것 하나

`BASELINE.md` §1이 요청한 **제어 채널 이름 환경변수화(`EQMUX_PIPE_NAME`)** 는 이 기능의 전제다.
지금 AgentCommender는 파이프 이름이 하드코딩돼 있어 **두 인스턴스가 뜨면 나중 것이 조용히 벙어리가 된다.**
세션 간 통신을 얹기 전에 이게 먼저다. 규모 `S`이고 **`S3-5`(설정 체계)에 묶으면 된다.**

- 새 요청은 **여기 먼저** 적는다. `FEATURES.md`·`WORKPLAN.md`로 내려보내는 건 차수가 확정된 뒤다.
