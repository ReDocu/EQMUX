## EQMUX란

**하나의 git 저장소를 AI 에이전트 팀이 함께 작업하고, 사람이 그것을 관제하는 데스크톱 앱입니다.**

터미널 멀티플렉서(여러 터미널을 한 창에서 다루는 도구)에 에이전트 팀 관제를 얹었습니다. 저장소마다 여러 개의 에이전트 세션을 병렬로 띄우고, 관제 대시보드에서 상태를 보고, 임무를 배정하고, 필요할 때 개입합니다.

EQMUX가 하는 일과 하지 않는 일이 뚜렷합니다.

- **하는 일** — 터미널을 띄우고, 에이전트 상태를 관측하고, 역할과 임무를 파일로 관리하고, 결과를 검토할 도구를 제공합니다.
- **하지 않는 일** — 스스로 AI를 호출하지 않습니다. API 키를 갖지 않습니다. 사용자 대신 승인하거나 커밋하지 않습니다. 자세한 내용은 [설계 경계](#설계-경계)를 보세요.

## 설치

### 요구 사항

| 항목 | 내용 |
|---|---|
| 운영체제 | Windows 10 / 11 (WebView2 런타임) |
| 에이전트 CLI | [Claude Code](https://claude.com/claude-code) 또는 Codex CLI — 에이전트 세션 기능에 필요. 설치하고 로그인해 두세요. 한 팀에 둘을 섞을 수 있습니다 |
| git | 저장소 연결 · 워크트리 · diff 기능에 필요 |

EQMUX 자체는 API 키를 요구하지 않습니다. 에이전트 인증은 CLI가 담당합니다.

### 설치하기

릴리스는 포터블 zip `EQMUX_<버전>_x64_portable.zip`으로 배포합니다. 압축을 풀고 `EQMUX\eqmux.exe`를 실행하면 됩니다. 설치 과정이 없어 **관리자 권한이 필요 없습니다**.

`eqmux.exe`는 앱이자 곧 CLI입니다 — 별도로 설치할 것이 없습니다. 앱이 띄우는 터미널에는 이 폴더가 `PATH` 앞에 붙으므로 어디서든 `eqmux` 명령을 쓸 수 있습니다.

### 소스에서 빌드

```powershell
npm install
npm run tauri dev      # 개발 모드
npm run tauri build -- --no-bundle    # eqmux.exe만 (배포용)
npm run tauri build                  # NSIS 설치본까지 생성
```

Node.js 18+ 와 Rust(stable)가 필요합니다.

## 시작하기

앱을 처음 켜면 관제 대시보드가 열립니다. 아직 저장소가 없으니 연결부터 합니다. 온보딩은 네 단계입니다 — **저장소 연결 → 실행 방식 → 세션 구성 → 시작**.

### 1단계 · 저장소 연결

탭 줄의 `+`를 눌러 연결 화면을 엽니다. 워크스페이스 탭을 우클릭하거나 `⋯`를 눌러 `워크스페이스 관리…`로도 열 수 있습니다.

![워크스페이스 연결](../screenshots/features/01-workspace-connection.png)

- **로컬 저장소 연결** — 이미 있는 git 저장소 폴더를 고릅니다
- **원격에서 Clone** — 원격 주소로 새로 받아옵니다

등록은 무제한이고, 동시에 열 수 있는 워크스페이스는 10개입니다. 저장소를 옮겼다면 `재지정`으로 경로만 다시 잡아주면 됩니다. `등록 해제`는 목록에서만 지우고 **디스크의 파일은 건드리지 않습니다.** 등록과 배치는 앱을 새 버전으로 바꿔도 남습니다.

### 2단계 · 실행 방식 고르기

저장소를 열면 첫 세션을 어떻게 시작할지 묻습니다.

![실행 방식 선택](../screenshots/features/02-launch-mode.png)

| 선택 | 언제 |
|---|---|
| **기본 터미널** (권장) | 일반 셸 작업, 빠른 확인, 수동 명령 실행. 역할·페르소나·임무 없이 바로 시작합니다 |
| **역할 팀 구성** (고급) | 병렬 구현·리뷰·조사처럼 책임이 분리된 작업. 슬롯마다 역할과 권한, 임무를 배정합니다 |

기본 터미널로 시작해도 나중에 언제든 역할을 부여할 수 있습니다.

### 3단계 · 팀 캐스팅 (역할 팀을 골랐다면)

![팀 캐스팅](../screenshots/features/10-team-casting.png)

편성 프리셋을 고르면 슬롯이 자동으로 채워집니다. 슬롯마다 **직무 + 페르소나**가 배정되고, 아래에 실행 권한(`write` / `commit` / `push`)이 미리 보입니다.

`편성 선택 →`을 누르면 `.eqmux/team.json`과 `team.md`가 저장되고 세션이 만들어집니다.

### 4단계 · 에이전트 띄우기

역할 세션 페인에는 `▶ Claude Code 기동`(Codex 슬롯이면 `▶ Codex 기동`) 버튼이 있습니다. 누르면 그 페인에서 역할·권한·훅이 붙은 에이전트가 뜨고, 상태(`busy` · `waiting` · `idle`)가 실시간으로 갱신됩니다. 빈 슬롯에서 역할 세션을 새로 만들면 만들면서 바로 기동합니다.

**터미널에 직접 `claude`를 치면 역할·훅·메시지 신원이 붙지 않습니다.** 대시보드는 그 프로세스를 감지해 배지를 붙이지만, 팀 메시지는 자동으로 넣지 않습니다. 쌓아 두었다가 페인 헤더의 `메시지 N건 · 넣기`를 사람이 눌렀을 때만 넣습니다.

> **왜 앱이 알아서 띄우지 않나요?** 상태를 바꾸는 것은 언제나 사용자의 버튼이라는 원칙 때문입니다. 재시작 후에도 에이전트를 되살리지 않고, 재개는 사람이 누릅니다.

### 5단계 · 임무 배정

앱 바의 **임무** 버튼에서 임무를 만들고 세션에 배정합니다. 배정하면 그 세션의 역할 파일에 임무가 기록되고, 살아 있는 에이전트에게는 한 줄 브리프가 전달됩니다.

## 핵심 개념

```
앱  ─────────────────── 워크스페이스 최대 10개 동시 오픈
└─ 워크스페이스 ──────── = git repo 1개 = 팀 1개 = 탭 1개
   ├─ 세션 1~N ───────── = 에이전트 1명 = 터미널 페인 1개
   │  └─ 역할 ────────── = 직무(job) + 페르소나(persona)
   └─ 임무 ───────────── = repo 안의 작업 단위 (브랜치 + 목표)
```

| 용어 | 뜻 |
|---|---|
| **워크스페이스** | git 저장소 하나 = 팀 하나 = 탭 하나. 이 1:1:1 덕분에 git·탐색기·diff·검색의 범위가 하나로 통일됩니다 |
| **세션** | 터미널 페인 하나 = 에이전트 한 명. 기본 4개, 설정에서 6·8개까지 |
| **보조 페인** | 에디터 · diff · 브라우저 · 트랜스크립트. 세션 슬롯을 쓰지 않습니다 |
| **패널** | 사이드 도구 서랍(대화·코드·실행·브라우저). 페인이 아니라 분할 그리드 밖에 있습니다 |
| **직무** | 책임과 권한. 고정 8종 |
| **페르소나** | 판단 성향. 직무와 분리되어 있습니다 |
| **임무** | 브랜치 + 목표 + 산출물. `.eqmux/missions/*.md` 파일이 원본 |

**세션이 기본 4개인 이유**는 리소스가 아니라 가독성입니다. 1920×1080에서 2×2 분할이 에이전트 TUI를 읽을 수 있는 한계입니다(8분할이면 페인당 14행). 설정에서 늘릴 수 있고, 줄여도 이미 열린 세션은 닫히지 않습니다.

**파일이 원본입니다.** 팀·역할·임무는 `.eqmux/` 아래 파일이 원본이고 데이터베이스는 캐시일 뿐입니다. 에이전트나 외부 편집기가 파일을 바꾸면 앱이 감지해 따라갑니다.

## 화면 안내

### 탭바

맨 왼쪽이 **관제 고정 탭**, 그 뒤로 워크스페이스 탭이 붙습니다. `Ctrl+Shift+D`로 관제와 직전 워크스페이스를 오갑니다.

### 앱 바 전역 도구

오른쪽 위 버튼들은 어디서든(터미널 전체 화면에서도) 열립니다.

| 버튼 | 여는 것 |
|---|---|
| 대화 | 사이드 패널 (대화 탭) |
| 임무 | 임무 · 파일 탐색기 (전체 화면) |
| 역할 | 역할 라이브러리 (전체 화면) |
| 설정 | 설정 (전체 화면) |
| 벨 | 알림 센터 — 최근 알림 50건. 누르면 그 페인으로 갑니다 |

전체 화면 팝업은 한 번에 하나만 열리고 `ESC`로 닫힙니다. 저장소 연결 화면은 탭 줄의 `+`가 엽니다.

### 워크스페이스 탭 메뉴

워크스페이스 탭을 우클릭하거나 `⋯`를 누르면 열립니다.

| 묶음 | 항목 |
|---|---|
| 열기 | `탐색기에서 열기` · `원격 저장소 열기` · `워크스페이스 관리…` |
| 알림 | `알림 음소거` · `다른 프로젝트 메시지 받기` |
| 닫기 | `닫기 (세션은 유지)` |

`원격 저장소 열기`는 `origin` 주소를 웹 주소로 바꿔 기본 브라우저로 엽니다. 주소에 든 사용자 정보(토큰)는 떼고 엽니다.

### 워크스페이스 화면

![터미널 워크스페이스](../screenshots/features/06-terminal-grid.png)

- **왼쪽 레일** — 세션 목록(두 자리 슬롯 번호 + 이름, 클릭=포커스, ⓘ=상세, 우클릭=메뉴) · 임무 수 · 워크트리 섹션
- **가운데** — 터미널 그리드 또는 트랜스크립트
- **아래 상태 바** — PTY 수 · 배치 · 출력량 · DB 크기 · 메모리 · 이벤트

### 사이드 패널

탭은 네 그룹이고, 그룹 안은 세그먼트로 나뉩니다. 그룹 탭을 다시 누르면 그 그룹에서 마지막으로 본 화면이 열립니다.

| 탭 | 세그먼트 | 내용 |
|---|---|---|
| **대화** | 대화 · 로그 | 에이전트 간 대화 스트림 / 이벤트 원장 스트림 + 전문 검색 |
| **코드** | git · 문서 | 브랜치 · 커밋 · 워크트리 · diff 진입 / Markdown 문서 보기 |
| **실행** | 서버 · 포트 | dev 서버를 띄우는 셸 / 세션이 연 포트와 시스템 포트 |
| **브라우저** | — | 임의의 http·https 주소를 여는 웹뷰. 에이전트도 `eqmux browser`로 같은 패널을 씁니다 |

패널은 좌/우 어느 쪽에도 붙일 수 있고, 위치는 저장됩니다.

## 팀 만들기

### 직무 (고정 8종)

직무는 **책임**입니다. 로스터는 8종으로 고정되어 있고 추가·삭제 없이 편집만 가능합니다.

![역할 라이브러리](../screenshots/features/12-role-library.png)

| 직무 | 책임 | write | commit | push |
|---|---|:---:|:---:|:---:|
| 리드 | 전체 구조 · 임무 분해 · 통합 · 최종 판단 | ✓ | ✓ | ✓ |
| 기획 | 요구 정리 · 조사 · 기획 문서 | ✓ | — | — |
| 개발 | 구현과 자체 검증 | ✓ | — | — |
| 디자인 | UI 설계 · 스타일 가이드 · 목업 | ✓ | — | — |
| QA | 테스트 · 증거 수집 · 변경 검토 | — | — | — |
| 디버거 | 재현 · 원인 규명 · 최소 수정 | ✓ | — | — |
| 문서 | 문서화 · 재현 절차 · 가이드 | ✓ | — | — |
| 릴리즈 | 커밋 정리 · 태그 · 배포 | — | ✓ | ✓ |

각 직무에는 **금지 사항**도 함께 정의되어 있습니다(예: QA는 "증거 없는 통과 판정 금지").

### 페르소나 (3단계)

페르소나는 **판단 성향**입니다. 프롬프트 예산은 5~10줄이고 초과하면 경고합니다.

| 레벨 | 담기는 것 |
|---|---|
| **기본** | 판단 힌트 한 줄 |
| **중간** | 판단 힌트 + 말투 + 성격 (각 3줄 예산, 말투 프리셋 제공) |
| **고급** | 캐릭터 시트 파일(`personas/<id>.character.md`). 역할 파일에는 정체성 한 줄과 경로만 들어갑니다 |

레벨을 바꿔도 값이 섞이지 않고, 낮은 레벨로 내려도 디스크의 내용은 보존됩니다.

### 캐스팅과 권한

편성 프리셋 4종으로 시작할 수 있습니다.

| 프리셋 | 구성 |
|---|---|
| 표준 | 리드 · 개발 2 · QA |
| 집중개발 | 개발 중심 |
| 제품기획 | 리드 · 기획 · 디자인 · 개발 |
| 품질 | 개발 · 디버거 · QA · 문서 |

**권한 바꾸기** — 세션 상세 패널에서 직무 기본 권한을 세션 단위로 덮어쓸 수 있습니다. 다만 실행 권한은 프로세스 수명 동안 고정이라, 권한을 바꾸면 **재시작 배지**가 뜨고 재개 기반 재시작으로 반영됩니다(대화는 유지됩니다).

**관계 보기** — 팀 편성 화면에서 보고선을 그림으로 확인합니다. 편성은 바꾸는 즉시 자동 저장됩니다.

**직함** — 같은 직무를 둘 둔 팀은 직함으로 나눕니다(예: 개발 직무의 `클라이언트 개발자`·`서버 개발자`). 페르소나에 직함을 두고, 세션 상세에서 이 워크스페이스에서만 덮어쓸 수 있습니다. 직함은 역할 파일과 `team.md`에 실려 팀원끼리 서로를 압니다.

![팀 편성](../screenshots/features/11-team-composition.png)

## 임무

임무는 `.eqmux/missions/<슬러그>.md` 파일이 원본입니다.

![임무 배정](../screenshots/features/13-missions.png)

### 임무 만들기

임무 화면 오른쪽에서 이름 · 목표 · 브랜치(선택)를 넣고 생성합니다. 목표는 **완료 조건을 측정 가능하게** 쓰는 것이 좋습니다.

### 배정

임무 카드의 세션 칩을 클릭하면 배정/해제가 토글됩니다. 배정하면

1. 그 세션의 역할 파일에 임무 블록이 삽입되고
2. 살아 있는 에이전트에게 자연어 브리프 한 줄이 전달됩니다

### 상태와 브랜치

- 상태 뱃지를 클릭하면 `todo → in-progress → in-review → done` 순으로 돕니다. 본문은 그대로 보존되고 frontmatter만 갱신됩니다.
- `⎇ 체크아웃`으로 임무 브랜치로 전환합니다. 공유 저장소 전체에 영향을 주므로 2단 확인을 거칩니다.
- ★ 뱃지로 **기본 임무**를 지정하면(워크스페이스당 1개), 임무 없는 새 역할 세션이 만들어질 때 자동으로 배정받습니다.

### 임무 · 파일 탐색기

앱 바 **임무** 버튼으로 열리는 전체 화면 팝업입니다. 왼쪽은 파일 트리, 오른쪽은 미리보기 — 임무 파일은 구조화되어 보입니다.

![임무 탐색기](../screenshots/features/14-mission-explorer.png)

파일 생성 · 이름 변경 · 삭제(휴지통) · 편집 저장이 모두 가능합니다. `.git` 폴더는 불가침이고, 삭제는 영구 삭제가 아니라 휴지통으로 갑니다.

## 에이전트 세션

### 셸 우선 모델

모든 세션은 일반 셸로 시작합니다. 에이전트 실행은 언제나 사용자의 명시적 행동입니다.

- 역할 세션은 페인의 `▶ Claude Code 기동` · `▶ Codex 기동` 버튼이나 우클릭 메뉴로 띄웁니다
- 터미널에서 직접 `claude`를 실행하면 대시보드가 감지해 배지만 붙입니다. 역할·훅은 붙지 않습니다

### 세션 이름과 번호

세션을 만들 때 이름을 정합니다. 비워 두면 기본 터미널은 `프로젝트명XX`(예: `EQMUX01`), 역할 세션은 페르소나 이름이 붙습니다. 이름은 24자 이내이고 공백·`@`는 쓸 수 없으며, 같은 워크스페이스에서 겹치면 다른 이름을 제안합니다. 페인 헤더와 레일의 이름 앞에는 두 자리 슬롯 번호(`01`~`08`)가 붙습니다. 번호는 이름을 바꾸거나 앱을 다시 켜도 그대로입니다.

### 상태 6종

| 상태 | 뜻 |
|---|---|
| `starting` | 기동 중 |
| `busy` | 작업 중 (실행 중인 도구와 서브에이전트 수를 함께 표시) |
| `waiting` | 사람의 승인·입력 대기 — **알림 대상** |
| `shell` | 에이전트 없이 셸만 |
| `idle` | 에이전트가 유휴 (턴 종료) |
| `dead` | 프로세스 종료 — **알림 대상** |

색은 `waiting`과 `dead`에만 씁니다. 나머지는 무채색 안에서 구분합니다.

### 세션 상세 패널

레일의 ⓘ 버튼(또는 세션 더블클릭)으로 엽니다.

![세션 상세](../screenshots/features/05-session-detail.png)

상태 · 임무 · 역할 · 서브에이전트 · 활동 · 비용 · 메모리 · 재개 가능 여부 · PID · cwd · 격리 방식과 함께, **실제 실행 플래그 원문**을 그대로 보여줍니다. 여기서 세션 이름 변경, 슬롯 권한 조정, 역할 변경, 점프·재개·중지를 할 수 있습니다.

### 재개와 재시작

- **재개** — 같은 세션 ID와 cwd로 `--resume`. 대화가 이어집니다. 재개 가능 여부는 트랜스크립트 존재로 실측합니다.
- **권한 재시작** — 권한이 바뀌면 재시작 배지가 뜹니다. 재개 기반으로 다시 띄우므로 대화는 유지됩니다.
- **자동 재시작 없음** — 프로세스가 죽으면 `dead`로 표시만 하고 되살리지 않습니다. 자동 재시작은 크래시 루프를 만들기 때문입니다.

### 알림

| 항목 | 동작 |
|---|---|
| 대상 | `waiting` · `dead` 진입, 에이전트의 완료 보고(`eqmux report --done`). 30초 넘게 일한 턴의 완료는 기본으로 칩만 띄우고, 설정에서 OS 알림을 켤 수 있습니다 |
| 알림 센터 | 앱 바 벨. 창에 포커스가 있어 OS 알림을 내지 않은 것도 쌓입니다. 누르면 그 페인으로 갑니다 |
| 다음 미확인으로 | `Ctrl+Shift+U` 또는 `⛶ 응답 대기` 칩. 열린 모든 워크스페이스를 오래 기다린 순으로 돕니다 |
| 억제 | 앱 창에 포커스가 있으면 알리지 않음 |
| 합침 | 세션당 최소 60초 간격, 그 사이 발생분은 "(N건 합침)" |
| 음소거 | 세션·워크스페이스 단위. 알림만 막고 인앱 미확인 표시는 유지 |
| 의도한 종료 | 사용자가 중지한 세션의 `dead`는 알리지 않음 |

미확인 표시는 세션 셀 → 워크스페이스 탭 → 관제 탭으로 전파되고, 해당 페인을 보거나 상세를 열면 해제됩니다.

### 관측 저하(degraded)

에이전트 상태를 읽는 경로에 접근할 수 없게 되면 살아 있는 세션에 **"낮은 신뢰"** 뱃지가 붙습니다. 그동안에도 앱은 계속 동작하고, 접근이 회복되면 자동으로 해제됩니다. 이 전환은 이벤트 피드에 기록됩니다 — 조용히 열화되지 않습니다.

### 엔진별 지원

Claude Code와 Codex는 같은 역할 파일 · 같은 메시지 버스(`eqmux send`) · 같은 권한 원천(역할 파일 frontmatter)을 씁니다. 다른 것은 각 CLI에 그것을 싣는 방법입니다. Codex는 Codex CLI 0.146.0에서 확인했습니다.

| 항목 | Claude Code | Codex |
|---|---|---|
| 역할 주입 | `--append-system-prompt`로 세션 시작 안내문을 붙이고, SessionStart 훅이 역할 파일을 컨텍스트로 싣습니다 | `-c developer_instructions='…'`로 같은 안내문을 붙이고, 같은 SessionStart 훅이 역할 파일을 싣습니다 |
| 훅 주입 | 앱 데이터의 `hook-settings.json`을 `--settings`로 얹습니다 | `-c hooks.<이벤트>=[…]` 인라인 설정으로 얹습니다. 앱이 쓴 `eqmux _hook`만 거는 훅이라 `--dangerously-bypass-hook-trust`로 훅 심사를 건너뜁니다 |
| 사용자 설정 | `~/.claude` · repo `.claude/`는 건드리지 않습니다 | `~/.codex` · repo `.codex/`는 건드리지 않습니다 |
| 승인 대기 감지 | Notification 훅 | PermissionRequest 훅 |
| 세션 id | 앱이 발급해 `--session-id`로 넘깁니다 | Codex가 정하고 SessionStart 훅이 알려 줍니다 |
| 재개 | `--resume <id>`, 같은 작업 폴더. 트랜스크립트가 있으면 가능 | `codex resume <id>`. SessionStart 훅이 알려 준 롤아웃 파일이 있으면 가능 |
| 권한 번역 | `--permission-mode` + `--disallowedTools`(git commit · push 금지) | `--sandbox read-only`(쓰기 권한 없음) 또는 `workspace-write` + `--ask-for-approval on-request`. Codex에는 도구 금지 플래그가 없어 git commit · push 금지는 지시문으로만 전합니다 |
| 권한 우회 | `bypassPermissions`를 만들지 않습니다 | `--dangerously-bypass-approvals-and-sandbox`를 만들지 않습니다 |
| 비용 | statusLine으로 누적 비용을 모읍니다 | 모으지 않습니다 |

## 대화

사이드 패널 **대화** 탭이 에이전트 간 대화 스트림입니다. 4줄이 넘는 메시지는 접혀 있고 `펼치기`로 엽니다.

![대화 패널](../screenshots/features/15-panel-conversation.png)

### 메시지 타입 5종

| 타입 | 쓰임 |
|---|---|
| `ask` | 질문 |
| `handoff` | 작업 넘기기 |
| `report` | 진척 보고 |
| `review` | 검토 요청·결과 |
| `escalate` | 판단 요청 (막혔을 때) |

**자유 텍스트는 거부됩니다.** 타입이 강제되어야 잡담이 아니라 업무 전달이 됩니다.

### 전달 규칙

수신 세션이 `idle`이면 즉시 전달하고, 작업 중이면 인박스에 쌓았다가 **턴이 끝날 때** 흘려보냅니다. `waiting` 상태에는 즉시 넣지 않습니다 — TUI 다이얼로그에 키가 잘못 들어가는 것을 막기 위해서입니다. 대기 중인 메시지는 탭 상단에 "누구 몇 건"으로 표시되고 재시작 후에도 유지됩니다(새 버전으로 업데이트할 때는 세션 DB와 함께 `.bak`으로 넘어갑니다).

### 사람의 참여

`@이름 내용` 형식으로 멘션하면 그 세션에게, 멘션을 생략하면 살아 있는 에이전트 전원에게 갑니다. 이름은 세션 이름이나 페르소나 이름입니다. 내가 보낸 메시지에는 `전달됨` 또는 `대기 중 · 상대 작업 중`이 붙습니다.

발신 상한은 발신자당 분당 10건입니다. 에이전트가 보내는 본문은 800자까지이고, 사람이 대화 탭에서 쓰는 글에는 길이 상한이 없습니다.

### 다른 프로젝트와

받는 사람은 열린 모든 프로젝트에서 찾습니다. 이름이 두 프로젝트에 겹치면 `@이름@프로젝트`로 씁니다. 프로젝트 간 메시지는 양쪽 대화 탭에 프로젝트 배지와 함께 남습니다. 받기 싫은 프로젝트는 워크스페이스 탭 메뉴에서 `다른 프로젝트 메시지 받기`를 끕니다.

다른 프로젝트나 팀원에게서 온 메시지는 요청일 뿐입니다. 권한 승인이나 위험 명령 허가로 쓰지 않는다는 문장이 역할 파일에 들어 있습니다.

## 코드 검토

### git 패널

![git 패널](../screenshots/features/16-panel-git.png)

한 줄 툴바에 저장소 선택 · 브랜치 · ahead/behind · 액션 버튼이 있습니다.

- **diff** — HEAD ↔ 워크트리 비교를 엽니다
- **pull · commit · push** — 명령을 **클립보드에 복사만** 합니다. 실행은 터미널에서 사람이 합니다
- **커밋 목록** — 행을 클릭하면 부모 커밋과의 diff가 열립니다
- **브랜치** — 클릭 체크아웃(2단 확인) · 새 브랜치 생성
- **워크트리** — 목록 · 생성 · 기존 브랜치 연결 · 그 트리에서 셸 열기

### diff 뷰어

![Git Diff](../screenshots/features/20-git-diff.png)

왼쪽에 변경 파일 트리(A/M/D/R 상태), 오른쪽에 나란히 비교. 읽기 전용이며 스테이지·커밋은 터미널에서 합니다.

### 워크트리 격리

세션마다 작업 트리를 분리하면 에이전트끼리 파일이 섞이지 않습니다.

![워크트리 생성](../screenshots/features/27-worktree-create.png)

역할 세션을 만들 때 체크박스로 켜면 `.eqmux/worktrees/<세션>`과 전용 브랜치가 만들어집니다. 좌측 레일의 워크트리 섹션에서 트리별로 어떤 세션이 도는지 볼 수 있고, `+`로 새 트리를 만들거나 기존 브랜치를 연결할 수 있습니다.

**워크트리 삭제 기능은 없습니다** — 머지와 정리는 사람의 몫입니다.

### 에디터

파일 탐색기에서 파일을 열면 CodeMirror 기반 편집기가 열립니다. 100여 개 언어 문법 강조, `Ctrl+S` 저장, 그리고 두 가지 안전장치가 있습니다.

- **외부 변경 충돌 감지** — 편집하는 동안 에이전트가 같은 파일을 바꿨으면 저장을 거부합니다
- **미저장 이탈 보호** — 저장하지 않고 다른 파일로 이동하려 하면 한 번 경고합니다

### 트랜스크립트

![트랜스크립트](../screenshots/features/21-transcript.png)

에이전트의 대화 로그를 턴 단위로 봅니다. 로그 파일을 **참조만** 하고 복사하지 않으며, 파일 끝 2MB만 읽어 큰 로그에서도 가볍습니다. 도구 호출은 기본 접힘이고 펼치면 입력·출력이 보입니다. 아래 입력창에 쓴 내용은 그대로 터미널로 전달됩니다.

## 영속성과 복구

### 무엇이 저장되나

| 대상 | 저장소 |
|---|---|
| 스크롤백 · 이벤트 · 대화 | 워크스페이스별 SQLite (WAL) |
| 설정 · 레이아웃 | JSON |
| 팀 · 역할 · 임무 | `.eqmux/` 파일 |

스크롤백은 **색(SGR)까지 보존**되어 재생 시 원래 색으로 나옵니다(설정에서 끄면 용량이 줄어듭니다). 보존 정책은 30일 · 세션당 줄 수 상한 · 전역 2GB이고, 먼저 닿는 것부터 정리합니다.

### 재시작하면

1. 열린 탭 · 페인 배치 · 분할 비율 · 선택 세션이 복원됩니다. 설정 `시작 화면`이 `마지막 워크스페이스`면 그 탭이 열립니다
2. 각 페인에 마지막 500줄이 흐리게 재생되고 경계선이 표시됩니다
3. 역할 세션은 셸로 뜹니다. 대화를 이으려면 페인 우클릭 메뉴나 세션 상세의 `재개`를 누릅니다
4. 재개할 수 없으면 세션 상세의 `재개` 행에 그 이유가 보입니다

**자동으로 실행되는 것은 없습니다.**

### 업데이트하면

새 버전을 처음 켜면 워크스페이스 등록 · 배치 · 설정 · 직무·페르소나 라이브러리는 그대로 남습니다. 워크스페이스마다 스크롤백 · 대화 · 재개 정보가 든 `session.db`는 지우지 않고 `session.db.bak`으로 옮긴 뒤 새로 시작합니다. 업데이트 전 대화와 재개 정보는 새 버전 화면에 나오지 않습니다.

### 비정상 종료 후

크래시 후 첫 실행에서 직전 세션 목록과 마지막 활동 시각, 재개 가능 여부를 보여줍니다. 여기서도 자동 재실행은 하지 않고, 실제 재개는 페인 메뉴와 세션 상세의 `재개`가 담당합니다.

### 화면이 죽어도

터미널은 Rust 백엔드가 소유하므로 렌더러(웹뷰)가 죽어도 세션은 계속 살아 있습니다. 화면이 자동으로 다시 뜨고 살아 있는 세션에 재부착됩니다.

### 종료

![종료 확인](../screenshots/features/23-exit-dialog.png)

창을 닫으면 앱이 완전히 종료됩니다(트레이 상주 없음). 실행 중인 세션이 있으면 목록과 재개 가능 여부를 보여주고 확인을 받습니다. 종료 시퀀스는 저장 flush → 전 세션에 Ctrl+C → 유예 후 프로세스 트리 정리 순입니다. 세션마다 Job Object로 자식 프로세스를 묶어두므로 **고아 프로세스가 남지 않습니다.**

## eqmux CLI

에이전트가 앱과 대화하는 통로입니다. 앱이 띄운 터미널에서는 `PATH`에 이미 잡혀 있습니다.

### `eqmux send`

다른 에이전트나 사람에게 메시지를 보냅니다.

```bash
eqmux send --type handoff --to @린 "session.ts 인터페이스 변경을 넘깁니다. migration test 부탁해요."
eqmux send --type escalate "refresh token 경계가 PRD와 충돌합니다. 판단이 필요합니다."
```

| 옵션 | 설명 |
|---|---|
| `--type` | `ask` · `handoff` · `report` · `review` · `escalate` (필수) |
| `--to` | `@이름`(세션 이름이나 페르소나 이름). 열린 모든 프로젝트에서 찾고, 겹치면 `@이름@프로젝트`. 생략하면 자기 프로젝트의 살아 있는 에이전트 전원 |
| `--file` | 긴 내용은 파일로 — `--file <경로> "요약"`. 저장소 안 경로만 받고(`.eqmux/notes/` 권장), 대화 탭에서 그 파일이 링크로 열립니다 |

PowerShell에서는 `--to "@린"`처럼 따옴표로 감쌉니다. `@`가 스플래팅 기호라 그냥 쓰면 사라집니다.

사람이 보내는 메시지와 같은 원장을 쓰고, 분당 10건 상한도 공유합니다. 본문은 800자까지이고, 넘으면 `--file`을 쓰라는 오류가 납니다. 보내면 전달 결과가 바로 나옵니다 — `전달함`(받는 세션이 유휴) 또는 `대기 — 상대 작업 중(대기 N건)`(턴이 끝나면 들어감). 없는 이름, 닫힌 프로젝트, 받기를 끈 프로젝트는 오류입니다.

### `eqmux report`

진척을 한 줄로 보고합니다. 대화 스트림과 세션 이벤트 피드에 동시에 기록됩니다.

```bash
eqmux report "auth/session.ts 리팩터 중 — 테스트 8/12"
eqmux report --done "auth/session.ts 리팩터 완료 — 테스트 12개 통과"
```

`--done`은 맡은 일이 끝났다는 뜻입니다. 대화 탭에 ✓ 배지가 붙고, 사람에게 `이름 · 완료` 알림이 가고, 이 세션에 handoff·ask를 주고 아직 회신을 받지 못한 팀원에게도 같은 보고가 갑니다.

### `eqmux who`

열린 모든 프로젝트의 세션을 번호 · 이름 · 프로젝트 · 직무(직함) · 상태로 보여 줍니다. 찍힌 주소를 그대로 `--to`에 쓸 수 있습니다.

### `eqmux browser`

브라우저 패널을 조종합니다 — `open <주소>` · `snapshot` · `click` · `type` · `get-text` · `eval` · `back` · `forward` · `reload`. 인자 없이 실행하면 사용법이 나옵니다. 사람이 보고 있는 그 패널이 움직입니다.

### `eqmux ping`

앱과 연결되는지 확인합니다.

### 내부 명령

`eqmux _hook` · `eqmux _statusline`은 앱이 에이전트에 주입하는 내부 진입점입니다. 직접 호출할 필요가 없습니다. 어떤 실패에도 종료 코드 0을 반환해 에이전트의 흐름을 막지 않습니다.

## 파일 구조

### 저장소 안 (`.eqmux/`)

| 파일 | 역할 | 커밋 |
|---|---|---|
| `team.json` | 팀 편성 원본 | ✅ |
| `team.md` | 에이전트·사람이 읽는 표 (파생) | ✅ |
| `roles/<세션>.md` | 세션별 역할. frontmatter의 `permissions`가 실행 권한을 결정 | gitignore |
| `missions/*.md` | 임무 정의 (브랜치 + 목표) | ✅ |
| `worktrees/<이름>/` | 워크트리 | gitignore |
| `notes/` | 긴 메시지 파일 (`send --file`) | 팀이 정함 |

`.eqmux/.gitignore`는 앱이 자동으로 만들어 `roles/`와 `worktrees/`를 제외합니다.

### 앱 데이터 (사용자 프로필)

| 위치 | 내용 |
|---|---|
| `jobs/*.md` · `personas/*.md` | 직무 · 페르소나 라이브러리 (전역) |
| `presets/*.json` | 편성 프리셋 |
| `settings.json` · `layout.json` | 설정 · 레이아웃 |
| `workspaces/<id>/session.db` | 워크스페이스별 SQLite |
| `workspaces/<id>/session.db.bak` | 업데이트 때 옮겨 둔 이전 버전의 SQLite |
| `~/.eqmux/logs/<세션>.log` | 세션 원문 로그 |

라이브러리는 **전역 + 워크스페이스 오버라이드** 2단입니다. 워크스페이스의 `.eqmux/`에 같은 id의 파일을 두면 그쪽이 이깁니다.

### 역할은 어떻게 전달되나

앱은 사용자의 `CLAUDE.md`를 수정하지 않습니다. 대신

1. 환경변수(`EQMUX_ROLE_FILE` · `EQMUX_TEAM_FILE`)로 역할 파일 경로를 알려주고
2. 360자 이하의 세션 시작 안내문에 역할 파일 포인터를 넣고 (Claude Code는 `--append-system-prompt`, Codex는 `developer_instructions`)
3. SessionStart 훅이 역할 파일을 컨텍스트로 싣습니다

파일이 원본이고 프롬프트는 포인터일 뿐입니다. 엔진별 차이는 [엔진별 지원](#엔진별-지원)에 있습니다.

## 레시피

### 4인 팀으로 기능 하나 끝내기

1. 워크스페이스를 열고 편성 프리셋 **표준**(리드 · 개발 2 · QA)으로 캐스팅합니다. 개발 둘에게는 직함을 붙여 나눕니다(예: `클라이언트 개발자` · `서버 개발자`).
2. 임무를 만들고 리드에게 배정합니다. 목표에는 완료 조건을 씁니다. 각 페인의 `▶ Claude Code 기동`으로 에이전트를 띄웁니다.
3. 리드가 일을 나눠 넘깁니다.
   ```bash
   eqmux send --type handoff --to @카이 "로그인 화면. 완료 조건은 .eqmux/missions/login.md"
   eqmux send --type handoff --to @노엘 "로그인 API. 응답 형식은 같은 문서"
   ```
4. 개발자는 일을 끝내면 완료를 보고합니다. 사람에게 알림이 가고, 일을 맡긴 리드에게도 같은 보고가 갑니다.
   ```bash
   eqmux report --done "로그인 API 완료 — 테스트 12개 통과"
   ```
5. 리드가 QA에게 검토를 넘기고, QA의 `report --done`이 오면 사람이 임무 카드의 `검토 중으로`를 누르고 git 패널에서 diff를 봅니다. 앱은 임무 상태를 스스로 바꾸지 않습니다.

### 리뷰어에게 handoff하기

1. 인계 내용이 길면 `.eqmux/notes/`에 파일로 씁니다. 에이전트 메시지 본문은 800자까지입니다. handoff는 결정 · 기각 · 위험 · 파일 · 남은 일 다섯 칸으로 씁니다(역할 파일에 형식이 들어 있습니다).
2. 파일 경로와 요약 한 줄을 보냅니다.
   ```bash
   eqmux send --type handoff --to @솔 --file .eqmux/notes/auth-review.md "auth 리팩터 검토 부탁 — 위험은 토큰 만료 경계"
   ```
3. 응답으로 전달 결과가 바로 나옵니다. `전달함`이면 리뷰어가 받았고, `대기 — 상대 작업 중(대기 N건)`이면 리뷰어의 턴이 끝날 때 들어갑니다. 사람은 대화 탭에서 첨부 경로를 눌러 같은 파일을 엽니다.
4. 리뷰어는 결과를 `review`로 돌려주고, 끝나면 완료를 보고합니다. `--done` 보고는 handoff를 준 쪽에 자동으로 회신됩니다.
   ```bash
   eqmux send --type review --to @카이 "만료 경계 테스트가 없다 — tests/auth/refresh.test.ts에 추가 필요"
   eqmux report --done "auth 리팩터 검토 끝 — 수정 요청 1건"
   ```
5. 리뷰어가 보고 없이 턴만 끝내면 페인에 `✓ 턴 끝남 · 보고 전` 칩이 뜹니다. 칩의 `보고 요청`은 사람이 눌렀을 때만 갑니다.

### Codex와 Claude를 한 팀에

1. Codex CLI를 설치하고 로그인합니다. 엔진이 없으면 세션 만들기 창에 공식 설치 명령과 복사 버튼이 보입니다. 설치는 터미널에서 직접 합니다.
2. 빈 슬롯에서 역할 세션을 만들 때 엔진을 고릅니다. 예를 들어 리드와 QA는 Claude Code, 개발 둘은 Codex로 둡니다. 엔진은 `team.json` 슬롯의 `cli`에 남습니다.
3. 메시지는 엔진을 가리지 않습니다. 같은 `eqmux send` · `eqmux report --done` · 같은 원장입니다.
   ```bash
   eqmux who
   eqmux send --type ask --to @노엘 "응답 스키마에 expires_at 넣었나요?"
   ```
4. 엔진 차이를 알고 배치합니다. Codex에는 git 금지 플래그가 없어 commit · push 금지가 지시문으로만 전해집니다. git 권한이 없는 직무를 Codex에 줄 때는 이 점을 감안합니다. 자세한 차이는 [엔진별 지원](#엔진별-지원)에 있습니다.

## 문제 해결

**에이전트를 실행했는데 대시보드에 배지가 안 뜹니다.**
감지는 프로세스 트리를 5초 주기로 스캔합니다. 잠시 기다려 보세요. 계속 안 뜨면 그 세션의 터미널에서 실행한 것이 맞는지(다른 창이 아닌지) 확인하세요.

**상태 라벨 옆에 "낮은 신뢰" 뱃지가 있습니다.**
에이전트 상태 레지스트리에 접근할 수 없는 상태입니다. 상태는 훅과 프로세스 생존만으로 유지되며, 접근이 회복되면 자동으로 사라집니다. 앱 동작에는 문제가 없습니다.

**재개 버튼이 비활성입니다.**
재개는 트랜스크립트와 작업 디렉터리가 모두 맞아야 가능합니다. 세션 상세 패널의 `재개` 행에 사유가 표시됩니다. 워크트리를 지웠거나 다른 머신에서 clone한 저장소라면 새로 시작해야 합니다.

**권한을 바꿨는데 반영이 안 됩니다.**
실행 권한은 프로세스 수명 동안 고정입니다. 재시작 배지를 눌러 재개 기반 재시작을 하면 대화를 유지한 채 반영됩니다.

**commit / push 버튼을 눌렀는데 아무 일도 없습니다.**
의도된 동작입니다. 명령이 클립보드에 복사되었으니 터미널에 붙여넣어 실행하세요. 앱은 git 이력을 조작하지 않습니다.

**브라우저 패널에 주소가 안 열립니다.**
브라우저 패널은 `http` · `https` 주소만 엽니다. `file://` 같은 다른 형식은 거부합니다. 터미널의 링크를 클릭하면 패널이 아니라 기본 브라우저로 열립니다.

**터미널 색이 이상합니다 / 라이트 테마인데 터미널만 어둡습니다.**
의도된 설계입니다. 터미널 페인은 ANSI 색 팔레트를 전제로 하므로 어느 테마에서든 다크로 유지됩니다.

**세션을 지웠는데 워크트리가 남아 있습니다.**
의도된 동작입니다. 머지되지 않은 작업이 사라지는 것을 막기 위해 워크트리는 보존합니다. 정리는 터미널에서 직접 하세요.

## 설계 경계

아래는 미구현이 아니라 **의도적으로 하지 않는 것**입니다.

| 하지 않는 것 | 이유 |
|---|---|
| API 키 보유 | 자체 AI 루프가 없습니다. 인증은 사용자의 CLI가 소유합니다 |
| 자동 실행 · 자동 재개 · 자동 재시작 | 상태를 바꾸는 것은 언제나 사용자의 버튼입니다 |
| `bypassPermissions` 제공 | 권한 체계를 무의미하게 만듭니다 |
| git 이력 조작 (commit · push · 스테이지) | 실행은 사람이 터미널에서 합니다 |
| 워크트리 삭제 | 머지·정리는 사람의 몫입니다 |
| 프로세스 강제 종료 (포트 패널) | 관측 도구이지 조작 도구가 아닙니다 |
| 승인·거부 대행 | 에이전트 TUI에 키를 주입하지 않습니다 |
| 웹 페이지에 앱 권한 주기 | 브라우저 패널의 원격 페이지에는 앱 IPC가 열리지 않습니다. 에이전트에게 페이지 내용은 자료일 뿐 지시가 아닙니다 |
| 팀원 메시지를 승인으로 쓰기 | 다른 에이전트나 프로젝트에서 온 메시지는 요청일 뿐, 권한 승인이 아닙니다 |
