## 터미널 4개를 알트탭으로 관제할 수는 없다

에이전트 CLI는 이미 훌륭하게 일합니다. 문제는 사람 쪽입니다 — 누가 승인을 기다리는지, 누가 죽었는지, 누가 무엇을 하고 있는지를 창 4개를 오가며 눈으로 쫓아야 합니다. EQMUX는 그 관제 업무를 화면 하나로 옮깁니다.

| 지금 | EQMUX |
|---|---|
| 승인 대기를 놓친다 | `waiting` 진입 즉시 OS 알림 — 창에 포커스가 있으면 억제하고, 반복은 합칩니다 |
| 죽은 세션을 늦게 발견한다 | `dead` 감지 + `재개` 버튼. 대화를 이어서 되살립니다 |
| 누가 뭘 하는지 모른다 | 상태 · 실행 중인 도구 · 서브에이전트 수 · 누적 비용 · 메모리를 실측해 보여줍니다 |

## 보인다 · 맡긴다 · 믿는다

**보인다** — 팀 상태가 한눈에.
워크스페이스×세션 그리드가 주의가 필요한 순서로 정렬됩니다. 색은 `waiting`과 `dead`에만 씁니다.

**맡긴다** — 팀에게 일을 나눠준다.
직무 8종과 페르소나로 팀을 캐스팅하고, 임무를 배정하고, 에이전트끼리 업무를 주고받게 합니다.

**믿는다** — 앱은 선을 넘지 않는다.
API 키를 보유하지 않고, 아무것도 자동 실행하지 않고, git 이력을 조작하지 않습니다.

## 보고, 배정하고, 개입한다

![관제 대시보드](../screenshots/features/04-dashboard.png)

관제 탭은 앱을 켜면 가장 먼저 보이는 고정 탭입니다. 등록된 모든 워크스페이스가 행으로, 세션이 셀로 놓이고, 주의가 필요한 것이 위로 올라옵니다.

- **상태 6종 실시간** — `starting` · `busy` · `waiting` · `shell` · `idle` · `dead`. 폴링이 아니라 스트림 구독입니다.
- **에이전트 감지 배지** — 세션 프로세스 트리를 스캔해 실제로 돌고 있는 CLI(Claude · Codex · Gemini …)를 표시합니다. 터미널에서 직접 띄운 것도 잡힙니다.
- **알림은 꼭 필요한 것만** — `waiting`·`dead` 진입과 에이전트의 완료 보고에만. 창에 포커스가 있으면 억제하고, 세션당 60초로 합칩니다.
- **놓쳐도 찾아간다** — 알림은 앱 바 벨(알림 센터)에도 쌓입니다. 항목을 누르거나 `Ctrl+Shift+U`를 누르면 봐야 할 페인으로 바로 갑니다.
- **액션은 세 개** — 점프 · 재개 · 중지. 승인·거부를 대신 눌러주지 않습니다.

세션 셀을 열면 인스펙터에 실행 플래그 원문, 재개 근거, 슬롯 권한, 메모리와 비용까지 그대로 나옵니다.

## 터미널이 작업 공간이다

![터미널 워크스페이스](../screenshots/features/06-terminal-grid.png)

EQMUX는 에이전트를 감싸는 채팅 UI가 아닙니다. 페인마다 진짜 터미널(ConPTY)이 있고, 실제 일은 거기서 벌어집니다.

- **배치 6종** — 그리드(행/열) · 세로 스택 · 가로 나열 · 메인+우측 · 메인+하단. `Ctrl+Shift+L`로 전환하고, 분할선을 끌어 비율을 조정합니다.
- **셸 4종** — PowerShell 7 · Windows PowerShell · Git Bash · cmd
- **터미널 내 검색** — `Ctrl+F`. TUI로 키를 흘려보내지 않고 검색 바를 엽니다.
- **클립보드 · 드래그 앤 드롭** — 이미지를 붙여넣으면 PNG로 저장하고 경로를 넣어줍니다
- **실행 패널** — 서버 · 포트 · 환경변수 탭. 포트는 시작 때와 `다시 실측`을 누를 때 잽니다. 환경변수는 워크스페이스의 `.env` 계열을 읽기 전용으로 보이고 값은 기본으로 가립니다.

배치·비율·열린 탭·선택 세션은 저장되어 다음 실행에 그대로 복원됩니다.

## 직무와 페르소나로 팀을 만든다

![팀 캐스팅](../screenshots/features/10-team-casting.png)

**직무**가 책임과 권한을 정하고, **페르소나**가 판단 성향을 정합니다. 둘은 분리되어 있습니다.

| | |
|---|---|
| **직무 8종 (고정)** | 리드 · 기획 · 개발 · 디자인 · QA · 디버거 · 문서 · 릴리즈 |
| **권한** | `write` / `commit` / `push` — push 권한은 리드와 릴리즈에만 |
| **페르소나 3단계** | 기본(판단 힌트) → 중간(+말투·성격) → 고급(캐릭터 시트) |
| **편성 프리셋** | 표준 · 집중개발 · 제품기획 · 품질 |
| **직함** | 직무 위에 붙이는 이름표. 역할 파일과 `team.md`에 들어가고 에이전트가 자기 직함으로 답합니다 |

캐스팅 결과는 `.eqmux/team.json`과 사람이 읽는 `team.md`로 저장되고 repo와 함께 커밋됩니다. **팀 구성이 코드와 같이 이동합니다.**

![팀 편성](../screenshots/features/11-team-composition.png)

## 임무를 주고, 에이전트끼리 말하게 하라

![임무 배정](../screenshots/features/13-missions.png)

임무는 `.eqmux/missions/*.md` 파일이 원본입니다 — 브랜치와 목표, 산출물 체크리스트. 배정하면 역할 파일에 임무 블록이 들어가고, 살아 있는 세션에는 한 줄 브리프가 전달됩니다.

에이전트 간 메시지는 다섯 타입이 강제됩니다 — `ask` · `handoff` · `report` · `review` · `escalate`. 잡담이 아니라 업무 전달입니다.

- 작업 중인 세션에는 **턴이 끝난 뒤** 전달되어 흐름을 끊지 않습니다
- 사람도 `@페르소나이름`으로 같은 스트림에 참여합니다
- 에이전트는 터미널에서 `eqmux send` · `eqmux report`로 합류합니다
- 일을 끝낸 에이전트는 `eqmux report --done`으로 사람과 일을 맡긴 팀원에게 함께 알립니다
- 열린 다른 프로젝트의 에이전트에게도 `@이름`으로 보냅니다. 주소는 `eqmux who`로 봅니다

## 에이전트가 만든 변경을 사람이 검토한다

![Git Diff](../screenshots/features/20-git-diff.png)

git 패널에서 현재 브랜치·변경·커밋을 보고, diff 뷰어에서 나란히 비교합니다. 커밋 행을 클릭하면 부모 커밋과의 차이가 열립니다.

- **워크트리 격리 (선택)** — 세션을 만들 때 고르면 `.eqmux/worktrees/<세션>`에 전용 작업 트리와 브랜치 `eqmux/<세션>`을 두어 에이전트끼리 작업이 섞이지 않습니다. 브랜치·워크트리 현황은 관제 레일에 보이고, 머지·정리는 사람이 합니다
- **파일 탐색기 + 에디터** — 100여 개 언어 문법 강조, 외부 변경 충돌 감지, 미저장 이탈 보호
- **트랜스크립트** — 에이전트 대화 로그를 턴 단위로 열람. 참조만 하고 복사하지 않습니다

**단, `commit`과 `push`는 앱이 대신 눌러주지 않습니다.** 버튼은 명령을 클립보드에 복사할 뿐이고, 실행은 언제나 터미널에서 사람이 합니다.

## 꺼도 사라지지 않는다

스크롤백은 색까지 그대로 SQLite에 저장되고, 재시작하면 마지막 500줄(설정에서 250·1000)이 재생됩니다.

- **재개는 사람이 누른다** — 자동으로 되살리지 않습니다. 복원된 페인은 셸로 뜨고, 페인 메뉴나 세션 상세의 `재개`를 누르면 대화가 이어집니다
- **업데이트해도 등록은 남는다** — 워크스페이스 등록·배치·설정·라이브러리는 그대로입니다. 스크롤백과 대화 기록이 든 세션 DB만 `session.db.bak`으로 옮겨 두고 새로 시작합니다. 등록·배치는 앱 데이터 밖에도 사본을 두어, 지워졌으면 시작할 때 되살립니다
- **웹뷰 크래시 생존** — 화면이 죽어도 터미널은 Rust가 쥐고 있어 그대로 이어집니다
- **고아 프로세스 0** — 세션마다 Job Object로 자식 트리를 묶습니다
- **전문 검색** — 저장된 모든 스크롤백을 워크스페이스 전체에서 찾습니다

## 다른 도구와 무엇이 다른가

경쟁이 아니라 층이 다릅니다. **herdr는 런타임, EQMUX는 팀입니다.** Emdash는 태스크를 병렬로, EQMUX는 팀으로 돌립니다. 아래는 Windows · 팀 · 메시지 세 축에 한국어 입력만 더해 추린 것입니다(2026-10-14 조사 기준).

| 도구 | 층 | Windows | 팀 | 에이전트 간 메시지 | 한국어 IME |
|---|---|---|---|---|---|
| **EQMUX** | 팀 관제 데스크톱 앱 | ✓ 네이티브 | 직무 8종 + 페르소나 + 직함. 역할 파일이 실행 권한을 정합니다 | 타입 5종 강제 + SQLite 원장. 상태를 보고 전달하고, 다른 프로젝트에도 보냅니다 | 실기 확인 전 |
| herdr | 에이전트 런타임 (세션을 띄우고 살려 둔다) | ✓ | 없음 | `agent prompt --wait` — 상대 화면에 입력합니다. 타입·원장 없음 | △ 부분 지원 (후보 창 위치 문제, 자체 문서) |
| Emdash | 태스크 병렬 실행 데스크톱 앱 | ✓ 서명 MSI | 없음 | 없음 | – |
| Claude Code Agent Teams | Claude Code 내장 실험 기능 | △ 분할 페인이 Windows Terminal에서 안 됨 | 리드와 팀원. 역할별 권한은 없음 | `SendMessage` 메일박스. 평문 | – |
| oh-my-claudecode | Claude Code 플러그인 | △ 실험 (psmux) | 역할 19종 자동 배정. 권한은 우회로 고정 | 리더 ↔ 워커, 아웃박스 타입 9종 | × 알려진 문제 (자체 문서) |

## 하지 않는 것이 곧 설계다

에이전트에게 repo를 맡기는 도구는, 무엇을 할 수 있는지보다 **무엇을 하지 않는지**가 중요합니다.

| 하지 않는 것 | 이유 |
|---|---|
| **API 키를 보유하지 않는다** | 자체 AI 루프가 없습니다. 인증과 과금은 사용자의 CLI 몫입니다 |
| **아무것도 자동 실행하지 않는다** | 재시작 후에도 에이전트를 되살리지 않습니다. 재개는 사람이 누릅니다 |
| **git 이력을 조작하지 않는다** | commit · push · 스테이지 버튼이 없습니다 (명령 복사만) |
| **승인을 대신 누르지 않는다** | 에이전트 TUI에 키를 주입하지 않습니다 |
| **사용자 설정을 건드리지 않는다** | `CLAUDE.md` · `~/.claude` · repo `.claude/`는 불가침입니다 |
| **파일이 원본이다** | 팀 · 역할 · 임무는 `.eqmux/` 파일. DB는 캐시일 뿐이고, 불일치하면 파일이 이깁니다 |

## 자주 묻는 질문

**API 키를 넣어야 하나요?**
아니요. EQMUX는 API 키를 보유하지 않습니다. 이미 로그인된 Claude Code CLI를 실행할 뿐이고, 인증과 과금은 전부 CLI 쪽에서 일어납니다.

**Claude Code가 꼭 필요한가요?**
아니요. 에이전트 세션 기능(상태 감지 · 재개 · 역할 전달 · 메시지)은 Claude Code와 Codex를 지원하고, 한 팀에 둘을 섞을 수 있습니다. 모든 세션은 일반 셸로도 쓸 수 있고, 터미널에서 직접 띄운 Gemini 같은 다른 CLI도 관제 대시보드가 감지해 표시합니다.

**에이전트가 마음대로 커밋하거나 push하지 않나요?**
실행 권한은 직무별로 역할 파일에 명시됩니다. Claude Code는 실행 플래그로 강제하고, Codex는 샌드박스 플래그와 실행 지시로 제한합니다. push 권한은 기본적으로 리드·릴리즈 직무에만 있습니다. 앱 자체는 git 이력을 바꾸는 어떤 버튼도 제공하지 않습니다.

**앱을 끄면 작업 내용이 사라지나요?**
스크롤백 · 이벤트 · 대화는 SQLite에 저장되고 재시작하면 화면과 함께 복원됩니다. 에이전트 대화는 페인 메뉴나 세션 상세의 `재개` 한 번으로 이어집니다. 새 버전으로 업데이트하면 워크스페이스 등록과 배치는 남고, 세션 DB는 `session.db.bak`으로 옮겨진 뒤 새로 시작합니다.

**세션이 왜 4개인가요?**
리소스가 아니라 가독성 한계입니다 — 1920×1080에서 2×2 분할이 에이전트 TUI를 읽을 수 있는 한계입니다. 설정에서 6·8개로 늘릴 수 있습니다.

**macOS / Linux는요?**
현재는 Windows 우선입니다 (ConPTY · Job Object · WebView2 기반).
