# EQMUX 0.6.5 macOS 판 릴리스 노트

2026-11-24 · 태그 `v0.6.5-macos` · Windows 판은 [EQMUX 0.6.5](https://github.com/ReDocu/EQMUX/releases/tag/v0.6.5)

## 다운로드

| 운영체제 | 파일 | 비고 |
|---|---|---|
| macOS 11 이상 (Intel·Apple Silicon) | `EQMUX_0.6.5_universal.dmg` | 처음 열 때 [처음 열기](#처음-열기) 절차가 한 번 필요합니다 |

[EQMUX 0.6.4](https://github.com/ReDocu/EQMUX/releases/tag/v0.6.4) 다음 macOS 배포입니다. 0.6.5의 새 기능을 모두 담았습니다. 여기에 macOS에서 찾은 저장소 경계 문제를 더 고쳤습니다. 이 고침은 다음 Windows 판에도 들어갑니다.

Windows 사용자는 [EQMUX 0.6.5](https://github.com/ReDocu/EQMUX/releases/tag/v0.6.5)를 쓰세요.

## 0.6.5에서 새로 생긴 것

자세한 내용은 [0.6.5 릴리스 노트](https://github.com/ReDocu/EQMUX/releases/tag/v0.6.5)에 있습니다.

- **페인 간격:** 설정 › 일반 › 페인 간격에서 0 · 2 · 4 · 8(기본) · 16px 중 고릅니다.
- **옆 페인으로 가기:** 터미널 페인 안에서 **⌘⇧←↑↓→**를 누르면 그 방향의 페인으로 키보드 포커스를 옮깁니다.
- **저장소 경계 — 밖은 읽기만:** 에이전트는 배정된 저장소 밖 파일을 읽을 수 있지만 고칠 수는 없습니다. 셸 명령에 밖 경로가 나오면 읽기 명령일 때만 통과합니다.
- **셸 페인에서 띄운 `claude`에도 경계:** 워크스페이스 폴더에서 연 셸 페인에서 `claude`를 직접 쳐도 같은 경계가 걸립니다.

## macOS 판에서 더 고친 것

### 저장소 경계가 시스템 · 설정 폴더 쓰기도 막습니다

0.6.5는 `/usr/bin/env node`나 `~/.cargo/bin/cargo` 같은 도구 실행을 막지 않으려고, 시스템 폴더와 홈의 점 폴더를 검사에서 뺐습니다. 그런데 이 예외가 쓰기에도 걸렸습니다. 그래서 셸 명령으로 저장소 밖의 `~/.zshrc`, `~/.ssh`, `~/Library`(LaunchAgents · 앱 설정), `/Applications`, `/usr/local`을 고칠 수 있었습니다.

이제 이런 폴더는 프로그램을 **실행할 때만** 봐줍니다. 명령 이름, `source`로 읽는 스크립트, `python` · `node` · `bash`가 돌릴 스크립트 파일이 여기에 들어갑니다. 쓰기 대상(`>`, `rm` · `cp` · `tee`의 인자)이면 사용자가 고칠 수 있는 곳은 막습니다.

### macOS 읽기 도구를 고치는 명령으로 보지 않습니다

`shasum` · `md5` · `mdls` · `xattr -l` · `defaults read` · `plutil -p` · `codesign -d` · `open -R` 같은 읽기 명령으로 저장소 밖 파일을 보면 거부되던 문제를 고쳤습니다. 밖 파일에 `xattr -d`나 그냥 `open`처럼 고치거나 실행하는 명령을 쓰면 그대로 막습니다.

### 경로를 실제 경로로 풀어 비교합니다

- 대소문자만 다르거나, 한글 정규화(NFC · NFD)가 다르거나, `/tmp` 같은 링크를 거친 저장소 안 경로를 밖으로 보던 문제를 고쳤습니다.
- 저장소 안에 있는 링크가 밖을 가리키면 이제 밖으로 봅니다.
- 임시 폴더(`/tmp`, `$TMPDIR`)에 파일을 쓸 수 있습니다. Claude Code가 작업 파일을 두는 곳입니다.

### 셸 페인 `claude`의 경계가 셸 설정에 상관없이 걸립니다

macOS 로그인 셸은 시작할 때 PATH를 다시 짭니다. 그래서 셸 설정이 `claude` 폴더를 PATH 앞에 붙이거나, `claude`가 `/usr/local/bin`에 있으면, 셸 페인에서 친 `claude`에 경계가 조용히 빠질 수 있었습니다.

이제 EQMUX가 셸 시작 파일을 거쳐 zsh · bash를 띄웁니다. 사용자의 `.zshenv` · `.zprofile` · `.zshrc` · `.zlogin`과 `~/.bash_profile`(또는 `~/.profile`)은 그대로 읽습니다. 다 읽은 뒤와 프롬프트마다 경계를 싣는 `claude`를 PATH 맨 앞에 둡니다. `ZDOTDIR`과 셸 기록(`HISTFILE`)도 평소대로 둡니다.

### 그 밖에

- 셸 페인에서 다른 저장소로 `cd`한 뒤 `claude`를 띄우면, 처음 저장소가 아니라 지금 선 저장소를 경계로 씁니다.
- 페인 간격 16px에서 분할선을 잡을 수 있는 폭이 간격 전체로 넓어졌습니다. 전에는 간격 가장자리를 끌면 글자가 선택됐습니다.

## 설치

1. `EQMUX_0.6.5_universal.dmg`를 받습니다. 하나의 파일로 Intel 맥과 Apple Silicon 맥을 모두 지원하고, macOS 11 이상이 필요합니다.
2. dmg를 열고 EQMUX를 응용 프로그램 폴더로 끌어 놓습니다. 0.6.4를 쓰고 있었다면 덮어씁니다. 세션과 설정은 그대로 남습니다.
3. **처음 열 때 한 번** — 아래 [처음 열기](#처음-열기) 절차를 따릅니다.
4. Claude Code가 없다면 앱이 알려 주는 명령으로 설치합니다.
   ```
   curl -fsSL https://claude.ai/install.sh | bash
   ```

받은 파일은 릴리스에 붙은 `SHA256SUMS.txt`와 대조할 수 있습니다.

```
shasum -a 256 ~/Downloads/EQMUX_0.6.5_universal.dmg
```

## 처음 열기

EQMUX는 Apple 공증(notarization)을 받지 않은 앱입니다. 서명은 ad-hoc입니다. 그래서 인터넷에서 받은 EQMUX를 처음 열면, macOS가 Gatekeeper로 실행을 막습니다. 앱이 고장 난 것은 아닙니다. 아래 절차는 처음 한 번만 하면 되고, 그다음부터는 그냥 열립니다.

### macOS 15 Sequoia 이상

macOS 15부터는 예전처럼 Control-클릭(우클릭) › [열기]로 넘어갈 수 없습니다. 시스템 설정에서 허용해야 합니다.

1. 응용 프로그램 폴더의 EQMUX를 더블클릭합니다.
2. **'"EQMUX" 열지 않음'** 창이 뜹니다. 여기서 **[완료]**를 누릅니다.
   - **[휴지통으로 이동]은 누르지 마세요.** 앱이 휴지통으로 갑니다. 이미 눌렀다면 휴지통에서 응용 프로그램 폴더로 다시 옮기세요.
3. **Apple 메뉴  › 시스템 설정 › 개인정보 보호 및 보안**을 엽니다.
4. 오른쪽을 맨 아래 **보안** 항목까지 내립니다. **'"EQMUX"이(가) Mac을 보호하기 위해 차단되었습니다.'** 옆의 **[그래도 열기]**를 누릅니다.
   - 이 문구는 1번에서 한 번 열기를 시도한 뒤 약 1시간 동안만 보입니다. 보이지 않으면 1번부터 다시 하세요.
5. 암호(또는 Touch ID)를 넣습니다.
6. 확인 창이 한 번 더 뜨면 **[그래도 열기]**를 누릅니다. EQMUX가 열립니다.

### macOS 11–14

1. 응용 프로그램 폴더에서 EQMUX를 **Control-클릭(또는 우클릭) › [열기]**를 고릅니다.
2. '확인되지 않은 개발자가 배포했기 때문에…' 창이 뜨면 **[열기]**를 누릅니다.

이 방법이 안 되면 위 macOS 15 절차의 3–6번(시스템 설정 › 개인정보 보호 및 보안 › [그래도 열기])을 따릅니다.

### 터미널로 한 번에 (모든 버전)

받은 파일에 붙은 격리 표시를 지우면, 확인 창 없이 바로 열립니다.

```
xattr -dr com.apple.quarantine /Applications/EQMUX.app
```

앱을 응용 프로그램 폴더가 아닌 곳에 두었다면 경로를 바꿔 주세요.

### 다른 문구가 뜰 때

- **'"EQMUX"이(가) 손상되었기 때문에 열 수 없습니다'**: 다운로드가 깨졌을 수 있습니다. dmg를 다시 받아 위의 체크섬을 확인한 뒤 다시 설치하세요. 그래도 같으면 위의 `xattr` 명령을 실행합니다.
- **dmg에서 바로 실행했을 때 열리지 않거나 저장이 안 될 때**: EQMUX를 응용 프로그램 폴더로 옮긴 뒤 여세요.

## 알려진 한계

- **서명은 ad-hoc이고 공증을 받지 않았습니다.** 그래서 처음 열 때 [처음 열기](#처음-열기) 과정이 필요합니다.
- **저장소 경계가 잡지 못하는 것:**
  - 경로 없이 밖을 고치는 명령(`git config --global`, `defaults write 도메인`, `npm config set`)
  - 스크립트 파일 안에서 하는 쓰기(`node x.js`)
  - fish · sh 셸 페인, 그리고 `command claude`나 전체 경로로 띄운 `claude`
  - Codex 세션에는 경계 훅이 없습니다. 전처럼 Codex 샌드박스와 안내문으로만 지킵니다.
- **입력칸이 따옴표와 대시를 바꿔 적습니다.** macOS의 텍스트 자동 고침 때문입니다. 임무 목표나 git 커밋 메시지에 친 `"`와 `--`가 둥근 따옴표와 긴 대시(`“ ” —`)로 바뀌고, 첫 글자가 대문자가 될 수 있습니다. 시스템 설정 › 키보드 › 텍스트 입력의 [편집…]에서 자동 대문자와 스마트 따옴표·대시를 끄면 피할 수 있습니다. 이 설정은 다른 앱에도 적용됩니다.
- **터미널에서 ⌘A(전체 선택)가 동작하지 않습니다.** 메뉴 막대는 아직 기본 메뉴라 설정(⌘,)이 없습니다. 폴더 선택 창은 영어로 뜹니다.
- **다시 켜면 화면이 일부만 돌아옵니다.**
  - Claude Code 페인의 이전 화면은 재생되지 않습니다. 지난 대화는 트랜스크립트 패널이나 페인에 뜨는 `claude --resume` 안내로 이어 가세요.
  - 기본 터미널은 다시 열리지 않습니다. [▶ 셸 다시 열기]로 엽니다.
- **줄 단위 입력에서 한글을 치면 화면에 빈칸이 남을 수 있습니다.** 셸 스크립트의 `read`처럼 줄 단위로 받는 곳에서 `한글 하나`가 `한 글    하나`처럼 보입니다. 프로그램이 받는 값은 맞습니다.
- **시험 범위:** Intel 맥의 macOS 15에서 확인했습니다. Apple Silicon 맥과 macOS 11–14는 실기로 확인하지 못했습니다.
- 시험 기록과 남은 문제는 [QA 문서](https://github.com/ReDocu/EQMUX/blob/v0.6.5-macos/docs/qa-0.6.5-macos.md)에 있습니다.
