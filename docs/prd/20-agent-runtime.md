## 1. 문제 정의

앱은 PTY에 외부 CLI를 띄울 뿐이고 그 안에서 무슨 일이 일어나는지 모른다. 관제가 제품의 핵심(§1 제품 정의)인데
**관제할 대상의 상태를 모르는 것**이 D가 없을 때의 상태다. 구체적으로 네 가지가 무너진다.

- **상태 미상** — 40세션(10 워크스페이스 × 4)에서 "지금 누가 내 승인을 기다리는가"에 답할 수단이 없다.
  터미널 출력을 눈으로 훑는 것은 4세션에서 이미 실패한다.
- **연속성 부재** — C10=완전 종료라 **재개(D10)가 유일한 연속성 장치**인데, 재개하려면 에이전트의
  세션 식별자를 우리가 알고 있어야 한다. 사후에 추측할 방법은 없다.
- **권한이 규범에 그침** — D5는 역할이 실행 권한을 결정한다고 정했지만, 그 결정을 **실제 실행 플래그로
  번역하는 표**가 없으면 리뷰어와 구현자가 같은 권한으로 뜬다.
- **죽음의 은폐** — 에이전트가 크래시해도 페인은 그냥 조용하다. 사용자는 30분 뒤에 안다.

### D2 확정이 바꾼 것

이 문제는 원래 **터미널 출력을 파싱하는 문제**였다. CLI 3종(Claude · Codex · Gemini)을 지원하려면
프롬프트 패턴 · OSC 133 · 유휴 휴리스틱으로 상태를 추측하는 수밖에 없었고, 추측의 정확도가 관제 품질의
상한이 됐다.

D2=Claude Code 단일 확정으로 이 문제는 **에이전트가 이미 구조화해 내보내는 것을 읽는 문제**로 바뀐다.
Claude Code는 세션 상태를 파일로 기록하고(§10.1), 수명주기 이벤트를 훅으로 밀어주고(§10.2),
대화 전문을 JSONL로 남긴다(§10.3). 추측이 사라지고 파싱만 남는다.

**그 대가는 결합이다.** 셋 다 공개 계약이 아닌 내부 구현이며, 특히 §10.1은 문서화되지 않았다.
이 PRD의 설계 부담 대부분은 그 결합을 어떻게 격리하느냐에 쓰인다(§4.7 · R1).

## 2. 목표 / 비목표

### 목표

1. 에이전트를 **결정론적으로 기동**한다 — 세션 식별자를 앱이 발급하고, 역할이 권한 플래그를 결정한다.
2. 상태를 **출력 파싱 없이** 획득한다.
3. **재개를 보장**한다 (D10 = P0).
4. **사용자의 전역 설정을 오염시키지 않고** 관측 훅을 건다.
5. 크래시·좀비를 감지해 **정직하게 표시**한다. 조용히 실패하지 않는다.
6. Claude 고유 지식을 **한 모듈에 가둔다** — 버전이 깨져도 앱은 살아 있게.

### 비목표

- 자체 AI 루프 · API 키 보유 — D1 · J2
- Claude Code 외 CLI 구현 — D2 (인터페이스만 남기고 구현체는 1종)
- PTY 소유 · 스크롤백 저장 — **PRD C**
- VT 파싱 · 상태 테두리 렌더 — **PRD A · B**
- 역할·임무 도메인 규칙 — **PRD E** (여기서는 `permissions` → 플래그 번역만)
- 메시지 라우팅 · 전달 타이밍 — **PRD F**
- 상태 분류 체계의 **표현**(색·문구·뱃지) — **PRD G** (여기서는 값의 정의만)

## 3. 사용자 시나리오

**S1. 팀 기동**
`시작`을 누르면 4개 페인에 Claude Code가 뜬다. 각 세션은 앱이 미리 발급한 식별자를 갖고 시작하고,
솔(검증·`write:false`)만 승인 게이트가 걸린 모드로 뜬다. 4개 전부 뜨는 데 3초 안쪽이다.

**S2. 병목 발견**
대시보드를 보니 노엘이 12분째 `승인 대기 — Bash(npm publish)`다. 나머지 셋은 작업 중이다.
사용자는 노엘의 셀을 눌러 페인으로 점프하고 거부한다. **터미널을 하나씩 열어보지 않았다.**

**S3. 재부팅 후 복귀**
앱을 다시 켜니 페인 4개에 직전 출력이 재생돼 있고, 넷 다 `재개` 칩이 떠 있다. 카이만 재개한다.
카이는 어제의 대화에 그대로 이어 붙고, 나머지 셋은 빈 셸로 남는다. **아무것도 자동 실행되지 않았다.**

**S4. 역할 변경의 한계**
린을 구현에서 리뷰로 바꾼다. 역할 파일은 즉시 갱신되고 "다시 읽어라" 한 줄이 전달되지만,
쓰기 권한 회수는 실행 플래그라 지금 프로세스에는 적용되지 않는다. 페인에 `재시작 필요` 배지가 뜨고,
사용자가 누르면 대화를 유지한 채(재개) 새 권한으로 다시 뜬다.

**S5. 조용한 죽음**
솔의 프로세스가 크래시한다. 페인 테두리가 즉시 회색으로 바뀌고 `종료됨 (exit 1)`이 표시된다.
자동 재실행은 없다. 재개 칩이 함께 뜬다.

**S6. 사용자 설정 불가침**
사용자가 개인적으로 쓰던 `~/.claude/settings.json`의 훅과 MCP 서버가 EQMUX 세션에서도
그대로 동작한다. 앱은 그 파일에 한 줄도 쓰지 않았다.

## 9. 수용 기준

1. `시작`을 누르면 4세션이 3초 내에 뜨고, 각 세션의 Claude `sessionId`가 **앱이 발급한 UUID와 일치**한다.
2. `write:false`인 세션만 승인 게이트가 걸린 모드로 뜨고, 세션 상세 패널에 실제 플래그가 그대로 표시된다.
3. 한 세션이 승인을 요구하면 **페인을 열지 않고** 대시보드에서 `waiting`과 대기 대상이 보인다.
4. 4세션이 각각 다른 상태(busy · waiting · shell · idle)일 때 대시보드가 네 상태를 정확히 구분한다.
5. 세션 하나를 작업 관리자로 죽이면 5초 내에 `dead`와 exit code가 표시되고, **자동 재실행되지 않는다**.
6. 앱을 강제 종료 후 재실행하면 4세션 모두 `재개` 칩이 뜬다. 하나만 재개하면 그 세션만 이전 대화에 이어 붙고 나머지는 빈 셸이다.
7. 역할의 `permissions`를 바꾸면 `재시작 필요` 배지가 뜨고, 누르면 **대화를 유지한 채** 새 플래그로 다시 뜬다.
8. 세션 실행 전후로 `~/.claude/settings.json`과 repo의 `.claude/`가 **바이트 단위로 동일**하다.
9. 사용자가 미리 설정해 둔 개인 훅이 EQMUX 세션에서도 그대로 실행된다.
10. 앱을 강제 종료해도 실행 중인 에이전트는 정상 동작하고, 앱 재실행 시 다시 상태가 붙는다.
11. 레지스트리 디렉터리를 접근 불가로 만들어도 앱이 죽지 않고 `degraded`로 전환해 busy/idle/waiting/dead를 유지한다.
12. 레지스트리 JSON에 모르는 필드를 넣어도 파싱이 성공하고, `status`를 지우면 훅 경로로 내려간다.

## 10. 실측 근거 — Claude Code 2.1.226

> 이 절의 내용은 **공개 계약이 아니다.** 버전 게이트(FR-D-62)의 기준선이며, R1의 대상이다.

### 10.1 세션 레지스트리 — `~/.claude/sessions/<pid>.json`

살아 있는 세션마다 파일 1개. 상태가 바뀔 때마다 갱신된다.

```json
{"pid":14764,"sessionId":"1cdd7ea4-…","cwd":"C:\\Users\\LEE\\Desktop\\EQMUX",
 "startedAt":1786321235709,"procStart":"1343079483201061 02","version":"2.1.226",
 "kind":"interactive","entrypoint":"cli","name":"eqmux-41","nameSource":"derived",
 "status":"busy","updatedAt":1786333454938,"statusUpdatedAt":1786333454938,
 "bridgeSessionId":"session_01HW…"}
```

스키마에 존재하는 필드 — `pid` `sessionId` `cwd` `startedAt` `procStart` `version` `kind` `entrypoint`
`name` `nameSource` `status` `waitingFor` `logPath` `jobId` `parkedJobId` `bridgeSessionId`
`agent` `state` `detail` `updatedAt` `statusUpdatedAt`.

`status` 값 — `idle` · `busy` · `waiting` · `shell`.
`busy`는 응답 생성 또는 서브에이전트 실행, `waiting`은 다이얼로그 대기(대상이 `waitingFor`),
`shell`은 유휴 상태에서 셸 명령 진행 중.

### 10.2 구독할 훅 이벤트

| 이벤트 | 쓰임 |
|---|---|
| `SessionStart` | 세션↔PID 결합 확정, `source`로 신규/재개 구분 |
| `UserPromptSubmit` | 턴 시작 |
| `PreToolUse` / `PostToolUse` | `activity` 필드 (무슨 도구를 쓰는 중인가) |
| `Notification` | `waiting`의 사유 보강 (`message`) |
| `Stop` | 턴 종료 → M3 메시지 전달 타이밍 |
| `SubagentStart` / `SubagentStop` | 서브에이전트 동시 실행 수 |
| `SessionEnd` | 정상 종료 (`reason`) |

전 이벤트 공통으로 `session_id` · `transcript_path` · `cwd` · `hook_event_name`이 stdin JSON에 들어와
§10.1·§10.3과 같은 키로 결합된다. **`SubagentStart`는 2.1.x에서 추가된 것으로, 서브에이전트 시작을
`PreToolUse` 매처로 우회할 필요가 없다.**

CLI가 선언하는 전체 이벤트 목록에는 위 외에 `PostToolUseFailure` `PostToolBatch` `UserPromptExpansion`
`StopFailure` `PreCompact` `PostCompact` `PermissionRequest` `PermissionDenied` `Setup`
`Elicitation` `ElicitationResult`가 있으나 **구독하지 않는다** (FR-D-37).

### 10.3 트랜스크립트 — `~/.claude/projects/<이스케이프된 cwd>/<session-id>.jsonl`

이스케이프 규칙 — 경로의 `:` 와 `\` 를 각각 `-` 로 치환.
`C:\Users\LEE\Desktop\EQMUX` → `C--Users-LEE-Desktop-EQMUX`

**cwd가 경로에 들어간다.** 이것이 FR-D-03(재개 시 같은 cwd)과 R4의 근거다.

### 10.4 statusLine 채널

`statusLine` 설정의 커맨드는 렌더 시마다 호출되며 stdin으로 `cost.total_cost_usd` ·
`total_duration_ms` · `total_lines_added/removed` · 모델 · 컨텍스트 초과 여부를 받는다.
FR-D-19(P2)의 데이터 원천이며, 하트비트로도 쓸 수 있다.
