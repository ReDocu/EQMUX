## 1. 문제 정의

터미널 4개에 에이전트를 띄우는 것만으로는 팀이 되지 않는다. 역할이 없으면 **네 개의 동일한 에이전트가
같은 저장소를 각자 마음대로 고치는 상태**가 되고, 이는 한 명을 쓰는 것보다 나쁘다.

구체적으로 네 가지가 없다.

- **책임 경계** — 누가 무엇을 맡는지 없으면 같은 파일을 동시에 고치고 서로의 작업을 덮어쓴다
- **권한 차등** — 리뷰어와 구현자가 같은 권한을 가지면 리뷰가 성립하지 않는다
- **판단 성향의 차이** — 넷 다 같은 성향이면 다양성이 없어 팀을 이룰 이유가 없다
- **작업 단위** — "무엇을 하는 중인가"가 없으면 관제할 대상이 없다

동시에 제약이 있다. 우리는 **외부 CLI 에이전트를 실행할 뿐이라 내부를 제어할 수 없다.**
역할을 주는 수단은 파일과 프롬프트와 실행 플래그뿐이다.

## 2. 목표 / 비목표

### 목표

1. git 저장소를 워크스페이스로 **연결하고 목록에서 다시 여는** 흐름을 만든다
2. 4슬롯에 **직무 + 페르소나를 캐스팅**해 팀을 구성한다
3. 역할을 **파일로 영속**시키고, 재시작·재개 후에도 동일하게 복원한다
4. 역할이 **실행 권한 모드를 결정**하게 한다
5. 임무를 정의·배정·해제하고 파일과 UI의 **정합성을 유지**한다
6. 페르소나를 **여러 워크스페이스에서 재사용**할 수 있게 한다

### 비목표

- 에이전트 실행·상태 감지·재개 구현 — **PRD D**
- 에이전트 간 메시지 전달 — **PRD F**
- 대시보드·관계도 렌더링 — **PRD G** (여기서는 데이터 스키마만 정의)
- git 조작 UI — **PRD H**
- 자체 AI로 역할·임무를 생성하는 기능 (D1=외부 CLI 전용)

## 3. 사용자 시나리오

**S1. 새 프로젝트 투입**
`+ 워크스페이스 연결` → 디스크의 git repo 선택 → 편성 프리셋 `표준` 선택 →
4슬롯에 카이(리드) · 노엘(구현) · 린(구현) · 솔(검증)이 자동 배정 →
`시작`을 누르면 4개 터미널에 에이전트가 뜨고 각자 자기 역할 파일을 읽는다.

**S2. 페르소나 재사용**
다른 저장소를 연결하면서 다시 카이를 리드로 캐스팅한다. 카이의 판단 성향은 전역 라이브러리에서
그대로 오고, 책임·관계는 이 워크스페이스 기준으로 새로 만들어진다.

**S3. 역할 변경 — 두 갈래**
린을 구현에서 리뷰로 바꾼다. 역할 파일이 갱신되고 린의 터미널에 "역할이 바뀌었다, 다시 읽어라"
한 줄이 전달된다. 책임·관계·금지는 **세션 재시작 없이** 다음 턴부터 적용된다.
다만 쓰기 권한 회수는 실행 플래그라 지금 프로세스에 적용되지 않는다 — 페인에 `재시작 필요` 배지가 뜨고,
사용자가 누르면 **대화를 유지한 채**(재개) 새 권한으로 다시 뜬다.

**S4. 임무 배정**
`인증 리팩터` 임무를 만들고 노엘·린에게 배정한다. 두 사람의 역할 파일에 임무 블록이 삽입되고,
터미널에 브리프가 전달된다. 카이는 리드라 배정 없이도 임무를 인지한다.

**S5. 권한 경계가 실제로 작동**
솔(검증, 쓰기 권한 없음)이 테스트 파일을 고치려 한다. 자동승인 없이 실행된 상태라
승인 카드가 뜨고 사람이 거부한다. 솔은 대신 카이에게 보고한다.

**S6. 정합성 회복**
앱 밖에서 저장소를 옮겼다. 다시 열면 경로 불일치를 감지해 목록에 `찾을 수 없음`으로 표시하고,
경로 재지정 또는 등록 해제를 제안한다.

```
   ├─ team.json             편성 원본                          ← 커밋
   ├─ team.md               편성표 (파생, 사람·에이전트용)       ← 커밋
   ├─ jobs/ personas/       워크스페이스 오버라이드 (선택)       ← 커밋
   ├─ missions/<임무>.md    임무 정의                          ← 커밋
   ├─ roles/<세션>.md       합성된 역할 + 임무 블록             ← gitignore
   └─ .gitignore            앱이 자동 생성
```

> **이전 모델과의 중요한 차이** — AgentCommender는 `CLAUDE.md`에 임무 블록을 삽입했다.
> 워크스페이스가 repo로 확정된 지금 `CLAUDE.md`는 커밋 대상이므로, 앱이 블록을 넣으면
> **git diff를 오염시킨다.** 임무 블록은 gitignore된 `roles/<세션>.md`로 옮긴다.

## 5. 비기능 요구사항

## 9. 수용 기준

1. git 저장소를 등록하고 목록에서 다시 열 수 있으며, 11번째 동시 오픈은 거부된다.
2. 편성 프리셋을 고르면 4슬롯이 자동 채워지고, `시작` 후 각 터미널에 에이전트가 뜬다.
3. 각 세션의 `.eqmux/roles/<세션>.md`가 생성되고, frontmatter의 `permissions`가 직무 기본값과 일치한다.
4. `write: false`인 세션의 에이전트는 자동승인 없이 실행되고, 파일 수정 시도가 승인 카드로 뜬다.
5. 책임·관계·임무를 변경하면 **세션 재시작 없이** 파일이 갱신되고 안내 한 줄이 전달된다.
5a. `permissions`를 변경하면 파일은 즉시 갱신되고 `재시작 필요` 배지가 뜬다. 누르면 **대화를 유지한 채**
   새 플래그로 다시 뜨고, 누르지 않으면 이전 권한으로 계속 동작한다 (자동 재시작 없음).
6. 같은 페르소나를 두 워크스페이스에 동시 캐스팅해도 충돌하지 않는다.
7. 임무를 배정하면 역할 파일에 임무 블록이 삽입되고, 재배정은 멱등이며, 해제하면 블록만 사라진다.
8. **사용자의 `CLAUDE.md`가 앱에 의해 수정되지 않는다** (git status로 확인).
9. `.eqmux/roles/`가 gitignore되어 `git status`에 나타나지 않는다.
10. `team.json`을 손상시켜도 앱이 죽지 않고 경고와 함께 부분 로드된다.
11. 저장소를 앱 밖에서 옮기면 목록에 `찾을 수 없음`으로 표시되고 재지정을 제안한다.
