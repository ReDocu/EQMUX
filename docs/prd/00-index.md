## 1. 제품 정의

**하나의 git 저장소를 4명의 AI 에이전트 팀이 함께 작업하고, 사람이 그것을 관제하는 데스크톱 앱.**

- **관제가 핵심이다.** 대시보드에서 팀 상태를 보고, 임무를 배정하고, 개입한다
- **터미널 4개가 작업 공간이다.** 실제 일은 각 페인의 에이전트 CLI가 한다
- **에이전트는 외부 CLI를 실행한다. 1차는 Claude Code 하나뿐이다** (D2). 자체 AI 루프는 1차에 없고,
  따라서 앱은 API 키를 보유하지 않는다
- **에이전트 간 대화는 부가 기능이다.** 사이드 패널 탭에서 채팅처럼 읽는다. 메인이 아니다

레퍼런스 5종(Ghostty · Orca · bbarit · Terax · AgentCommender) 중 **팀·직책·관계를 가진 것은
AgentCommender뿐**이고, 그것이 EQMUX의 직계 선행 제품이자 차별 축이다.

## 2. 도메인 모델

```
앱  ─────────────────── 워크스페이스 최대 10개 동시 오픈 (하드)
└─ 워크스페이스 ──────── = git repo 1개 = 팀 1개 = 탭 1개
   ├─ 세션 1~4 ───────── (하드) = 에이전트 1명 = 페인 1개
   │  └─ 역할 ────────── = 직무(job) + 페르소나(persona)
   └─ 임무 ───────────── = repo 안의 작업 단위 (브랜치 + 목표)
```

**불변 규칙**

1. 워크스페이스 · repo · 팀 · 탭은 1:1:1:1이다. 이 덕분에 git · 탐색기 · diff · 프리뷰 · 검색의
   스코프가 하나로 통일된다
2. 세션 상한 4는 리소스가 아니라 **가독성** 때문이다 (1920×1080 기준 2×2는 페인당 28행,
   8분할은 14행 — 에이전트 TUI를 읽을 수 없다)
3. 보조 페인(에디터 · diff · 브라우저)은 **세션 슬롯을 소비하지 않는다**
4. 팀 · 역할 · 임무의 **원본은 파일**이다. DB는 캐시이며 불일치 시 파일이 이긴다

### 2.1 용어 정의 — 화면 어휘 (2026-08-11 확정)

| 용어 | 정의 | 규칙 |
|---|---|---|
| **페인** | 워크스페이스 탭 안의 화면 분할 단위. MUX 표준 계층(창 ⊃ 탭 ⊃ 페인)을 상속 | 유형은 아래 둘뿐 |
| **세션 페인** | 세션(= 에이전트 1명 = PTY)이 소유한 터미널 페인. 세션과 1:1 | 워크스페이스당 최대 4 (B2) · 재개·저장·메모리 계측 규칙의 대상 |
| **보조 페인** | 에디터 · diff · 브라우저 · 트랜스크립트 | **세션이 아니다** — 슬롯 미소비 · 세션 레코드 없음 (불변 규칙 3) |
| **패널** | 사이드 도구 서랍 (git · 포트 · 로그 · 임무 · 대화) | 페인이 아니다 — 분할 그리드 밖에 있다 |

> **"보조세션"이라는 표현은 쓰지 않는다** — 세션의 하드 규칙(상한 4 · 재개 · 세션당 보존 상한 ·
> 메모리 계측)이 보조 페인에 오적용되는 것을 막기 위함. 코드 표현은 `PaneKind = "session" | "aux"`.
