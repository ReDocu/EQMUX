## 3. 이 값의 한계

1. **압력 방향 — 실제 값은 482보다 높을 수 있다.** 시작 여유 3.01 GB는 게이트를 턱걸이로 넘긴 값이고,
   측정 중 80.3 → 82.4%로 올랐다. 판정 **대상** 측정에서 압력은 워킹셋을 잘라 **값을 낮추는(유리한)** 쪽으로
   작용한다. 즉 이 482는 **하한에 가깝다** — 판정 방향(초과)을 뒤집을 수 없는 오차다.
2. **`기타` 48.5 MB의 정체를 이 실행에서 확인하지 못했다.** eqmux·msedgewebview2·셸(pwsh/conhost) 밖의
   자손 프로세스다. 앱 소속이면 판정값이 그만큼 **낮게** 잡힌 것이다 — 이 역시 판정 방향은 안 바뀐다.
   다음 실행 때 하니스가 이름을 찍도록 보강한다.
3. **300초까지 쟀다** — `#6` 규격 10표본이 채워지는 지점. §3.5·§3.6과 같은 한계를 물려받는다.
4. **관제·세션 없는 순수 터미널 4개다.** AgentCommender 기준선(§3.6)도 같은 조건(`mode=terminal`)이라
   비교는 성립한다.
5. 측정 시간대에 라이브 세션 9개가 같은 기계에서 돌고 있었다 — 시작·종료 통지 사이 빌드 동결을 요청했고,
   측정 중 압력 곡선(80.3 → 82.4%)에 급변은 없었다.
