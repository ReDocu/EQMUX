## 0. 전제 — 무엇을 만드는가

**EQMUX는 AgentCommender의 후속작이다. Tauri로 재작성한다.** (팀장님 결정, 2026-08-04)

wmux는 **경쟁 제품**이지 원본이 아니다. 원본은 우리 것이다.

| | AgentCommender (acmux) | EQMUX |
|---|---|---|
| 상태 | v0.1.0 · 운영 중 · **기능 동결** | 신규 |
| 스택 | Electron + React + xterm.js + node-pty | **Tauri 2 + WebView2 + Rust** |
| 코드 | TS/TSX 44파일 · 11,802줄 | — |
| 사양 문서 | 2,760줄 | **계승** |
| 디자인 | `design.pen` (Pencil) | **계승** |

**자산 처리 (팀장님 결정)**
- **사양 계승 + 코드 참조** — 우리 코드이므로 클린룸 제약 없음. `Persona_Spec` `Team_Spec` `Mission_Spec`을 EQMUX 설계서로 승계한다
- **wmux/cmux 소스는 계속 안 본다** — 클린룸 원칙은 남의 코드에만 적용된다
- AgentCommender는 **기능 동결, 유지보수만.** 지금 이 세션들이 그 위에서 돌고 있으므로 죽이지 않는다

## 1. 기준선 — 재작성 대상의 실측값

**기준선은 wmux가 아니라 AgentCommender다.** 우리가 대체하는 건 그쪽이다.

| 항목 | AgentCommender | wmux 0.13.0 | 비고 |
|---|---|---|---|
| 자체 코드 (dist) | **7.3 MB** | — | 우리가 쓴 것 |
| 런타임 (node_modules) | **432.5 MB** | — | Electron |
| 앱 데이터 | ~0 MB | **512 MB** | wmux는 내장 Chromium 캐시 |
| 크래시 덤프 | 0건 | **10건 / 19일** | AgentCommender가 더 안정적 |
| 세션당 자동 로드 | **≈450 토큰** | — | CLAUDE.md (관리 블록 2종) |

### 이 표에서 읽어야 할 한 줄

> **우리가 쓴 코드는 7.3MB다. 런타임이 432MB다.**

최적화 대상은 우리 코드가 아니다. **런타임이다.** Tauri로 가면 배포물이 ~10MB가 된다 —
Windows 11이 WebView2를 이미 갖고 있어서 브라우저 엔진을 안 싣기 때문이다.

**즉 "성능 최적화"는 코드를 다듬는 일이 아니라 런타임을 바꾸는 단 한 번의 결정이다.**
그 결정은 이미 내렸다. 나머지는 그걸 망치지 않는 일이다.

> AgentCommender는 wmux보다 이미 안정적이다(크래시 0건 vs 10건).
> **재작성의 명분은 "불안정해서"가 아니라 "무거워서"다.** 이 구분을 흐리면 안 된다 —
> 흐리면 안정성을 깎아 먹으면서 재작성하게 된다.

## 2. 철학 — 검증 가능한 형태로

팀장님이 주신 5개를 **지킬 수 있는 규칙**으로 옮겼다. 지표가 없는 철학은 구호다.

### 철학 1. 기능은 토큰0 ⭐

> **앱의 기능이 늘어도, 세션이 자동으로 읽는 토큰은 늘지 않는다.**

지금 세션 하나가 시작할 때마다 `CLAUDE.md` **≈450 토큰**을 자동으로 읽는다.
여기에 팀 관계가 붙고, 스킬 목록이 붙고, MCP 목록이 붙으면 순식간에 2,000 토큰이 된다.
**세션 8개면 매 시작마다 16,000 토큰이다.** 아무도 안 쓰는 정보에.

| 규칙 | 내용 |
|---|---|
| R1 | 세션에 정보를 전달해야 하는 기능은 **CLAUDE.md 블록이 아니라 CLI로 조회**하게 만든다 |
| R2 | 자동 로드 층에는 **"무엇이 있는지"만**, 내용은 **"물어보면"** 준다 |
| R3 | 새 기능 PR은 CLAUDE.md 바이트 증가분을 보고한다 |

**지표: 기능 수와 무관하게 세션당 자동 로드 ≤ 500 토큰 고정**

> AgentCommender의 페르소나 3계층 구조(`CLAUDE.md 5줄 → PERSONA.md 20줄 → detail/ 무제한`)가
> 이미 이 철학의 구현체다. **계승하고 전 기능으로 확장한다.**

### 철학 2. 터미널 UI/UX 편의성 최대화

> **터미널로서 먼저 훌륭하다. 에이전트 기능은 그 위에 얹는다.**

| 규칙 | 내용 |
|---|---|
| R4 | 에이전트 기능이 터미널 기본기를 방해하면 **에이전트 쪽이 양보한다** |
| R5 | 마우스 없이 전 기능에 도달 가능하다 |
| R6 | 한국어 입력이 1급 시민이다 (IME·CJK 폭) |

**지표: 터미널 모드만 켜고 하루 8시간 일할 수 있다**

### 철학 3. GIT 연결성

> **git 상태가 항상 보이고, git 작업이 앱을 떠나지 않는다.**

AgentCommender 현재: 팀 폴더 2단계 내 `.git/config` origin 감지, git 주소 연결.
확장 방향: 브랜치 · dirty · ahead/behind · **워크트리**.

> **워크트리를 제안합니다.** 에이전트를 여러 개 병렬로 돌릴 때 가장 큰 문제는
> 같은 저장소를 동시에 건드리는 것입니다. `git worktree`로 에이전트마다 독립 작업본을 주면
> 충돌이 구조적으로 사라집니다. **"멀티플렉서 + 에이전트"의 진짜 알맹이가 여기 있다고 봅니다.**
> 다만 이건 제 제안이지 팀장님 지시가 아니므로 4차 범위로만 적어 둡니다.

**지표: 브랜치 확인·전환·상태 파악에 터미널 명령을 치지 않아도 된다**

### 철학 4. 멀티플렉서 연계

> **외부에서 EQMUX를 조작할 수 있고, EQMUX가 외부를 조작할 수 있다.**

AgentCommender의 `acmux` CLI(named pipe)가 출발점이다.

| 규칙 | 내용 |
|---|---|
| R7 | 앱이 하는 일은 **전부 CLI로도 할 수 있다** (UI 전용 기능을 만들지 않는다) |
| R8 | 프로토콜은 **하나**만 쓴다 (JSON-RPC). 텍스트/JSON 이중화는 부채다 |
| R9 | 명령 이름과 인자는 v0.2에 확정하고 **이후 하위 호환을 지킨다** |

**지표: 에이전트가 자기 작업 환경을 스스로 구성할 수 있다**

> ⚠️ **확인 필요.** "멀티플렉서 연계"를 (a) *CLI/IPC로 외부·에이전트와 연계*로 읽었습니다.
> (b) *tmux 등 기존 멀티플렉서와 연동*을 뜻하신 거라면 설계가 달라집니다. 알려주십시오.
> 그 전까지는 (a)로 진행합니다 — AgentCommender의 `acmux` 확장선이라 되돌리기 쉽습니다.

### 철학 5. 성능 최적화

> **측정하지 않은 것은 최적화하지 않는다.**

| 규칙 | 내용 |
|---|---|
| R10 | 상한은 **코드에 박는다.** "관리하겠다"가 아니라 "구조적으로 못 넘는다" |
| R11 | 성능 목표 미달이면 **기능을 자른다.** 목표를 낮추지 않는다 |

**지표: 배포물 ≤ 40MB · 콜드 스타트 ≤ 1.5초 · 키 입력 p99 ≤ 16ms · 14일 무크래시**

## 3. 모드 3개 — 그리고 1·2차가 왜 여기 들어가나

팀장님이 정하신 세 모드:

| 모드 | 정의 | 규약 파일 | AgentCommender 현황 |
|---|---|---|---|
| **터미널 모드** | 순수 터미널. 사용자가 직접 관리 | 없음 | 구현됨 (`TeamMode: terminal`) |
| **페르소나 개인모드** | 세션 1개 = 인격 1개 | `CLAUDE.md` + `Persona/` | 구현됨 (`TeamMode: persona`) |
| **페르소나 팀모드** | 세션 여러 개 = 편성 + 관계 | + `team.json` · `TEAM.md` | **오늘 커밋됨** (`Team_Spec`) |

### 여기서 나온 것

**팀장님의 1차·2차는 세 모드 중 첫 번째를 두 단계로 쪼갠 것입니다.**

- 1차 "wmux 터미널 클론" = 터미널 모드를 **만든다**
- 2차 "터미널 모드 기능 + 세팅" = 터미널 모드를 **쓸 만하게 한다**

그러면 나머지가 자연스럽게 따라옵니다:

```
1차 ─┐
     ├─ 터미널 모드
2차 ─┘
3차 ─── 페르소나 개인모드
4차 ─── 페르소나 팀모드
5차 ─── 공개 배포
```

**모드가 곧 로드맵입니다.** 억지로 맞춘 게 아니라 팀장님이 정하신 두 구조가 원래 같은 것이었습니다.

## 4. 단계별 목적

날짜는 없습니다(팀장님 확인). **관문 통과로만 넘어갑니다.**

### 1차 — 터미널 모드를 만든다

> **목적: 페르소나도 에이전트도 없이, 순수 터미널로서 AgentCommender를 대체한다.**

이 단계에 차별점은 없다. **동등성이 목표다.**

| | |
|---|---|
| **성공 판정** | 팀이 EQMUX 터미널 모드로 2주 일하고 **AgentCommender로 돌아가지 않는다** |
| **범위** | 터미널 코어(A) · 멀티플렉싱(B) · 최소 세션 영속 · `config.toml` |
| **제외** | 페르소나 · 팀 · 임무 · 에이전트 · 알림 · 셸 통합 심화 |
| **관문** | ① 한글 입력 ② CJK 폭(`┌─┐` 안 깨짐) ③ 키 입력 p99 ≤ 16ms ④ 유휴 RAM 실측 |

**왜 "돌아가지 않는다"로 판정하는가.** 클론의 함정은 *80% 비슷한데 못 쓰는 것*입니다.
터미널은 매일 8시간 쓰는 도구라 결함 하나가 치명적입니다 — 한글이 안 쳐지거나, 복사가 안 되거나.
기능 체크리스트를 100% 채워도 사람이 옛날 앱을 켜면 실패입니다. **행동이 유일한 진짜 검증입니다.**

### 2차 — 터미널 모드를 쓸 만하게 한다

> **목적: 설정을 안 건드려도 쓸 만하고, 건드리면 내 것이 된다.**

1차가 *"쓸 수 있다"*라면 2차는 *"쓰고 싶다"*입니다.

| | |
|---|---|
| **성공 판정** | ① 설정 파일을 한 번도 안 열고 30분 쓸 수 있다 ② 열면 원하는 대로 바뀐다 |
| **범위** | 셸 통합(C) · **GIT 연결성** · 설정 체계(`config.toml`) · 단축키 · 테마 2종 · 알림 기반 |
| **제외** | 페르소나 · 팀 · 임무 |
| **관문** | 팀 외부 1명이 설치해서 안내 없이 터미널로 쓸 수 있다 |

**철학 3(GIT 연결성)이 실현되는 단계입니다.** 브랜치·dirty·ahead/behind가 항상 보이는 것.

### 3차 — 페르소나 개인모드 (개요)

> **목적: 세션 하나에 인격 하나를 심고, 그 인격이 성장한다.**

`_personas/` 라이브러리 → 세션 `Persona/` 심기. 3계층 토큰 구조. `memories/` 성장 영역.
**AgentCommender `Persona_Spec.md`를 설계서로 승계** — 새로 설계하지 않습니다.
**철학 1(토큰0)의 시험대**입니다. 여기서 자동 로드 층이 부풀면 원칙이 무너집니다.

### 4차 — 페르소나 팀모드 (개요)

> **목적: 여러 인격이 관계를 갖고 한 임무를 함께 한다.**

팀 편성 · 관계 4종(보고·지도·리뷰·협업) · `TEAM.md` · 임무 배정.
**`Team_Spec.md` · `Mission_Spec.md` 승계.** 여기서 워크트리(철학 3)를 검토합니다.

### 5차 — 공개 배포 (개요)

> **목적: 남이 설치해서 쓸 수 있다.**

코드 서명 · SmartScreen · 포터블 zip · 라이선스 확정 · 문서.
**기능이 하나도 안 늘어나는데 시간은 제일 많이 먹는 단계입니다.**
