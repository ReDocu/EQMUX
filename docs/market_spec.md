## 1. 포지셔닝

| 항목 | 내용 |
|---|---|
| **한 줄 정의** | 하나의 git 저장소를 AI 에이전트 팀이 함께 작업하고, 사람이 그것을 관제하는 Windows 데스크톱 앱 |
| **카테고리** | 터미널 멀티플렉서 + 에이전트 팀 관제 (agent team command center) |
| **타깃** | Claude Code 등 에이전트 CLI를 이미 쓰는 개발자 중, 세션을 2개 이상 병렬로 돌리며 한계를 느낀 사람 |
| **핵심 차별점** | ① 팀(직무·페르소나·임무) 개념이 있는 유일한 축 ② 자동 실행 없음·API 키 미보유라는 **신뢰 설계** ③ 파일이 원본(`.eqmux/` 커밋 가능) — 팀 구성이 repo와 함께 이동 |
| **톤앤매너** | 단정적·기술적·과장 없음. 명령형 헤드라인("관제하라"). 터미널 감성(모노스페이스·다크) 유지 |

### 경쟁 구도에서의 위치

- 일반 터미널 멀티플렉서(tmux·Ghostty 등) — 페인은 있지만 **팀·상태·임무가 없다**
- 에이전트 매니저류 — 세션 목록은 있지만 **터미널이 1급 작업 공간이 아니다**
- EQMUX — 둘을 합치고, 사람의 **개입 지점**(waiting 알림·승인·재개)을 제품의 중심에 둔다

### ② 문제 제기

- **헤드라인**: `터미널 4개를 알트탭으로 관제할 수는 없다`
- **본문**: `에이전트 CLI는 이미 훌륭하게 일합니다. 문제는 사람 쪽입니다 — 누가 승인을 기다리는지, 누가 죽었는지, 누가 무엇을 하고 있는지를 창 4개를 오가며 눈으로 쫓아야 합니다. EQMUX는 그 관제 업무를 화면 하나로 옮깁니다.`
- **포인트 3개**:
  - `승인 대기를 놓친다` → waiting 진입 즉시 OS 알림
  - `죽은 세션을 늦게 발견한다` → dead 감지 + 재개 제안
  - `누가 뭘 하는지 모른다` → 상태·활동·서브에이전트·비용 실측 표시

### ③-1 관제 대시보드 — "보고, 배정하고, 개입한다"

- **본문**: `워크스페이스×세션 그리드가 주의가 필요한 순서로 정렬됩니다. 색은 waiting과 dead에만 씁니다 — 눈이 갈 곳에만 갑니다. 셀 클릭 한 번으로 해당 터미널로 점프하고, 죽은 세션은 대화를 이어서 재개합니다.`
- **불릿**: 상태 6종 실시간 스트림 · OS 알림 2종(포커스 시 억제·60초 합침) · 이벤트 피드 3단 스코프 · 실행 중 에이전트 CLI 감지 배지(Claude·Codex·Gemini)
- **이미지**: `docs/screenshots/readme/dashboard.png`

### ③-2 터미널 워크스페이스 — "터미널이 작업 공간이다"

- **본문**: `EQMUX는 에이전트를 감싸는 채팅 UI가 아닙니다. 페인마다 진짜 터미널(ConPTY)이 있고, 실제 일은 거기서 벌어집니다. 배치 6종, 분할선 드래그, 줌, 터미널 내 검색까지 — 멀티플렉서로서도 부족함이 없습니다.`
- **불릿**: 셸 4종 선택 · Ctrl+F 검색 · 링크 감지 · 클립보드/드래그 앤 드롭 · 상태 테두리 · 스크롤백 디스크 페이징
- **이미지**: `docs/screenshots/promo/terminal.png` (또는 `readme/workspace.png`)

### ③-3 팀 캐스팅 — "직무와 페르소나로 팀을 만든다"

- **본문**: `리드·기획·개발·디자인·QA·디버거·문서·릴리즈 — 고정 직무 8종이 책임과 권한(write/commit/push)을 정하고, 페르소나가 판단 성향을 정합니다. 프리셋 하나로 4슬롯 캐스팅이 끝나고, 결과는 .eqmux/ 파일로 저장되어 repo와 함께 커밋됩니다.`
- **불릿**: 편성 프리셋 4종 · 페르소나 3단계(판단 힌트→말투·성격→캐릭터 시트) · 슬롯 권한 오버라이드 · push는 리드·릴리즈만
- **이미지**: `docs/screenshots/readme/casting.png`

### ③-4 대화와 임무 — "에이전트끼리 말하게 하라"

- **본문**: `에이전트 간 메시지는 다섯 타입(ask·handoff·report·review·escalate)이 강제됩니다 — 잡담이 아니라 업무 전달입니다. 작업 중인 세션에는 턴이 끝난 뒤에 전달되어 흐름을 끊지 않습니다. 사람도 @멘션으로 같은 스트림에 참여합니다.`
- **불릿**: 임무 = 브랜치 + 목표(`missions/*.md`) · 기본 임무 자동 배정 · `eqmux send`/`report` CLI · 발신 상한(분당 10건)
- **이미지**: `docs/screenshots/readme/conversation.png`

### ③-5 검토 — "에이전트가 만든 변경을 사람이 검토한다"

- **본문**: `git 패널에서 브랜치·워크트리·커밋을 보고, diff 뷰어에서 HEAD와 워크트리를 나란히 비교합니다. 세션마다 워크트리를 격리하면 에이전트끼리 작업이 섞이지 않습니다. 단, commit과 push는 앱이 대신 눌러주지 않습니다 — 실행은 언제나 터미널에서 사람이 합니다.`
- **불릿**: 커밋 diff(부모↔커밋) · 워크트리 생성/attach · 파일 탐색기 + CodeMirror 에디터(충돌 감지) · 트랜스크립트 턴 열람
- **이미지**: `docs/screenshots/readme/gitdiff.png`

### ③-6 영속성 — "꺼도 사라지지 않는다"

- **본문**: `스크롤백은 SQLite에 색까지 저장되고, 재시작하면 마지막 500줄이 재생됩니다. 자동으로 되살리지는 않습니다 — 재개할지, 새로 시작할지, 셸로 둘지는 카드에서 사람이 고릅니다. 렌더러가 죽어도 세션은 Rust가 쥐고 있어 그대로 이어집니다.`
- **불릿**: 전문 검색(FTS) · 재개 제안 카드 · 비정상 종료 복구 · Job Object로 고아 프로세스 0
- **이미지**: 별도 없음 (아이콘/다이어그램 권장 — §5 추가 자산)

### ④ 신뢰 원칙 — "하지 않는 것이 곧 설계다"

> 이 섹션이 EQMUX의 가장 강한 차별화 메시지입니다. 감추지 말고 전면에 내세웁니다.

- **인트로**: `에이전트에게 repo를 맡기는 도구는, 무엇을 할 수 있는지보다 무엇을 하지 않는지가 중요합니다.`
- **원칙 카드 6개**:
  1. `API 키를 보유하지 않는다` — 자체 AI 루프 없음. 인증은 사용자의 CLI 몫
  2. `아무것도 자동 실행하지 않는다` — 재시작 후에도 자동 재개 대신 재개 제안
  3. `git 이력을 조작하지 않는다` — commit·push 버튼은 명령을 복사할 뿐
  4. `승인을 대신 누르지 않는다` — 에이전트 TUI에 키를 주입하지 않는다
  5. `사용자 설정을 건드리지 않는다` — CLAUDE.md·~/.claude 불가침
  6. `파일이 원본이다` — 팀·역할·임무는 .eqmux/ 파일. DB는 캐시일 뿐

### ⑥ FAQ

1. **Q. API 키를 넣어야 하나요?**
   A. 아니요. EQMUX는 API 키를 보유하지 않습니다. 이미 로그인된 Claude Code CLI를 실행할 뿐이고, 인증과 과금은 전부 CLI 쪽에서 일어납니다.
2. **Q. Claude Code가 꼭 필요한가요?**
   A. 에이전트 세션 기능(상태 감지·재개·역할 전달)은 1차로 Claude Code를 지원합니다. 다만 모든 세션은 일반 셸로도 쓸 수 있고, 터미널에서 직접 띄운 Codex·Gemini 등 다른 CLI도 관제 대시보드가 감지해 표시합니다.
3. **Q. 에이전트가 마음대로 커밋하거나 push하지 않나요?**
   A. 실행 권한(write/commit/push)은 직무별로 역할 파일에 명시되고, 에이전트 실행 플래그로 강제됩니다. push 권한은 기본적으로 리드·릴리즈 직무에만 있습니다. 앱 자체는 git 이력을 조작하는 어떤 버튼도 제공하지 않습니다.
4. **Q. 앱을 끄면 작업 내용이 사라지나요?**
   A. 스크롤백·이벤트·대화는 SQLite에 저장되고, 재시작하면 마지막 화면과 함께 복원됩니다. 에이전트 대화는 재개 제안 카드에서 한 번의 클릭으로 이어집니다.
5. **Q. 세션이 왜 4개인가요?**
   A. 리소스가 아니라 가독성 한계입니다 — 1920×1080에서 2×2 분할이 에이전트 TUI를 읽을 수 있는 한계입니다. 설정에서 6·8개로 늘릴 수 있습니다.
6. **Q. macOS / Linux는요?**
   A. 현재는 Windows 우선입니다 (ConPTY·Job Object·WebView2 기반).

## 7. 카피 작성 원칙 (금지 사항)

1. **과장 금지** — "알아서 다 해준다", "완전 자동" 류 문구 금지. 제품 철학(자동 실행 없음)과 정면 충돌한다.
2. **타사 상표** — "Claude Code"는 요구 사항·호환성 맥락에서만 사실 서술로 사용. 제휴·보증을 암시하는 배치(로고 병렬 등) 금지.
3. **미확정 사항 표기 금지** — 가격, 자동 업데이트, macOS 지원, MCP 연동은 확정 전까지 싣지 않는다. 로드맵 섹션도 1차 출시 페이지에는 두지 않는다.
4. **수치는 실측만** — 세션 수·상한·저장 정책 등 수치는 기능 명세와 일치해야 한다. 마케팅용 반올림 금지.
5. **데모 표기** — 스크린샷·영상에는 "데모 데이터" 부기를 유지한다.
