# EQMUX 0.5.1 범위 정리 — 0.5.0에서 남은 것 · 0.6 이후 목록 재분류 · VT 서버 모델 검토

2026-10-15 · 근거 `docs/update-plan-0.5.0.md` · `docs/update-0.5.0-status.md` · `docs/fix-0.5.0-qa-status.md` · `docs/prd/12-session-store.md`

## 요약

- 0.5.0 기획 범위(P0 13 · P1 24 · 요청 기능 6 · UX 기반 · 주의 고리 · 메뉴 정리 · 바로 가기)는 모두 코드에 들어갔다. 남은 것은 P2 4건, 실기 미확인 항목, 알려진 한계다.
- 기획서가 "0.6 이후"로 미룬 18줄을 0.5.1로 당길 수 있는지 다시 나눴다. **선행 조건 없이 바로 할 수 있는 것**, **결정이 먼저 필요한 것**, **0.5.1에 넣으면 위험한 것** 셋으로 갈린다.
- VT 서버 모델은 Rust 백엔드 대부분을 데몬으로 옮기는 일이라 0.5.1 패치에 넣지 않는다. "앱을 닫아도 에이전트가 안 죽는 것"은 **트레이로 숨기기**로 먼저 얻는다.

## 1. 0.5.0에서 남은 것

### P2 중 안 했거나 일부만 한 것

| 항목 | 상태 | 이유 |
|---|---|---|
| A12 종료 경로 `thread::sleep` → `tokio::time::sleep` | 안 함 | tokio 직접 의존을 늘릴 가치가 없다 (`job.rs:309` 등 그대로) |
| C9 대화 탭 이름 찾기 메모 | 안 함 | 효과가 작다 |
| A2 OS 알림 토스트 클릭 → 페인 | 코드만 있음 | 설치본에서 눌러 확인해야 한다. 안 되면 0.6 |
| 임무 산출물 체크리스트 | 일부 | 앱 안 체크 토글이 없다. 체크는 임무 파일을 고친다 |

### 기획서와 다르게 간 것

9건. `@이름` 해석을 자기 프로젝트 먼저로, 직함 없는 역할 파일에도 `## 팀 통신` 섹션, 새로 시작의 요약을 시작 안내문 끝에, 넣기 팝오버를 작은 다이얼로그로, 기본 터미널 이름을 같은 슬롯 재생성 때 복원 등. 전체는 `docs/update-0.5.0-status.md` §기획서와 다르게 간 것.

### 실기 미확인

- 한국어 IME(H4 · B98), DE 자판 AltGr(B81)
- 에이전트 4명이 장시간 일할 때 UI 멈춤 여부(짧은 부하만 확인)
- 창이 다른 앱 뒤에 있을 때의 OS 알림
- Codex 엔진 전환·미설치(B82 · B85), 서버 탭 `npm run dev`(B77)
- B83 · B90 · B92 · B93 · B94 · B110 · U66

### 알려진 한계와 미결정

| 항목 | 내용 |
|---|---|
| Codex `--dangerously-bypass-hook-trust` | 0.4.2부터 사용. 유지 여부 미결정 |
| P26 자동 승인 | `eqmux`가 아닌 명령과 섞인 복합 명령은 여전히 승인을 묻는다 |
| U59 | `eqmux browser` 결과 문구와 세션 시작 역할 컨텍스트는 한국어만 |
| B93 | 대기 브리프는 앱 메모리에만 있어 재시작 때 사라진다 |
| **사용자 앱 데이터 소실** | QA 중 등록·워크스페이스 폴더가 두 번 사라졌다. 원인 미상 — 가장 무거운 남은 문제 |

## 2. "0.6 이후" 목록 재분류

기획서의 0.6 이후 18줄을 0.5.1로 당길 수 있는지로 다시 나눴다. 이미 0.5.x로 잡힌 13건(멈춘 세션 표시, `eqmux read`, 한도·컨텍스트 배지, 확장 탭 MCP·플러그인·스킬 등)은 그대로 0.5.1 후보다.

### 2-1. 바로 0.5.1에 넣을 수 있다 — 코드만 있으면 된다

| 항목 | 메모 |
|---|---|
| 직함으로 수신자 지정(`--to @클라이언트개발자`), 직함별 담당 경로 | `ipc.rs` 수신자 해석에 직함 매칭 추가 |
| 메시지 회신 연결 `--re <id>`, `eqmux send --wait`, 임무 의존성 `depends_on` | 완료 신호의 열린 handoff 추적 위에 얹는다 |
| 대화 탭 임무 필터 | 기존 필터 칩에 하나 더 |
| 승인·결정 게이트 대시보드 버튼, `escalate` 심각도, 상태 판정 근거 보기 | 0.5 알림 센터 화면에 붙인다 |
| Jump 팔레트, diff 줄 코멘트 → `review`, 과거 세션 검색·재개, 서브에이전트 목록 | 새 화면이지만 독립적이다. 단축키 표와 함께 설계 |
| 파일 탐색기를 코드 그룹 `[git \| 파일 \| 문서]`로 | §결정 21. 임무 팝업에서 옮긴다 |
| CLI 버전 범위 검증, 레지스트리 stale 판정 | 작다 |
| OS 종료·로그오프 시 종료 절차 | `WM_QUERYENDSESSION` 처리. 재현 환경 필요 |
| 워크트리 준비·`.env` 복사, 세션별 포트 범위 | 서버 탭과 함께 |
| DB 손상 복구, 전역 2GB 보존 상한 | 저장 계층 묶음. 결정 1(b)로 `.bak` 이전은 이미 있다 |
| CLI 세션 원격 입력, 파이프 프로토콜 버전 협상 | 외부 인터페이스. VT 서버 모델을 하면 협상은 어차피 필수 |

### 2-2. 결정이 먼저 필요하다

| 항목 | 정할 것 |
|---|---|
| 조용한 메시지 타입(`report`·`review`가 유휴 수신자를 깨우지 않음) | `report --done`이 맡긴 팀원을 깨우는 0.5 동작과 충돌한다. `review`만 조용하게 할지 |
| Codex 샌드박스 실패 시 대체 경로 | bypass를 쓰지 않는다는 권한 원칙을 풀지 |
| 시크릿 차단 · 인가 · 텔레메트리 | 무엇을 막고 무엇을 보낼지 정책. **로그 마스킹만 떼면 바로 가능** |
| 주입 에코 확인·재시도, Stop 훅으로 인박스 넘기기 | 0.5.x 주입 결과 로그로 실패 빈도를 재지 않고 바로 넣을지 |

### 2-3. 0.5.1에 넣으면 위험하다 — 0.6

| 항목 | 이유 |
|---|---|
| **VT 서버 모델**(앱을 꺼도 세션 유지) | 아래 §3. 0.5.0 전체와 맞먹는 규모 |
| 명령 기록·셸 통합(OSC 133), 피드 → 스크롤백 점프 | VT 서버 없이도 가능하지만, VT 서버를 하면 다시 만든다 |
| **코드 서명 · 자동 업데이트** · WebView2 오프라인 번들 | 클라우드 서명 계정과 CI가 필요하다. 계정이 준비되면 0.5.1로 당길 수 있다 |
| 전역 방송 구독 분리, 도메인별 tick | 모든 화면을 건드리는 리팩터. 패치에서 회귀 위험이 크다 |
| EQMUX 자체 MCP 서버 · 플러그인 체계 | 별도 기획이 필요한 크기 |

## 3. VT 서버 모델 검토

### 지금

- Tauri 앱의 Rust 백엔드가 ConPTY를 직접 소유한다(`lib.rs`의 `portable_pty`).
- 세션마다 Job Object를 `KILL_ON_JOB_CLOSE`로 건다(`job.rs:42`). 앱이 꺼지면 에이전트 트리가 함께 죽는다.
- 다시 켜면 스크롤백 500줄을 재생하고 `claude --resume` 재개를 제안한다.
- PRD 12 C1(데몬 분리 안 함, 앱 내장)과 C10(완전 종료 + 확인창)의 결과다.

### 바뀌는 구조

```
[eqmux-server (상주)]  ConPTY · Job Object · 세션마다 헤드리스 VT 화면
        ↑ 명명 파이프
[EQMUX 앱 (클라이언트)]   [eqmux CLI]   (나중에 원격·모바일)
```

데몬이 세션마다 VT 에뮬레이터를 돌려 화면 상태를 쥔다. 앱은 붙을 때 `snapshot`(화면 전체 + 커서)을 받고 이후 프레임을 스트림으로 받는다. PRD 12 §7.1의 `snapshot(id)`가 이것이다.

### 얻는 것

- 앱을 닫거나 앱·웹뷰가 죽어도 에이전트가 계속 일한다. 하던 턴이 끊기지 않는다.
- 다시 열면 재생이 아니라 화면 그대로다. 재개가 필요 없고 컨텍스트를 다시 읽는 토큰도 들지 않는다.
- 앱만 업데이트할 때 세션이 산다(데몬은 그대로라는 전제).
- `eqmux attach`, 원격·모바일 클라이언트의 바탕이 된다(Paseo · wmux 방식).

### 바뀌어야 하는 것

1. **Rust 백엔드 대부분이 데몬으로 간다.** 앱이 꺼져 있어도 메시지 전달·유휴 주입·상태 감지·원장·알림이 돌아야 하기 때문이다. `agent.rs` · `messages.rs` · `ipc.rs` · `store.rs` · `job.rs` · `ports.rs`. 지금 Rust는 약 1.5만 줄이다.
2. **Tauri 명령이 전부 파이프 프로토콜로 바뀐다.** 프런트 `invoke` 층을 다시 깔고, 앱·데몬 버전 불일치에 대비한 프로토콜 버전 협상이 필수다.
3. **세션마다 VT 화면을 쥐는 메모리.** 8세션 × 화면 + 스크롤백.
4. **데몬 수명 관리.** 자동 기동, 사용자당 하나, "앱만 닫기 / 전부 종료" 종료 메뉴, 트레이 표시.
5. **앱이 꺼진 동안의 OS 알림**은 데몬이 직접 띄운다.
6. 데몬 자체를 업데이트하면 결국 세션이 죽는다. "데몬 갱신은 나중에" 흐름이 필요하다.

### 한계와 원칙 충돌

- **Windows에서는 로그오프·재부팅 때 데몬도 죽는다.** 그때는 지금처럼 재개한다. 앱을 껐다 켜는 경우만 산다.
- 사람은 앱을 껐다고 생각하는데 acceptEdits 에이전트가 계속 파일을 고치고 토큰을 쓴다. C10이 완전 종료를 고른 이유다. "백그라운드에서 N개 실행 중" 표시가 필수다.
- 기능마다 앱이 붙은 상태 / 떨어진 상태 두 경우를 테스트해야 한다. QA 부담이 두 배쯤 된다.

### 권장

- **0.5.1: 트레이로 숨기기.** 창을 닫으면 프로세스는 남고 Job Object가 닫히지 않아 에이전트가 산다. 트레이 아이콘·닫기 동작·종료 메뉴 정도의 작은 변경이고, PRD 12 R5가 "후방 호환으로 추가 가능"으로 남겨 둔 선택지다. 앱 크래시·업데이트 때는 지금처럼 죽는다.
- **0.6 첫 안건: VT 서버 모델.** 크래시·업데이트까지 살려야 하면 그때 간다. 보안은 Paseo 설계(루프백 기본, 페어링 = 공개키)를 참고한다.

## 4. 0.5.1 권장 범위

1. 0.5.x로 잡아 둔 13건
2. §2-1 바로 넣을 수 있는 것

5. §1의 사용자 앱 데이터 소실 원인 조사 — 범위와 별개로 먼저
