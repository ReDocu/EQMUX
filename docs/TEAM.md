# EQMUX 멀티에이전트 개발팀 구성

> 이 문서는 EQMUX 프로젝트에서 실제로 호출 가능한 에이전트·스킬·외부 도구를 정리한 것입니다.
> 가상의 페르소나가 아니라 실제 동원 가능한 리소스 목록입니다.
>
> 각 리소스를 캐릭터로 의인화해 "누가 뭘 잘하는지" 익히는 학습 자료는
> [AGENT-PERSONA-GUIDE.md](./AGENT-PERSONA-GUIDE.md) 를 참고하세요.

---

## 1. 메인 (Opus 5)

오케스트레이터 겸 실제 구현 담당.

- 코드 작성/수정, 파일 탐색, 셸 실행, git 작업을 직접 수행
- 아래 팀원들을 언제 어떻게 투입할지 결정
- 기본적으로 단독 처리하며, 병렬화가 확실히 이득일 때만 팀을 펼침

## 2. 서브에이전트 (독립 컨텍스트로 병렬 실행)

| 에이전트 | 역할 | 투입 시점 |
|---|---|---|
| **Explore** | 읽기 전용 탐색 전문. 파일·디렉토리를 넓게 훑어서 "어디에 뭐가 있는지"만 추출 | 코드베이스가 커져서 검색 범위가 넓을 때 |
| **Plan** | 소프트웨어 아키텍트. 구현 전략, 단계별 계획, 핵심 파일 식별, 설계 트레이드오프 | 착수 전 설계가 필요할 때 |
| **general-purpose** | 다단계 조사·검색·실행 범용 (모든 툴 사용 가능) | 복합 리서치나 긴 작업 위임 |
| **claude-code-guide** | Claude Code / Agent SDK / Claude API 관련 질문 전담 | 툴 자체 사용법이 막힐 때 |
| **claude** | 위 분류에 안 맞는 나머지 전부 | 기타 |

여러 개를 한 메시지에 동시에 띄우면 병렬로 실행됩니다.

## 3. 스킬 (전문 워크플로우 — 필요 시 로드)

### 개발 / 품질

| 스킬 | 용도 |
|---|---|
| `/review` | GitHub PR 리뷰 |
| `/security-review` | 현재 브랜치 변경분 보안 점검 |
| `/simplify` | 변경분 리팩터링·정리 (품질 전용, 버그 헌팅 아님) |
| `/run` | 앱을 실제로 실행해서 동작 확인 |
| `/init` | CLAUDE.md 초기화 |
| `unity-mcp-skill` | Unity 에디터 자동화 (GameObject, 스크립트, 씬, 테스트) |

### 기획 / PM (pm-execution 세트)

- **문서**: PRD 작성, 유저 스토리 / 잡 스토리 / WWA 백로그
- **스프린트**: 스프린트 계획, 회고, 릴리스 노트
- **전략**: OKR 수립, 우선순위 프레임워크 (RICE / ICE / Kano / MoSCoW 등)
- **검증**: 프리모템 리스크 분석, 전략 레드팀, 이해관계자 맵
- **테스트**: 테스트 시나리오 생성, 더미 데이터셋 생성

### 디자인 / 산출물

| 스킬 | 용도 |
|---|---|
| `dataviz` | 차트·대시보드 설계 |
| `artifact-design` / `artifact-diagramming` | 공유 가능한 웹 페이지 산출물 |
| `pencil` (MCP) | `.pen` 디자인 파일 편집 |

## 4. 외부 연결 (MCP)

- **claude-in-chrome** — 실제 Chrome 브라우저 조작
  - 클릭, 폼 입력, 콘솔 로그 읽기, 네트워크 요청 확인, 스크린샷 / GIF 녹화
- **wmux 브라우저 패널** — 요청 시 우측 패널에 띄워 실시간 확인 가능

## 5. 대규모 오케스트레이션 (`Workflow`)

수십 개 에이전트를 스크립트로 펼치는 모드.

- 토큰 소모가 크므로 **명시적 요청 시에만** 실행
- 트리거: "워크플로우로 돌려줘" 또는 `ultracode`
- 적합한 작업: 대규모 마이그레이션, 전수 감사, 다각도 병렬 리뷰

---

## 운영 원칙

1. 평소엔 메인이 단독으로 빠르게 처리
2. 탐색 범위가 넓거나 설계·리뷰를 병렬로 돌리는 게 이득일 때 Explore / Plan / general-purpose 투입
3. PM 문서나 Unity 작업처럼 정형화된 작업은 해당 스킬을 로드해서 처리
4. 대규모 팬아웃은 사용자 명시 요청 시에만
