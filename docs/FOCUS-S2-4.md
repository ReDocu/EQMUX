# FOCUS — `S2-4` 방향 포커스 이동 + 패널 줌

> 키 정본: [KEYMAP-S2-7.md](KEYMAP-S2-7.md) §2 — 이동 `Ctrl+Alt+↑↓←→` · 줌 **`Ctrl+Shift+Z`**
> 상태: **구현 완료 · tsc 0건 · 줌 포함 전체 동작** (`setZoom`/`zoomedLeaf` · d3d9e80) · 기계 검증(§4)은 KR3 측정 뒤

## 1. 동작 정의

| 키 | 동작 |
|---|---|
| `Ctrl+Alt+←→↑↓` | 활성 패널에서 그 방향의 패널로 포커스 이동 (화면 기하 기준) |
| `Ctrl+Shift+Z` | 활성 패널 확대 토글 — 다른 패널은 `visibility: hidden` (세션 유지) |

## 2. 설계 결정 — 브리프가 "해원 판단으로 정하고 적으라"고 한 자리들

| # | 결정 | 이유 |
|---|---|---|
| 1 | **줌 중 분할·닫기 → 줌 해제 후 보여준다** — `onLayoutChanged`에서 **잎 집합이 실제로 바뀌었을 때만** `setZoom(null)` | panels.ts는 줌 중 새 잎을 숨은 채 만들고 그대로 둔다(*"언제 걸지는 호출자 몫"*). 안 풀면 "분할 키가 죽었다"로 읽힌다. ⚠️ `setZoom` 자체도 알림을 울리므로 **알림마다 풀면 줌이 걸리는 즉시 풀린다** — 잎 집합 비교가 그 방어다 |
| 2 | **줌 중 방향 이동 → 줌 풀고 이동** | 숨은 패널로 포커스만 가면 "입력은 가는데 안 보이는" 상태가 된다 |
| 3 | **wrap 없음** — 방향에 잎이 없으면 no-op | 2×2에서 끝 패널의 오버슈트가 반대편으로 감기면 손이 위치 감각을 잃는다 |
| 4 | 겹침 동률(±0.5px)·전부 0(계단 배치) → **가장 가까운 잎** | 브리프 "겹침 최대"의 동률 처리. 결정 없이 두면 트리 순서가 답이 되는데 그건 기하가 아니다 |
| 5 | 줌 키는 `e.code === "KeyZ"` (물리 키) | `e.key`는 한글 IME 상태에 흔들린다. 자판이 한글이어도 줌이 잡혀야 한다 |
| 6 | 리스너를 **계측 모드 포함 전 경로**에 건다. 상시 비용은 `!e.ctrlKey` 분기 1회 | 실사용 키는 항상 이 리스너를 지난다 — A-3도 같은 조건에서 재야 회귀를 잡는다 (§4) |
| 7 | 패널 1개면 줌 no-op | 이미 전체 화면이다 |
| 8 | **줌은 `e.repeat` 무시** — 반복 입력은 삼키되 동작만 막는다 (이안 리뷰 후속 · 1dc69c1) | 누르고 있으면 토글이 깜빡인다. 통과시키면 반복분이 터미널로 새므로 삼킨다. 이동은 반복 허용 — 화살표를 눌러 걷는 동작이다 |

### 경계 이슈 — 요소 접근자 요청 → **세아가 상태 API로 답했다** (d3d9e80)

처음에 `panelElement(leafId)` 개방을 요청했는데(줌이 요소에 클래스를 걸어야 한다고 봤다),
세아가 **요소 대신 상태를 여는** 쪽으로 설계했다 — `setZoom(id|null)` · `zoomedLeaf()`.
이유가 정확하다: *분할 껍데기는 렌더마다 다시 짜여서 밖에서 요소에 건 상태는 다음 reconcile에
증발한다.* 시각(`display: none` + `:has`로 분할 상자까지 접기)·fit·정리는 전부 panels.ts가 소유하고,
focus.ts는 **언제 걸고 언제 풀지**만 정한다. 경계가 처음 설계보다 좋아졌다 — 요청이 값을 했다.

### 줌 메커니즘 — panels.ts 소유

`setZoom`이 클래스 적용·fit(숨은 패널은 크기 0이라 건너뜀)·포커스 재적용·알림까지 처리한다.
줌된 잎이 **닫히면** panels.ts `reconcile`이 스스로 줌을 푼다 — focus.ts가 정리할 것은 없다.
브리프의 `visibility: hidden` 표기와 다른 `display: none`을 세아가 택한 이유는 styles.css 주석에 있다
(형제 숨김만으론 조상 분할의 빈 상자가 남는다). **DOM을 떼지 않는 것은 같아서 세션은 산다** — §4-2 3번이 그걸 확인한다.

## 3. 방향 알고리즘 (`pickDirectional`)

1. 활성 잎 rect 기준, 해당 방향에 있는 잎만 후보로 — 경계 허용치 2px(분할선 1px + 반올림)
2. **수직 축 겹침 최대** 잎 선택 · 동률이면 축 방향 거리 최소
3. 후보 없음 → no-op

기하는 전부 `panelRect()`(공개 API · viewport 좌표)에서 온다. 드래그로 비율이 바뀌어도
매 키 입력마다 현재 기하를 다시 읽으므로 항상 화면과 일치한다.

## 4. 검증 — 구현자와 검증자가 다르다 (`#18` 규칙 2)

### 4-1. 기계 검증 (해원 · 자기 확인)

| 항목 | 상태 |
|---|---|
| `npx tsc --noEmit` | ✅ 0건 |
| `--panes-probe` 회귀 (격리 3연속 · M2 · exe 17:32 빌드) | ✅ **3연속 통과 exit 0** — 패널 4/4 · PTY 4→1 · 캔버스 8→2 · 죽인 PTY 3개 모두 정리 · 렌더러 생존 4/4 (S2-3 실측과 동일) |
| A-3 회귀 (`--latency-probe-run=500 --panes=4`) — 리스너가 hot path에 얹힌 조건 | ⏳ **조용한 창 대기** — KR3 측정 직후 같은 창에서 돈다 (압력이 지연을 부풀리는 방향이라 여유 창이 조건이다) |

> **빌드는 KR3 파이프라인이 죽어 있던 틈(타임아웃 직후)에 돌렸다** — 빌드가 게이트를 닫아 두거나
> 게이트가 열리는 순간과 겹치면 콜드스타트 표본을 오염시키기 때문에, 아무 측정도 걸려 있지 않은
> 창을 골랐다. panes-probe는 기능 판정이라 압력과 무관해 바로 돌렸다.

### 4-2. 교차 검증 절차 (세아 또는 이안) — 이대로 따라 하면 된다

준비: 격리 4분할 (`LAYOUT-S2-2.md` §6 그대로 · `--panes=4` · 2×2). 각 패널에
`echo P1`~`echo P4`를 쳐서 위치 표식을 만든다 (좌상=P1 · 우상=P2 · 좌하=P3 · 우하=P4 가정 —
실제 표식 기준으로 읽는다). 포커스는 패널 막대 하이라이트로 확인한다.

| # | 조작 | 기대 |
|---|---|---|
| 1 | **방향 전수 16조합** — 각 패널을 클릭으로 활성화한 뒤 4방향 키 | 인접 패널로만 이동: P1→(→P2·↓P3), P2→(←P1·↓P4), P3→(→P4·↑P1), P4→(←P3·↑P2). **화면 밖 방향(예: P1에서 ←·↑)은 아무 일 없음** |
| 2 | 드래그로 좌우 비율을 크게 바꾼 뒤 1 반복 | 여전히 화면 위치 기준으로 이동 (트리 순서 아님) |
| 3 | **줌 왕복** — P2 활성 → `Ctrl+Shift+Z` → 다시 | 확대: P2가 전체 화면·나머지 안 보임 → 해제: 2×2 복원, **P1·P3·P4 셸에 쳐 둔 표식이 그대로**(세션 생존) |
| 4 | 줌 상태에서 `Ctrl+Alt+←` | 줌이 풀리고 P1로 이동 (결정 2) |
| 5 | 줌 상태에서 확대 패널의 분할 버튼 클릭 | 줌이 풀리고 분할 수행 (결정 1) |
| 6 | **키 누수** — 터미널 포커스 상태에서 `Ctrl+Alt+→` 연타 | 셸 입력줄에 **아무 문자도 안 들어감** (`^[[C` 등 이스케이프 잔여 없음) |
| 7 | 통과 확인 — `Ctrl+C`(SIGINT) · 화살표 단독(히스토리/커서) · `Alt+화살표` 단독 · `Ctrl+Shift+D`(분할) | 전부 기존대로 동작 — 앱 층 키 둘 외에는 안 가로챈다 |
| 8 | 패널 1개로 줄인 뒤 `Ctrl+Shift+Z`·방향 키 | 전부 no-op |

## 5. 다음 사람이 밟을 함정

1. **`onLayoutChanged`는 `setZoom` 자체로도 울린다.** 알림마다 무조건 `setZoom(null)`을 부르면
   줌이 걸리는 즉시 풀린다 — 그래서 **잎 집합(leafIds) 비교**로 구조 변경만 골라낸다.
   구독 콜백을 단순화하고 싶어지면 이 함정부터 기억할 것.
2. `installFocusKeys()`는 계측 경로에도 걸려 있다 — **빼면 A-3이 실사용과 다른 조건이 된다.**
   빼고 싶어지면 §4-1의 A-3 회귀 근거부터 다시 세울 것.
3. 방향 후보 필터의 허용치 2px는 분할선 폭(5px 히트존·1px 선)과 무관하게 **경계 반올림**용이다.
   분할선이 두꺼워져도 이 값을 키울 필요는 없다 — 이웃 판정은 rect 경계로 한다.
4. 줌 상태를 focus.ts에 별도로 저장하지 말 것 — **정본은 `zoomedLeaf()` 하나다.** 복사본을 두면
   reconcile의 자동 해제(줌된 잎 닫힘)와 어긋난 순간 유령 줌이 생긴다.
