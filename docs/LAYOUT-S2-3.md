## 1. 동작 — 프런트 선행, 놓는 순간 확정

```
pointerdown(분할선) ──▶ 드래그 중: 이웃 두 칸의 flex-grow만 변경 (CSS가 화면을 끌고 간다)
                        fit 정지 — pty_resize 0회 (제약 ①)
pointerup ──────────▶ ① 전 패널 fit → 크기가 실제로 바뀐 패널만 pty_resize 1회
                        ② layout_set_weights(split_id, 현재 flex-grow 배열) → 백엔드 확정
                        ③ 실패 시 트리 값으로 화면 되돌림 (화면·트리 분기 금지)
```

- 분할선은 잡는 폭 5px · 보이는 선 1px 헤어라인. 매 렌더 새로 만든다 —
  split id는 `normalize`가 걷어내며 사라지는 값이라 오래 붙잡지 않는다(`LAYOUT-S2-1` §7-4).
- 드래그 중 터미널 격자는 **일부러 얼려 둔다**(`overflow: hidden` 클립). ConPTY reflow를
  매 프레임 보내면 그게 A-3에 얹힌다 — 브리프 제약 ①이 그 금지다.
- 계측용 정적 그리드에도 같은 분할선을 조작 없이 둔다 — 계측 화면과 실사용 화면의
  기하가 같아야 같은 조건의 숫자다.

## 2. 최소 크기 가드 — 양쪽 (제약 ③)

| 쪽 | 가드 | 성격 |
|---|---|---|
| 프런트 | `MIN_PANEL_PX = 100` — 드래그 클램프. 쌍의 합이 200px 미만이면 드래그 자체를 안 연다 | UX |
| 백엔드 | `layout.rs::set_weights` — 0·음수·비유한 비율 거부, 칸 수 불일치 거부 (**S2-1부터 있던 불변식**, 이번에 경로 확인만) | 불변식 |

프런트 클램프 덕에 정상 경로에서는 0이 만들어질 수 없고, 비정상 경로(직접 invoke)는
백엔드가 거부한다. 확정 실패 시 트리 값으로 화면을 되돌린다(§1-③).

## 3. `S2-4` 경계 API (#18 규칙 3 · 이안 요청)

해원의 포커스·줌은 **새 파일에서 아래만** 쓴다. 내부(DOM 구조·`Panel` 필드)에 기대지 않는다.

| API | 무엇 |
|---|---|
| `leafIds(): string[]` | 트리 순서(왼쪽부터)의 잎 id |
| `activeLeaf(): string \| null` | 포커스 잎 id |
| `panelRect(id)` / `panelRects()` | 화면 기하(viewport 좌표) — 방향 탐색은 이 좌표로 계산 |
| `focus(id): Promise<void>` | 포커스 이동 (백엔드 확정 포함) |
| `onLayoutChanged(cb): () => void` | 분할·닫기·드래그 확정 뒤 알림. 반환값이 구독 해지 |

모자라면 **API를 여기에 늘리는 것**이지 `panels.ts`를 직접 고치는 게 아니다 — B 영역 관할(세아).

### 4-1. 검증이 잡은 잠복 결함 — ConPTY drop이 메인 스레드를 얼린다

S2-3 첫 빌드에서 `--panes-probe`가 3회 중 2회 **판정 없이 동결**됐다(창은 산 채로).
원인은 S2-2에서 고친 `PtyManager::kill()`의 세션 drop — ConPTY 닫기가 conhost 상태에 따라
블로킹되고, `layout_close`는 동기 명령이라 **메인 스레드째** 얼었다. S2-2 빌드에서 세 번
통과한 것은 운이었다(메모리 여유 ~1.7GB 상황에서 드러남). **S2-3 프런트 변경과 무관한
코어 잠복 결함**이다.

수정: 세션 drop을 전용 스레드로 이관(`pty.rs::kill`). 맵 제거는 여전히 즉시라
`pty_list`·A2 관점의 정리는 그대로고, 자원 반납만 명령 스레드 밖으로 나갔다.
수정 후 3연속 통과. **닫기 UX에도 같은 효과다** — 패널 닫기가 컨트롤 불가능한
conhost 타이밍에 인질로 잡히지 않는다.

## 5. 다음 사람이 밟을 함정

1. **드래그 중 `pty_resize`를 다시 켜고 싶어질 것이다**(터미널이 실시간으로 리플로우되게).
   그러려면 디바운스+A-3 재실측이 선행이다 — 제약 ①은 미관이 아니라 관문이 근거다.
2. 분할선 요소는 렌더마다 새로 생긴다. 분할선에 상태를 붙이지 말 것 — 다음 렌더에 사라진다.
3. `commitWeights`는 요소의 flex-grow를 그대로 보낸다(합이 1이 아니어도 된다) —
   정규화는 백엔드 `normalize`가 한다. 프런트에서 미리 정규화하지 말 것(반올림 이중 적용).
