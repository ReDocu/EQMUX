- **M3 전달 = 인박스 + 상태 기반** — 수신 세션이 `idle`이면 즉시 PTY 주입, busy·waiting·starting이면 인박스에 쌓았다가 idle 전이(턴 종료) 때 흘려보냄. waiting에 즉시 주입하지 않는 것은 TUI 다이얼로그 키 주입 회피(G7과 같은 이유). 대기 현황은 대화 탭 상단에 "누구 몇 건"으로 표시

### PRD I — 외부 인터페이스 (M14 부분 실물)
- **단일 바이너리 CLI** — `eqmux.exe`가 argv 첫 토큰(send·report·_hook·ping)으로 CLI 모드 분기. 에이전트·셸 PTY의 PATH 앞에 앱 폴더가 붙어 어디서든 `eqmux`로 잡힌다
- **운반로 = Windows 명명 파이프** `\\.\pipe\eqmux-bus-<사용자>` (C7 — GUI 1 + CLI 다수, 같은 OS 사용자) — JSON 한 줄 요청/응답, 연결당 스레드
- **`eqmux send --type <5종> [--to @이름] "내용"`** — 발신자 신원은 EQMUX_SESSION(앱이 심은 env)뿐, 워크스페이스·cwd는 앱 추적 맵에서 푼다. 수신자는 페르소나 이름·id → 세션 id로 해석(2단 라이브러리). 사람 발신과 같은 원장 경로(messages::send + message-new) — 검증·상한 공유
- **`eqmux report "한 줄"`** (V4 · FR-G-88) — 대화 스트림(report 타입, 사람에게 미확인)과 세션 이벤트 피드에 동시 기록
- **`eqmux _hook <Event>`** — Claude Code 훅 진입점. stdin JSON을 동봉하고 어떤 실패에도 exit 0 (에이전트 흐름 불가침)
- 에이전트에게는 `--append-system-prompt` 한 줄로 표면을 알려준다
- 유닛 테스트: CLI 파싱(플래그 순서 무관·세션/타입 필수) · 훅 이벤트→상태 매핑

**미구현 (I)**: MCP 서버 · 플러그인 · statusLine · `eqmux` 원격 인증(I6) · 파이프 프로토콜 버전 협상

### PRD H — 도구 패널 (읽기 전용 실측)
- **git** — 활성 워크스페이스 스코프 · 10초 폴링. `git_overview`: 브랜치(분리 HEAD·빈 저장소 표시) · 업스트림 ahead/behind · `status --porcelain` 요약 · 최근 커밋 8건(+ref 뱃지)
- **포트** — `netstat -ano` 파싱 5초 폴링. 소유 pid를 세션 Job Object pid 목록과 대조해 세션/시스템 포트 분리, 프로세스명 실측, 충돌·외부 노출 집계
- **탐색기** — 실제 FS 트리(깊이 3·400개 상한, .git/node_modules 등 제외) + 텍스트 미리보기(64KB 상한·경로 탈출 거부). 임무 파일은 실측 임무 데이터로 구조화 표시
- **로그** — event 테이블 실스트림 (M3)
- **diff 뷰어** — 변경 파일 목록(porcelain+numstat) + HEAD↔워크트리 나란히 비교(`git diff -U999999` 양측 재구성). 신규=전부 add · 삭제=전부 del · 바이너리=사유 표시 · 3,000줄 상한
- **브라우저** — 세션 포트 미리보기 (M17). 실측 포트 칩(netstat + Job Object 귀속 공유) + 주소 입력 → iframe 렌더 + 새로고침. **대상은 localhost·127.0.0.1로 제한** — 임의 웹 브라우징은 사용자의 브라우저 몫 (관측 지향 원칙)
- **쓰기 작업은 어디에도 없다** (pull·push·commit·스테이지·프로세스 kill·파일 편집) — 실행은 터미널 페인에서 사람이 한다 (G7과 같은 원칙)
- 유닛 테스트: git 임시 저장소 왕복 · netstat 파싱 · 트리 제외/경로 탈출 가드 · diff 양측 재구성(M/A/D)
