## 1. 요약

EQMUX는 여러 AI 코딩 에이전트를 한 화면에서 동시에 돌리고 감시하기 위한 Windows 데스크톱 앱이다.

**우리는 이미 그런 앱을 갖고 있다 — AgentCommender.** 잘 돌아가고, 지금 이 팀이 그 위에서 일하고 있다.
문제는 무게다: **우리가 쓴 코드는 7.3MB인데 런타임이 432MB다.**

EQMUX는 AgentCommender를 **Tauri로 재작성한 후속작**이다.
기능을 다시 발명하지 않는다 — 사양과 디자인을 계승하고 **런타임만 바꾼다.**
그 한 번의 결정이 최적화의 거의 전부다. 나머지는 그 결정을 망치지 않는 일이다.

> **wmux는 원본이 아니라 경쟁 제품이다.** 소스를 보지 않는다 (라이선스 표기 3중 불일치 — 3절 참조).

## 3. 배경

### 지금 무슨 일이 벌어지고 있나

Claude Code 같은 CLI 에이전트를 여러 개 동시에 돌리는 작업 방식이 자리를 잡았다.
그런데 터미널 창이 흩어지면 사람이 **"지금 누가 나를 기다리는지"**를 놓친다.
에이전트는 멈춰 서서 입력을 기다리는데 사람은 다른 창을 보고 있다. 이게 실제 병목이다.

이 문제를 노린 제품이 이미 두 개 있다.

| 제품 | 플랫폼 | 스택 | 라이선스 |
|---|---|---|---|
| **cmux** | macOS | Swift / AppKit / libghostty | GPL-3.0-or-later (+ 상업 라이선스 별매) |
| **wmux** | Windows | Electron / React / TypeScript / xterm.js(WebGL) / node-pty·ConPTY | 표기 불일치 (아래 참조) |

### 우리 위치 — 이미 만든 것이 있다

**AgentCommender (acmux) v0.1.0.** 우리가 만들었고, 지금 돌고 있고, 오늘도 커밋되고 있다.
터미널 멀티플렉서 + 관제 + 페르소나 + 팀 편성까지 구현돼 있다. TS/TSX 44파일 11,802줄, 사양 문서 2,760줄.

**EQMUX는 이것의 후속작이다.** 백지가 아니다.

### 왜 지금인가

**첫째, 무게가 런타임에서 온다.** 실측했다.

| 항목 | AgentCommender | wmux 0.13.0 (경쟁) |
|---|---|---|
| **자체 코드** (dist) | **7.3 MB** | — |
| **런타임** (node_modules) | **432.5 MB** | — |
| 앱 데이터 | ~0 MB | **512 MB** (93%가 Chromium 캐시) |
| 크래시 덤프 | **0건** | **10회 / 19일** |

> **우리가 쓴 코드는 7.3MB다. 런타임이 432MB다.**
>
> 최적화 대상은 우리 코드가 아니라 런타임이다. 코드를 아무리 다듬어도 432MB는 안 줄어든다.
> **Tauri로 가면 배포물이 ~10MB가 된다** — Windows 11이 WebView2를 이미 갖고 있어서 브라우저 엔진을 싣지 않기 때문이다.

**중요한 구분:** AgentCommender는 wmux보다 **이미 안정적이다** (크래시 0건 대 10건).
**재작성의 명분은 "불안정해서"가 아니라 "무거워서"다.**
이 구분을 흐리면 안정성을 깎아 먹으면서 재작성하게 된다.

**둘째, 지금이 구조를 바로잡을 마지막 기회다.**
AgentCommender는 터미널 → 관제 → 페르소나 → 팀 순으로 기능이 **얹혀 왔다.**
모드 3개(터미널 / 페르소나 개인 / 페르소나 팀)를 처음부터 설계에 넣으려면 재작성 시점밖에 없다.

**셋째, 이제 뺄 수 있다.** Windows 11에는 WebView2 런타임이 기본 탑재되어 있다.
Chromium을 배포물에 넣지 않고도 웹 기술로 UI를 만들 수 있다. 2년 전이라면 어려웠다.

**둘째, 원인이 명확하다.** wmux는 이미 xterm.js WebGL 렌더러를 쓴다. 터미널 렌더링은 이미 GPU 가속 상태다.
그런데도 무겁다는 건, 무게가 **터미널이 아니라 Electron 런타임 + 내장 Chromium 브라우저 패널**에서 온다는 뜻이다.
즉 최적화로 짜낼 문제가 아니라, **빼면 없어지는 문제**다.

**셋째, 이제 뺄 수 있다.** Windows 11에는 WebView2 런타임이 기본 탑재되어 있다.
Chromium을 배포물에 넣지 않고도 웹 기술로 UI를 만들 수 있다. 2년 전이라면 어려웠다.

### 라이선스 리스크 (착수 전 확정 사항)

wmux의 라이선스 표기가 세 갈래로 갈린다.

| 출처 | 주장 |
|---|---|
| 저장소 LICENSE 파일 | MIT (© Amir Lehmam, 2025–2026) |
| wmux.org 공식 문서 푸터 | AGPL-3.0 |
| 저장소 한 줄 설명 | "Port of cmux" |
| README 본문 | "cmux 소스를 재사용하지 않은 독립 재구현" |
| 상류 cmux | GPL-3.0-or-later |

저장소 설명("Port of cmux")과 README("포트 아님")가 서로를 반박한다.
MIT가 사실이면 참조해도 되지만, **사실인지 확인할 방법이 없다.**
만약 실제로 cmux 파생이라면 원저작자에게 MIT로 재라이선스할 권한이 없고, 그걸 믿고 참조한 EQMUX가 하류 리스크를 그대로 승계한다.

> **결정: 클린룸 개발. wmux·cmux 소스 코드를 열람하지 않는다.**
> 공개 매뉴얼과 실행 파일의 관찰 가능한 동작만을 근거로 새로 설계한다.
> EQMUX 자체 라이선스는 v1.0 공개 전까지 별도 결정한다 (권고: MIT 또는 Apache-2.0).

비용은 거의 없다. 어차피 스택을 바꾸고(Electron→Tauri), 브라우저를 빼고, 기능을 줄일 것이므로 참조할 코드가 애초에 별로 없다.

## 4. 목표

### 목표

**여러 에이전트를 돌리는 사람이, 노트북 배터리와 램을 걱정하지 않고 하루 종일 켜둘 수 있는 작업 환경을 만든다.**

기능으로 경쟁하지 않는다. **가벼움으로 경쟁한다.**
AgentCommender가 하는 일을 **더 적은 자원으로** 한다. 기능을 더 넣어 이기려 하면 진다.

이 목표는 다섯 철학 위에 선다 (전문: [OBJECTIVES.md](OBJECTIVES.md) 2절):

| 철학 | 한 줄 |
|---|---|
| **기능은 토큰0** | 기능이 늘어도 세션이 자동으로 읽는 토큰은 늘지 않는다 |
| **터미널 UI/UX 최대화** | 터미널로서 먼저 훌륭하다. 에이전트는 그 위에 얹는다 |
| **GIT 연결성** | git 상태가 항상 보이고, git 작업이 앱을 떠나지 않는다 |
| **멀티플렉서 연계** | 앱이 하는 일은 전부 CLI로도 할 수 있다 |
| **성능 최적화** | 측정하지 않은 것은 최적화하지 않는다 |

## 5. 대상 사용자

### 1차 — 내부 팀 (v0.x ~ v1.0)

**하는 일:** Claude Code 등 CLI 에이전트를 2~6개 동시에 돌리며 개발한다.
**겪는 문제:** 어느 에이전트가 입력을 기다리는지 놓쳐서 유휴 시간이 쌓인다. 터미널 앱이 무거워 정작 빌드가 느려진다.
**제약:** Windows 11. 이미 Chrome을 상시 띄워 놓고 쓴다. 설치 마법사·자동 업데이트 불필요.

### 2차 — 공개 배포 (v1.0 이후)

같은 문제를 겪는 Windows 개발자. 다만 **이들에게는 신뢰 비용이 추가로 든다** — 코드 서명, SmartScreen 대응, 이슈 대응, 문서.
이 비용은 v1.0 스코프에 명시적으로 포함한다. (범위 관리 실패의 가장 흔한 지점)

### 비대상 (명시적 제외)

- **iOS** — iOS는 앱이 임의 프로세스를 spawn할 수 없다(fork/exec 봉쇄). App Store 심사도 다운로드된 코드 실행을 금지한다. iOS에서 EQMUX는 로컬 터미널이 될 수 없고 원격 세션 뷰어가 한계다. **그건 다른 제품이다.**
- **Linux** — Tauri가 지원하지만 수요 근거가 없다. v2 이후 재평가.
- **일반 터미널 사용자** — 에이전트를 안 돌리는 사람에게는 Windows Terminal이 이미 충분하다. 이들을 노리면 기능이 부풀고 KR6이 무너진다.

## 6. 가치 제안

### 우리가 더 잘하는 것

| 고객의 일 | wmux | EQMUX |
|---|---|---|
| 여러 에이전트 동시 감시 | 가능 | 가능 (동등) |
| 하루 종일 켜두기 | 이틀에 한 번 죽음 | **14일 무크래시 목표** |
| 노트북에서 쓰기 | 512MB + Chromium 상주 | **60MB 상한, Chromium 미탑재** |
| 브라우저로 결과 확인 | 앱 안에 내장 (무거움) | **쓰던 Chrome을 그대로 조작** |
| Mac에서도 쓰기 | 불가 (별도 제품 cmux) | **v2 목표 — 코드 공유** |

### 값 곡선 — 무엇을 버리고 무엇에 몰빵하는가

**과감히 버린다 (경쟁사 대비 의도적 열위)**
- 테마 450개 → **2개** (라이트/다크). 테마는 차별점이 아니다.
- 내장 브라우저 → **없음.** 외부 Chrome을 CDP로 조작한다.
- GitHub PR 상태·포트 감지 → v2. 있으면 좋지만 없어도 일한다.
- 오케스트레이터 플러그인 → 범위 밖. Claude Code가 이미 한다.
- 자동 업데이트·설치 마법사 → v1.0까지 없음. 포터블 zip.

**여기에 몰빵한다**
- **에이전트 상태 가시화** — 이게 없으면 그냥 tmux다. 유일한 진짜 차별점.
- **가벼움** — 측정 가능한 숫자로 방어한다 (KR1~KR5).
- **안 죽는 것** — KR6. 나머지 전부보다 우선한다.

## 7. 솔루션

### 7.1 화면 구조

```
┌──────────┬────────────────────────────────────────────┐
│ 사이드바 │  패널 (분할 가능)                          │
│          │  ┌──────────────┬───────────────────────┐  │
│ ● EQMUX  │  │ [탭1][탭2]   │ [탭1]                 │  │
│   ⏳ 2   │  │              │                       │  │
│ ○ 프로젝트│  │  터미널      │  터미널               │  │
│   ✓      │  │  (진세아)    │  (윤해원)             │  │
│ ○ 문서   │  │              │                       │  │
│          │  │  ⏳ 입력대기 │  ▶ 작업중             │  │
│          │  └──────────────┴───────────────────────┘  │
└──────────┴────────────────────────────────────────────┘
```

**상태 배지 — 제품의 심장**

| 배지 | 뜻 | 사용자 행동 |
|---|---|---|
| `▶ 작업중` | 에이전트가 출력 중 | 놔둔다 |
| `⏳ 입력대기` | 사람의 답을 기다림 | **지금 간다** |
| `✓ 완료` | 턴 종료 | 확인한다 |
| `✗ 오류` | 비정상 종료 | 본다 |

사이드바 배지는 **입력대기 개수만** 센다. 완료·오류는 색으로만 표시한다.
이유: 숫자가 여러 종류면 사람이 안 읽는다.

### 7.2 핵심 기능 (v1.0 범위)

**F1. 터미널 멀티플렉싱**
- 패널 수평/수직 분할, 패널당 탭
- ConPTY 기반. 각 터미널은 독립 프로세스
- 키보드 우선. 마우스 없이 전 기능 도달 가능

**F2. 워크스페이스**
- 프로젝트 단위 컨테이너 (작업 디렉터리 + 패널 배치 + 탭 구성)
- 사이드바에서 전환. git 브랜치·dirty 여부 표시

**F3. 에이전트 상태 감지 ⭐**
- Claude Code 훅으로 상태 수신 (수동 설정 불필요, 자동 주입)
- 훅이 없는 CLI는 출력 정지 시간으로 추정 (fallback)
- 상태 변화 → 패널 테두리 + 사이드바 배지 + Windows 토스트

**F4. 알림 일원화**
- "입력대기"만 토스트를 띄운다. 나머지는 시각 표시만
- 토스트 클릭 → 해당 패널로 즉시 이동
- 이유: 알림이 흔하면 사람이 끈다. 끄면 제품이 죽는다

**F5. 세션 영속**
- 30초 자동 저장 + 종료 시 저장
- 앱이 죽어도 워크스페이스·패널 배치·작업 디렉터리 복구
- 터미널 **스크롤백은 복구하지 않는다** (디스크 상한 KR2를 지키기 위한 의도적 포기)

**F6. CLI / IPC**
- 명명 파이프(`\\.\pipe\eqmux`)로 외부·에이전트가 앱 조작
- 최소 명령: `new-workspace`, `split`, `send`, `list`, `notify`, `browser open`
- 에이전트가 자기 작업 환경을 스스로 구성할 수 있어야 한다

**F7. 외부 Chrome 연결**
- 앱은 브라우저를 탑재하지 않는다
- CDP(Chrome DevTools Protocol)로 사용자의 Chrome을 조작: 열기, 스크린샷, 텍스트 읽기, 콘솔 로그
- **대가:** 화면이 앱 밖에 있어 시각적 일체감이 깨진다. 팀장님 승인 완료 (2026-08-04)

### 7.3 기술

**런타임: Tauri 2 + WebView2 (Rust 백엔드)**

| 후보 | 채택 | 사유 |
|---|---|---|
| **Tauri 2 + WebView2** | ✅ | Win11에 WebView2 기본 탑재 → Chromium 미배포. 바이너리 ~10MB. macOS 확장 경로 확보 |
| Electron | ❌ | wmux와 동일 경로. 512MB·2일 1크래시 문제를 구조적으로 상속 |
| 순수 네이티브 (WinUI) | ❌ | macOS 지원 0. cmux/wmux가 이미 이 길을 갔고, **같은 제품을 두 코드베이스로 두 번 만들고 있다** |

**핵심 제약 — Mac 확장을 살리는 한 줄**

> **PTY와 셸 통합은 반드시 플랫폼 추상화 계층 뒤에 둔다.**
> Windows는 ConPTY, Unix는 forkpty로 완전히 다르다.
> Rust `portable-pty` crate(wezterm 제작)가 양쪽을 이미 추상화하므로 이를 채택한다.
> 이 한 줄을 지키면 v2 macOS 이식 비용이 UI 재작성이 아니라 셸 스크립트 수준으로 떨어진다.

**터미널 렌더링:** xterm.js + WebGL 애드온 (검증된 조합, wmux도 동일 선택)
**상태 관리:** 프런트는 최소한으로. 상태의 원본은 Rust 쪽에 둔다.

**디스크 상한 강제 (KR2 방어책)**
- 캐시·로그·세션 파일에 **하드 상한을 코드로 박는다**. 초과 시 오래된 것부터 삭제
- "관리하겠다"가 아니라 "구조적으로 못 넘는다"로 만든다. wmux가 실패한 지점이 정확히 여기다

### 7.4 가정 (검증 필요)

| # | 가정 | 틀리면 생기는 일 | 검증 방법 | 담당 |
|---|---|---|---|---|
| A1 | 무게의 주범은 내장 Chromium이다 | 브라우저를 빼도 안 가벼워짐 → KR1·KR2 붕괴 | wmux 유휴 RAM 측정, 브라우저 패널 켜기 전/후 비교 | 윤해원 |
| A2 | WebView2가 Win11에 항상 있다 | 런타임 설치 안내 필요 → 설치 경험 악화 | 대상 환경 실사 | 윤해원 |
| A3 | 외부 Chrome 방식이 실사용에 견딘다 | 일체감 상실이 생각보다 크게 불편 → F7 재설계 | v0.3에서 2주 자체 사용(dogfooding) | 전원 |
| A4 | Claude Code 훅으로 상태를 충분히 잡는다 | 상태 표시가 부정확 → 제품의 유일한 차별점 붕괴 | 훅 이벤트 목록 확인 후 상태 매핑표 작성 | 진세아 |
| A5 | xterm.js WebGL이 WebView2에서 잘 돈다 | 렌더러 직접 작성 → 일정 대폭 증가 | v0.1 walking skeleton에서 즉시 확인 | 진세아 |

> **A5가 가장 위험하다.** 가장 먼저, 가장 싸게 검증한다. v0.1의 존재 이유다.

## 8. 릴리스 계획

날짜 대신 순서와 관문(gate)으로 관리한다. 각 단계는 **앞 단계의 관문을 통과해야** 시작한다.

### v0.1 — Walking Skeleton
**목표:** 가장 위험한 가정(A5)을 가장 싸게 죽인다.
- 창 하나, 터미널 하나. ConPTY 연결, xterm.js WebGL 렌더
- 분할·탭·세션·알림 **전부 없음**
- **관문 A:** 한글 입력(IME) · CJK 폭 · 키 입력 지연 — 실작업 p99 ≤ 8ms · 총지연 ≤ 2프레임 ([issue](issue.md) #10)
- **관문 A2:** 유휴 RAM — 터미널 4개 · 앱 전용 **≤ 219.8MB**(기준선 549.6MB · **M2**의 40%). **`S2-2` 직후** ([issue](issue.md) #11·#15)
  — S1은 터미널이 1개뿐이라 기준선(4개)과 조건이 다르다

### v0.2 — 내부 MVP
**목표:** 내부 팀이 실제로 이걸로 일한다.
- F1 분할·탭 / F2 워크스페이스 / F3 에이전트 상태 / F4 알림 / F5 세션 / F6 CLI
- **관문:** 내부 팀 전원이 2주간 주력 도구로 사용. KR6 중간 점검(7일 무크래시)

### v0.3 — 외부 Chrome 연결
- F7 CDP 연동
- **관문:** A3 검증 — 2주 사용 후 "일체감 상실이 견딜 만한가" 판정. 아니면 F7 재설계

### v1.0 — 공개 배포
- 코드 서명, SmartScreen 대응, 포터블 zip 배포
- 라이선스 확정, README·매뉴얼, 이슈 템플릿
- **관문:** KR1~KR6 **전부** 충족. 하나라도 미달이면 공개하지 않는다

> v1.0은 기능 추가가 아니라 **신뢰 비용 지불** 단계다. 여기를 과소평가하면 일정이 무너진다.

### v2.0 — macOS
- Tauri + WKWebView, `portable-pty` Unix 경로 활성화
- 셸 통합 재작성(zsh/bash), 단축키 관습 전환(Ctrl→Cmd), 알림 API 교체
- **전제:** v1.0에서 플랫폼 추상화 제약(7.3)이 지켜졌을 것
