## 1. 스키마

```jsonc
{
  "version": 1,                    // u32 · 필드의 뜻이 바뀌면 올린다
  "root": { /* Node */ },
  "focus": "leaf-1"                // 포커스된 잎 id · 없으면 생략
}
```

### Node — `type` 태그로 갈린다

| 필드 | 타입 | 어디에 | 설명 |
|---|---|---|---|
| `type` | `"leaf"` \| `"split"` | 공통 | 태그. **사람이 JSON을 읽을 수 있어야 한다** |
| `id` | string | 공통 | 한 프로세스 안에서 유일. `leaf-3` · `split-7` |
| `kind` | string | leaf | 지금은 `"terminal"` 뿐 |
| `pty_id` | string? | leaf | 붙은 PTY. **소유가 아니라 참조**(§3) |
| `title` | string? | leaf | 사용자가 붙인 이름 (`FEATURES` D3) |
| `cwd` | string? | leaf | 복구용 작업 디렉터리 (`FEATURES` D5) |
| `direction` | `"row"` \| `"column"` | split | `row`=좌우 · `column`=상하. **CSS `flex-direction`과 같은 뜻** |
| `children` | `Child[]` | split | **2개 이상.** 1개짜리는 검증에서 걷힌다 |
| `Child.weight` | f64 | split | 형제 사이 비율. **합이 1.0이 되게 정규화** |

`?`는 `null`을 쓰지 않고 **필드를 생략**한다. 30초마다 쓸 파일이라 빈 필드를 안 싣는다.

### 나중에 못 고치는 것 넷 — 왜 이렇게 잡았나

**① `kind`를 열거형이 아니라 문자열로.**
`BACKLOG` B1(폴더 탐색기)이 붙으면 터미널이 아닌 잎이 들어온다. 열거형이면 **모르는 값에서
파싱이 죽거나 값이 증발한다.** 문자열이면 모르는 종류도 **그대로 들고 있다가 그대로 다시 쓴다.**
(테스트 `모르는_kind는_버리지_않고_그대로_왕복한다`) **B1은 구현하지 않았다 — 자리만 비웠다.**

**② n분할을 중첩으로 흉내 내지 않는다.**
`Split`이 자식을 여럿 갖는다. 좌우 분할을 또 좌우로 나누면 **형제로 끼워** 트리가 안 깊어진다.
4분할이 한 줄이면 `children`도 넷이다. `S2-3` 드래그는 **인접한 두 `weight`만** 만지면 된다.
중첩으로 흉내 냈으면 층마다 드래그 핸들이 생겼을 것이다.

**③ 픽셀이 아니라 비율.**
창 크기가 바뀌어도, DPI가 다른 기계에서 복원해도 같은 화면이 나와야 한다.
M1(DPR 1)에서 저장한 세션을 M2(DPR 2)에서 열면 픽셀 값은 그대로 절반짜리 화면이 된다.

**④ 잎이 PTY를 소유하지 않는다.** → §3

## 2. 버전 정책 — **모르는 버전을 만나면 백업하고 초기화한다**

브리프 §2-1이 요구한 "행동"이다. 셋 중 **③ 백업 후 초기화**를 골랐다.

| 상황 | 행동 | stderr |
|---|---|---|
| 파일 없음 | 기본 레이아웃(터미널 1개). **에러가 아니다** | `새 레이아웃 — 상태 파일 없음` |
| `version` == 1 | 읽는다 → 정규화 → 검증 | `복원 — 잎 N개 · v1` |
| `version` < 1 | **이관(migrate).** v1이 최초라 아직 도달 불가 — 자리를 비워 뒀다 | `이관 경로가 없다` |
| `version` > 1 | **백업 후 초기화** | `⚠️ 미래 버전 v99 (현재 v1) — 백업 후 초기화: <경로>` |
| JSON 깨짐 · `version` 없음 · 검증 실패 · 1 MB 초과 | **백업 후 초기화** | `⚠️ 상태 파일을 못 쓴다 (<이유>) · 백업 <경로>` |

백업 이름은 `state.json.bak-<태그>-<밀리초>`다. **덮어쓰지 않으므로 여러 번 겪어도 다 남는다.**

**왜 ②"읽을 수 있는 만큼만"이 아닌가.** 미래 버전은 필드가 **늘어난 것만이 아니라 뜻이 바뀐 것**일
수 있다. `weight`의 의미가 바뀌었는데 이름이 같으면 읽히기는 하고 화면만 조용히 틀어진다.
**조용한 손상이 요란한 초기화보다 나쁘다.**

**왜 ①"거부하고 빈 레이아웃"이 아닌가.** 사용자 파일을 지우면 되돌릴 방법이 없다.
백업은 남기는 비용이 거의 없고, 구버전으로 내려갔을 때 그 파일이 그대로 필요하다.

**어느 경우에도 앱은 뜬다.** 레이아웃 파일 하나 때문에 터미널을 못 쓰게 만들지 않는다.

## 3. 소유권 — 잎이 사라질 때 PTY는 누가 죽이나

> **`LayoutState::close`가 죽일 PTY id를 돌려주고, 그것을 호출한
> `commands::layout::layout_close`가 `PtyManager::kill`을 부른다. 프런트는 죽이지 않는다.**

**왜 프런트가 아닌가.** 프런트는 언제든 사라질 수 있는 쪽이다 — 새로고침·크래시·창 닫힘.
거기에 죽이는 책임을 두면 그때마다 고아 PTY가 남는다. `PtyManager`는 프로세스가 살아 있는 한
남는 쪽이다. **죽이는 책임은 오래 사는 쪽에 둔다.**

**트리에서 빼는 것과 프로세스를 죽이는 것이 한 명령 안에서 끝난다.** 둘로 나누면 그 사이에
죽는 경로가 생기고, 그러면 트리에는 없는데 살아 있는 PTY가 된다.

> 이미 죽은 PTY를 다시 죽이는 것은 실패로 안 친다 — 트리에서는 이미 뺐다. stderr에만 남긴다.

**불러올 때 `pty_id`를 전부 지운다.** 지난 실행의 프로세스는 살아 있지 않다
(`FEATURES` D8 — 원리적으로 복구 불가). 안 지우면 `S2-2`가 "이미 붙어 있다"고 착각해
새 셸을 안 띄운다. **복원된 잎은 PTY가 없는 상태로 시작한다.**

## 4. API

### 트리 조작 (`layout.rs`)

| 함수 | 하는 일 |
|---|---|
| `LayoutState::single_terminal()` | 기본 레이아웃 — 터미널 잎 하나 |
| `split(target_leaf, direction) -> 새 잎 id` | 같은 방향이면 형제로, 아니면 중첩으로 |
| `close(leaf_id) -> 죽일 PTY id들` | 외자식 분할은 걷어낸다. **마지막 잎은 거부** |
| `set_weights(split_id, &[f64])` | 칸 수 불일치·0 이하·비유한 값 거부 후 정규화 |
| `set_focus(leaf_id)` / `attach_pty(leaf_id, Option<String>)` | 잎이 아니면 거부 |
| `normalize()` / `validate()` | 합 1.0 · 외자식 걷기 / id 중복·빈 kind·칸 수·비율·포커스 |

### Tauri 명령 (`commands/layout.rs`) — 7개

`layout_get` · `layout_split` · `layout_close` · `layout_set_weights` ·
`layout_focus` · `layout_attach_pty` · `layout_save`

**호출자는 아직 없다**(브리프 §1이 허용). `S2-2`가 `layout_get`으로 그리기 시작하면 붙는다.

> **드래그(`S2-3`)는 IPC를 프레임마다 왕복시키지 않는다.** 프런트가 자기 사본으로 먼저 움직이고
> 놓는 순간 `layout_set_weights`로 확정한다. 60 Hz(M2는 120 Hz)로 IPC를 때리면
> A-3에서 벌어 둔 여유를 여기서 다 쓴다.

### 파일

- 경로: `Paths.state_file` = `EQMUX_STATE_PATH` 또는 `<app_data>/state.json` (`config.rs:58`)
- 쓰기: **임시 파일에 쓰고 `rename`으로 갈아끼운다.** `S3-4`가 30초마다 부르게 되는데,
  그 빈도로 "쓰는 도중"이 존재하면 언젠가 그 순간에 죽는다
- 상한: 직렬화 결과가 **1 MB를 넘으면 저장을 거부**한다. 노드 **512개** 상한도 같은 이유다.
  `D9`(스크롤백 복구)를 제외로 못 박은 그 방어선이다 — 화면 내용이 새어 들어오면 여기서 막힌다

### 5-2. 무인 왕복 검증 — `--layout-probe`

```powershell
$env:EQMUX_STATE_PATH = "$env:TEMP\eqmux-s2-1\state.json"
& .\src-tauri\target\release\eqmux.exe --layout-probe --layout-probe-out="$env:TEMP\layout.json"
```

```
[eqmux] 격리 인스턴스로 왕복 검증한다
[eqmux][layout] 복원 — 잎 4개 · v1 (…\eqmux-s2-1\state.json)
[eqmux][layout-probe] 통과 — 잎 4→4 · 왕복 동일 예 · pty 정리 예 · 577 B · …
exit=0
```

**창을 열지 않는다.** 4분할 트리를 만들어 → 저장 → 불러오기 → **직렬화 결과 문자열 비교**다.
`pty_id`는 불러올 때 의도적으로 지워지므로 그 한 자리만 맞춰 놓고 비교한다 —
**비교 대상을 슬쩍 넓히면 아무것도 못 잡는다.**

> 왜 실제 상태 경로로 도는가: 격리 스위치를 존중하는지까지 **같이** 증명된다.
> 임시 경로를 따로 만들었으면 그 부분은 영영 안 재 본 채로 남는다.

### 5-3. 미래 버전 — **실물 바이너리로** 확인

단위 테스트만으로는 "빌드된 물건이 그렇게 도는가"를 답하지 못한다. 그래서 실행 파일로 다시 했다.

```
state.json ← {"version":99,"root":{"type":"leaf","id":"미래","kind":"hologram"},…}

[eqmux][layout] ⚠️ 미래 버전 v99 (현재 v1) — 백업 후 초기화: …\state.json.bak-v99-1785898147436
```

백업 파일 **88 B · 원본 그대로**. 같은 실행에서 PTY 왕복도 통과했다 — **앱은 정상으로 뜬다.**

### 5-4. 격리 스위치

| 확인 | 결과 |
|---|---|
| `EQMUX_STATE_PATH`를 준 실행이 라이브 파일을 건드렸나 | **아니오** — `%APPDATA%\com.redocu.eqmux\state.json`은 **존재조차 안 한다** |

## 7. 다음 사람이 밟을 함정

1. **`--layout-probe`는 상태 파일을 덮어쓴다.** `EQMUX_STATE_PATH`로 격리하고 돌린다.
   격리 없이 돌리면 경고가 뜨지만, 경고는 막아 주지 않는다.
2. **복원된 잎에는 `pty_id`가 없다.** 일부러 지운다(§3). "복원했는데 셸이 안 붙어 있다"는
   버그가 아니라 설계다 — 붙이는 것은 `S2-2`가 `layout_attach_pty`로 한다.
3. **`weight`는 비율이지 픽셀이 아니다.** 합은 항상 1.0으로 정규화된다.
   드래그에서 픽셀을 그대로 넣으면 다음 정규화에서 비율이 바뀐다.
4. **`Split`의 자식은 2개 이상이다.** 하나가 되면 `normalize`가 그 층을 걷어낸다 —
   `S2-2`가 노드 id로 DOM을 캐싱하면 그 순간 사라진 id를 붙잡고 있게 된다.
5. **`version`은 필드의 뜻이 바뀔 때만 올린다.** 필드가 늘기만 하면 안 올려도 된다
   (`skip_serializing_if` + `default`). 뜻이 바뀌었는데 안 올리면 **구버전이 그 파일을
   읽어서 조용히 틀린 화면을 그린다** — 그게 §2가 막으려는 사고다.
