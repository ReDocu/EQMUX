## 2. 무인 플래그 전수 — **화면 없이 다 잴 수 있다**

```powershell
$exe = ".\src-tauri\target\release\eqmux.exe"

# ── 앱 데이터 크기 (S2-1b) · 창을 안 연다
& $exe --appdata-report
& $exe --appdata-report-out="$env:TEMP\appdata.json"

# ── A-2 폭 계측 (S1-3c) · 창을 열어 재고 바로 끝난다
& $exe --font-probe --font-probe-out="$env:TEMP\font.json"
& $exe --font-probe '--font-stack="굴림체", monospace'    # 스택 강제(터미널에도 먹는다)
$env:EQMUX_FONT_STACK = '"D2Coding", monospace'           # 환경변수도 같다(플래그 우선)

# ── 키 입력 지연 (S1-3b)
& $exe --latency-probe-run=500 --latency-probe-out="$env:TEMP\lat.jsonl"
& $exe --latency-probe-run=500 --latency-probe-inject-ms=5 ...     # 자가검증 ②
& $exe --latency-probe-run=500 --latency-probe-gap-ms=21 --latency-probe-frame-hold=4 ...  # ③

# ── 셸 왕복 (S1-2·S1-4, 기존)
& $exe --pty-probe --pty-probe-cmd=dir --pty-probe-ms=4000 --pty-probe-out="$env:TEMP\pty.txt"
```

**판정은 전부 stderr에 한 줄로 나온다.** 파일을 안 열어도 통과/미달이 보인다 —
GUI 서브시스템이라 **stdout이 아니라 stderr**다.

> ⚠️ **서로 겹치면 안 되는 조합은 코드가 막고 stderr로 알린다.**
> `--latency-probe` + `--pty-probe`, `--latency-probe` + `--font-probe`.
> 그리고 **계측 모드에서는 앱 데이터 훑기가 아예 안 돈다** — 표본을 재는 4초 동안
> 옆에서 디스크를 긁으면 그 잡음이 A-3에 얹힌다.

## 3. 작업별 결과

### 3-1. `S2-1b` 앱 데이터 크기 리포트

| 조건 | 값 |
|---|---|
| 라이브 인스턴스 | **13.75 MB** · 캐시 계열 **93%** · KR2(60MB)의 **23%** |
| 빈 폴더 → 창 뜨는 순간 | **4.06 MB** (WebView2가 창보다 먼저 쓴다) |
| 빈 폴더 → 셸 붙고 7초 후 | **13.70 MB** |

**세는 규칙을 문서에 박아 뒀다**([APPDATA-S2-1b.md](APPDATA-S2-1b.md) §2) — `#7` ②의 3회 측정이
같은 자로 나와야 하기 때문이다. 뿌리는 `webview`(캐시가 쌓이는 곳) + `state` 두 개,
**워크스페이스는 뺀다**(기본 경로에서 `state` 폴더 안에 있어서, 안 빼면 사용자 저장소가
우리 앱 데이터로 둔갑한다 — 20MB 파일 심어 `0.00 MB` 확인).

> **WebView2 기본 폴더 경로를 짐작하지 않았다.** `tauri 2.11.5`의 `manager/webview.rs`가
> `LocalData/<identifier>`로 강제하는 것을 코드에서 확인하고 디스크에서도 봤다.
> 짐작했으면 빈 폴더를 재고 "0 MB"라고 보고했을 것이다.

**해원 교차확인 반영**(§3.5): 제 캐시 규칙이 `BASELINE.md`의 4폴더 지정보다 넓어서
**비중 %는 나란히 놓으면 안 된다.** 총계는 비교 가능. §0에 각주 달았다. 규칙은 안 바꿨다 —
지울 것을 고르는 게 목적(`S3-6`)이면 넓은 쪽이 맞다.

### 3-2. `S1-3b` 계측 4점 분리 — **인수**

갈아엎지 않았다. 설계가 `GATE-A.md` §2-1의 함정을 **구조적으로** 피한다 —
대기를 재서 `work`를 빼는 대신 **일한 구간을 직접 재므로**, 구간을 놓치면 `work`가 줄지 않고
`wait`가 커진다. 다시 짜도 같은 설계로 간다.

**자가검증 3항을 제 손으로 다시 돌렸다** (n=500 × 4회):

| 항 | 결과 |
|---|---|
| ① 무부하 | `work` p99 **0.3~0.4** · 재현됨 |
| ② 5 ms 주입 | `work` p50 0.2 → **5.1** (+4.9) · `naive_work`는 0.1 → **0.1**(못 잡는다) |
| ③ 프레임 지연 (유효 15 Hz) | `work` p50/p95 **±0.0** · `wait` p50 8.8 → **33.2** |

> **③은 이안이 아직 안 돌린 항목이었다** — `GATE-A.md` §4-2에는 ②만 있다. 그래서 그것부터 했다.

### 3-3. `S1-3c` A-2 폭 계측

**규칙 한 줄**: CJK는 거의 모든 폰트에서 **1.0em**이다. 그래서 비율이 2가 되려면
**ASCII advance가 정확히 0.5em이어야 한다.** 그것뿐이다.

| 폰트 | ASCII em | 한글 비율 |
|---|---|---|
| 굴림체 · 돋움체 · D2Coding ligature | **0.5000** | **2.0000** ✅ |
| **Cascadia Mono** *(현행 스택의 실제 ASCII 폰트였다)* | 0.5859 | **1.7067** ❌ |
| Consolas | 0.5498 | 1.8188 ❌ |
| 굴림 · 맑은 고딕 | 0.64~0.66 | 1.52~1.56 ❌ |

**판정선은 기기 픽셀 0.5 / 1.0**으로 뒀다([FONT-A2.md](FONT-A2.md) §2).
근거: 사람이 보는 건 비율이 아니라 글리프가 제 칸을 넘었는가이고 그건 픽셀 사건이다.
**다만 이 선이 실제로 하는 일은 거의 없다** — 통과 조합은 오차 **0.000px**, 미달은 −2.4px로
회색지대에 걸린 조합이 하나도 없었다. em이 0.5냐 아니냐로 갈리는 **이산 문제**라 그렇다.

### 3-4. `S1-3d` D2Coding 동봉

| | 동봉 후 | 동봉 없었다면(대조군) |
|---|---|---|
| ASCII | 7px **0.5em** | 8.203px 0.586em |
| 가 · 漢 | **2.0000** | 1.7067 ❌ |
| → · ■ | **1.0000** | 1.0000 |
| **굵게** | **2.0000** | 1.8286 ❌ |
| 오차 | **0.000 px** | −1.4 ~ −2.4 px |

**`@font-face`가 폭 문제만이 아니라 이름 문제까지 없앤다** — 우리가 선언한 이름이 곧 패밀리
이름이라, 설치본(`D2Coding ligature`)과 어긋나 매칭이 안 되던 함정이 사라진다.
터미널도 실제로 바뀌었다: 같은 창에서 **`cols` 135 → 155**(셀 8.203px → 7px).

**대조군은 일부러 미달로 남겼다.** 동봉 직후 `D2Coding 제외` 스택이 설치본을 잡아 통과로
바뀌었는데, 그러면 동봉이 무엇을 막는지 안 보인다. 이름 둘 다 빼도록 고쳤다.

## 4. 발견하고 고친 결함

### 계측기 결함 3건 — **전부 "그럴듯한 숫자"로 나왔다**

| # | 무엇 | 어떻게 드러났나 |
|---|---|---|
| 1 | **자가검증 실행의 `gate`가 판정처럼 나온다** | `--latency-probe-frame-hold=4`는 유효 주사율을 1/4로 낮춰 A-3-② 상한을 33.4 → **133.4 ms**로 벌린다. `a3_2_pass: true`가 찍히는데 **통과가 아니라 무의미**다. → `gate.verdict_valid` 추가 |
| 2 | **굵기 측정이 문법 오류로 조용히 무시됐다** | `14px bold "X"`는 잘못된 CSS 단축 속성(굵기가 **크기 앞**). 대입이 거부되면 캔버스는 **직전 폰트로 계속 잰다** — 200px 보통 글씨를 재고 비율 `2.0000`을 뱉어 **틀린 값이 통과처럼 보였다.** → `widthOf`가 대입 후 크기를 되읽어 확인 |
| 3 | **동봉 폰트가 로드되기 전에 쟀다** | 캔버스 `measureText`는 안 붙은 `@font-face`를 **폴백으로 대체하고 로드를 유발하지도 않는다.** 첫 실행에서 `설치: D2Coding✗` — 동봉은 됐는데 안 붙은 상태. → `ensureFontsLoaded()`를 **터미널 생성 전에** |

> **3번은 제품 버그이기도 하다.** xterm은 **셀 크기를 생성 시점에 한 번만** 잰다.
> 그때 폰트가 없으면 격자가 폴백 기준으로 굳고, 나중에 폰트가 바뀌어도 안 고쳐진다.

## 6. 다음 사람이 밟을 함정

1. **`cargo build --release`를 직접 쓰지 말 것.** 프런트가 컴파일 시점에 박히는데 `dist/`만
   바뀌면 cargo가 다시 빌드하지 않는다 — **옛 프런트가 박힌 바이너리가 조용히 남는다.**
   (README 빌드 절. 여기서 한 시간 잃은 기록이 있다)
2. **`FONT_STACK` 순서를 바꾸기 전에 [FONT-A2.md](FONT-A2.md)를 읽을 것.**
   ASCII가 0.5em이 아니면 CJK 2배는 **산술적으로 불가능**하다. `terminal.ts` 주석에 규칙을 박아 뒀다.
3. **폰트를 서브셋하지 말 것.** 4.2MB가 부담돼도, 서브셋은 OFL상 **수정본**이라
   `D2Coding` 이름을 못 쓴다. 그 이름이 곧 `@font-face`의 패밀리이자 스택 첫 항목이다.
4. **계측기를 고치면 대조군이 무력화되지 않았는지 볼 것.** 동봉 직후 대조군이 통과로
   바뀌었다 — **통과가 늘어난 게 반가워서 넘어갈 뻔한 자리다.**
5. **`gate.verdict_valid`를 먼저 볼 것.** `false`면 판정에 인용하지 않는다.
6. **다른 기계 값끼리 비교하지 말 것**(`#10`). 측정 문서 머리에 기계 코드(M1/M2/M3)를 적는다.
