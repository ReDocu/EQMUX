> 기준: `#6` — 앱 전용 유휴 RAM ≤ **219.8 MB** (기준선 549.6 × 40% · M2 · [BASELINE.md](BASELINE.md) §3.6)

## 0. 판정

```
실측 482 MB  >  판정선 219.8 MB        — 2.19배. 미달.
```

**검산 (이안).** 표본 10개 정렬 중앙값 (482.0+482.1)/2 = 482.05 → **482** ✓ · 분해 24.0(호스트)+458.0(WebView2) ✓ ·
진동 폭 3.0 MB(역대 최소) ✓ · 조건 준수 8항 전부 확인 ✓. **측정에는 문제가 없다. 문제는 값이다.**

**이 판정은 뒤집힐 여지가 없는 종류다.** 해원이 한계에 적었듯 측정 중 압력(80.3→82.4%)은 워킹셋을
잘라 값을 **낮추는** 쪽으로 작용한다 — 482는 하한에 가깝고, 실제는 더 높을 수 있다.
2.19배는 표본 요행·압력·기계 차이 어느 것으로도 설명되지 않는다.

## 1. 이 숫자가 말하는 것

**재작성이 유휴 RAM을 12.3%밖에 못 줄였다** (549.6 → 482). 배포물(440 → 5 MB, −99%)과 정반대 그림이다.

| | 값 | 뜻 |
|---|---:|---|
| Rust 호스트 (eqmux.exe) | **24 MB** | 재작성이 잘한 부분 — Electron 메인 프로세스 대비 압도적으로 작다 |
| **WebView2 프로세스군** | **458 MB (95%)** | xterm.js×4 · WebGL 컨텍스트×4 · **Chromium 상주** — 문제의 전부가 여기다 |

> WebView2도 Chromium이다. **런타임 교체는 "디스크에 실어 나르는 Chromium"을 없앴지,
> "화면에 떠 있는 동안의 Chromium"을 없애지 못했다.** `#7`이 앱 데이터에서 확인한 구조가
> RAM에서 반복됐다 (해원 분석 그대로 인용 — 정확하다).

## 2. 사전 약속을 이행한다 — 목표부터 낮추지 않는다

`#6`이 판정선을 세울 때 미리 적어 둔 문장:

> *"이번에 목표를 낮췄으므로 미달이 나오면 그때는 '기준이 이상하다'가 아니라 **구현이나 스택을 본다**."*

그래서 순서는 이거다. **① 원인 분해(스파이크) → ② 그 숫자로 경로 결정(`#19`) → ③ 필요하면 그때 재산정.**
지금 목표를 바로 219.8에서 올리면, 오늘 하루 종일 지킨 규칙(*결과를 보고 규격을 바꾸면 판정이 아니다*)을
관문에서 어기는 셈이다. 미달은 미달로 기록하고, 다음 행동을 결정한다.

**WORKPLAN A-4 원문 절차 확인**: *"목표 재산정 또는 스택 재검토. **S3로 넘기지 않는다.**"*
→ **`#19`가 닫히기 전에 S3를 시작하지 않는다.** S2 잔여 작업(S2-4~S2-9)은 이 판정의 영향을 받지 않는다.

## 3. 다음 행동 — SPIKE-A4 (세아 배정)

482를 **바닥·패널비용·레버**로 분해한다. 결정은 추측이 아니라 이 네 숫자로 한다.

| # | 측정 | 답하는 질문 |
|---|---|---|
| 1 | **빈 WebView2 바닥** (xterm 로드 없이 마크업만) | 플랫폼 바닥(B)이 얼마인가 — **219.8의 실현 가능성이 여기서 갈린다** |
| 2 | **1패널 vs 4패널** | 패널당 한계 비용(P) — 458 중 우리 코드 몫 |
| 3 | **WebView2 프로세스군 내역** (browser/gpu/renderer별) | 458이 어느 프로세스에 있나 — GPU면 WebGL, renderer면 JS 힙 |
| 4 | **`MemoryUsageTargetLevel` 등 WebView2 메모리 레버** | 플랫폼이 공식으로 열어 둔 감축 수단이 몇 MB나 버나 |

**판정 기준을 미리 적는다** (`#17`에서 배운 대로 — 결과 보고 정하면 그건 결정이 아니다):

- **B + 4P(최적화 후 추정) ≤ 220 근처** → 최적화 경로. 1차 안에서 승부한다
- **B 단독 ≥ ~180 MB** → 219.8은 플랫폼 바닥 아래다. **재산정**이 정당해진다 — 단 새 목표는
  "우리 실력"이 아니라 **"바닥 + 우리 몫 상한"** 형태로 유도한다 (40% 같은 비율 재탕이 아니라)
- **스택 재검토**(WebView 포기·네이티브 렌더러)는 위 둘이 다 막힐 때만 연다 — 1차 일정과 트레이드오프가 크다
