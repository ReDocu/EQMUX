2026-10-15 · 리드 eqmux-77 · 분담은 `docs/update-0.5.0-work-split.md`, 근거는 `docs/update-plan-0.5.0.md`

## 요약

기획서의 P0 13건, P1 24건, 요청 기능 6건, UX 기반, 주의 고리, 메뉴 정리, 바로 가기를 코드에 넣었다. P2 22건 중 19건을 넣고 3건은 일부만 했거나 넘겼다. 자동 검증은 모두 통과했다. 그 뒤 2단계로 화면을 `design.pen` 시안에 맞추고, QA 빌드를 실제로 띄워 실기 체크리스트를 돌렸다(아래 §실기 결과). 실기에서 찾은 버그는 모두 고치고 다시 확인했다. 커밋: 1차 `sub_main` b3d111a, 시안·실기 반영은 그다음 커밋.

## 하지 않았거나 넘긴 것

- **A12** `tokio::time::sleep` — tokio 직접 의존을 늘릴 가치가 없다(W1·W2 같은 판단).
- **C9** 대화 탭 이름 찾기 메모 — 효과가 작다.
- **A2** OS 알림 클릭 → 페인 — 코드는 넣었다. 설치본에서 실기로 눌러 확인해야 하고, 안 되면 0.6으로 넘긴다.
- **H4** 한국어 IME — 비교표에 "실기 확인 전"으로 두었다.
- 산출물 체크리스트는 앱 안 토글이 없다. 체크는 임무 파일을 고친다.
- `package-lock.json`의 version은 0.4.0으로 남아 있다(기획서 버전 파일 목록 밖, 이전부터 맞춰 오지 않았다).

## 실기 결과 (2026-10-15)

## 결정이 필요한 것

1. **에이전트의 `eqmux` 명령 자동 승인** — acceptEdits에서 `eqmux send`·`report`·`browser`마다 사람 승인이 필요해 팀 통신이 승인 창에서 멈춘다. W2가 좁은 허용 목록 초안(send·report·who·browser 읽기 동작만, Claude만)을 만들었다. 기획서가 "자동 승인"을 원칙상 제외로 두어서 적용하지 않았다.
2. **Codex 기동 플래그 `--dangerously-bypass-hook-trust`** — 0.4.2(M37)부터 쓰고 있다. Codex 화면에 경고가 뜬다. 유지할지 정해야 한다.
