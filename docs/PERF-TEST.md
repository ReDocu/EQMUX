## 1. 공통 규칙 — 이걸 어기면 숫자가 서로 비교가 안 된다

### 1-1. 측정 기계는 **M1 하나**로 고정한다

[MACHINE-SPEC.md](MACHINE-SPEC.md) — i7-14700KF · 64 GB · RTX 4070 Ti SUPER · **60 Hz 고정**(`#12`) ·
Windows 11 Pro 26200.8973 · `pwsh` 7.6.4.

> **M2·M3 값은 판정에 쓰지 않는다** (`MACHINE-SPEC.md` §6).
> 지금 도는 세션 중 M2·M3에 있는 것이 하나도 없어 **재현이 불가능**하기 때문이다.
> 인용할 때는 **기계 코드를 반드시 붙인다.**

### 1-2. 격리 규칙 — 라이브를 죽이지 않고 재는 법

AgentCommender를 재려면 **별도 인스턴스**를 띄운다. 상태·워크스페이스·캐시를 전부 분리한다.

```
--user-data-dir=<임시>              Electron 단일 인스턴스 락 회피 (락은 userData 기준)
ACMUX_STATE_PATH=<임시>/state.json  라이브 state.json 미접촉
ACMUX_WORKSPACE_ROOT=<임시>/ws      라이브 워크스페이스 미접촉
```

**환경변수로 분리되지 않는 것이 하나 있다 — 명명 파이프** (`\\.\pipe\acmux` 하드코딩).
그래서 순서 규칙이 있다:

| 규칙 | 내용 |
|---|---|
| 1 | 격리 인스턴스는 **라이브가 이미 떠 있을 때만** 띄운다 |
| 2 | 격리가 떠 있는 동안 **라이브를 재시작하지 않는다** |
| 3 | 측정 **전후로 `acmux list`** 를 찍어 라이브 세션이 응답하는지 확인한다 |
| 4 | 격리 인스턴스를 쓰기 전에 **이안에게 알린다** |
| 5 | 끝나면 격리 프로세스가 **0개**인지 확인한다 |

> EQMUX는 이 제약을 물려받지 않게 **제어 채널 이름을 환경변수로** 덮어쓸 수 있어야 한다
> (`EQMUX_PIPE_NAME`). 없으면 도그푸딩(관문 B) 중 측정이 **파괴적 행위**가 된다. → 세아

### 1-3. 지표 정의를 바꾸면 그 전 값과 비교하지 않는다

| 무엇 | 이 프로젝트가 쓰는 값 |
|---|---|
| RAM | **`WorkingSet64`** (공유 페이지 중복 포함). Private Bytes로 바꾸면 전부 다시 잰다 |
| 앱 데이터 | **캐시 계열 판정은 [APPDATA-S2-1b.md](APPDATA-S2-1b.md) §2-3 규칙** — 이름에 `cache` 포함 또는 `dictionaries`/`shared dictionary`/`service worker`/`blob_storage` |
| 지연 | `#10`의 3분할 — **①실작업(판정) ②총지연(판정) ③주사율·기계(기록 필수)** |

### 1-4. 조건을 유리하게 바꾸지 않는다 (`#12`)

> 판정을 유리하게 만드는 방향으로 규격을 바꾸는 건 판정이 아니다.
> **불리해지는 방향이어도 근거 없이 바꾸지 않는다.**

## 2. 항목별 규격

### P1. 콜드 스타트

| | |
|---|---|
| **정의** | `T0` = 프로세스 생성 시각(`Get-Process.StartTime`, 커널값) → `T1` = **셸이 첫 출력을 낸 시각** |
| **조건** | 팀 1개 × 세션 4개(`t1`~`t4`) · `mode=terminal` · 상태 복원 |
| **표본** | **n=10** + 워밍업 1회(버림) · 중앙값·p95 보고 |
| **현재값** | M1 · AgentCommender — 첫 프롬프트 **476 ms** (p95 506) · 4개 준비 506 (p95 568) |
| **문서** | [BASELINE.md](BASELINE.md) §2.1 |

> ⚠️ **`T1`을 "session.log 첫 바이트"로 잡으면 틀린다.** 첫 바이트는 셸 출력이 아니라
> `pty-manager.ts:111`이 세션 생성 즉시 쓰는 헤더다. **두 값은 90 ms 차이 난다.**
> 헤더 줄 **뒤에** 처음 붙는 실내용을 봐야 한다.
>
> ⚠️ **이 값은 "웜 재기동"이다.** 연속 기동이라 디스크 캐시가 뜨겁다.
> 진짜 콜드(부팅 후 최초 1회)는 **재부팅당 1표본**밖에 못 얻는다. 필요하면 별도 지시.

**EQMUX 쪽 요구**: 세션 로그를 안 쓰면 **등가 신호**를 정해야 한다 —
권장은 *"PTY 첫 출력 바이트 수신 시각을 stderr에 1줄"* 찍는 측정 전용 플래그.
**신호를 바꾸면 두 숫자는 비교 불가다.**

### P2. 유휴 RAM

| | |
|---|---|
| **정의** | 프로세스 트리 전체의 `WorkingSet64` 합 · **앱 전용**은 앱 프로세스만 |
| **조건** | 터미널 **4개** · 아무 입력 없음 · `mode=terminal` |
| **표본** | `#6` — **안정화 30초 후 · 30초 간격 · 10표본 · 중앙값** |
| **현재값** | M1 · AgentCommender — 앱 **558.2 MB** · 트리 895.2 · 셸 페이로드 337.0 · 진동 폭 12.5 |
| **판정** | A-4(관문 A2): EQMUX 앱 전용 **≤ 223.3 MB** (기준선의 40%) |
| **문서** | [BASELINE.md](BASELINE.md) §3.5 |

> ✅ **`#6`의 10표본 규격이 실제로 문제를 없앴다.** 단일 표본 시절 진동 폭이 86.5 MB로
> 목표치의 3배였는데(판정 기준으로 못 쓸 수준), 10표본 중앙값에서 **12.5 MB**로 떨어졌다.
>
> 📌 **RAM은 기계 성능으로 안 풀린다.** 같은 기계 교체에서 콜드스타트는 3.2배 움직였는데
> **앱 RAM은 1.0% 움직였다.** 디스크·CPU가 바꾸는 건 시간이지 상주 크기가 아니다.

### P3. 앱 데이터

| | |
|---|---|
| **정의** | 앱이 디스크에 쌓는 상태+캐시. **층을 맞추는 게 전부다** |
| **층** | AgentCommender = Electron `userData` **한 폴더** / EQMUX = `LOCALAPPDATA`(webview) **+** `APPDATA`(state) **합산** |
| **빼는 것** | 워크스페이스 · 재파스 포인트(링크·정션) · 겹치는 뿌리 |
| **현재값** | M1 · AgentCommender 빈 폴더 → 10분 유휴 **30.43 MB** (캐시 100%) |
| **문서** | [BASELINE.md](BASELINE.md) §3.2c · [APPDATA-S2-1b.md](APPDATA-S2-1b.md) §2·§3.5 |

> 📌 **"10분 유휴" 규격이 얻는 게 없다.** 7초에 30.43 MB에 도달한 뒤
> **600초까지 소수점 둘째 자리도 안 움직였다.** 캐시는 **페이지를 열 때** 자라고 유휴는 아무것도 안 연다.
>
> → **`#7`의 3회 측정이 의미 있는 이유는 "시간이 지나서"가 아니라 "그 사이에 썼기 때문"이다.**
> 측정 시점마다 **경과 시간이 아니라 사용량**을 같이 기록해야 비교가 선다. (→ `#7` 절차 보강 제안)
>
> 참고: 30.43 MB 중 **`Dictionaries` 10.94 MB는 안 써도 항상 붙는 Chromium 고정 자산**이다.
> wmux·AgentCommender 실측에서 **같은 값**으로 나온다.

### P4. 키 입력 지연

| | |
|---|---|
| **판정** | `#10` — ① 프레임 대기 제외 **실작업 p99 ≤ 8 ms** · ② 총지연 p99 **≤ 2프레임**(60Hz = 33.4 ms) |
| **기록 필수** | rAF 간격 중앙값(실효 주사율) · GPU · PTY 연결 여부 · 표본 수 |
| **계측기 인수 기준** | [GATE-A.md](GATE-A.md) §2-2 **자가 검증 3항** — 부하 5 ms를 넣으면 `work_ms`가 5 ms 오르고, 프레임을 늦추면 `work_ms`는 안 변해야 한다 |
| **현재값** | M1 · EQMUX — rAF p50 **16.7 ms(59.9 Hz)** · `frame_wait` p99 16.1~16.3 · `total` p99 16.3 |
| **막힌 것** | **A-3-①(실작업)은 아직 못 잰다** — `S1-3b` 선행 |

> ⚠️ **순진하게 rAF 틱으로 자르면 회귀를 숨긴다.** 메인 스레드가 바쁘면 rAF 콜백 자체가 밀려서
> **느려질수록 `work`는 그대로이고 `wait`만 커진다.** 그래서 계측기부터 자가 검증을 통과해야 한다.
>
> AgentCommender 쪽 기준선은 **없다**(`#9` — 계측기 이식 안 함). 따라서
> *"AgentCommender보다 빠르다"* 는 **주장하지 않는다.** 절대 기준 단독으로 판정한다.

### P5. 폰트 폭 (A-2)

| | |
|---|---|
| **정의** | CJK advance width / ASCII advance width = **2.0** 이어야 한다 |
| **판정선** | 기기 픽셀 오차 **≥ 1.0 → 미달** (글리프가 제 칸을 한 픽셀 이상 벗어난다) |
| **현재값** | **1.7067 — 미달.** 현행 / D2Coding 제외 / Cascadia 단독 **세 스택 전부 같은 값** |
| **문서** | [FONT-A2.md](FONT-A2.md) |

> ⚠️ **원인이 기계가 아니라 산술이다.** CJK advance는 사실상 모든 폰트에서 1.0em이므로
> **비율이 2가 되려면 ASCII advance가 정확히 0.5em이어야 한다.** Cascadia Mono는 0.586em이다.
> **기계를 바꿔도 안 바뀐다.**
>
> ⚠️ **측정 기계 전제가 하나 무너졌다.** M1에 설치된 패밀리 이름은 `D2Coding ligature`인데
> 스택 첫 항목은 `"D2Coding"`이라 **한 번도 매칭된 적이 없다.**
> → **M1은 이미 폴백이 도는 기계였다.** `GATE-A.md` §1의 *"D2Coding이 잡혀서 폴백이 안 돌았다"* 는
> 전제가 성립하지 않는다. **→ `GATE-A.md` §1 갱신 필요.**
>
> ⚠️ **폭 계측은 육안을 대체하지 않는다** (`FONT-A2.md` §6). 비율이 틀리면 볼 것도 없이 미달이고,
> 맞으면 **그때 눈으로 본다.** 지금은 전자다.

## 3. 재현이 실패하는 실제 원인 — 겪은 것만

문서에 절차를 적어 두는 것과 그 절차가 실제로 도는 것은 다르다. **셋 다 직접 밟았다.**

| # | 함정 | 증상 | 고치는 법 |
|---|---|---|---|
| **1** | **열려 있는 파일을 독점 모드로 읽음** | 폴링이 **100% 실패**하는데 `catch`가 `false`를 돌려줘 **30초 타임아웃까지 조용하다** | `FileShare.ReadWrite \| Delete`로 연다. **감지 루프의 catch는 실패 횟수를 세서 출력한다** |
| **2** | **신호를 잘못 정함** | `session.log` 첫 바이트를 "프롬프트"로 읽었는데 실제로는 앱이 쓴 헤더 (90 ms 차이) | 신호가 **누가 언제 쓰는 값인지** 코드로 확인하고 정한다 |
| **3** | **기계가 같다고 가정** | 값이 3.2배 달라 *"내 방법이 틀렸나"* 부터 의심했다. 기계가 달랐다 | 측정 문서 **머리에 기계 코드**를 박는다. 값보다 먼저 |

> **3번 판별법**: 빌드 번호만 보면 *"업그레이드됐나 보다"* 로 넘어간다.
> **레지스트리 `InstallTime`과 에디션(Home/Pro)** 을 같이 본다. 에디션은 기능 업데이트로 안 바뀐다.
