## 3. 경쟁력

### 앞서는 것 (지킬 것)

- **역할 권한 + 타입 메시지 + 파일 원장 + 자동 실행 없음.** 47개 도구 중 이 조합을 가진 것은 없다(벤치마크 요약 §1).
- **Windows 네이티브(ConPTY + Job Object)에 한국어 UI.** 경쟁 도구 대부분은 mac이나 tmux 기반이다.
- **주의 고리는 0.5에서 메웠다.** 알림 센터, `Ctrl+Shift+U`, `report --done`이 들어갔다.

### 뒤처진 것 (시장 기본기)

| 기능 | 경쟁 도구 | EQMUX |
|---|---|---|
| 앱을 닫아도 세션 유지 | 데몬·tmux 계열 거의 전부, Orca, wmux | 0.6에 트레이, 0.7에 VT 서버 |
| 서명 + 자동 업데이트 | Emdash(서명 MSI), Orca 등 | 0.6 §1-3, CI부터 필요 |
| 한도 표시 | Orca, wmux | 0.6 F1 |
| 회신 고리(`--re`, `--wait`) | herdr, workmux, Agent Teams | 0.6 §4 |
| 원격·모바일로 보기 | Orca, wmux, Superset, amux 등 다수 | 범위 밖으로 정했다 |

### 구조적 위험

1. **플랫폼 흡수.** Claude Code Agent Teams와 Codex 앱이 팀 기능을 직접 넣고 있다. 관제 화면까지 붙으면 핵심 가치가 겹친다.
2. **상위 CLI 의존.** Claude Code의 훅, 플래그, Notification 동작이 바뀌면 상태 감지가 깨진다. B67(유휴 안내를 승인 대기로 오판한 버그)이 그 예다. CLI 버전 범위 검증도 없다(0.6 §4 후순위).
3. **범위가 넓다.** 관제, 터미널, git, 에디터, diff, 브라우저, 포트, 환경변수, 로그, 트랜스크립트, 메시지 버스를 한 사람이 유지한다. 패널 하나하나가 VS Code나 Windows Terminal과 비교된다. 기능을 늘릴수록 버그 면적이 커진다.
4. **"자동 실행 없음"의 양면.** 신중한 팀에게는 해자지만, 일반 개발자에게는 클릭이 많다는 불만으로 읽힌다. 원칙은 지키되, 승인 같은 반복 클릭은 대시보드 버튼 한 번으로 끝나게 해야 한다(0.6 §4 "승인·결정 게이트 버튼").

## 4. 권장 순서

기능을 더하기보다 **처음 쓰는 사람이 막히는 곳을 없애는 일**을 먼저 한다.

### P0 — 설치와 첫 10분

1. **GitHub Actions CI → SignPath 서명 → Tauri 자동 업데이트.** 서명 문서의 순서를 그대로 따른다. SmartScreen 경고가 사라지는 것만으로 이탈이 크게 준다.
2. **"빠른 시작" 경로.** 저장소 폴더를 고르면 기본 2세션(리드 + 개발)으로 바로 뜬다. 캐스팅, 페르소나, 임무는 나중에 알게 한다. 기본 세션 수는 4에서 2로 낮추는 것을 검토한다(한도 부담).
3. **첫 실행 안내 한 장.** "앱은 여기에만 씁니다 · 엔진 설정(`~/.claude`·`~/.codex`)은 고치지 않습니다" + 다른 도구 전역 지시 점검 결과(0.6 §14). 신뢰 문제와 서명 정책 요구를 같이 푼다.
4. **30초 데모 GIF를 README 맨 위에 둔다.** 영문 README를 GitHub 기본으로 할지도 정한다.

### P1 — 매일 쓰게 만들기

5. **트레이**(0.6 §1-1) — 창을 닫아도 에이전트가 계속 돈다.
6. **한도 표시**(F1) — 4명이 동시에 쓰면 한도가 가장 먼저 문제가 된다.
7. **한국어 버그**(PowerShell 인코딩, IME 실기 확인) — 처음 쓸 사람은 대부분 한국 사용자다.
8. **이슈 템플릿 + "진단 정보 복사" 버튼.** 앱은 네트워크로 아무것도 보내지 않는다는 원칙을 지키면서, 사용자가 버전, OS, 에이전트 CLI 버전, 최근 오류를 한 번에 복사해 이슈에 붙이게 한다.

### P2 — 사람을 모으기

9. **배포 채널:** winget, Scoop 등록. 서명이 끝나야 의미가 있다.
10. **첫 사용자 10~20명 모집:** GeekNews, 디스콰이엇, r/ClaudeAI, Claude Code 커뮤니티. 1주 뒤에도 켜는지(유지율)를 본다.
11. **기여 입구:** `CONTRIBUTING.md`와 good-first-issue 몇 건. 외부 기여자 20명은 Claude for Open Source 조건 중 하나이기도 하다.

### 하지 않을 것

- 새 패널과 새 화면(0.6 §4의 화면 4개 포함)은 첫 사용자 피드백이 오기 전까지 미룬다.
- VT 서버는 0.6 권장대로 0.7로 둔다. 트레이를 써 보고 불만이 나오면 그때 정한다.

## 5. 지금 배포해도 되는가

v0.1.0~v0.5.1이 이미 GitHub Releases에 공개돼 있다. 그러니 남은 질문은 **누구에게 알리느냐**다.

| 대상 | 판단 | 이유 |
|---|---|---|
| 지인과 커뮤니티 10~20명에게 "베타"라고 밝히고 공유 | **지금 하는 것이 맞다** | 0.5.0 QA 88행은 모두 고쳤다. 막히는 버그(B67·B69)는 실제 앱에서 재확인했다. 외부 피드백이 없는 것이 가장 큰 위험이다 |
| 넓은 공개 홍보 (GeekNews 메인, Show HN, Reddit) | **이르다** | 서명이 없어 경고창이 뜬다. 자동 업데이트가 없어 첫 사용자가 고친 버전을 받기 어렵다. 창을 닫으면 세션이 죽는다. 한글 IME를 실제 앱에서 확인하지 않았다. 첫인상은 한 번뿐이다 |

**베타 전에 할 것 (1~2일 분량)**

1. README 맨 위에 베타 표시, SmartScreen 우회 방법, 앱이 쓰는 곳과 쓰지 않는 곳(`~/.claude`는 고치지 않는다)을 적는다.
2. `.github/ISSUE_TEMPLATE`을 만들고, 피드백 채널(Discussions나 오픈채팅) 하나를 연다.
3. 한글 IME(B98)를 실제 앱에서 확인한다. 베타 사용자는 대부분 한국 사용자다.
4. 알려진 한계 목록을 릴리스 본문에 적는다. 창을 닫으면 세션 종료, PowerShell 파이프 한글 깨짐, 0.4.x 이하 실행 금지.

**넓은 공개 전에 할 것:** CI → 서명 → 자동 업데이트, 트레이, 빠른 시작, 한도 표시(§4 P0·P1).

**이날 검증:** `tsc --noEmit` 오류 0, `npm test` 23파일 135개 통과, `cargo test --lib` 151개 통과·1개 실패·1개 무시. 실패한 것은 `ports::tests::attributes_a_port_opened_inside_a_session_job`이다. 단독으로 다시 돌리면 통과한다. 다른 테스트와 병렬로 돌 때 10초 대기 안에 node가 포트를 열지 못한 것으로 보인다. 제품 결함이 아니라 테스트가 불안정한 것이다.

## 6. 한 줄 요약

경쟁력의 핵심(역할, 권한, 원장, 사람 관제)은 이미 있다. 막힌 곳은 **서명 없는 설치, 개념이 많은 첫 실행, 한도, 창을 닫으면 죽는 세션**이다. 이 넷을 고치고 외부 사용자 10명을 데려오는 일이 기능 하나를 더하는 일보다 효과가 크다.
