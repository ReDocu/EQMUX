- **코드 리뷰:** 서브 에이전트 셋이 커밋 안 된 수정을 Rust+backend · screens · components+i18n으로 나눠, 회귀와 효과 없는 수정을 찾았습니다.

## 먼저 고칠 것

1. **B248 — 릴리스 빌드에서 사람이 페인에 친 `eqmux who`·`ping`·`send`가 아무것도 출력하지 않는다.**
   - 원인: 릴리스 exe는 `windows_subsystem = "windows"`입니다(`src-tauri/src/main.rs:9`). 부모 콘솔에 붙는 함수는 사용법을 출력하는 경로에서만 부릅니다(`src-tauri/src/cli.rs:116-126`).
   - 증상: pwsh 7 페인에서는 출력이 사라지고 `$LASTEXITCODE`도 빕니다. PowerShell이 GUI 서브시스템 exe를 기다리지 않으므로 `send --wait`도 기다리지 않습니다.
   - 범위: 파이프를 붙이거나 에이전트(Bash 도구)로 부르면 정상입니다. 하지만 실기 확인 목록 Q1·Q2·Q7·Q11·K24는 사람이 페인에서 친다고 전제합니다.
2. **B249 — 환경변수 [편집] 칸은 약 3초, [원문 편집]은 약 11초 만에 저절로 닫힌다.** 원문에 고친 내용은 묻지 않고 사라집니다.
   - 원인: 워크스페이스를 옮길 때 편집 상태를 끄는 효과가 있습니다(`src/components/EnvPanelTab.tsx:55-67`, B147). 이 효과는 `scopeWorkspace()`를 통해 `tick()`을 따라가므로, 백엔드에서 방송이 올 때마다 값이 같아도 돕니다(`src/state.ts:188-191`).
   - 이 코드는 수정 라운드 전(HEAD)에도 있었습니다. 목 모드에서는 방송이 드물어 보이지 않았습니다.
3. **중간 7건 (코드 리뷰, 실기 미확인)**
   - B250: 스킬 미리보기의 상대 링크를 누르면 메인 웹뷰가 그 주소로 넘어갑니다. B242 수정에서 생긴 회귀입니다.
   - B251: commands.json `run`의 제어문자가 PTY로 그대로 들어가, readline 셸에서는 버튼 한 번에 명령이 실행될 수 있습니다(U145 불완전).
   - B252: B186 수정이 Rust가 실패를 삼키는 문제를 그대로 둡니다.
   - B253: 기본 터미널을 되살릴 때 셸 라벨이 실행 파일 이름으로 넘어갑니다(B202 경로).
   - B254: 전체 화면의 맨 셸에서 vim의 ESC가 막힙니다(B199의 부작용).
   - B270: BOM이 붙은 임무 파일에 선행 임무를 걸면 frontmatter가 망가집니다.
   - U172: 기본 터미널 구성 화면에 카드가 약속한 셸·이름 칸이 없습니다.

## 시험 환경과 되돌림

- **앱 데이터:** 실앱이 `%APPDATA%\com.eqment.eqmux`를 쓰므로 실행 전에 통째로 백업했습니다. 끝난 뒤 백업으로 되돌렸고, `diff -rq`로 똑같음을 확인했습니다.
  - 0.6 앱이 고친 것은 설정 기본 키·`firstRunSeen`·레이아웃·세션 DB 이전입니다. 여기에 제가 등록한 시험 워크스페이스가 더해졌습니다.
  - 테스트 뒤 상태는 지우지 않고 스크래치패드 `appdata-after-test`에 옮겨 두었습니다. 그래서 0.6 첫 실행 고지는 다음에 다시 뜹니다.
- **로그:** `~/.eqmux/logs`에는 이번 실행 로그가 남았습니다.
- **실기 확인에 쓴 도구:** 스크래치패드의 `cdp.mjs`(CDP로 eval·클릭·키·스크린샷)와 `clickt.mjs`입니다.
- **못 본 것:**
  - 에이전트(Claude Code) 세션을 띄우는 과업은 사용 한도를 쓰지 않으려고 하지 않았습니다. 승인함, 동시 편집, 임무 검토, 메시지 버스가 여기에 듭니다.
  - OS 폴더 고르기 창은 CDP로 조작할 수 없어 `ws_register`를 직접 불렀습니다.
  - 영어 화면은 설정 변경이 필요해 하지 않았습니다.
