## 요약

0.6.3을 `macos-support`에 합친 뒤 universal 번들을 로컬에서 빌드했다. 그 번들로 다시 봤다.

- **빌드:** CI의 macOS 작업과 같은 단계로 만들었다. 결과는 `EQMUX_0.6.3_universal.dmg`(12.2MB)다. 두 바이너리 모두 x86_64 + arm64이고, ad-hoc 서명이다. `codesign --verify`와 `hdiutil verify`가 통과했다. 경고는 `is_powershell` 미사용(cli.rs:176) 하나다(T115).
- **리드:** 실앱(Intel 기기, macOS 15)에서 팀 흐름 과업 10개를 했다(T101–T110).
- **CD:** GUI를 띄우지 않고 코드를 봤다. 시험을 돌리고, `_guard` CLI와 프런트 순수 함수를 실측했다. 번들 호환과 5라운드 행 재판정도 맡았다(T111–T119).

리드 21행과 CD 26행에서 2건을 합쳐 45행을 `interview.csv`에 이어 붙였다. 각 행의 `재현 절차·근거` 칸 앞에 `[0.6.3 macOS 6라운드 · 리드 LD-xxx]` 또는 `[… · CD CD-xxx]`를 적었다.

## 먼저 고칠 것

1. **B329(높음) — 오래된 WebKit에서 앱이 빈 창으로 뜬다(번들 근거, 실기 미확인).**
   - `gitWrite.ts:42·88`의 `split(/(?<=\n)/)`가 정규식 뒤돌아보기다. 0.6 Git 화면과 함께 들어왔다.
   - 이 파일은 지연 청크가 아니라 메인 번들(`dist/assets/index-CuDqcoWq.js`)에 들어 있다. 리드가 번들에서 2곳을 직접 확인했다.
   - Safari 16.4 미만 WebKit은 정규식 리터럴을 읽는 순간 번들 전체를 SyntaxError로 버린다. Git 화면만이 아니라 앱 전체가 뜨지 않고, 안내도 없다.
   - 영향을 받는 기기는 Safari를 올리지 않은 macOS 11·12와 macOS 13.0–13.2다. 앱은 `minimumSystemVersion` 11.0을 내건다.
   - 0.5.1 macOS 수정(`7581521`)이 `termPaths.ts`에서 같은 문법을 걷어 냈다. 회귀다.
   - 같은 번들에 Safari 15.4 이상 API(`.at` 3곳 · `Object.hasOwn` 1곳)도 있다(T118).
   - 뒤돌아보기 없이 고쳐 쓰고, 다시 들어오면 시험이 실패하게 한다(S45).
   - **이번에 빌드한 0.6.3 dmg도 같은 문제를 안고 있다.** 이 dmg를 macOS 11–13.2 사용자에게 주면 안 된다.
2. **B330(높음) — 입력칸이 아직 문장부호를 바꿔 적는다. 이제 git 기록에도 남는다(실기 확인).**
   - 5라운드 B313이 그대로다. 임무 목표에 친 `--done "ok" … it's … --`가 `—done “ok” … it’s … —`로 바뀌었다.
   - 임무 이름 `r6-quote`는 첫 글자가 대문자로 바뀌어 `R6-quote`가 됐다.
   - 0.6에 새로 생긴 git 커밋 메시지칸도 같다. `add sub() -- r6 "qa" commit`이 `add sub() — r6 “qa” commit`으로 커밋됐다(`86b411c`, od로 바이트 확인).
   - 커밋 메시지는 amend해야 고칠 수 있고, push하면 남는다.
   - 명령·경로·커밋 메시지를 받는 칸은 `autocorrect`·`autocapitalize`·`spellcheck`를 끈다. 앱 도메인의 Quote·Dash 치환도 끈다(S30).
3. **B331 — 역할 세션을 띄울 때마다 같은 초 안에 한 번 끄고 다시 띄운다(실기 확인).**
   - 페인 로그에 `session start → ^D → session exit → session start`가 같은 초 안에 이어진다.
   - 이벤트 피드에 사람이 하지 않은 '사용자 요청으로 종료'가 찍힌다. 이 문구는 `pty_kill`(lib.rs:1040)만 남긴다.
   - 첫 프로세스가 남긴 `^D`가 페인 맨 위와 재기동 뒤 재생에 보인다. 5라운드 B311의 `^D`도 같은 뿌리로 보인다.
4. **B332 — 전체 화면 Claude는 화면 기록이 남지 않는다(공용, 재생 공백은 실기 확인).**
   - 0.6.1은 위로 밀려난 줄만 저장한다. 0.6.2부터 Claude Code를 늘 대체 화면으로 띄운다(`CLAUDE_CODE_NO_FLICKER=1`).
   - 그래서 재기동 재생에는 `^D`와 resume 안내만 나온다.
   - 에이전트끼리 쓰는 `eqmux read`도 스크롤백 DB만 읽는다. Claude 팀원을 읽으면 이유 없이 빈 결과가 온다(CD 코드 근거, 실기 미확인).
   - read와 재생은 트랜스크립트 원본으로 잇는다. 최소한 '전체 화면이라 기록이 없다 — `eqmux send`로 물어라'를 덧붙인다.
5. **B333 · B334 — macOS 조건에서 0.6 기능이 어긋나는 자리(코드 근거, 실기 미확인).**
   - **B333:** `_guard`는 엔진 작업 폴더로 `temp_dir()/claude`를 열어 둔다. macOS에서 그 값은 `$TMPDIR`(/var/folders/…)다. 하지만 macOS의 Claude Code는 `/private/tmp/claude-<uid>/` 아래에 백그라운드 출력을 둔다. 역할 세션이 그 출력 파일을 Read로 열면 '저장소 밖'으로 거부된다.
   - **B334:** 창을 Dock으로 숨기면 웹뷰 박동 타이머가 잠들 수 있다. 180초 끊기면 `WEBVIEW-SILENT`로 표시된다. 그 뒤의 Dock › 종료 · ⌘Q · 메뉴 막대 [전부 종료]는 확인 없이 세션을 모두 끈다. 앱은 App Nap을 끄지 않는다. 종료 요청이 오면 먼저 창을 보이고 묻는다.

- **U216–U219:**
  - 드롭한 경로가 작은따옴표로 들어가 공백·아포스트로피에서 링크가 끊긴다(U207 보강).

## 한계

- **P106:** CD는 GUI를 띄우지 않았다(단일 인스턴스 잠금). B329 · B332(read) · B333 · B334는 코드로만 판정했다. 다음 실기에서 볼 목록은 P106에 있다.
