## 1. 범위 — 하는 것과 안 하는 것

**한다**

- 레이아웃 트리 자료구조 (분할 노드 / 잎 노드, 방향, 비율)
- JSON 직렬화·역직렬화 + **왕복 검증**(저장 → 복원 → 같은 트리)
- 상태 파일 읽기·쓰기 배선 (`config.rs`의 `Paths.state_file`)
- 트리 조작 API — 분할·닫기·비율 변경. **호출자는 아직 없어도 된다**

**안 한다 (다음 작업들이다)**

| 미루는 것 | 어디로 |
|---|---|
| 화면에 실제로 분할해 그리기 | `S2-2` |
| 분할선 드래그 | `S2-3` |
| 포커스 이동·줌 | `S2-4` |
| 탭·워크스페이스 | `S2-5`·`S2-6` |
| 30초 자동 저장 주기 | `S3-4` (지금은 저장·복원 **함수**만 있으면 된다) |

> 범위를 좁게 잡은 이유: `S2-2` 직후에 **관문 A2**가 온다.
> 모델이 흔들린 채로 UI를 얹으면 A2 미달 시 **어디를 고쳐야 하는지 안 갈린다.**

## 2. 설계 제약 — 나중에 못 고치는 것부터

### 2-1. 🔴 **스키마에 버전 필드를 처음부터 넣는다**

[FEATURES.md](FEATURES.md) D절이 못 박은 항목이다 — *"버전 없이 시작하면 그때 사용자 세션이 다 날아갑니다."*
`S3-4`가 이 포맷을 그대로 쓰고, `S2-5`(탭)·`S2-6`(워크스페이스)에서 **필드가 반드시 늘어난다.**

**모르는 버전을 만났을 때의 행동까지 정해서 문서에 적어 주십시오.** 셋 중 하나면 됩니다 —
① 거부하고 빈 레이아웃 ② 읽을 수 있는 만큼만 ③ 백업 후 초기화.
**행동이 안 정해진 버전 필드는 숫자만 있는 장식입니다.**

### 2-2. **잎(leaf)을 "터미널"로 굳히지 말 것**

지금 잎은 터미널 하나뿐입니다. 그런데 [BACKLOG.md](BACKLOG.md) **B1(프로젝트 폴더 탐색기)** 이
2차 후보로 올라와 있고, 그게 붙으면 **터미널이 아닌 패널**이 트리에 들어옵니다.

> 잎에 `kind` 한 칸만 있으면 됩니다. **지금 안 쓰더라도 그 칸이 없으면 2차에 트리를 다시 짭니다.**
> B1은 아직 팀장님 회신 대기라 **구현하지 말고 자리만 비워 두십시오.**

### 2-3. **백엔드는 이미 다중 PTY를 듭니다 — 새로 만들지 마십시오**

`pty.rs`의 `PtyManager`가 `HashMap<String, Session>`이고 `spawn`/`write`/`resize`/`kill`/`list`가
전부 **id 기반**입니다(`:73-180`). 다중 터미널의 백엔드는 이미 있습니다.
**없는 것은 프런트입니다** — `main.ts`가 터미널을 하나만 만듭니다.

→ 트리의 잎이 **PTY id를 든다.** 잎이 PTY를 소유하지 않습니다.
   잎이 사라질 때 `pty_kill`을 누가 부르는지 **소유권을 문서에 한 줄로 적어 주십시오.**

### 2-4. **상태 파일은 `config.rs`의 경로 체계를 씁니다**

`Paths.state_file` = `EQMUX_STATE_PATH` 또는 `<app_data>/state.json`입니다(`config.rs:58`).
**측정용 격리 스위치(`isolated`)를 존중해야 합니다** — 안 그러면 해원의 측정이
라이브 세션 상태를 덮어씁니다. [BASELINE.md](BASELINE.md) §1이 그걸 막으려고 만든 장치입니다.

### 2-5. **상태 파일이 커지지 않게 합니다 (KR2)**

`D9`(스크롤백 내용 복구)는 **제외로 확정**된 항목입니다 — 디스크 상한 방어입니다.
레이아웃 트리에 화면 내용이 새어 들어가지 않는지 보십시오.
`S2-1b`에서 확인한 앱 데이터가 **13.75 MB / 상한 60 MB**입니다. 여유는 있지만 이 파일은
**30초마다 쓰이게 될 파일**입니다(`S3-4`).
