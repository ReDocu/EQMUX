## 1. 무엇이 생겼나

`S2-1`의 트리를 처음으로 **화면에 그린다.** 분할·닫기 버튼이 패널 막대에 있고,
비율은 균등 고정이다(드래그는 `S2-3`).

| 파일 | 역할 |
|---|---|
| `src/panels.ts` | **새 파일.** 트리 → 중첩 flex DOM 렌더 · 패널 생명주기 · `--panes` 분할 · 계측용 정적 그리드 |
| `src/main.ts` | 기동 분기 재구성: 폭 계측 > 지연 계측 > 패널 검증 > 일반. 단일 터미널 코드가 매니저 호출로 바뀜 |
| `src/terminal.ts` | `TerminalHandle.dispose()` 추가(§2-1) · GPU 판별 1회 캐시(§3-2) · 컨텍스트 유실 콜백 |
| `src/pty.ts` | `pid` 게터만 추가 (상태줄용) |
| `src/latency.ts` | 요약 JSON `config.panels` 추가 — 1패널 값과 4패널 값이 섞이지 않게 |
| `src-tauri/src/lib.rs` | `PanesConfig` 배선 + 충돌 경고 + `panes_probe_finish` 등록 |
| `src-tauri/src/commands/probe.rs` | `panes_probe_finish` — 통과 여부가 종료 코드(0/1) |
| `src-tauri/src/commands/system.rs` | `app_info`에 `panes` 노출 |
| `index.html` · `src/styles.css` | `#term` → `#layout` · 패널/분할 스타일 (헤어라인 경계) |

### 렌더 방식 — 왜 이렇게

- **잎 패널 DOM은 잎 id로만 캐싱**하고, 분할 껍데기는 조작마다 새로 짠다.
  분할(split-N) id는 `normalize`가 걷어내며 사라지기 때문이다(`LAYOUT-S2-1.md` §7-4).
  잎 패널 요소는 새 위치로 **옮겨질 뿐** 파괴되지 않는다 — xterm 버퍼·WebGL 컨텍스트가 산다.
- 트리의 정본은 백엔드다. 조작(분할/닫기) 후 `layout_get`으로 다시 읽어 화면을 맞춘다.
  프런트 사본으로 먼저 움직이는 것은 드래그(`S2-3`)부터다.
- **균등 고정**: 같은 방향 분할에 형제로 끼면 백엔드는 낀 칸만 반으로 나눠 [¼,¼,½]이 된다.
  분할 직후 그 분할 하나만 `layout_set_weights`로 등분해 되돌린다.

## 2. 닫으면 진짜로 없어지는가 (§2-1)

```
닫기 버튼 → layout_close(leaf_id)     ← 백엔드가 트리에서 빼고 PTY를 죽인다 (S2-1 소유권 규칙)
          → layout_get → reconcile    ← 트리에서 사라진 잎마다:
              PtyLink.dispose()          이벤트 구독 해제 (+이미 죽은 PTY kill 재시도 — 무해)
              TerminalHandle.dispose()   WebglAddon.dispose → term.dispose → WEBGL_lose_context
              panel.el.remove()          DOM 제거
```

- `WEBGL_lose_context.loseContext()`를 **명시적으로** 부른다 — dispose가 캔버스를 떼도
  GPU 자원은 GC를 기다린다. A2가 유휴 RAM을 재므로 기다리지 않는다.
- 새로고침(F5)이 남긴 죽은 `pty_id` 참조는 부트 때 `pty_kill` + `layout_attach_pty(null)`로 끊는다.
  크래시로 살아남은 고아도 같은 경로로 죽는다.

### 2-1. 첫 실행에서 잡힌 누수 — `PtyManager::kill`

`--panes-probe` 첫 실행이 **미달**을 냈다: 3개를 닫았는데 `pty_list`가 4개 그대로였다.

원인은 `S1-2`의 `kill()`이다 — 자식만 죽이고 세션은 맵에 남긴다. 걷어내기는 읽기 스레드의
EOF → `reap()`인데, ConPTY는 **마스터가 닫혀야** 읽기 파이프를 놓는 경우가 있다.
reap은 EOF를 기다리고 EOF는 drop을 기다린다 — 원형 대기. 죽인 셸의 ConPTY·conhost가
프로세스가 사는 동안 유휴 RAM으로 남는다. **A2가 쟀다면 구현이 아니라 이 누수를 쟀다.**

수정: `kill()`이 세션을 **맵에서 먼저 꺼내고** 죽인다. drop이 마스터를 닫고, 읽기 스레드는
EOF로 끝난다. 자연 종료(`exit` 입력) 경로는 그대로다 — 그쪽은 reap이 걷어낸다.
(`pty.rs`는 이안 대행 작성분이지만 A 터미널 코어 관할이라 세아가 직접 고쳤다 — #18 규칙)

## 3. 관문 리스크 둘 — 어떻게 막았나

### 3-1. 폰트 스택 (§2-3 · A-2 회귀)

패널이 몇 개든 xterm 옵션은 **`createTerminal` 한 곳**에서만 만들어진다.
`PanelManager`는 `fontStack`을 생성자에서 한 번 받아 모든 패널에 그대로 넘긴다.

### 3-2. WebGL 컨텍스트 (§2-2 · A-3 회귀)

- **찾은 것**: `attachWebgl`이 GPU 문자열 확인용 **별도 캔버스에 컨텍스트를 하나 더** 딴 채
  놓지 않고 있었다. 1패널에선 2개라 무해했지만 4패널이면 8개 — 브라우저 동시 상한(보통 16)을
  우리가 앞당기는 구조였다. → 판별을 **프로세스당 1회 캐시**로 바꾸고, 확인용 컨텍스트는
  읽은 즉시 `loseContext()`로 놓는다. 이제 **WebGL 컨텍스트는 패널당 정확히 1개**다.
  (DOM 캔버스 요소는 패널당 2장이 실측됐다 — 컨텍스트를 잡는 건 애드온 캔버스 1장이고,
  `--panes-probe`의 캔버스 검증은 장수를 박지 않고 패널 수에 비례로 잰다)
- 유실은 생성 시점이 아니라 나중에 온다 — `onContextLoss`가 패널 표시등(●)을 실시간으로
  뒤집고 stderr에 남긴다. 조용한 캔버스 폴백은 없다.
- 패널별 렌더 판정은 `report_renderer`의 `panels[]`로도 나간다 — 화면 없이 확인 가능.

## 4. 무인 검증 — 플래그 셋

| 플래그 | 무엇 | 종료 코드 |
|---|---|---|
| `--panes=N` | 기동 직후 제일 넓은 패널을 긴 축으로 잘라 N개(4→2×2). 창은 열려 있는다 | — |
| `--panes-probe` | 4분할 → 렌더러 생존 확인 → 전부 닫기 → **남긴 만큼만 있는지** 확인 후 종료 | 통과 0 · 미달 1 |
| `--latency-probe --panes=4` | **4분할 상태의 A-3.** 백엔드·PTY 없이 화면만 나눈다(§2-4 격리 유지) | 기존과 동일 |

`--panes-probe`의 판정 항목: 패널 수 도달 · PTY=패널 수 · 캔버스=패널 수 · 렌더러 생존 ·
닫은 뒤 잎 1 · **`pty_list` 길이 1** · **죽인 id가 목록에 없음** · **캔버스 1**.
"비어 있음"이 아니라 "남긴 만큼만"인 이유: 마지막 잎은 규격상 닫지 않는다(`layout.rs`).

## 6. 관문 A2 재현 방법 (인계 · §3-1)

```powershell
# 격리 인스턴스 + 4분할 재현 (해원용) — 손으로 나눌 필요 없음
$iso = "$env:TEMP\eqmux-a2-iso"
$env:EQMUX_STATE_PATH     = "$iso\state.json"
$env:EQMUX_WORKSPACE_ROOT = "$iso\workspace"
$env:EQMUX_DATA_DIR       = "$iso\webview"
& <repo>\src-tauri\target\release\eqmux.exe --panes=4
# 창이 뜨고 2×2 · 셸 4개. 이 상태가 A-4 측정 대상("터미널 4개 유휴")이다.
# 상태 파일은 격리 경로에만 생긴다. 측정 전 눈으로 확인: 상단 배지 "격리 인스턴스".
```

- 앱은 레이아웃을 **저장하지 않는다** — `layout_save`는 여전히 호출자가 없다(`S3-4` 몫).
  좁게 자른 결정이다: 자동 저장 파일 크기·빈도는 아직 아무도 안 쟀다.
- 측정 중 분할·닫기를 누르지 말 것. 재현 조건이 손 조작으로 오염된다.

## 7. 다음 사람이 밟을 함정

1. **`--panes-probe`도 상태 경로를 읽는다**(쓰지는 않는다). 라이브 상태에 잎이 4개면
   `--panes=4`는 아무것도 안 나눈다 — 격리 경로에서 돌리면 항상 1→4라 재현이 같다.
2. **패널을 늘렸으면 컨텍스트도 늘었다.** 패널당 정확히 1개(§3-2). 캔버스 수와 패널 수가
   다르면 어딘가 폴백했거나 샜다 — `--panes-probe`의 `canvas_per_panel`이 그걸 잡는다.
3. **`dispose()`를 안 부르는 제거 경로를 만들지 말 것.** 트리에서 잎을 빼는 모든 길은
   `reconcile`을 지나야 한다. DOM만 지우면 xterm 리스너와 컨텍스트가 산 채로 남는다.
4. **계측 모드는 layout_* 명령을 부르지 않는다**(§2-4). 정적 그리드는 화면일 뿐
   트리가 아니다 — 계측 중 분할 버튼도 없다.
